# 배포 패키지 구성·무결성 확인 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 발송처가 라이브러리를 **받아서 바로 쓸 수 있는 하나의 묶음으로 구성·전달하고, 받은 쪽이 그것이 허브 산출물인지 확인**하는 처리다. 런타임 요청 처리가 아니라 **배포 절차**이며, 허브 애플리케이션 안에서 실행되지 않는다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 3 — "발송처에 전달하는 **배포 패키지**(라이브러리 파일·호출 샘플·규약 버전 표기)와 **규약 적합성 테스트 벡터**를 함께 제공한다."
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §1 — "**배포 무결성** — 발송처가 받은 파일이 허브가 낸 산출물인지 확인할 수 있어야 한다."

### 레이어 대응 (FE/BE 구분이 성립하지 않는 이유)

**본 프로세스는 허브 애플리케이션 안에서 실행되지 않는다.** 허브 운영자가 산출물을 묶어 발송처에 전달하고 발송처가 확인하는 **배포 절차**이며, 브라우저 화면도 허브 서버 처리도 없다(내려받기 화면·포털을 두지 않는다 — [`../screens/spec-screens.md`](../screens/spec-screens.md) §화면을 갖지 않는 IA 노드). 로직 실행 순서의 두 하위 섹션을 아래로 대응시킨다([`spec-process.md`](spec-process.md) §라이브러리 프로세스의 레이어 대응).

- **"FE 측 처리" 자리 → 절차 수행 주체**(허브 운영자·발송처) — `C` 라벨.
- **"BE 측 처리" 자리 → 패키지 산출물 생성 절차**(빌드·구성·체크섬 생성) — `L` 라벨.

### 진입점 및 진입 조건

- **진입점**: 라이브러리 릴리스 시점의 **배포 절차 실행**(허브 운영자). HTTP 접점·명령 진입점을 두지 않는다.
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.** 배포 절차의 접근 통제는 저장소·전달 수단의 문제이며 허브 애플리케이션의 표면이 아니다.
- **사전 검증**: ① 라이브러리 산출물 빌드 완료(`PROC-401`·`PROC-402` 구현) ② 규약 테스트 벡터 생성·대조 통과(`PROC-404`) ③ **규약 개정 시 라이브러리와 허브를 함께 배포**하는지 확인(`SEC-001-12`) ④ **잠정값 상태의 운영 배포가 아닌지** 확인(`OPS-001-03`).
- **배포 전달 경로**(파일을 어떤 수단으로 전달할지)는 build 단계에서 확정한다.

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | 라이브러리 산출물 | 파일 | Y | 산출물명은 상수표가 정본(`<LIB_BIN>`) |
| 입력 | C# 호출 샘플 | 파일 | Y | 콘솔 형태. 검증 하네스와 같은 형태를 쓴다 |
| 입력 | 규약 테스트 벡터 | 파일 | Y | `PROC-404` 산출물([`MDL-019`](../datas/model_MDL-019-022.md) 묶음) |
| 입력 | 규약 버전·기준 URL 값 | 문자열 | Y | 사용 안내에 채운다. **본 사양에 값을 복제하지 않는다** |
| 출력 | 배포 패키지 | 파일 묶음 | - | [`MDL-020`](../datas/model_MDL-019-022.md) — **정확히 5 구성** |
| 출력 | 체크섬 파일 | `SHA256SUMS.txt` | - | 각 줄 `<소문자 16진수 64자>  <패키지 내 상대 경로>` |
| 출력 | 무결성 확인 결과 | 일치·불일치 | - | 발송처가 수령 시 판정 |

### 연관 데이터 및 외부 호출

- **호출 API**: 없음.
- **데이터 조회 대상**: 없음.
- **데이터 변경 대상(CRUD)**: 없음 — 저장 대상 셋 어디에도 기록하지 않는다.

### 실행 제약사항

- **트랜잭션 경계**: **없음(절차).** 배포는 데이터베이스 트랜잭션의 대상이 아니다.
- **동시성 제어**: 릴리스 절차는 한 번에 하나만 수행한다. 동시 릴리스를 가정하지 않는다.
- **멱등성**: 같은 산출물에서 같은 패키지·같은 체크섬이 나온다. 재실행이 안전하다.
- **성능 요구**: 사람이 수행하는 절차라 응답 시간 요구를 두지 않는다.
- **보안 요구**: **자가진단 경로 값을 패키지 어디에도 담지 않는다**(`SEC-003-02`) — 경로 비공개는 **노출 범위를 줄이는 장치**이며 반복 시도를 막는 완화 장치가 아니다(`OPS-002-06`). 값이 패키지에 남으면 그 범위 축소마저 사라진다. 발송처에 경로를 알리는 수단은 배포 안내가 아닌 **별도 비공개 전달**이며 그 절차는 배포 절차가 정한다. **테스트 벡터에 실사용자 값을 넣지 않는다**(`DATA-001-02`).
- **무결성 수단**: **SHA-256 체크섬 파일**. 어셈블리 서명은 코드 서명 인증서의 조달·갱신이 필요해 이번 범위의 비용 균형에 맞지 않으며, 도입은 후속 보완 사안이다.

### 로직 실행 순서

#### FE 측 처리 (의사코드) — 절차 수행 주체

```
C1. 산출물 수집 (허브 운영자)

  진입 트리거: 라이브러리 릴리스 결정 시점 (신규 배포 또는 규약 개정)
  사용 값:
    libFile     = 라이브러리 파일 (산출물명은 상수표 <LIB_BIN> 가 정본)
    sampleProj  = C# 호출 샘플(콘솔) — 검증 하네스와 같은 형태
    vectorFile  = PROC-404 가 만든 protocol-test-vectors.json
  선행 확인 (절차 게이트):
    PROC-404 의 벡터 재생성·대조가 통과했는가 (POL SEC-001-12)
    규약 개정이면 허브도 함께 배포되는가 — 한쪽만 배포하려는 경우 절차를 중단한다
  → L1 로 넘어간다

C2. 전달 (허브 운영자)

  진입 트리거: L4 패키지 확정 후
  선행 확인 (절차 게이트):
    잠정값 상태의 운영 배포가 아닌가 (POL OPS-001-03)
    사용 안내의 기준 URL 기재란이 그 시점 확정 값으로 채워졌는가
  전달: 배포 패키지를 발송처에 파일로 전달한다 (전달 수단은 build 단계 확정)
  // 내려받기 화면·포털을 두지 않는다 — 허브의 공개 표면을 늘리지 않는다

C3. 무결성 확인 (발송처)

  진입 트리거: 패키지 수령 직후
  절차:
    표준 도구로 SHA256SUMS.txt 를 대조한다
    if (전 구성 파일 일치)   → C4 로 진행
    else                      → 그 파일을 쓰지 않고 재수령을 요청한다
                                // 런타임 응답이 아니므로 EX 코드를 갖지 않는다
  실패 처리: 불일치 파일을 참조·실행하지 않는다

C4. 통합 (발송처)

  절차:
    자기 C# 프로젝트에서 라이브러리를 참조한다
    사용 안내 §환경별 허브 기준 URL 기재란에서 자기 환경 값을 확인해 호출 인자로 쓴다
    규약 버전 대조 (BR-017):
      hubVersion = 자가진단 API(PROC-204) 응답의 protocolVersion
      if (MAJOR(hubVersion) != MAJOR(InterlockRequestBuilder.ProtocolVersion))
          → 비호환. 새 패키지를 수령해 재배포한다
      else → 호환 (MINOR 차이는 그대로 사용)
    테스트 벡터 대조 (PROC-404 C1) — 불일치면 통합을 멈추고 원인을 확인한다 (BR-024)
  결과: 통합 완료 → PROC-401·PROC-402 를 호출할 수 있는 상태
```

#### BE 측 처리 (의사코드) — 패키지 산출물 생성 절차

```
L1. 패키지 구성 — POL SEC-001-12 (transform)

  package.files = [
      libFile,                    // ① 라이브러리 파일
      sampleProj,                 // ② C# 호출 샘플(콘솔)
      usageGuide,                 // ③ 사용 안내 (L2 에서 만든다)
      vectorFile,                 // ④ 규약 테스트 벡터
      checksumFile ]              // ⑤ 무결성 확인 수단 (L3 에서 만든다)
  // 정확히 다섯이다. 여섯 번째 구성을 늘리지 않는다 (MDL-020)

L2. 사용 안내 구성 — POL OPS-001-04 · SEC-003-02 (transform)

  usageGuide 는 아래 여섯 절을 고정으로 갖는다
    1) 규약 버전 표기와 호환 판단 방법 (MAJOR 불일치 = 비호환)
    2) 공개 진입점 — 두 함수의 시그니처·인자 설명·반환값
    3) 오류 사유 코드 목록 (자가진단과 같은 값 체계)
    4) 환경별 허브 기준 URL 기재란
         패키지를 만들 때 CLAUDE.env.md §연동 구성 상수 — 발송처 호출 입력 값에서
         그 시점의 확정 값을 가져와 채운다. 본 사양에는 값을 적지 않는다
    5) 무결성 확인 절차 — 체크섬 대조 방법
    6) 규약 적합성 확인 절차 — 테스트 벡터 대조와 자가진단 호출
  금지:
    자가진단 경로 값(<SELFCHECK_PATH>)을 어디에도 담지 않는다 (POL SEC-003-02)
    규약 세부 값(알고리즘·정규화·인코딩)을 복제하지 않고 정책 문서를 참조하게 한다

L3. 무결성 수단 생성 (transform)

  for each f in package.files 중 checksumFile 을 제외한 전부:
      digest = SHA256(f 의 바이트열) → 소문자 16진수 64자
      checksumFile 에 한 줄 추가: "<digest>  <패키지 내 상대 경로>"
  // 구성 파일 목록과 체크섬 파일을 같은 절차에서 만들어 항상 동기 상태를 유지한다

L4. 패키지 확정

  return package                                // MDL-020
  // 저장 대상 셋 어디에도 기록하지 않는다 · 실행 이력 저장소를 두지 않는다
  후속 이벤트 발행: 없음
```

| 코드 | 발생 조건 | 처리 방향 | 결과 |
|------|----------|----------|------|
| BR-017 | `C4` 규약 버전 대조 | MAJOR 불일치 → 비호환(재수령·재배포) / MINOR 차이 → 호환 | 재배포 필요 여부 |

### 실행 결과

- **정상 결과**: [`MDL-020`](../datas/model_MDL-019-022.md) 배포 패키지 1벌(5 구성) + 체크섬 파일. 발송처의 통합 완료.
- **실패 결과**: 절차 중단(체크섬 불일치·규약 동시 배포 위반·잠정값 배포·벡터 불일치). **부분 배포를 하지 않는다.**
- **후속 트리거**: PROC-401·PROC-402 — 발송처가 라이브러리를 호출할 수 있게 된다. PROC-204 — 규약 버전 대조와 통합 확인.

### 의존 프로세스

- **호출 관계**: PROC-404(산출물 동봉).
- **선행 관계**: PROC-401 · PROC-402(구현 완료) · PROC-404(벡터 생성·대조 통과).
- **이벤트 관계**: PROC-401 · PROC-402 · PROC-204.

### 구현 가이드

- **구성 파일 목록과 체크섬 파일을 같은 절차에서 만든다.** 따로 만들면 동기가 깨져 대조가 실패한다.
- **호출 샘플과 검증 하네스를 같은 형태로 둔다.** 산출물이 하나로 줄고, 발송처가 복사해 바로 실행할 수 있다.
- **자가진단 경로 값을 패키지에 담지 않는다.** 경로 비공개는 **노출 범위를 줄이는 장치**이고(`OPS-002-06`) 패키지는 발송처 쪽에 남는 문서라, 값이 섞이면 그 범위 축소가 무너진다.
- **규약 세부 값을 안내에 복제하지 않는다.** 정책 문서를 참조하게 해야 규약 개정 시 안내를 다시 쓰지 않아도 된다.
- **기준 URL 기재란은 값을 문서에 박는 자리가 아니다.** 패키지를 만드는 시점의 확정 값을 상수 단일 출처에서 가져와 채우고, 값이 바뀌면 안내만 갱신한다.
- **여섯 번째 구성을 늘리지 않는다.** 늘리면 체크섬·안내·검증 절차가 함께 흔들린다.
