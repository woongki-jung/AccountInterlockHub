# 연동 지표 집계 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 추적 레코드가 보관 기간이 지나 지워진 뒤에도 **사용량·성공률을 낼 수 있도록** 개인정보 없는 일자별 건수를 누적하는 처리다. 추적 키를 담지 않아 개별 연동으로 환원되지 않으므로 삭제 대상이 아니다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 11 — "**연동 지표 집계**: 일자 단위 요청·성공·실패 건수만 누적한다. 추적 키를 포함하지 않아 개별 연동으로 환원되지 않으며 보관 기간 삭제의 영향을 받지 않는다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §성과 지표 — 지표 정의와 산출 근거. **목표치 수치는 그 문서를 참조하며 본 사양에 옮겨 적지 않는다.**

### 진입점 및 진입 조건

본 프로세스는 외부 표면을 갖지 않는다. **상위 프로세스가 계수 계기(`kind`)를 붙여 호출**한다.

| `kind` | 호출 지점 | 갱신 대상 |
|---|---|---|
| `REQUEST` | PROC-301 `B3`(레코드 최초 생성) | `request_count` +1 |
| `UNIDENTIFIED_FAILURE` | PROC-101 `B5` · PROC-102 `B4b` · PROC-104 `B2` | `request_count` +1 **및** `decrypt_failed_count` +1 |
| `RESULT` | PROC-301 `B4`(결과 확정) | 해당 결과 구분 카운터 +1 |

- **호출되지 않는 자리**: 재진입 · 본인확인 재시도 · 확정 결과 재안내(`BIZ-005-03`) · 자가진단 호출(EXC-BIZ-11) · 완료 콜백 수신.
- **`exec` 를 넘기지 않는 자리는 `UNIDENTIFIED_FAILURE` 하나뿐이다.** 그 세 호출 지점(PROC-101 `B5` · PROC-102 `B4b` · PROC-104 `B2`)은 호출측이 경계를 열지 않아 **넘길 실행 문맥이 없다** — 표기 누락이 아니라 사양이며, `exec` 인자를 나중에 채워 넣지 않는다([`../functions/function_FN-012-013.md`](../functions/function_FN-012-013.md) FN-013 §시그니처). `REQUEST`·`RESULT` 는 반대로 **`exec` 전달이 참여의 성립 조건**이다.
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.** 상위 프로세스 안에서 실행된다.
- **`B5` 지표 산출**은 런타임 호출이 아니라 **저장분을 직접 확인해 수행**하는 읽기 절차다(허브 운영자 — `SVC-016` 사용자 정의).

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | `kind` | string | Y | `REQUEST` · `UNIDENTIFIED_FAILURE` · `RESULT` |
| 입력 | `resultCode` | string | N | `kind = RESULT` 일 때만 필수. 결과 구분 3종(`BIZ-001-01`) |
| 입력 | `at` | datetime | Y | 계기 발생 시각(시간대 유지) — 일자 산출 기준 |
| 입력 | `exec` | TxExecutor | N | 호출측이 연 트랜잭션의 커넥션·실행자. **`UNIDENTIFIED_FAILURE` 외 전부 필수** — 본 프로세스의 모든 문과 하위 FN(FN-013)을 이 실행자 위에서 수행하며 커넥션을 스스로 얻지 않는다. `UNIDENTIFIED_FAILURE` 는 호출측이 경계를 열지 않는 자리라 넘길 실행 문맥이 없고, `B3`·`B4` 의 UPSERT 한 문장이 그 자체로 원자적이다 |
| 출력 | — | — | - | **반환값 없음.** 실패는 예외로만 알린다 |

### 연관 데이터 및 외부 호출

- **호출 API**: 없음.
- **데이터 조회 대상**: 없음(계수 경로). **지표 산출(`B5`)만 기간 조회를 수행한다.**
- **데이터 변경 대상(CRUD)**: [`ENT-003`](../datas/data_ENT-003.md) 원자적 UPSERT 1건. **DELETE 경로가 없다**(`DATA-002-03`).

### 실행 제약사항

- **트랜잭션 경계**: **호출측 트랜잭션에 참여**한다. 레코드 기록(PROC-301)과 함께 커밋되거나 함께 되돌려져야 이중 계수·누락이 생기지 않는다(`SVC-014` F-008). **참여는 호출측이 넘긴 `exec`(같은 커넥션·실행자) 위에서만 성립한다** — 본 프로세스는 `BEGIN`·`COMMIT`·`ROLLBACK` 을 수행하지 않고 커넥션도 스스로 얻지 않으며, 받은 `exec` 를 하위 FN-013 에 그대로 넘긴다. **`UNIDENTIFIED_FAILURE` 만 예외로 참여할 경계가 없어 `exec` 없이 단독 갱신한다**(§진입점 및 진입 조건).
- **동시성 제어**: **삽입과 증가를 한 문장(원자적 UPSERT)으로 처리**한다. 일자 행을 조회한 뒤 없으면 만들고 있으면 더하는 2단계로 나누면 동시 요청에서 계수가 유실된다.
- **멱등성**: **본 프로세스는 멱등하지 않다** — 부르면 항상 +1 이다. 멱등은 호출측이 보장한다(레코드 최초 생성·결과 최초 확정에서만 호출). **추적 키를 알 수 없는 실패는 같은 요청인지 판정할 수단이 없어 시도마다 계수되며, 이 중복은 수용 한계다**(`BIZ-005-05`).
- **성능 요구**: UPSERT 1회. 감산·재계수·이동이 없다.
- **보안 요구**: **인증 없음**(`AUTH-001`). 추적 키·개인정보를 담지 않는다 — **담을 컬럼이 스키마에 없는 것이 1차 방어다**(`DATA-001-01`).

### 로직 실행 순서

#### FE 측 처리 (의사코드)

**사용자 화면이 없다.** 조회 화면·조회 API 를 두지 않으며 지표 산출은 저장분 직접 확인이다. FE 자리에는 **호출측(상위 프로세스와 지표를 읽는 허브 운영자)** 처리를 `C` 라벨로 적는다.

```
C1. 계수 계기 전달 (상위 프로세스)

  진입 트리거: 아래 세 시점 중 하나
    ① PROC-301 B3 이 레코드를 새로 만든 직후          → kind = 'REQUEST'
    ② PROC-101 B5 · PROC-102 B4b · PROC-104 B2 실패    → kind = 'UNIDENTIFIED_FAILURE'
    ③ PROC-301 B4 가 결과를 확정한 직후                → kind = 'RESULT' + resultCode
  트랜잭션: ①·③은 상위가 연 경계 안에서 호출하고 그 커넥션·실행자를 exec 로 함께 넘긴다
            — 넘기지 않으면 별도 커넥션에서 갱신돼 참여가 성립하지 않는다 (성립 조건이다)
            ②는 상위가 경계를 열지 않는 자리라 넘길 실행 문맥이 없다 — exec 없이 부르는 것이 옳다
  전달 값: { kind, resultCode?, at, exec }        // ②(UNIDENTIFIED_FAILURE)는 exec 를 뺀다
           at 은 호출측이 정한 계기 시각이다 — 일자 산출 기준이 갈리면 안 된다
  호출하지 않는 자리: 재진입 · 본인확인 재시도 · 확정 결과 재안내 · 자가진단 · 완료 콜백

C2. 지표 산출 (허브 운영자 — 읽기 절차)

  저장된 4개 카운터를 직접 조회해 지표를 낸다 (조회 API·화면을 두지 않는다)
    전체 요청 기준 성공률   = success_count ÷ request_count                    // 결과 미확정 포함
    결과 확정 건 기준 성공률 = success_count ÷ (success_count + decrypt_failed_count
                                              + delivery_failed_count)        // 미확정 제외
    사용량                 = 기간 내 request_count 합계
  // 두 정의가 갈리는 지점은 결과 미확정 요청의 분모 포함 여부다 (ENT-003 §지표 산출)
  // 어느 정의를 목표치 판정에 쓸지는 담당자 이월이다 (POL BIZ-005-06)
  // 목표 수치를 본 사양에 옮겨 적지 않는다 — docs/prd/PRD.md §성과 지표를 참조한다
  // 나눗셈은 실수 연산으로 수행한다 (정수 나눗셈이 되지 않게)
```

#### BE 측 처리 (의사코드)

```
B1. 계수 계기 수신 — POL BIZ-005-02 (validate)

  엔드포인트·메서드: 없음 — 상위 프로세스 안에서 함수로 실행된다
  인증·인가 검증: 인증 없음 — AUTH-001 인용
  입력 재검증:
    if (kind not in ['REQUEST','UNIDENTIFIED_FAILURE','RESULT'])       → throw EX-BIZ-003 (500)
    if (kind == 'RESULT' AND resultCode 가 3종에 없다)                  → throw EX-BIZ-003 (500)

B2. 일자 확정 — ENT-003 §일자 경계 기준 (transform)

  metricDate = DATE_IN_TIMEZONE(at, 'Asia/Seoul')
  // 시간대를 명시적으로 지정한다 — 서버·세션 기본 시간대에 의존하면
  //   같은 데이터에서 다른 지표가 나온다
  // 한국은 서머타임이 없어 하루가 23·25시간이 되는 경계 사고가 없다

B3. 요청 수 계수 — POL BIZ-005-02 · BIZ-005-03 · BIZ-005-05 (트랜잭션 참여)

  if (kind == 'REQUEST')
      columns = { request_count: 1 }
  if (kind == 'UNIDENTIFIED_FAILURE')
      columns = { request_count: 1, decrypt_failed_count: 1 }
      // 추적 키를 알 수 없는 실패는 시도마다 계수된다 — 수용 한계 (POL BIZ-005-05)
  → B5 로 이어지지 않고 아래 UPSERT 로 간다

B4. 결과 구분 카운터 갱신 — POL BIZ-005-04 · BIZ-001-01 · BIZ-001-03 (트랜잭션 참여)

  if (kind == 'RESULT')
      columns = { <대응 컬럼>: 1 }
          SUCCESS         → success_count
          DECRYPT_FAILED  → decrypt_failed_count
          DELIVERY_FAILED → delivery_failed_count
      // 대응표를 한 곳에만 둔다. 저장 계층에서 별칭·대소문자 변형을 만들지 않는다
      // 거부 카운터를 두지 않는다 — 값 체계에 없는 값이다 (POL BIZ-005-01 · BIZ-001-01)
      // 레코드당 1회만 호출된다 — 감산·이동이 없다 (결과는 바뀌지 않는다)
      // 결과가 확정되지 않은 채 끝난 연동(미동의 이탈·본인확인 미완료 이탈)은
      //   이 자리로 오지 않는다 — 요청 수에만 남는다 (POL BIZ-005-04)

  ── 공통 영속화 (B3·B4 가 같은 문장을 쓴다) ──
  INSERT INTO tbl_interlock_metric_daily (metric_date, <columns 의 키들>)
  VALUES (:metricDate, 1 …)
  ON CONFLICT (metric_date)
  DO UPDATE SET <각 컬럼> = tbl_interlock_metric_daily.<각 컬럼> + 1;
  -- 삽입과 증가를 한 문장으로 처리한다 (조회 후 분기하면 동시 요청에서 계수가 유실된다)
  -- WHERE 절 없음 · 락은 기본 키 충돌 처리에 맡긴다
  -- exec 가 주어지면 그 실행자 위에서 수행한다 (호출측 경계와 함께 커밋·되돌림된다)
  -- 없으면 단독 갱신이다 — 이 한 문장이 그 자체로 원자적이다 (UNIDENTIFIED_FAILURE 전용)
  --   FN-013 에도 같은 exec 를 그대로 넘긴다 — 커넥션을 스스로 얻지 않는다
  -- 파생 비율(성공률)을 저장하지 않는다 (POL BIZ-005-01)
  실패 시                                        → throw EX-BIZ-003 (500)
  return                                         // 반환값 없음

B5. 지표 산출 (읽기 절차 — 런타임 계수 경로가 아니다)

  SELECT metric_date, request_count, success_count,
         decrypt_failed_count, delivery_failed_count
  FROM tbl_interlock_metric_daily
  WHERE metric_date BETWEEN :from AND :to
  ORDER BY metric_date;
  -- 기본 키가 그대로 처리한다 · 별도 인덱스를 두지 않는다
  -- 조회 API·화면을 두지 않으므로 이 조회는 저장분 직접 확인으로 수행한다
  // 두 성공률 정의를 모두 산출할 수 있다 (POL BIZ-005-06)
  // 목표치 수치를 본 사양에 옮겨 적지 않는다
```

| 5 | BE `B4` | 결과 구분 카운터 갱신 | `metric_date`·결과 구분 | 대응 컬럼 1개 선택 후 원자적 UPSERT | (커밋) |
| 6 | BE `B5` | 지표 산출 | 저장분 | 기간 조회 — 비율은 읽는 시점 계산 | 지표 값 |

### 구현 가이드

- **삽입과 증가를 한 문장으로 처리한다.** 조회 후 분기하면 동시 요청에서 계수가 유실된다([`../datas/data_ENT-003.md`](../datas/data_ENT-003.md) §구현 가이드).
- **레코드 기록과 같은 트랜잭션 경계에 둔다.** 한쪽이 실패하면 함께 되돌린다.
- **일자 산출 시 시간대를 명시적으로 지정한다.** 서버·세션 기본 시간대에 의존하면 배포 환경에 따라 경계가 달라진다.
- **파생 비율을 저장하지 않는다.** 정의가 담당자 이월 상태이므로 값을 고정하면 정의 변경 시 과거 데이터를 다시 만들어야 한다.
- **결과 구분 → 컬럼 대응표를 한 곳에만 둔다.** 여러 곳에 두면 별칭이 생기고 지표가 갈린다(`BIZ-001-03`).
- **`UNIDENTIFIED_FAILURE` 의 중복 계수를 결함으로 다루지 않는다.** 같은 요청인지 판정할 수단이 없어 생기는 수용 한계다(`BIZ-005-05`).
