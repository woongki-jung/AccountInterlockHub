# 애플리케이션 기동·상수 검증 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 배포된 애플리케이션이 기동할 때 **주입된 연동 구성 상수의 존재·형식을 확인하고, 충족하지 않으면 기동을 중단**하는 처리다. 이 서비스는 배포 시점 상수로만 움직이므로 **상수가 제대로 주입됐는지가 곧 서비스 정상성**이다.
- **관련 PRD 요구사항**:
	- [`../../prd/devspec/infra.md`](../../prd/devspec/infra.md) §연동 구성 상수 주입 — "애플리케이션은 기동 시 필수 상수의 존재·형식을 확인하고, 충족하지 않으면 기동을 중단한다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §시스템 제약사항 — "**연동 구성 = 배포 시점 상수**: … 값 변경은 **재배포**로만 반영된다. 런타임 변경 수단을 두지 않는다."

### 진입점 및 진입 조건

- **진입점**: 애플리케이션 프로세스 기동 — 웹 서버 기동, 스케줄 작업 등록, **CLI 진입점 실행**(`PROC-304` 수동 실행) 모두 이 과정을 먼저 거친다.
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.** 기동은 배포 절차의 일부이며 런타임 요청이 아니다.
- **사전 검증**: 배포 시 애플리케이션 설정으로 상수가 주입돼 있어야 한다. **런타임 변경 수단(구성 화면·구성 API)을 두지 않는다**(`OPS-001-01`).
- **잠정값 여부는 애플리케이션이 판별하지 않는다** — 형식 검증은 통과하므로 개발·검증 환경 기동을 막지 않는다. 잠정값 상태의 운영 배포 금지는 **배포 절차의 확인 항목**이다(`OPS-001-03`·EXC-OPS-01).

### 연관 데이터 및 외부 호출

- **호출 API**: 없음.
- **데이터 조회 대상**: **없음** — 구성 테이블이 존재하지 않는 것이 이 제품의 설계다(`DATA-001-05`).
- **데이터 변경 대상(CRUD)**: 없음.

### 실행 제약사항

- **트랜잭션 경계**: **없음.** 데이터베이스를 쓰지 않는다.
- **동시성 제어**: 기동 시 1회 실행이며 인스턴스마다 독립이다. 인스턴스 간 조율이 필요 없다 — 같은 상수에서 같은 결과가 나온다(버전 식별자 산출이 결정적이다).
- **멱등성**: 자명하다 — 같은 상수 집합에서 같은 구성·같은 버전 식별자를 낸다.
- **성능 요구**: 상수 파싱과 해시 1회. 기동 시간을 지배하지 않는다.
- **보안 요구**: **자가진단 경로의 운영 값은 git 관리 상수표에 적지 않고 배포 시 주입되는 비밀 값으로 다룬다**(`SEC-003-01`). 경로 값을 로그·응답·클라이언트 번들에 담지 않는다(`SEC-003-02`). 기동 실패 출력에도 **상수명만 남기고 값을 남기지 않는다**(FN-015).
- **실패 시 처리**: **부분 기동을 하지 않는다.** 하나라도 미충족이면 어떤 표면도 열지 않고 중단한다.

### 로직 실행 순서

#### FE 측 처리 (의사코드)

**사용자 화면이 없다.** 구성 화면·관리자 화면을 두지 않으며 구성 변경은 상수 갱신·재배포로만 이뤄진다(`AUTH-001-01`). FE 자리에는 **호출측(배포 절차·기동 판독)** 처리를 `C` 라벨로 적는다.

```
C1. 배포 설정 주입 (배포 절차)

  진입 트리거: 배포 실행
  전달 값: 필수 상수 전량을 애플리케이션 설정으로 주입한다 (MDL-022)
    허브 주입 대상 — 진입 경로 · 자가진단 경로 · 수신처 전달 주소 · 복귀 주소 ·
                     동의 항목 · 동의 안내 문구 · 보관 기간 3종
    // 동의 안내 문구만 선택이고 나머지 8종이 필수다 (MDL-022 — B3 검증 대상과 같은 집합)
    // 값의 단일 출처는 CLAUDE.env.md §연동 구성 상수. 본 사양에 값을 복제하지 않는다
    // <HUB_BASE_URL_PROD>·<HUB_BASE_URL_DEV> 는 허브 주입 값이 아니라
    //   발송처가 라이브러리 호출 인자로 넘기는 값이라 검증 대상이 아니다 (EXC-OPS-04)
  절차 게이트 (애플리케이션이 판별하지 않는다):
    운영 배포이면 잠정값이 실제 값으로 교체됐는지 체크리스트로 확인한다 (POL OPS-001-03)
    자가진단 경로의 운영 값을 배포 시점에 새로 지정한다 (POL SEC-003-01·SEC-003-05)

C2. 기동 결과 판독 (배포 절차)

  정상 기동 → 서비스 표면이 열린다 (사용자 진입 경로 · 서버 대면 API · 스케줄 작업)
  기동 중단 → 표준 출력의 **미충족 상수명 목록**을 보고 설정을 보완한 뒤 다시 배포한다
              // 값이 아니라 이름만 나온다 (POL DATA-001-04)
              // HTTP 응답이 없다 — 서비스가 뜨지 않았으므로 응답할 주체가 없다
  CLI 진입점(PROC-304 수동 실행)도 같은 검증을 먼저 거친다:
    기동 실패면 요약 JSON 이 없고 0 이외 코드로 끝나므로 기동 실패로 판독한다
```

#### BE 측 처리 (의사코드)

```
B1. 기동 시작

  엔드포인트·메서드: 없음 — 프로세스 기동 시 1회 실행된다
  인증·인가 검증: 인증 없음 — AUTH-001 인용 (기동은 런타임 요청이 아니다)
  실행 문맥: 웹 서버 기동 · 스케줄 작업 등록 · CLI 진입점 실행이 모두 이 과정을 먼저 거친다

B2. 기동 시 상수 로드 — POL OPS-001-01 · DATA-001-05 · SEC-003-01 (validate)

  constants = 애플리케이션 설정에서 필수 상수를 읽는다        // MDL-022
  // 데이터베이스·구성 API 에서 읽지 않는다 — 구성 엔터티가 존재하지 않는다
  // 런타임 변경 수단을 만들지 않는다 (값 변경은 재배포로만 반영된다)
  // 자가진단 경로는 배포 시 주입되는 비밀 값으로 다룬다 (소스·정적 자산에 넣지 않는다)

B3. 기동 시 상수 형식 검증 — POL OPS-001-02 (validate)

  missing = []
  for each 필수 상수 k in MDL-022:               // 반복 대상은 MDL-022 의 **필수** 상수 8종이다
      if (constants[k] 가 없거나 빈 값)          missing += k
      else if (constants[k] 가 형식을 벗어난다)   missing += k
  형식 기준 (상수표가 정의한 형태 — 값이 아니라 형태만 검사한다):
      경로 형태(진입 경로·자가진단 경로) · URL 형태(수신처 전달 주소·복귀 주소) ·
      개월 수의 양의 정수(보관 기간 3종) · 동의 항목의 JSON 배열 구조와 필수 속성
      // 위 넷이 MDL-022 필수 상수 8종을 남김없이 덮는다
      // 복귀 주소는 절대 URL 조건까지 형태로 본다 — 조건의 정본은 MDL-022·POL BIZ-001-06 이며
      //   본 사양에 복제하지 않는다. 주소에 접속해 도달 가능 여부는 보지 않는다 (SVC-018 F-002)
  // <CONSENT_NOTICE> 는 선택 상수라 미충족 판정 대상이 아니다 —
  //   부재·빈 값은 미충족이 아니라 빈 문자열로 다룬다 (MDL-022 기본값 · EXC-BIZ-07)
  // 허용 형태(최대 400자·최대 3단락·평문)도 검증하지 않는다. 근거 둘 —
  //   ① 화면이 안내 문구를 평문으로만 출력하고 서식·링크·HTML 을 해석하지 않아
  //      실행·해석 위험이 없다 (POL DATA-003-05)
  //   ② 판정 기준을 만들면 한국어 산문의 정상 문자(`<`·`>` 등)를 오탐해 기동을 막는다
  //   통제 지점은 상수 작성·배포 절차다 (EXC-DATA-08 — OPS-001-03·EXC-OPS-01 과 동형)
  // 모든 미충족 항목을 모아 한 번에 보고한다 — 하나씩 실패시키면 배포자가 여러 번 재시도한다
  // 잠정값 여부는 판별하지 않는다 (형식은 통과한다 — EXC-OPS-01)
  if (LENGTH(missing) > 0)                       → B7 (기동 중단)

B4. 기동 시 버전 식별자 산출 — POL DATA-003-03 (transform)

  items   = PARSE_JSON(constants['<CONSENT_ITEMS>'])          // 배열
  notice  = constants['<CONSENT_NOTICE>'] (없으면 빈 문자열)
  version = 상수 값의 결정적 해시                              // 산출 규칙의 정본은
      // data_ENT-002.md §버전 식별자 산출 규칙 (파싱 → 개행 정규화 → 정렬
      //   → 속성 순서 재구성 → 공백 없는 JSON → 끝 공백 제거한 문구
      //   → 0x1F 로 결합 → SHA-256 → 소문자 16진수 64자)
      // 본 사양은 규칙을 복제하지 않고 참조한다 (단계 번호도 적지 않는다 — 번호는 정본이 갖는다)
      // 개행 정규화는 해시 입력에만 적용된다 — 화면 노출 문구와 증적 스냅샷은 원문 그대로다
  consent = { version, notice, items: SORT_BY_CODE_ASC(items) }   // MDL-008
  if (산출 실패)                                  → B7 (기동 중단 — POL OPS-001-02)
  // 런타임 내내 이 값을 읽는다. PROC-103 F1 노출과 PROC-302 B2 증적이 같은 값을 쓴다

B5. 자가진단 경로 라우팅 구성 — POL SEC-003-02 (transform)

  주입된 <SELFCHECK_PATH> 값 하나로만 라우팅을 만든다
  // 경로가 아닌 요청은 경로의 존재를 드러내지 않는 일반 404 로 응답하도록 구성한다
  // 경로 값을 로그·응답·클라이언트 번들에 담지 않는다

B6. 기동 완료 — POL AUTH-001-01

  서비스 표면을 연다
    사용자 진입 경로 (PROC-101·PROC-102·PROC-103)
    서버 대면 API 4종 (PROC-201·PROC-202·PROC-203·PROC-204)
    일 단위 스케줄 작업 (PROC-304)
  // 관리자 경로·구성 API·인증 미들웨어를 만들지 않는다
  // "통과시키는 인증 계층"도 두지 않는다 — 두지 않는 것이 규칙이다
  후속 이벤트 발행: 없음

B7. 기동 중단 (미충족 시) — POL OPS-001-02 (validate)

  표준 출력에 미충족 상수명 목록을 남긴다        // 이름만 · 값은 남기지 않는다 (FN-015)
  비정상 종료 코드로 프로세스를 끝낸다            // 사유 코드 EX-OPS-001
  // HTTP 응답이 없다 — 어떤 표면도 열리지 않았다
  // 부분 기동을 하지 않는다 (일부 상수만으로 일부 표면을 여는 구성을 만들지 않는다)
```

| 응답→호출측 | `C2` | 기동 결과 | 배포 판정 | 정상 기동 또는 설정 보완 후 재배포 |

- **`도메인→ENT`·`ENT→도메인` 지점이 없다** — 연동 구성을 데이터베이스에 두지 않는다.

### 실행 결과

- **정상 결과**: 서비스 표면 개방 + [`MDL-008`](../datas/model_MDL-007-010.md) 동의 항목 구성(런타임 내내 유지) + 자가진단 경로 라우팅. **영속화·이벤트 발행 없음.**
- **실패 결과**: 표준 출력의 미충족 상수명 목록 + 비정상 종료 코드. **어떤 표면도 열리지 않는다.**
- **후속 트리거**: 전 허브 프로세스 — 기동이 성공해야 어떤 요청도 처리되지 않는다. `PROC-103`·`PROC-302` 는 산출된 동의 항목 구성을, `PROC-204` 는 라우팅을, `PROC-304` 는 보관 기간 상수를 쓴다.

### 의존 프로세스

- **호출 관계**: 없음.
- **선행 관계**: 배포(상수 주입). 데이터베이스 상태에 의존하지 않는다.
- **이벤트 관계**: 전 허브 프로세스(PROC-101~105 · 201~204 · 301~304)의 실행 전제다.

### 구현 가이드

- **모든 미충족 항목을 모아 한 번에 보고한다.** 하나씩 실패시키면 배포자가 여러 번 재시도해야 한다.
- **잠정값을 애플리케이션이 판별하려 하지 않는다.** 상수표의 잠정 표기는 문서 표기이지 주입 값이 아니다. 판별 장치를 만들면 개발·검증 환경 기동이 막힌다.
- **`<CONSENT_NOTICE>` 를 형식 검증 대상에 넣지 않는다.** 선택 상수이며 부재·빈 값은 빈 문자열로 다룬다. 허용 형태(글자 수·단락 수·평문)를 판별하는 장치를 만들면 정상 문구의 문자를 오탐해 기동을 막는다 — 통제 지점은 상수 작성·배포 절차다(`MDL-022` §속성 정의 · `EXC-DATA-08`).
- **버전 식별자를 기동 시 1회만 산출한다.** 증적 기록 시점에 다시 계산하면 같은 배포 안에서 값이 흔들릴 수 있다.
- **자가진단 경로를 설정 값 하나로 주입받는다.** 소스·정적 자산·프런트엔드 번들 어디에도 값을 넣지 않는다.
- **인증 미들웨어·가드를 만들지 않는다.** "통과시키는 인증 계층"도 두지 않는다 — 두지 않는 것이 규칙이다(`AUTH-001` 구현 가이드).
- **부분 기동 구성을 만들지 않는다.** 일부 상수만으로 일부 표면을 여는 구성은 어떤 표면이 살아 있는지 배포자가 알 수 없게 만든다.
- **기동 실패 출력에 값을 남기지 않는다.** 상수명만 남긴다 — 수신처 주소·자가진단 경로가 로그로 새면 완화 장치가 사라진다.
