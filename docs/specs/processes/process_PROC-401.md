# 데이터 암호화(라이브러리) 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 발송처가 전달 데이터 X·발송처키·사용자 생년월일로 **`encX`·`encY` 를 산출**하는 처리다. 허브의 복호화 판정(`PROC-102`·`PROC-104`·`PROC-204`)과 **같은 규약의 반대 방향**이며, 두 구현이 같은 입력에서 같은 결과를 내야 연동이 성립한다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 3 — "**연동 라이브러리 (발송처 제공)**: 발송처의 C# 프로젝트에서 호출하는 **.NET 클래스 라이브러리**로 **데이터 암호화**와 **연동 요청 URL 생성**을 제공한다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §시스템 제약사항 — "**암호화·복호화 규약 대칭**: 연동 라이브러리가 암호화하고 허브가 복호화한다."

### 레이어 대응 (FE/BE 구분이 성립하지 않는 이유)

**본 프로세스는 허브 애플리케이션 안에서 실행되지 않는다.** 발송처의 C# 프로젝트가 참조하는 **별도 배포 단위**이며([`../functions/spec-functions-api.md`](../functions/spec-functions-api.md) §표면 구분), 브라우저 화면도 허브 서버 처리도 존재하지 않는다. 따라서 로직 실행 순서의 두 하위 섹션을 아래로 대응시킨다([`spec-process.md`](spec-process.md) §라이브러리 프로세스의 레이어 대응).

- **"FE 측 처리" 자리 → 라이브러리 호출측**(발송처 애플리케이션 코드) 처리를 `C` 라벨로 기술한다.
- **"BE 측 처리" 자리 → 라이브러리 내부** 처리를 `L` 라벨로 기술한다.

### 진입점 및 진입 조건

- **진입점**: `InterlockRequestBuilder.Encrypt(payloadJson, senderKey, birthDate)` — 정적 메서드([`../functions/spec-functions-lib.md`](../functions/spec-functions-lib.md) §공개 API 시그니처).
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.** 라이브러리는 자격을 확인하지 않으며, 호출 권한은 발송처 애플리케이션의 내부 문제다.
- **사전 검증**: ① 인자 존재(`null` 검사) ② 생년월일 형식 ③ 전달 데이터가 JSON 객체 형태 ④ 평문 크기 상한.
- **스레드 안전**: 공개 진입점은 **호출 간 상태를 공유하지 않는다**. 정적 메서드이며 반환 타입은 불변이다.
- **발송처키·기준 URL 을 내장하지 않는다** — 호출 인자로 받는다.

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | `payloadJson` | string | Y | 전달 데이터 X 의 JSON 문자열. **발송처가 직렬화해 넘긴다**([`MDL-016`](../datas/model_MDL-016-018.md)) |
| 입력 | `senderKey` | string | Y | 발송처키. 라이브러리에 내장하지 않는다. 공백만 불가 |
| 입력 | `birthDate` | string(6) | Y | 사용자 생년월일 `yyMMdd` |
| 출력 | `EncX` | string(Base64URL) | - | 전달 데이터 암호문([`MDL-004`](../datas/model_MDL-004-006.md)) |
| 출력 | `EncY` | string(Base64URL) | - | 키 암호문 |

- **JSON 직렬화기를 쓰지 않는다** — 대상 런타임 외의 구성요소를 추가로 요구하지 않기 위해 이미 직렬화된 문자열로 받는다.

### 연관 데이터 및 외부 호출

- **호출 API**: 없음. **네트워크 호출을 하지 않는다** — 허브에 연결하지 않고 로컬에서 값을 만든다.
- **데이터 조회 대상**: 없음.
- **데이터 변경 대상(CRUD)**: 없음.

### 실행 제약사항

- **트랜잭션 경계**: **없음.** 영속화가 없는 순수 계산이다.
- **동시성 제어**: 상태를 공유하지 않으므로 락이 필요 없다. **같은 입력은 항상 같은 출력을 낸다** — 초기화 벡터가 키에서 결정적으로 파생되기 때문이며, 이 성질이 규약 테스트 벡터(`PROC-404`)를 성립시킨다.
- **멱등성**: 자명하다(순수 함수).
- **성능 요구**: AES-256-CBC 암호화 2회. 평문 상한이 있어 상한 시간이 정해진다.
- **보안 요구**: **예외 메시지·로그에 발송처키·생년월일·전달 데이터·암호값·정규화 키를 담지 않는다**(`DATA-001-04`). 사유 코드와 어느 제약을 어겼는지 이상은 담지 않는다.
- **수용 리스크**: 초기화 벡터가 키에서 파생되므로 **같은 키·같은 평문은 항상 같은 암호문**이 된다. 상위 규약이 정한 한계이며 결함으로 다루지 않는다(EXC-SEC-01).

### 로직 실행 순서

#### FE 측 처리 (의사코드) — 라이브러리 호출측

```
C1. 입력 준비 (발송처 애플리케이션)

  진입 트리거: 발송처가 특정 회원의 연동 요청을 발행하려는 시점
  사용 값:
    payloadJson = 발송처가 직렬화한 전달 데이터 X 의 JSON 문자열
                  반드시 trackingKey 필드를 포함한다 (허브의 판정 4단계가 이를 요구한다)
    senderKey   = 발송처가 보관·관리하는 발송처키   // 라이브러리에 내장하지 않는다
    birthDate   = 그 회원의 생년월일 yyMMdd 6자리
  검증 규칙 (호출측 1차 방어):
    trackingKey 의 유일성은 발송처가 책임진다 (POL DATA-004-02)
    실사용자 값을 테스트 벡터에 재사용하지 않는다 (POL DATA-001-02)

C2. 호출

  pair = InterlockRequestBuilder.Encrypt(payloadJson, senderKey, birthDate)
  // 정적 메서드 · 호출 간 상태를 공유하지 않으므로 병렬 호출이 안전하다

C3. 결과·예외 처리 (BR-020 — 3층 구분)

  정상    → pair.EncX · pair.EncY 를 PROC-402 로 넘긴다
  ArgumentNullException · ArgumentException  → 호출 코드를 고친다 (자기 입력 문제)
  InterlockProtocolException(ReasonCode)     → 사유 코드로 원인을 좁힌다
      EX-AUTH-001 생년월일 형식 · EX-SEC-002 전달 데이터 형태 · EX-SEC-004 평문 크기 상한
      // 자가진단 API 의 사유 코드와 같은 값 체계다 (두 경로에서 같은 진단을 얻는다)
  그 밖의 런타임 예외                          → 실행 환경을 점검한다 (감싸지 않고 전파된다)
  실패 처리: 로그에 payloadJson·senderKey·birthDate·pair 를 남기지 않는다 (POL DATA-001-04)
```

#### BE 측 처리 (의사코드) — 라이브러리 내부

```
L1. 인자 검사 (호출 오류 — 대상 런타임 관용)

  if (payloadJson == null OR senderKey == null OR birthDate == null)
                                                → throw ArgumentNullException
  if (TRIM(senderKey) == "")                    → throw ArgumentException
  // 규약 위반이 아니라 호출 자체가 성립하지 않는 경우다 (BR-020 1층)

L2. 생년월일 형식 검증 — POL AUTH-002-02 (validate)

  if (!MATCH(birthDate, "^[0-9]{6}$"))
                                                → throw InterlockProtocolException("EX-AUTH-001")
  // 달력 유효성을 검사하지 않는다 — 허브의 FN-005 와 같은 기준이어야 한다

L3. 전달 데이터 형태 검증 — POL SEC-002-01 ③ 의 사전 방어 (validate)

  trimmed = TRIM(payloadJson)
  if (trimmed 가 '{' 로 시작하지 않거나 '}' 로 끝나지 않는다)
                                                → throw InterlockProtocolException("EX-SEC-002")
  // JSON 을 파싱하지 않는다 — 추가 의존을 만들지 않기 위함이며,
  //   필드 수준 적합성(trackingKey 존재)은 자가진단(PROC-204)이 판정한다

L4. 직렬화·크기 상한 검증 — POL SEC-001-02 · SEC-001-09 (validate)

  plain = UTF8_BYTES(payloadJson)
  if (LENGTH(plain) > 규약 평문 상한)            // 값은 POL SEC-001 §규약 확정값
                                                → throw InterlockProtocolException("EX-SEC-004")
  // 암호화를 수행하지 않고 끝낸다

L5. 키 산출(정규화) — POL SEC-001-05 · SEC-001-06 · SEC-001-03 · SEC-001-04 (transform)

  keyX = 정규화(senderKey + birthDate)          // ① 이어 붙인 뒤 ② 정규화한다 (순서 필수)
  keyY = 정규화(birthDate)                       // 6바이트 + '_' 26개
  // 정규화 = UTF-8 바이트 변환 → 32바이트 초과면 앞 32바이트 절단 / 미만이면 '_'(0x5F) 우측 패딩
  // 초기화 벡터 = 정규화된 키의 앞 16바이트 (난수 IV·별도 IV 전달을 두지 않는다)
  // 허브의 FN-001 과 글자 그대로 같은 규칙이다

L6. 암호화 수행 — POL SEC-001-01 · SEC-001-07 (transform)

  cipherX = AES256_CBC_PKCS7_ENCRYPT(plain,    keyX.key, keyX.iv)
  cipherY = AES256_CBC_PKCS7_ENCRYPT(keyX.key, keyY.key, keyY.iv)
  // encY 의 평문은 encX 암호화에 쓴 **정규화된 32바이트 키 바이트열 그대로**다 —
  //   허브가 복호화 결과를 재정규화하지 않고 그대로 쓰기 때문이다 (POL SEC-001-07)
  // 다른 블록 모드·패딩을 쓰지 않는다

L7. 전달 인코딩 — POL SEC-001-08 (transform)

  encX = Base64Url(cipherX)                     // RFC 4648 §5 · 패딩 '=' 제거
  encY = Base64Url(cipherY)
  // 퍼센트 인코딩을 겹쳐 적용하지 않는다 — 이미 URL 에 그대로 실을 수 있다

L8. 결과 반환

  return new EncryptedPair(encX, encY)          // 불변 타입 (MDL-004)
  // 중간 값(plain·keyX·keyY·cipherX·cipherY)을 지역 값으로만 두고 반환·로그에 담지 않는다
  영속화 쿼리: 없음 · 사전 조회 쿼리: 없음 · 후속 이벤트 발행: 없음
```

#### 데이터 변환 흐름

| 변환 지점 | 변환 위치 | 입력 형태 | 출력 형태 | 변환 규칙 요약 |
|----------|----------|----------|----------|--------------|
| 호출측→요청 | `C1`·`C2` | 발송처 도메인 값 | [`MDL-016`](../datas/model_MDL-016-018.md) | 발송처가 X 를 직접 직렬화 · 발송처키를 인자로 전달 |

| 도메인→도메인 | `L5` | 키 원문 문자열 | 정규화 키 + 초기화 벡터 | 이어 붙이기 → 절단·`_` 패딩 → 앞 16바이트 |
| 도메인→도메인 | `L6` | 평문·키 | 암호문 바이트열 | AES-256-CBC + PKCS#7 · `encY` 평문은 정규화 키 그대로 |

| 응답→호출측 | `C3` | `MDL-004` | 발송처 보유 값 | PROC-402 입력으로 넘긴다 |

| 키 정규화 · encX 키 산출 · encY 키 산출 | SVC-006 Happy Path 3 · `SEC-001-03`~`06` | `L5` |

| 결과 반환 | SVC-006 Happy Path 6 | `L8` |

### 분기 및 예외 흐름

| 코드 | 발생 조건 | 처리 방향 | 결과 |
|------|----------|----------|------|
| BR-020 | 오류 구분 | 인자 문제 → 호출 오류 예외 / 규약 위반 → 전용 예외(사유 코드) / 런타임 → 그대로 전파 | 호출측이 원인을 구별한다 |

| `EX-SEC-002` | 전달 데이터가 JSON 객체 형태가 아님 | 암호화 미수행 | 전용 예외 |
| `EX-SEC-004` | X 평문 크기 상한 초과 | 암호화 미수행 | 전용 예외 |

### 실행 결과

- **정상 결과**: [`MDL-004`](../datas/model_MDL-004-006.md) 암호값 쌍(불변). 영속화·이벤트 발행 없음.
- **실패 결과**: 세 층 중 하나의 예외. **부분 결과를 반환하지 않는다.**
- **후속 트리거**: PROC-402(같은 호출측이 이어서 요청 URL 을 만든다) · PROC-404(테스트 벡터의 기대 출력 산출).

### 의존 프로세스

- **호출 관계**: 없음(FN-001·FN-002 에 해당하는 로직을 내부에 구현한다).
- **선행 관계**: 없음 — 발송처 프로세스 안에서 독립 실행된다.
- **이벤트 관계**: PROC-402 · PROC-101(사용자가 그 URL 로 진입한다) · PROC-204(발송처가 결과를 자가진단에 넣는다).

### 구현 가이드

- **이어 붙이기 → 정규화 순서를 지킨다.** 발송처키와 생년월일을 각각 정규화한 뒤 이어 붙이면 다른 키가 나온다(`SEC-001-05`).
- **`encY` 의 평문은 정규화된 키 그대로다.** 원본 문자열을 담으면 허브가 복호화 결과를 그대로 쓰지 못한다(허브는 발송처키가 없어 키를 직접 만들 수 없다 — EXC-SEC-04).
- **내부 정규화·인코딩 도구를 공개하지 않는다.** 공개 표면은 진입점 2개·불변 결과 타입·전용 예외·규약 버전 상수뿐이다.
- **JSON 을 파싱하지 않는다.** 추가 의존을 만들지 않기 위한 결정이며, 필드 수준 적합성은 자가진단이 판정한다.
- **예외 메시지에 값 자체를 담지 않는다.** 사유 코드와 위반한 제약 이름까지만 남긴다.
- **패딩 검증을 끄지 않는다**(복호화 측과 대칭). 규약 테스트 벡터로 양쪽 결과가 일치하는지 확인한다(`PROC-404`).
