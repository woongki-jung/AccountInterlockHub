# 규약 테스트 벡터 생성·대조 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: "이 값을 넣으면 이 값이 나와야 한다"를 미리 고정해 **라이브러리와 허브가 같은 규약을 구현했는지 값으로 증명**하는 처리다. 발송처는 자기 환경에서 결과 일치를 확인하고, 허브는 규약 대칭(왕복) 검증의 근거로 삼는다.
- **관련 PRD 요구사항**:
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §1 — "**규약 테스트 벡터**(`LIB-04`) — 알려진 입력과 기대 출력(`encX`·`encY`·요청 URL)의 대조 표."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §프로그램 구성·기술스택·검증 방법 — "**규약 대칭(왕복) 검증**은 별도 통합 검증 항목으로 둔다."

### 레이어 대응 (FE/BE 구분이 성립하지 않는 이유)

**본 프로세스는 허브 애플리케이션 안에서 실행되지 않는다.** 벡터 생성은 허브 운영자가 라이브러리를 호출해 수행하는 **배포 산출물 생성 절차**이고, 대조는 발송처의 하네스 실행과 허브 운영자의 왕복 확인이다. 브라우저 화면도 허브 서버 요청 처리도 없다. 로직 실행 순서의 두 하위 섹션을 아래로 대응시킨다([`spec-process.md`](spec-process.md) §라이브러리 프로세스의 레이어 대응).

- **"FE 측 처리" 자리 → 대조 수행 주체**(발송처·허브 운영자) — `C` 라벨.
- **"BE 측 처리" 자리 → 벡터 생성 절차**(라이브러리 호출로 기대 출력 산출) — `L` 라벨.

### 진입점 및 진입 조건

- **진입점**: 라이브러리 릴리스·규약 개정 시점의 **벡터 생성 절차**(허브 운영자) 와 **대조 실행**(발송처 하네스 · 허브 왕복 확인).
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.**
- **사전 검증**: `PROC-401`·`PROC-402` 가 구현돼 있어야 기대 출력을 산출할 수 있다. **왕복 검증은 라이브러리 산출물과 허브가 모두 준비된 뒤 수행**한다.
- **규약이 바뀌면 벡터를 다시 만들고, 재생성·대조 통과를 배포 전제로 삼는다**(`SEC-001-12`).

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | 규약 확정값 | 정책 참조 | Y | 경계 사례 선정 근거(`SEC-001` §규약 확정값) |
| 입력 | 예시 입력 집합 | 목록 | Y | `senderKey`·`birthDate`·`payload` — **실사용자 값 금지** |
| 출력 | 벡터 파일 | `protocol-test-vectors.json` | - | 파일 1개. `protocolVersion`·`hubBaseUrl`(파일 수준)·`cases[]` |

| 출력 | 대조 결과 | 일치·불일치 | - | 하네스 요약 JSON + 종료 코드 |

### 연관 데이터 및 외부 호출

- **호출 API**: 없음(벡터 생성). **왕복 검증**에서만 허브의 복호화 판정을 대조 대상으로 쓴다.
- **데이터 조회 대상**: 없음.
- **데이터 변경 대상(CRUD)**: 없음 — 저장 대상 셋 어디에도 기록하지 않는다.

### 실행 제약사항

- **트랜잭션 경계**: **없음(절차).**
- **동시성 제어**: 벡터 생성은 릴리스마다 한 번 수행한다. 동시 생성을 가정하지 않는다.
- **멱등성**: **같은 입력은 항상 같은 출력을 낸다** — 초기화 벡터가 키에서 파생되는 규약이라 값 대조 방식이 성립한다. 난수 초기화 벡터를 쓰는 규약이라면 이 프로세스 자체가 불가능하다.
- **성능 요구**: 사람이 수행하는 절차라 응답 시간 요구를 두지 않는다. 하네스는 종료 코드로 판정한다.
- **보안 요구**: **실사용자 생년월일·실 발송처키·실 회원 정보를 벡터에 넣지 않는다**(`DATA-001-02`) — 벡터는 저장소와 발송처 양쪽에 남는 문서다. `hubBaseUrl` 은 **벡터 전용 예시**이며 실제 환경 값과 무관하다.

### 로직 실행 순서

#### FE 측 처리 (의사코드) — 대조 수행 주체

```
C1. 발송처 대조 (검증 하네스 실행)

  진입 트리거: 발송처가 패키지를 수령해 통합을 시작한 시점(PROC-403 C4) 또는 규약 개정 후
  실행:
    <하네스 실행 파일> --vectors protocol-test-vectors.json
    // 하네스는 각 case 에 대해 PROC-401 Encrypt · PROC-402 BuildRequestUrl 을 호출하고
    //   expected 와 대조한다. hubBaseUrl 은 파일 수준 값을 쓴다
  관측:
    표준 출력 마지막 줄 요약 JSON  {"total":n,"passed":n,"failed":0,"failedCaseIds":[]}
    진단 문구는 표준 오류로 나간다
    종료 코드 0 = 전건 일치 / 0 이외 = 불일치·실행 실패
  판정 (BR-024):
    일치   → 규약 대칭이 성립한 것으로 보고 통합을 계속한다
    불일치 → 통합을 멈추고 failedCaseIds 의 boundaryNote 로 어느 경계가 어긋났는지 좁힌다
             라이브러리를 그대로 쓰면 EX-SEC-002 사유가 나오지 않으므로
             자체 구현·환경 차이를 먼저 의심한다

C2. 왕복 대조 (허브 운영자 — 통합 검증 항목)

  진입 트리거: 라이브러리 산출물과 허브가 모두 준비된 뒤
  실행:
    for each case in vectors.cases:
        허브의 복호화 판정(FN-004)에 case.expected.encX · encY 와 case.input.birthDate 를 넣는다
        복원된 X 가 case.input.payload 와 같은지 대조한다
        // 자가진단 API(PROC-204)를 경로로 쓰면 판정 결과·사유 코드만 확인할 수 있고,
        //   원문 복원 대조는 응답에 원문이 없으므로 저장분 없이 직접 수행한다
  판정:
    일치   → 규약 대칭 성립. 배포를 진행한다
    불일치 → 배포 절차를 중단한다. 라이브러리·허브 중 어느 쪽이 규약을 벗어났는지 확인해
             함께 고친다 (한쪽만 고쳐 배포하지 않는다 — POL SEC-001-12)
```

#### BE 측 처리 (의사코드) — 벡터 생성 절차

```
L1. 벡터 입력 선정 — POL SEC-001-03 · SEC-001-08 · SEC-001-09 · DATA-001-02 (validate)

  아래 경계를 **최소 6항목**으로 반드시 덮는다
    ① 키 원문(발송처키+생년월일)이 32바이트 **미만**      → '_' 우측 패딩 확인
    ② 키 원문이 **정확히 32바이트**                        → 절단·패딩이 없는 경계
    ③ 키 원문이 32바이트 **초과**                          → 앞 32바이트 절단
    ④ 암호값에 Base64URL 치환 문자('-'·'_')가 나오는 값    → 전달 인코딩 확인
    ⑤ X 평문이 크기 상한 **바로 아래**                      → 상한 판정 경계
    ⑥ X 에 다국어 문자 포함                                → UTF-8 직렬화 확인
  각 항목에 caseId 와 boundaryNote(어떤 경계를 덮는지)를 붙인다
  금지: 실사용자 생년월일·실 발송처키·실 회원 정보 (POL DATA-001-02)
  // 각 payload 에는 trackingKey 필드를 넣는다 (허브 판정 4단계가 요구한다)

L2. 기대 출력 산출 — PROC-401 · PROC-402 호출 (transform)

  hubBaseUrl = <벡터 전용 예시 기준 URL>        // 실제 환경 값과 무관하다
  for each case in 입력 집합:
      pair = InterlockRequestBuilder.Encrypt(case.input.payload 직렬화,
                                             case.input.senderKey,
                                             case.input.birthDate)
      url  = InterlockRequestBuilder.BuildRequestUrl(hubBaseUrl, pair)
      case.expected = { encX: pair.EncX, encY: pair.EncY, requestUrl: url }
  // 규약대로 산출한 값이 기대 출력이 된다 — 손으로 적지 않는다

L3. 벡터 파일 구성 (transform)

  file = { protocolVersion: <규약 버전 문자열>,
           hubBaseUrl:      hubBaseUrl,          // 항목이 아니라 파일 수준 값이다
           cases:           [ … MDL-019 … ] }
  파일명: protocol-test-vectors.json             // JSON 파일 1개
  // 사람이 읽고 기계가 파싱할 수 있어야 발송처 자체 확인과 검증 절차가 같은 파일을 쓴다
  // 기준 URL 을 항목마다 반복하지 않는다 — 기대 URL 은 기준 URL 하나를 전제로 산출된다

L4. 벡터 동봉 — PROC-403 로 이관

  PROC-403 L1 의 패키지 구성 ④ 로 넘긴다
  영속화 쿼리: 없음 · 사전 조회 쿼리: 없음 · 후속 이벤트 발행: 없음
```

### 실행 결과

- **정상 결과**: `protocol-test-vectors.json` 1개(경계 6항목 이상) · 대조 전건 일치(하네스 종료 코드 `0`).
- **실패 결과**: 대조 불일치 — 통합·배포 중단. **부분 통과를 통과로 다루지 않는다.**
- **후속 트리거**: PROC-403(패키지 동봉) · PROC-401·PROC-402(대조 대상 호출) · PROC-204(발송처가 값 대조 대신 허브에 직접 묻는 다른 경로).

### 의존 프로세스

- **호출 관계**: PROC-401 · PROC-402(기대 출력 산출).
- **선행 관계**: PROC-401 · PROC-402 구현 완료. 왕복 대조(`C2`)는 허브의 복호화 판정(PROC-102·PROC-104·PROC-204 가 공유하는 FN-004)이 준비돼야 한다.
- **이벤트 관계**: PROC-403 — 벡터를 패키지에 동봉한다.

### 구현 가이드

- **기대 출력을 손으로 적지 않는다.** 라이브러리 호출 결과를 그대로 기록해야 규약 구현과 벡터가 어긋나지 않는다.
- **경계 6항목을 줄이지 않는다.** 정규화 경계(①②③)가 빠지면 절단·패딩 이탈을 잡지 못하고, 치환 문자 사례(④)가 빠지면 인코딩 이탈을 잡지 못한다.
- **`hubBaseUrl` 을 항목마다 반복하지 않는다.** 파일 수준 값 하나를 전제로 기대 URL 이 산출되므로 반복하면 불일치 원인이 늘어난다.
- **실 데이터를 벡터에 넣지 않는다.** 벡터는 저장소와 발송처 양쪽에 남는다.
- **왕복 검증을 발송처 대조로 대체하지 않는다.** 발송처 대조는 암호화 방향만 증명하고, 복호화 방향은 허브가 직접 확인해야 대칭이 성립한다.
- **벡터가 통과해도 연동 성공을 보장하지는 않는다.** 규약 구현의 일치만 증명하며, 수신처 전달 주소·기준 URL 같은 환경 값의 정확성은 별도 확인 대상이다.
