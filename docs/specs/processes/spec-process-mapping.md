# 프로세스 매핑 색인 (SVC · SCR · FN · ENT · 단계명)

정본 목록은 [`spec-process.md`](spec-process.md). 정책 규칙 매핑은 분량이 커서 [`spec-process-policy-map.md`](spec-process-policy-map.md) 로 분기했다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

본 문서는 **상위 사양이 프로세스로 빠짐없이 내려왔는지**를 확인하는 색인이다. 각 표의 마지막에 커버리지 수치를 적는다.

| SCR | 액션(인터랙션) | 서버 호출 | 호출 접점 | 트리거 PROC | 진입 단계 라벨 |
|---|---|---|---|---|---|
| SCR-001 | 문서 수신(최초 렌더) | ✕(직전 응답 소비) | — | PROC-101(서버가 이미 수행) | PROC-101 `F1` |
| SCR-001 | 생년월일 입력 | ✕(화면 안 처리) | — | 없음 | PROC-102 `F1` 이전 |
| SCR-001 | **확인 버튼 클릭·엔터** | ✅ | `POST <INTERLOCK_ENTRY_PATH>/verify` | **PROC-102** | PROC-102 `F1` |
| SCR-002 | 단계 진입(자동) | ✕(직전 응답 소비) | — | PROC-103(동의 항목 구성) | PROC-103 `F1` |
| SCR-002 | 동의 항목 체크 | ✕(화면 안 처리) | — | 없음 | PROC-103 `F2` |

**커버리지 — 서버를 호출하는 화면 액션 2 / 2 가 트리거 PROC 을 갖는다(100%).** 나머지 11 항목은 ① 화면 안에서만 처리되는 입력·체크 2건 ② 직전 응답을 소비하는 자동 전이 4건 ③ **화면 게이팅에서 차단되는 제출 1건**(SCR-002 비활성 승인 버튼 — BR-004) ④ **서버를 부르지 않는 화면 후처리 2건**(SCR-004 복귀 이동 — 자동·수동) ⑤ 조작 요소가 없는 자리 2건이며, 서버를 부르지 않으므로 트리거 PROC 이 없는 것이 정상이다.

- **거부 제출 액션이 사라져 서버 호출 액션이 3 → 2 로 줄었다**(`BIZ-003-03` — 거부를 제출하는 인터페이스를 두지 않는다). 미동의 제출은 화면 게이팅(BR-004)에서 끝나 접점에 도달하지 않는다.
- **한 화면 액션은 하나의 PROC 을 트리거한다.** 승인 이후의 복호화·전달·기록·결과 선택은 PROC-103 **내부의 호출 관계**이며 화면이 따로 부르지 않는다([`../screens/screen_SCR-002.md`](../screens/screen_SCR-002.md) §사용자 인터랙션).
- **트리거 PROC 이 없는 화면 2종**(SCR-003·SCR-004)은 **서버를 부르는 액션이 없는** 화면이다. SCR-003 은 조작 요소 자체가 없고, **SCR-004 에는 조작 요소가 하나 있다** — 복귀 안내 영역의 **수동 이동 링크**이며 서버를 부르지 않는 화면 후처리라 트리거 PROC 이 없다([`../screens/screen_SCR-004.md`](../screens/screen_SCR-004.md) §복귀 이동).

- **선행 도메인 단계명은 모두 대응 단계를 갖는다 — 다만 표기가 확정 단계명과 글자 그대로 같지는 않다.** 정책 §적용 지점 매핑의 "적용 단계" 칸은 **여러 프로세스를 한 줄로 묶은 요약 표기**여서 위 색인의 확정 단계명과 문자열이 다를 수 있다. 아래 §별칭 색인이 그 표기를 규칙별로 확정 단계에 이어 준다 — **대응 단계가 없는 표기는 0건**이다.
- 서비스 1건(`SVC-014` Happy Path 5)·화면 2건(`SCR-002`·`SCR-003` 의 `PROC-104` 상태 전이)의 표기는 **확정 단계명으로 정정**했으므로 별칭이 남지 않는다.
- 선행 문서의 단계 서술과 어긋난 지점은 [`spec-process.md`](spec-process.md) §확정 사항과 각 프로세스 문서의 §구현 가이드가 근거를 남긴다.
