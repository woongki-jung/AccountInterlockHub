# 연동 링크 진입·형식 판정 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 발송처가 만든 연동 요청 URL 로 사용자가 들어왔을 때, **생년월일 없이 판정할 수 있는 것만 먼저 판정**하고 화면 문서를 돌려주는 처리다. 복호화를 시도하지 않고, 추적 레코드도 만들지 않는다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 4 — "**사용자 진입·본인확인·동의·승인**: 발송처 링크로 고정 진입 경로에 진입 …"
	- [`../../prd/ia/IA.md`](../../prd/ia/IA.md) `USR-01` — "발송처가 만든 링크로 고정 진입 경로에 진입해 `encX`·`encY`를 받고 형식을 판정(무효 링크는 결과 안내로 분기)"

### 진입점 및 진입 조건

- **진입점**: `GET <INTERLOCK_ENTRY_PATH>` — 쿼리 파라미터 `encX`·`encY`([`../functions/spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §연동 요청 진입). 허브가 정적 자산 서빙보다 앞서 직접 처리한다.
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.** 세션·계정·토큰·권한을 확인하지 않으며 자격이 담긴 요청이 와도 무시한다(`AUTH-001-02`·`AUTH-001-03`). 링크를 가진 누구나 진입한다.
- **요청 제한**: **미적용 — 수용 리스크**(`OPS-002-03`). 반복 진입을 막는 장치를 두지 않는다.
- **사전 검증**: ① 요청 URL 전체 길이 상한(`SEC-001-10`) ② 파라미터 존재·중복 ③ 암호값 구조(FN-003). **복호화는 시도하지 않는다** — 생년월일이 없어 판정할 수 없다.

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | `encX` | string(Base64URL) | Y | 전달 데이터 암호문([`MDL-004`](../datas/model_MDL-004-006.md)) |
| 입력 | `encY` | string(Base64URL) | Y | 키 암호문 |
| 입력 | (요청 URL 전체) | string | Y | 길이 상한 판정 대상([`MDL-018`](../datas/model_MDL-016-018.md)) |
| 출력 | 화면 문서 | `text/html; charset=utf-8` | - | 200 고정. 판정 실패도 200 이다 |
| 출력 | 초기 상태 | `{ stage, resultPath?, reasonCode?, isReAnnouncement?, returnUrl? }` | - | `stage` = `IDENTITY` 또는 `RESULT`. `RESULT` 는 [`MDL-009`](../datas/model_MDL-007-010.md) 값 체계. **`returnUrl` 은 계약에만 있고 이 접점에서는 나타나지 않는다** — 진입 실패는 항상 경로 ② 다(`BIZ-001-06`) |

### 연관 데이터 및 외부 호출

- **호출 API**: 없음. 본 프로세스는 밖으로 호출하지 않는다.
- **데이터 조회 대상**: 없음. **추적 키를 알 수 없으므로 조회할 대상이 없다**(`BIZ-002-02`).
- **데이터 변경 대상(CRUD)**: 판정 실패 시 [`ENT-003`](../datas/data_ENT-003.md) 카운터 갱신 1건(U/C) — PROC-303 `B3` 이 수행한다. 성공 시 변경 없음.

### 실행 제약사항

- **트랜잭션 경계**: 단일 트랜잭션 — 판정 실패 시의 지표 계수 하나뿐이다. 성공 경로에는 트랜잭션이 없다.
- **동시성 제어**: 상태를 만들지 않으므로 락이 없다. 같은 링크의 동시 진입도 서로 간섭하지 않는다.
- **성능 요구**: 복호화·조회가 없어 상수 시간이다. 응답 대기 상한을 별도로 두지 않는다.
- **보안 요구**: **인증 없음**(`AUTH-001`). 응답·로그에 `encX`·`encY`·요청 URL 전체를 담지 않는다(FN-015). **요청 URL 을 통째로 남기는 접근 로그를 켜지 않는다** — URL 자체가 암호값을 담고 있다.
- **감사 로그**: 없음(`OPS-003-01`). 실패는 지표 집계로만 남는다(`OPS-003-02`).

### 로직 실행 순서

#### FE 측 처리 (의사코드)

```
F1. 문서 수신 → 초기 상태 해석

  진입 트리거: 브라우저가 <INTERLOCK_ENTRY_PATH>?encX=…&encY=… 를 연다 (페이지 mount)
  사용 상태:
    initial   = 문서에 주입된 초기 상태
                { stage, resultPath?, reasonCode?, isReAnnouncement?, returnUrl? }
                // §입력/출력 정의와 같은 형상이다 (한 문서 안에서 형상을 둘로 적지 않는다)
                // 담는 형식의 정본은 spec-functions-api-user.md §초기 상태 주입 형식 —
                //   id 로 찾은 application/json 데이터 블록의 텍스트를 JSON.parse 한다
                //   (문서 안 위치·순서에 의존하지 않고, 역이스케이프도 하지 않는다)
                //   판독은 id 가 일치하는 요소를 전부 모아 개수까지 세어 수행한다 —
                //     첫 요소만 돌려주는 수단을 쓰면 아래 조건 ② 가 성립할 수 없다
    stage     = 로컬 상태<'IDENTITY' | 'RESULT'>(초기값 initial.stage)
  검증 — 부재 판정 4조건 (정본은 같은 절 "값이 없을 때의 거동"):
    if (요소가 없다 · 같은 id 요소가 둘 이상 · JSON.parse 실패 · stage 가 두 값 밖)
                                              → stage = 'RESULT', resultPath = 2
                                              // 빈 화면을 만들지 않는다 (SVC-005 F-003)
                                              // 'IDENTITY' 로 폴백하면 사양 위반이다 —
                                              //   서버 판정 통과 여부를 알 수 없다 (POL BIZ-001-02)
    // 이 폴백은 reasonCode 를 만들지 않는다 — 사유 코드 없는 상태로 SCR-004 가 그려지며,
    //   SCR-004 §결과 3경로가 미상 코드를 EX-OPS-002 문구로 수렴시키고
    //   미매핑은 경로 ② 로 안내한다 (FN-014 · SVC-005 F-003)
    //   새 EX 코드를 만들지 않고 reasonCode 를 억지로 채우지도 않는다
  호출 수단: 없음 — 진입 응답에 이미 실려 있다. 추가 요청을 보내지 않는다
  진행 중 UI: 없음 — 첫 그림에 이미 내용이 있으므로 스켈레톤을 쓰지 않는다

F2. 자기 URL 쿼리에서 암호값 판독 → 메모리 보유

  사용 상태:
    encPair = 로컬 상태<{ encX, encY }>  ← URLSearchParams(location.search) 에서 읽는다
  정책 적용 지점: DATA-001-04 — 초기 상태에 암호값이 없다. 화면이 URL 에서 직접 읽는다
  보관 규칙: 페이지 메모리에만 둔다. localStorage·sessionStorage·쿠키·숨은 필드에 쓰지 않는다
  UI 전이: 어떤 요소에도 그리지 않는다 (SCR-001 §데이터 표시)

F3. 단계 화면 선택

  if (stage == 'IDENTITY')   → SCR-001 본인확인 렌더 (PROC-102 F1 이 이어받는다)
  if (stage == 'RESULT')     → SCR-004 결과 안내 렌더 (PROC-105 F1 이 이어받는다)
  캐시·전역 상태: 두지 않는다 — 새로고침은 진입부터 다시 시작한다 (AUTH-001-02)
  실패 처리: 이 단계에는 서버 호출이 없어 실패 경로가 없다
```

#### BE 측 처리 (의사코드)

```
B1. GET <INTERLOCK_ENTRY_PATH> 진입

  엔드포인트·메서드: GET <INTERLOCK_ENTRY_PATH>  (경로 값은 상수 주입 — OPS-001-04)
  인증·인가 검증: 인증 없음 — AUTH-001 인용
                  토큰·세션·역할을 읽지 않는다. 401·403 을 정의하지 않는다 (AUTH-001-03)
  요청 제한: 미적용 — 수용 리스크 (OPS-002-03)
  메서드 불일치: 405 (본문 없음)
  캐시: 응답에 캐시 금지를 지정한다 (URL 에 암호값이 실려 있다)

B2. 요청 URL 길이 판정 — POL SEC-001-10 (validate)

  fullUrl = 요청 스킴·호스트·경로·쿼리를 합친 전체 문자열
  if (LENGTH(fullUrl) > 규약 URL 길이 상한)      // 값은 POL SEC-001 §규약 확정값
      reason = 'EX-SEC-004' → B5 로 간다

B3. 진입 파라미터 파싱 — POL SEC-001-08 (transform)

  encX = 쿼리에서 'encX' 를 대소문자 구분해 읽는다
  encY = 쿼리에서 'encY' 를 대소문자 구분해 읽는다
  if (같은 이름의 파라미터가 둘 이상)            → reason = 'EX-SEC-001' → B5
  그 밖의 파라미터는 읽지 않고 무시한다 (OPS-002-05)
  // 퍼센트 디코딩을 겹쳐 적용하지 않는다 — Base64URL 은 그대로 실린다

B4. 진입 파라미터 구조 판정 — FN-003 · POL SEC-002-02 (validate)

  try  cipher = FN-003({ encX, encY })          // 존재·빈 값·Base64URL·16의 배수 검사
  catch (EX-SEC-001)                            → reason = 'EX-SEC-001' → B5
  // 복호화를 시도하지 않는다 — 생년월일이 없다 (FN-003 §구현 가이드)
  // 판정 결과 cipher 는 이 단계 이후 쓰지 않고 버린다 (요청 간 보존 없음 — DATA-001-03)
  판정 통과 → B6 (stage = 'IDENTITY')

B5. 판정 실패 계수 — PROC-303 호출 · POL BIZ-002-02 · BIZ-005-02 ② (트랜잭션)

  // 추적 키를 알 수 없으므로 추적 레코드를 만들지 않는다
  PROC-303({ kind: 'UNIDENTIFIED_FAILURE', at: NOW() })
      → 영속화 쿼리는 PROC-303 B3 (tbl_interlock_metric_daily 원자적 UPSERT)
      → request_count +1 · decrypt_failed_count +1
  실패 시: 계수 실패가 응답을 막지 않는다 — 화면은 그대로 경로 ② 를 안내하고,
           기술적 실패는 운영 로그에만 남긴다 (OPS-003-03)
  보안 이벤트 기록: 만들지 않는다 (OPS-003-02)

B6. 초기 상태 구성 — PROC-105 호출 · POL SEC-002-05 (mask)

  if (판정 실패)
      resultInfo = PROC-105({ source: 'ENTRY_FAILURE', reasonCode: reason })
      initial    = { stage: 'RESULT', resultPath: resultInfo.resultPath,
                     reasonCode: reason, isReAnnouncement: false }
      // returnUrl 은 실리지 않는다 — 진입 판정 실패는 항상 경로 ② 라
      //   PROC-105 B3 의 동봉 조건(경로 ① 한정)이 성립하지 않는다 (POL BIZ-001-06)
  else
      initial    = { stage: 'IDENTITY' }
  마스킹: FN-015 로 내보내기 직전 정제 — encX·encY·요청 URL·복호화 중간 값을 담지 않는다
  // 추적 키도 담지 않는다 — 이 단계에서는 알 수도 없다

B7. 화면 문서 응답 (다음 단계 이관)

  200 text/html; charset=utf-8
  본문: 사용자 웹 화면 문서 + initial 주입
        // 담는 형식의 정본은 spec-functions-api-user.md §초기 상태 주입 형식 —
        //   <script id="__INTERLOCK_INITIAL_STATE__" type="application/json"> 요소를 정확히 하나 두고
        //   초기 상태의 JSON 직렬화 1건을 텍스트로 담는다(UTF-8). 전역 변수 주입·별도 API 를 쓰지 않는다
  이스케이프: 주입 측(서버) 의무다 — 직렬화 결과의 `<`·`>`·`&`·U+2028·U+2029 를 값의 출처를
        따지지 않고 무조건 치환해 넣는다 (같은 절 2 — 전부 유효한 JSON 이스케이프라 값이 바뀌지 않고,
        화면은 역이스케이프를 하지 않는다)
  // 판정 실패도 200 이다 — 사용자가 보는 것은 언제나 화면이지 오류 본문이 아니다
  // 리다이렉트를 쓰지 않는다 (spec-functions-api-user.md §프로토콜 확정)
  후속 이벤트 발행: 없음
```

| 변환 지점 | 변환 위치 | 입력 형태 | 출력 형태 | 변환 규칙 요약 |

### 실행 결과

- **정상 결과**: 200 `text/html` + 초기 상태 `{ stage: 'IDENTITY' }`. 영속화·이벤트 발행 없음.
- **실패 결과**: 200 `text/html` + 초기 상태 `{ stage: 'RESULT', resultPath: 2, reasonCode }`. 지표 집계에 요청 수 +1 · `decrypt_failed_count` +1. **추적 레코드는 만들지 않는다.**
- **후속 트리거**: PROC-102(사용자가 생년월일을 제출하면) · PROC-105(결과 경로 구성) · PROC-303(실패 계수).

### 의존 프로세스

- **호출 관계**: PROC-303(동기 — 판정 실패 시) · PROC-105(동기 — 결과 경로 산출).
- **선행 관계**: PROC-901(기동·상수 검증) — 진입 경로 라우팅과 상수가 준비돼야 한다. PROC-402(발송처가 URL 을 만들어야 진입이 성립한다).
- **이벤트 관계**: PROC-102 — 화면이 다음 제출을 수행한다.

### 구현 가이드

- **길이 판정을 구조 판정보다 먼저 한다.** 상한을 넘은 URL 은 파싱 비용을 들일 이유가 없고, 두 실패의 사유 코드가 다르다(`EX-SEC-004` vs `EX-SEC-001`).
- **판정에 쓴 디코딩 결과를 요청 간에 남기지 않는다.** 본인확인 단계에서 다시 디코드한다(`DATA-001-03`).
- **정적 자산 라우팅보다 진입 경로 처리를 앞에 둔다.** 뒤에 두면 미리 빌드된 화면 문서가 초기 상태 없이 서빙되고, 그러면 `F1` 의 부재 판정이 발동해 **정상 진입까지 경로 ② 로 끝난다**(판정이 아니라 배선 때문에 전건이 실패한다 — [`../functions/spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §초기 상태 주입 형식 4).
- **요청 URL 을 로그에 남기지 않는다.** 필요하면 경로만 남긴다(FN-015 §구현 가이드).
- **지표 계수 실패를 응답 실패로 승격시키지 않는다.** 사용자에게 보여 줄 화면은 이미 결정돼 있고, 계수 유실은 수용 범위다(`BIZ-005-05` 의 정신).
