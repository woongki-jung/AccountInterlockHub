# 보관정책 배치 — 로직 실행 순서

정본은 [`process_PROC-304.md`](process_PROC-304.md).

#### FE 측 처리 (의사코드)

**사용자 화면이 없다.** 스케줄과 명령 진입점으로만 실행하며 관리 화면·HTTP 관리 경로를 두지 않는다. FE 자리에는 **호출측(스케줄러·허브 운영자)** 처리를 `C` 라벨로 적는다.

```
C1. 스케줄 발화 (시스템)

  진입 트리거: 애플리케이션 안의 일 단위 스케줄 작업
    시간대 앵커: Asia/Seoul (UTC+09:00) 벽시계 기준 · 하루 1회
      // 기산 프레임이 Asia/Seoul 이라(POL DATA-002-06 ①) 앵커가 다르면 실행 시점의 달력 날짜와
      //   임계값 산출의 달력 날짜가 어긋난다 (EXC-DATA-12 ⓑ)
      // 서버 OS 기본 시간대·UTC 앵커를 쓰지 않는다
    구체 발화 시각(시·분): build 결정 — 사양이 고정하지 않는다 (§진입점 및 진입 조건)
  전달 값: 없음 — 기준 일시를 넘기지 않는다 (산정 기준이 갈리면 안 된다)
  관측: 요약 1줄이 유일한 관측 수단이다 — 이 경로에는 종료 코드가 없다
        성패와 무관하게 프리픽스 없는 JSON 1줄을 표준 출력으로 내보내고,
          성패는 그 줄의 failureReason 으로 읽는다        (§스케줄 경로의 관측 표면)
        진단 문구는 애플리케이션 로거로 다른 줄에 내보낸다 — 요약 줄에 섞지 않는다
        별도 실행 이력을 남기지 않는다                     (POL OPS-003-04)
  실행 실패: 상주 프로세스를 끝내지 않는다 — 요약으로 알리고 다음 회차를 기다린다
             (POL OPS-004-01 인용 · EXC-OPS-12 — 프로세스 하나가 곧 서비스 전체다)

C2. 수동 실행 (허브 운영자)

  진입 트리거: 운영자가 배포 단위 안에서 명령을 실행한다
    실행 명령: node dist/cli/retention.js        (개발 편의 별칭 npm run retention:run)
    인자·옵션: 없다
  // HTTP 관리 경로를 쓰지 않는다 — 인증 없는 삭제 트리거를 공개 표면에 두면
  //   관리자 경로를 두지 않기로 한 결정과 정면 충돌한다 (POL AUTH-001-01)

C3. 결과 판독 (검증의 관측 지점) — 경로별로 판독 수단이 다르다

  CLI 경로 (C2 로 실행한 경우) — 종료 코드로 먼저 분기한다
    0        → 성공. 표준 출력 마지막 줄의 요약 JSON 을 파싱해 건수를 확인한다
    0 이외   → 실패
        요약 JSON 이 있으면  failureReason 으로 사유를 읽는다 (건수는 그 시점까지 실제 삭제분)
        요약 JSON 이 없으면  기동 실패로 판독한다 (미충족 상수명이 표준 출력에 있다)
    // 진단 문구는 표준 오류로 나가므로 표준 출력은 항상 파싱 가능하다

  스케줄 경로 (C1 로 발화한 경우) — 종료 코드가 없다. 표준 출력을 줄 단위로 읽는다
    JSON 파싱에 성공하고 4키를 갖는 줄을 요약으로 식별한다   (§스케줄 경로의 관측 표면 1)
      failureReason == null  → 성공. 건수를 확인한다
      failureReason != null  → 실패. 사유를 읽는다 (건수는 그 시점까지 실제 삭제분)
    요약 줄이 아예 없다      → 그 회차가 발화하지 않았거나 요약 출력이 누락된 것이다 (결함)
        // 기동 실패는 이 경로의 판독 대상이 아니다 — 기동하지 못하면 스케줄 작업 자체가
        //   등록되지 않아 실행 시도가 일어나지 않는다
    // 진단 줄이 함께 흐르므로 "표준 출력 전체가 요약"이라는 전제로 판독하지 않는다
    // "마지막 줄" 로 찾지 않는다 — 상주 프로세스에는 마지막 줄이 없다
```

#### BE 측 처리 (의사코드)

```
B1. 실행 진입 — POL DATA-002-04 · AUTH-001-01 (validate)

  엔드포인트·메서드: 없음 — 스케줄 작업 또는 CLI 진입점이 애플리케이션 컨텍스트를 기동해
                      삭제 로직을 1회 실행하고 종료한다
  인증·인가 검증: 인증 없음 — AUTH-001 인용 (관리자 경로·관리자 인증을 두지 않는다)
  선행 조건: PROC-901 기동 검증 통과. 필수 상수 미충족이면 여기 도달하기 전에 중단된다
             (표준 출력에 미충족 상수명 · 0 이외 종료 · 요약 JSON 없음 — EX-OPS-001)
  두 진입 경로가 같은 함수를 부른다 — 아래 B2~B6 이 그 함수다 (BR-015)
  // 공용 범위: 삭제 로직·산정 기준·요약 레코드와 그 직렬화 형상까지다
  // 경로별 범위: 요약이 놓이는 자리·진단 문구의 분리 방식(B6)과 성패의 귀결(B7)
  //   — 종료 코드는 프로세스가 끝나는 CLI 경로에만 있는 수단이다
  //   (§스케줄 경로의 관측 표면 · spec-functions-api-server.md §관측 표면의 경로별 분리)

B2. 기준 일시 산정 — POL DATA-002-06 · OPS-001-04 (transform)

  baseAt = NOW()                     // 실행 1회당 한 번만 취한다 (POL DATA-002-06 ②)
  // 이 한 값에서 세 기준 일시가 전부 파생하고, B6 요약의 baseAt 도 같은 값이다.
  // 이후 어디서도 현재 시각을 다시 읽지 않는다 — 질의 조건절에서도 읽지 않는다.
  //   질의마다 새로 읽으면 기준 일시들이 서로 다른 순간을 기준으로 삼고,
  //   요약의 baseAt 으로 임계값을 재현할 수 없게 된다.

  function 개월감산(base, months):    // 세 기준 일시가 예외 없이 같은 절차를 쓴다 (POL DATA-002-06)
    1) 벽시계 분해   (Y, M, D, h, m, s, ms) = base 를 시간대 'Asia/Seoul' 로 명시 지정해 분해
                     // 달력 프레임 = Asia/Seoul 고정 (POL DATA-002-06 ① · 근거 EXC-DATA-12)
                     // 서버 OS·데이터베이스 세션의 기본 시간대에 의존하지 않는다.
                     //   UTC 달력은 기각됐다 — 재논쟁 근거로 "배포 결정성"·"대상 컬럼이
                     //   절대 시각"을 쓰지 않는다 (EXC-DATA-12)
    2) 연·월 감산    (Y', M') = (Y, M) 에서 months 개월을 뺀 연·월     // 고정 길이가 아닌 달력 연산
    3) 월말 clamp    D' = min(D, (Y', M') 의 말일)
                     // 다음 달로 이월(rollover)하지 않는다 (POL DATA-002-06 ③ · 근거 EXC-DATA-13)
                     // 예) 2026-05-31 − 3개월 = 2026-02-28 이다. 2026-03-03 이 아니다
    4) 시각 보존     (h, m, s, ms) 를 그대로 쓴다                      // 자정 절삭·반올림 없음
                     // (POL DATA-002-06 ④) — 절삭하면 요약의 baseAt 과 임계값의 시각 요소가
                     //   어긋나 관측자가 요약만으로 임계값을 재현할 수 없다
    5) 절대 시각 복원 (Y', M', D', h, m, s, ms) 를 Asia/Seoul(+09:00) 벽시계로 해석해
                     절대 시각 하나로 되돌린다
                     // 비교는 절대 시각끼리 이뤄진다 — 프레임은 임계값을 만드는 데만 쓴다
    return 그 절대 시각

  trackingConfirmBefore = 개월감산(baseAt, <RETENTION_MONTHS>)               // POL DATA-002-01 ①
  trackingCreatedBefore = 개월감산(baseAt, <RETENTION_MAX_MONTHS>)           // POL DATA-002-01 ②
  consentBefore         = 개월감산(baseAt, <CONSENT_PROOF_RETENTION_MONTHS>) // POL DATA-002-02
  // 상수 주입 값으로 실행 시점에 계산한다. 값을 코드·사양에 복제하지 않는다 (POL OPS-001-04)
  // 세 기준 일시 전부에 같은 규칙을 적용한다 — 예외 없다 (POL DATA-002-06 ⑤ 말미)
  // 경계 판정 부등호는 B3·B4 에서 '미만(<)' 으로 쓴다 (POL DATA-002-06 ⑤)

B3. 추적 레코드 삭제 대상 산정 — POL DATA-002-01 · DATA-002-06 ⑤ · BR-016 (validate)

  -- 기준 ① 결과 확인 완료 기산 (부분 인덱스 idx_interlock_tracking_result_confirmed_at)
  SELECT tracking_key FROM tbl_interlock_tracking
  WHERE result_confirmed_at IS NOT NULL
    AND result_confirmed_at < :trackingConfirmBefore     -- 미만(<) — POL DATA-002-06 ⑤
  ORDER BY result_confirmed_at
  LIMIT :batchSize;                         -- 대량 삭제를 나눠 수행하기 위한 상한(멱등 유지)

  -- 기준 ② 생성 기산 절대 상한 (인덱스 idx_interlock_tracking_created_at)
  SELECT tracking_key FROM tbl_interlock_tracking
  WHERE created_at < :trackingCreatedBefore             -- 미만(<) — POL DATA-002-06 ⑤
  ORDER BY created_at
  LIMIT :batchSize;

  targetsTracking = 두 결과의 합집합           -- 먼저 도달한 기준이 자동으로 반영된다
  -- 두 기준을 OR 로 묶지 않는다 — 하나의 조건절에 묶으면 계획이 흔들린다
  -- 지표 집계는 대상에 넣지 않는다 (POL DATA-002-03)
  -- 부등호는 strict 다: 기준 일시와 정확히 같은 시각의 행은 남긴다 (이하(<=) 는 반려)

B4. 동의 증적 삭제 대상 산정 — POL DATA-002-02 · DATA-002-06 ⑤ (validate)

  SELECT consent_proof_id FROM tbl_consent_proof
  WHERE consented_at < :consentBefore                    -- 미만(<) — POL DATA-002-06 ⑤
  ORDER BY consented_at
  LIMIT :batchSize;                          -- 인덱스 idx_consent_proof_consented_at
  targetsConsent = 조회 결과
  -- 추적 레코드와 다른 기준을 쓴다. 추적 레코드가 지워진 뒤 증적만 남은 상태가 정상이다
  -- 부등호는 strict 다: 기준 일시와 정확히 같은 시각의 행은 남긴다 (POL DATA-002-06 ⑤)

B5. 삭제 수행 — POL DATA-002-04 (대상별 독립 트랜잭션)

  BEGIN;
    DELETE FROM tbl_interlock_tracking WHERE tracking_key IN (:targetsTracking);
    trackingDeletedCount = 삭제 행 수
  COMMIT;

  BEGIN;
    DELETE FROM tbl_consent_proof WHERE consent_proof_id IN (:targetsConsent);
    consentProofDeletedCount = 삭제 행 수
  COMMIT;

  -- 하드 삭제만 쓴다. 논리 삭제 컬럼이 없다 (보관 정책의 목적이 삭제다)
  -- FK 가 없어 순서 제약이 없다. 두 삭제는 서로 독립이다
  -- tbl_interlock_metric_daily 를 건드리지 않는다 (POL DATA-002-03)
  실패 시: 그 시점까지의 건수를 유지하고 failureReason 에 사유를 담은 뒤 B6 으로 간다
          (다음 실행이 남은 대상을 마저 지운다 — 멱등하므로 안전하다)

B6. 결과 요약 출력 — POL OPS-003-04 (mask)

  summary = { baseAt: baseAt → ISO 8601 + Asia/Seoul 오프셋(+09:00),
              trackingDeletedCount, consentProofDeletedCount,
              failureReason: (실패 사유 문자열 또는 null) }
      // 형상은 두 경로 공용이다 — 키 4개 고정 · 순서 불변
      //   (직렬화 형상 정본: spec-functions-api-server.md §출력 스키마)
  line = summary 를 프리픽스·접미 없는 JSON 1줄로 직렬화한 문자열

  성패와 무관하게 line 을 반드시 1줄 내보낸다        // 실패해도 낸다 (failureReason 을 채워서)
  진입 경로별 — 놓이는 자리와 진단 문구의 분리 방식만 다르다 (BR-015)
    CLI    : 표준 출력의 **마지막 줄**로 line 을 내보낸다
             진단 문구·경고는 전부 표준 오류로        // 표준 출력이 항상 파싱 가능하도록
    스케줄 : 표준 출력에 line 을 그대로 내보낸다      // 로거 장식(타임스탬프·레벨)을 붙이지 않는다
             진단 문구는 애플리케이션 로거로 다른 줄에 // 요약 줄에 섞지 않는다
             요약을 로거 경로에만 싣지 않는다          // 실패 시 표준 출력이 비면 관측이 갈린다
             // 상주 프로세스라 "마지막 줄"이 성립하지 않는다 — 관측자는 줄 단위로 읽어
             //   JSON 파싱에 성공하고 4키를 갖는 줄을 요약으로 식별한다
             //   (§스케줄 경로의 관측 표면)
  마스킹: FN-015 — 추적 키·증적 식별자·삭제 대상 목록을 출력에 담지 않는다
  // 지표 집계 삭제 건수 항목이 없다 — 삭제 대상이 아니라 셀 것이 없다
  // 별도 실행 이력 테이블을 두지 않는다 (POL OPS-003-04)

B7. 실행 귀결 — 경로별 (CLI 는 종료 코드 반환) — POL OPS-003-04 · OPS-004-01

  CLI 경로
    if (failureReason == null)   exit 0
    else                         exit 1                 // 0 이외 = 실패
  스케줄 경로
    종료 코드가 없다 — 성패는 B6 요약의 failureReason 이 알린다
      null = 성공 / 문자열 = 실패                       // CLI 의 exit 0 / exit 1 에 1:1 대응
    프로세스를 끝내지 않는다
      exit·강제 종료를 호출하지 않고, 예외를 스케줄 작업 밖으로 던지지 않는다
      // 새 판단이 아니라 POL OPS-004-01 의 인용이다 — 어떤 실패도 애플리케이션 프로세스를
      //   종료시키지 않으며 의도된 종료는 기동 시 상수 검증 실패 하나뿐이다 (POL OPS-001-02)
      // EXC-OPS-12 — 사용자 웹·백엔드 API·보관 배치가 한 배포 단위라
      //   프로세스가 죽으면 서비스 전체가 내려가고 보관 배치도 함께 멈춘다
    실패 시: 다음 회차를 기다린다                        // 남은 대상은 다음 실행이 마저 지운다
                                                        //   (POL DATA-002-04 — 멱등)
  후속 이벤트 발행: 없음
```

|----------|----------|----------|----------|--------------|
| 호출측→요청 | `C1`·`C2` | (없음) | 실행 요청 | 인자를 두지 않는다 — 산정 기준이 갈리지 않게 |
| 요청→도메인 | BE `B2` | [`MDL-022`](../datas/model_MDL-019-022.md) 상수 + 1회 취한 `baseAt` | 기준 일시 3종 | `Asia/Seoul` 달력 개월 감산 — 월말 clamp·시각 요소 보존(`DATA-002-06` ①~④) |
| ENT→도메인 | BE `B3`·`B4` | `tbl_interlock_tracking`·`tbl_consent_proof` 행 | 대상 키 집합 | 기준별 분리 산정 후 합집합 · 경계는 **미만(`<`)**(`DATA-002-06` ⑤) |
