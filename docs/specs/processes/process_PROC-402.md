# 요청 URL 생성(라이브러리) 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 허브 기준 URL 과 암호값 쌍으로 **사용자를 허브로 보낼 연동 요청 URL 을 조립**하는 처리다. 발송처가 규약 문서를 해석해 직접 URL 을 만들지 않게 하는 것이 목적이며, 진입 경로와 파라미터 이름은 허브(`PROC-101`)와 공유하는 계약이다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §제공 가치 — "**통합 부담 없는 발송처 연동**: 발송처는 암호화 규약을 구현하지 않고 **연동 라이브러리 호출**로 암호값과 요청 URL 을 얻는다."
	- [`../../prd/ia/IA.md`](../../prd/ia/IA.md) `LIB-02` — "허브 진입 경로에 encX·encY를 결합한 연동 요청 URL 산출"

### 레이어 대응 (FE/BE 구분이 성립하지 않는 이유)

**본 프로세스는 허브 애플리케이션 안에서 실행되지 않는다.** 발송처의 C# 프로젝트가 참조하는 **별도 배포 단위**이므로 브라우저 화면도 허브 서버 처리도 없다. 로직 실행 순서의 두 하위 섹션을 아래로 대응시킨다([`spec-process.md`](spec-process.md) §라이브러리 프로세스의 레이어 대응).

- **"FE 측 처리" 자리 → 라이브러리 호출측**(발송처 애플리케이션 코드) — `C` 라벨.
- **"BE 측 처리" 자리 → 라이브러리 내부** — `L` 라벨.

### 진입점 및 진입 조건

- **진입점**: `InterlockRequestBuilder.BuildRequestUrl(hubBaseUrl, pair)` — 정적 메서드([`../functions/spec-functions-lib.md`](../functions/spec-functions-lib.md) §공개 API 시그니처).
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.**
- **사전 검증**: ① 인자 존재 ② 기준 URL 이 절대 URL 형태 ③ 조립 후 전체 길이 상한.
- **기준 URL 을 내장하지 않는다** — 환경마다 다른 값이므로 호출 인자로 받는다(`<HUB_BASE_URL_PROD>`·`<HUB_BASE_URL_DEV>` 는 상수표가 단일 출처이며 **본 사양에 값을 복제하지 않는다**).
- **진입 경로는 라이브러리 내부 상수로 갖는다** — 라이브러리는 허브의 배포 설정을 받을 수 없고, 진입 경로는 규약의 일부인 확정 상수다. 경로가 바뀌면 규약 버전을 올려 라이브러리와 허브를 함께 배포한다(`SEC-001-12`).
- **스레드 안전**: 호출 간 상태를 공유하지 않는다.

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | `hubBaseUrl` | string | Y | 환경별 허브 기준 URL. 절대 URL 형태여야 한다([`MDL-017`](../datas/model_MDL-016-018.md)) |
| 입력 | `pair` | [`MDL-004`](../datas/model_MDL-004-006.md) | Y | `PROC-401` 이 만든 불변 암호값 쌍 |
| 출력 | (반환 문자열) | string | - | 연동 요청 URL([`MDL-018`](../datas/model_MDL-016-018.md)) |

### 연관 데이터 및 외부 호출

- **호출 API**: 없음. **네트워크 호출을 하지 않는다** — 기준 URL 이 실제로 살아 있는지 확인하지 않는다.
- **데이터 조회 대상**: 없음.
- **데이터 변경 대상(CRUD)**: 없음.

### 실행 제약사항

- **트랜잭션 경계**: **없음.** 순수 문자열 계산이다.
- **동시성 제어**: 상태를 공유하지 않으므로 락이 필요 없다.
- **멱등성**: 자명하다(순수 함수). 같은 입력은 항상 같은 URL 을 낸다 — 이 성질이 규약 테스트 벡터의 기대 요청 URL 을 성립시킨다.
- **성능 요구**: 문자열 결합과 길이 비교뿐이다.
- **보안 요구**: **반환한 URL 전체를 로그·예외 메시지에 담지 않는다** — URL 이 암호값을 담고 있다([`MDL-018`](../datas/model_MDL-016-018.md) 마스킹 규칙 · `DATA-001-04`).
- **길이 판정을 통과한 값만 반환한다** — 상한을 넘는 URL 을 만들어 돌려주면 진입 시점(`PROC-101` `B2`)에서야 실패가 드러난다.

### 로직 실행 순서

#### FE 측 처리 (의사코드) — 라이브러리 호출측

```
C1. 입력 준비 (발송처 애플리케이션)

  진입 트리거: PROC-401 이 암호값 쌍을 돌려준 직후
  사용 값:
    pair       = PROC-401 의 반환값 (EncryptedPair)
    hubBaseUrl = 자기 환경의 허브 기준 URL
                 // 배포 패키지 사용 안내의 §환경별 허브 기준 URL 기재란에서 확인한다
                 // 운영·개발 값이 다르므로 실행 환경에 맞는 값을 고르는 책임은 발송처에 있다
  검증 규칙 (호출측 1차 방어):
    hubBaseUrl 이 절대 URL 인지 확인한다 (아니면 라이브러리가 호출 오류 예외를 던진다)
    끝 구분자('/') 유무는 신경 쓰지 않아도 된다 — 라이브러리가 같은 결과를 낸다

C2. 호출

  url = InterlockRequestBuilder.BuildRequestUrl(hubBaseUrl, pair)

C3. URL 사용

  정상 → 사용자에게 그 URL 을 전달한다 (링크·메시지 등 — 전달 수단은 발송처 소관이다)
  InterlockProtocolException("EX-SEC-004")
       → 요청 URL 길이 상한 초과. 전달 데이터 X 를 줄여 PROC-401 부터 다시 수행한다
  ArgumentNullException · ArgumentException  → 호출 코드를 고친다 (기준 URL 형태 등)
  실패 처리: 로그·오류 화면에 url 전체를 남기지 않는다 (암호값이 담겨 있다 — POL DATA-001-04)
  주의: URL 을 만든 뒤 임의로 파라미터를 덧붙이거나 순서를 바꾸지 않는다.
        허브는 두 파라미터 외의 값을 읽지 않으며(OPS-002-05), 이중 인코딩은 진입 실패를 부른다
```

#### BE 측 처리 (의사코드) — 라이브러리 내부

```
L1. 인자 검사 (호출 오류 — 대상 런타임 관용)

  if (hubBaseUrl == null OR pair == null)       → throw ArgumentNullException
  if (hubBaseUrl 이 절대 URL 형태가 아니다)      → throw ArgumentException
  // 규약 위반이 아니라 호출 자체가 성립하지 않는 경우다 (BR-020 1층)

L2. 기준 경로 결합 (transform)

  baseUrl = TRIM_TRAILING(hubBaseUrl, '/')      // 끝 구분자 유무에 관계없이 같은 결과
  url     = baseUrl + <INTERLOCK_ENTRY_PATH>    // 진입 경로는 라이브러리 내부 상수다
  // 값의 단일 출처는 CLAUDE.env.md §연동 구성 상수이며 본 사양에 복제하지 않는다

L3. 파라미터 결합 — POL SEC-001-08 (transform)

  url = url + "?encX=" + pair.EncX + "&encY=" + pair.EncY
  // 파라미터 이름은 허브와 공유하는 확정값이다 — 대소문자를 구분한다
  // 이미 URL 에 실을 수 있는 형태이므로 퍼센트 인코딩을 겹쳐 적용하지 않는다
  // 두 파라미터 외의 값을 붙이지 않는다 (링크 만료·1회성 표시를 나타내는 파라미터가 없다)

L4. 길이 상한 판정 — POL SEC-001-10 (validate)

  if (LENGTH(url) > 규약 URL 길이 상한)          // 값은 POL SEC-001 §규약 확정값
                                                → throw InterlockProtocolException("EX-SEC-004")
  // 상한을 넘는 값을 돌려주지 않는다 — 진입 시점에야 실패가 드러나면 원인 추적이 어려워진다

L5. 결과 반환

  return url                                    // MDL-018 · 길이 판정을 통과한 값만 돌려준다
  // 예외 메시지에 url·암호값을 담지 않는다 (POL DATA-001-04)
  영속화 쿼리: 없음 · 사전 조회 쿼리: 없음 · 후속 이벤트 발행: 없음
```

### 실행 결과

- **정상 결과**: [`MDL-018`](../datas/model_MDL-016-018.md) 연동 요청 URL 문자열. 영속화·이벤트 발행 없음.
- **실패 결과**: 세 층 중 하나의 예외. **부분 결과·상한 초과 값을 반환하지 않는다.**
- **후속 트리거**: PROC-101 — 사용자가 그 URL 로 진입한다. PROC-404 — 테스트 벡터의 기대 요청 URL 산출.

### 의존 프로세스

- **호출 관계**: 없음(PROC-401 의 결과를 입력으로 소비한다).
- **선행 관계**: PROC-401 — 암호값 쌍이 있어야 URL 을 만들 수 있다.
- **이벤트 관계**: PROC-101 · PROC-404.

### 구현 가이드

- **퍼센트 인코딩을 겹쳐 적용하지 않는다.** Base64URL 결과는 이미 URL 에 그대로 실린다. 이중 인코딩은 진입 단계 디코드 실패의 대표 원인이다(`SEC-001-08`).
- **길이 판정을 반환 직전에 둔다.** 상한 초과 값을 돌려주면 실패가 사용자 진입 시점으로 미뤄져 원인 추적이 어려워진다.
- **기준 URL 을 내장하지 않는다.** 환경마다 다르며, 내장하면 환경 전환이 재배포 사안이 된다(`OPS-001-01`).
- **진입 경로는 내부 상수로 둔다.** 라이브러리는 허브의 배포 설정을 받을 수 없다. 경로가 바뀌면 규약 버전을 올려 함께 배포한다(`SEC-001-12`).
- **반환 URL 을 로그에 남기지 않는다.** URL 이 암호값을 담고 있어 그대로 기록하면 무저장 원칙이 깨진다.
- **끝 구분자 처리로 두 결과가 갈리지 않게 한다.** `https://host` 와 `https://host/` 가 같은 URL 을 내야 발송처 환경 차이가 규약 이탈로 이어지지 않는다.
