# 연동 규약 자가진단 API 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 발송처가 만든 암호값이 **규약에 맞는지만 판정해 응답**하는 처리다. 연동으로 취급하지 않으므로 수신처 전달·추적 레코드·동의 증적·지표 집계 어느 것도 만들지 않고 복호화 원문도 반환하지 않는다. 노출 경로는 상수로 고정한 **비공개 경로**이며 그것이 유일한 완화 장치다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 8 — "**연동 규약 자가진단 API**: 발송처가 만든 암호값의 규약 적합성만 판정해 응답한다. 수신처 전달·기록을 하지 않고 복호화 원문도 반환하지 않는다. 노출 경로는 상수로 고정한 **비공개 경로**다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §제공 가치 — "**통합 시점의 규약 확인**: … 규약 이탈을 운영 트래픽이 아니라 통합 시점에 발견한다."

### 진입점 및 진입 조건

- **진입점**: `POST <SELFCHECK_PATH>` — 상수로 고정한 **비공개 경로**([`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수). 본 사양은 값을 복제하지 않는다.
- **진입 조건**: **인증 없음 — `AUTH-001` 인용.** 경로 비공개는 인증이 아니라 **노출 축소 장치**이며, 경로를 아는 요청은 그대로 처리된다(EXC-AUTH-01).
- **요청 제한**: **미적용 — 수용 리스크**(`OPS-002-03`·EXC-SEC-09). 경로 비공개가 유일한 완화 장치다.
- **사전 검증**: ① 경로 일치(불일치·메서드 불일치는 **본문 없는 일반 404**) ② 세 입력 존재 ③ 생년월일 형식.
- **운영 환경 노출** — **담당자 확인 대기 항목이며 기본안을 적용했다**([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑨). 운영 환경에도 노출하되 비공개 경로를 유지한다.

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | `encX`·`encY` | string(Base64URL) | Y | 발송처가 자기 라이브러리로 만든 값([`MDL-014`](../datas/model_MDL-011-015.md)) |
| 입력 | `birthDate` | string(6) | Y | 판정에 쓸 생년월일. 저장하지 않는다 |
| 출력 | `isConform` | boolean | - | 규약 적합 여부([`MDL-015`](../datas/model_MDL-011-015.md)) |
| 출력 | `reasonCode` | string\|null | - | 부적합 사유. **정책 EX 코드 값을 그대로** 쓴다 |
| 출력 | `protocolVersion` | string | - | 허브의 규약 버전(`<MAJOR>.<MINOR>`) |

- **부적합 판정도 HTTP 200 이다** — 판정이 정상 수행된 결과이지 요청 오류가 아니다.

### 연관 데이터 및 외부 호출

- **호출 API**: 없음.
- **데이터 조회 대상**: **없음.**
- **데이터 변경 대상(CRUD)**: **없음** — 추적 레코드·동의 증적·지표 집계 어느 것도 만들지 않는다(`SEC-003-03`·EXC-BIZ-11).

### 실행 제약사항

- **트랜잭션 경계**: **없음.** 영속화가 없는 순수 판정이다.
- **동시성 제어**: 상태를 갖지 않으므로 락·멱등 키가 필요 없다. 같은 입력은 항상 같은 판정을 낸다.
- **성능 요구**: 복호화 2회(AES-256-CBC). 조회·저장이 없다.
- **보안 요구**: **인증 없음**(EXC-AUTH-01). **복호화 원문·키·초기화 벡터·중간 값·단계 번호를 응답에 절대 담지 않는다**(`SEC-003-03`·`SEC-002-05`·`DATA-001-04`) — 담을 속성이 [`MDL-015`](../datas/model_MDL-011-015.md) 에 없는 것이 1차 방어다. **경로 값을 응답·오류 메시지·로그에 담지 않는다**(`SEC-003-02`).

### 로직 실행 순서

#### FE 측 처리 (의사코드)

**사용자 화면이 없다.** 발송처가 서버에서 직접 호출하는 접점이며 진단 화면·포털을 두지 않는다. FE 자리에는 **호출측(발송처 서버 또는 통합 확인 도구)** 처리를 `C` 라벨로 적는다.

```
C1. 호출측 요청 구성 (발송처)

  진입 트리거: 발송처가 통합 시점 또는 운영 중 규약 적합성을 확인하려는 시점
  사용 값:
    pair      = 자기 라이브러리 PROC-401 이 만든 EncryptedPair { EncX, EncY }
    birthDate = 그 값을 만들 때 쓴 생년월일 (발송처가 이미 아는 값이다)
  요청 DTO 변환:
    body    = { encX: pair.EncX, encY: pair.EncY, birthDate }
    headers = { 'Content-Type': 'application/json; charset=utf-8' }
    // 인증 헤더를 붙이지 않는다 (AUTH-001-03)
  호출 수단: POST <허브 기준 URL><SELFCHECK_PATH>
  경로 취급: 경로 값을 소스·공개 문서·클라이언트 번들에 넣지 않는다 (POL SEC-003-02)
             값은 배포 안내가 아닌 별도 비공개 전달로 받는다

C2. 판정·버전 대조

  200 & isConform == true   → 규약 적합. 연동을 진행해도 된다
  200 & isConform == false  → reasonCode 로 원인을 좁힌다
        EX-SEC-001 구조 위반 · EX-AUTH-002 키 불일치 · EX-SEC-002 규약 위반 · EX-SEC-004 크기 초과
        // 라이브러리 오류 사유 코드와 같은 값 체계라 두 경로에서 같은 진단을 얻는다
  규약 버전 대조 (BR-017):
    if (MAJOR(res.protocolVersion) != MAJOR(InterlockRequestBuilder.ProtocolVersion))
        → 비호환. 새 배포 패키지를 받아 재배포한다
    else → 호환 (MINOR 차이는 그대로 사용)
  400 EX-SEC-003 / EX-AUTH-001 → 요청 값을 고친다
  404 → 경로가 틀렸다 (허브는 경로의 존재를 알려 주지 않는다)
```

#### BE 측 처리 (의사코드)

```
B1. 경로 판정(라우팅) — POL SEC-003-02 (mask)

  주입된 <SELFCHECK_PATH> 값 하나로만 라우팅을 만든다 (PROC-901 B5 가 구성한다)
  if (요청 경로가 <SELFCHECK_PATH> 가 아니다)   → 404 (본문 없음 · EX 코드 없음)
  if (메서드가 POST 가 아니다)                  → 404 (본문 없음)
      // 405 를 쓰지 않는다 — 405 는 "그 경로가 있다"는 사실을 알려 준다
  인증·인가 검증: 인증 없음 — AUTH-001 인용 (경로 비공개는 인증이 아니다 — EXC-AUTH-01)
  요청 제한: 미적용 — 수용 리스크 (OPS-002-03 · EXC-SEC-09)
  캐시: 응답에 캐시 금지를 지정한다

B2. 입력 존재 검증 — POL SEC-003-04 (validate)

  if (본문을 JSON 으로 해석할 수 없다)          → 400 FN-014('EX-SEC-003')
  if (encX·encY·birthDate 중 하나라도 없다)     → 400 FN-014('EX-SEC-003')
  // 판정을 수행하지 않는다

B3. 생년월일 형식 검증 — FN-005 · POL AUTH-002-02 (validate)

  try  FN-005(body.birthDate)                   // ^[0-9]{6}$
  catch                                         → 400 FN-014('EX-AUTH-001')
  // 판정을 수행하지 않는다

B4. 복호화 판정 — FN-004 · POL SEC-002-01 · SEC-003-03 (validate)

  try  payload = FN-004({ encX: body.encX, encY: body.encY }, body.birthDate)
       // 연동 경로(PROC-102·PROC-104)와 같은 함수를 쓴다 —
       // 판정이 갈리면 자가진단이 통과시킨 값이 연동에서 실패한다
       conform = true · reason = null
  catch (EX-SEC-001)   conform = false · reason = 'EX-SEC-001'   → B6
  catch (EX-AUTH-002)  conform = false · reason = 'EX-AUTH-002'  → B6
  catch (EX-SEC-002)   conform = false · reason = 'EX-SEC-002'   → B6
  // 기록·전달·계수를 하지 않는다 (POL SEC-003-03 · EXC-BIZ-11)
  // 중간 값은 지역 값으로만 둔다 (POL DATA-001-03)

B5. X 평문 크기 상한 검사 — POL SEC-001-09 (validate)

  if (conform == true)
      size = LENGTH(UTF8_BYTES(payload 원문 바이트열))
      if (size > 규약 평문 상한)                // 값은 POL SEC-001 §규약 확정값
          conform = false · reason = 'EX-SEC-004'
  // FN-004 는 이 검사를 하지 않는다 — 자가진단이 규약 적합성 판정을 목적으로 하므로
  // 본 프로세스가 반환 후 별도로 검사한다 (function_FN-004.md §판정 경계에 대한 확정 사항 2)
  payload 를 지역 변수에서 버린다               // 원문을 응답에 담지 않는다

B6. 응답 구성 — POL SEC-001-11 · SEC-002-05 · DATA-001-04 (mask)

  body = { isConform:       conform,
           reasonCode:      reason,             // 적합이면 null
           protocolVersion: 허브가 구현한 규약 버전 문자열 }   // POL SEC-001 §규약 확정값
  return 200 FN-015(body)                       // 부적합도 200 이다
  // 복호화 원문·키·초기화 벡터·중간 값·실패 단계 번호·경로 값을 담지 않는다
  // 담을 속성이 MDL-015 에 없는 것이 1차 방어이고 FN-015 가 2차 방어다
  영속화 쿼리: 없음 · 사전 조회 쿼리: 없음
  후속 이벤트 발행: 없음
```

### 실행 결과

- **정상 결과**: 200 [`MDL-015`](../datas/model_MDL-011-015.md) — 적합 또는 부적합. **영속화·전달·계수·이벤트 발행이 모두 없다.**
- **실패 결과**: 400(요청 자체가 성립하지 않음) · 404(경로 불일치) · 500(내부 실패).
- **후속 트리거**: 없음. 발송처가 판정을 보고 자기 구현을 고치거나 재배포를 결정한다.

### 의존 프로세스

- **호출 관계**: 없음.
- **선행 관계**: PROC-901(경로 라우팅 구성·상수 주입) · PROC-401(발송처가 만든 암호값이 입력이다).
- **이벤트 관계**: 없음.

### 구현 가이드

- **연동과 같은 판정 함수를 쓴다.** 자가진단이 별도 구현을 가지면 존재 의의가 사라진다 — "자가진단은 통과했는데 연동은 실패"가 바로 그 사고다(`SEC-002` 구현 가이드).
- **경로 불일치를 404 로만 답한다.** 405·403·힌트 문구 어느 것도 쓰지 않는다. 경로의 존재를 드러내는 순간 유일한 완화 장치가 사라진다.
- **경로 값을 애플리케이션 설정 하나로 주입받는다.** 소스·정적 자산·프런트엔드 번들 어디에도 값을 넣지 않는다(`SEC-003-01`).
- **부적합을 4xx 로 올리지 않는다.** 판정이 정상 수행된 결과이며, 4xx 로 만들면 호출측이 요청 오류와 구별할 수 없다.
- **크기 상한 검사를 FN-004 안으로 옮기지 않는다.** 연동 경로는 진입 시점의 URL 길이 판정(`SEC-001-10`)이 이미 상한을 억제하며, 판정 함수의 책임 경계를 흐리면 두 경로의 결과가 갈린다.
- **어떤 기록도 남기지 않는다.** 호출 횟수 카운터·진단 이력도 두지 않는다(`SEC-003-03`·`OPS-003-01`).
