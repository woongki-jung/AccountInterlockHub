# 연동 결과 안내 기능 정의

정본 목록은 [`spec-process.md`](spec-process.md). 단계 라벨 체계도 그 문서가 갖는다. 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정의 대상**: 연동이 어떻게 끝났는지를 **네 경로 중 하나로 골라 안내 정보를 구성**하는 처리다. 결과 구분 → 경로 번호 대응이 이 프로세스 한 곳에만 있다 — 대응을 여러 곳에 두면 화면이 보는 결과와 발송처가 조회하는 결과가 갈린다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 6 — "결과를 네 경로로 구분해 사용자에게 표시한다 … 결과가 이미 확정된 링크로 다시 진입하면 **그 결과 경로를 그대로 다시 안내**한다(경로를 추가하지 않는다)."

### 진입점 및 진입 조건

본 프로세스는 외부 표면을 갖지 않는다. **결과 또는 실패가 확정된 지점에서 상위 프로세스가 응답을 만들기 직전에 호출**한다.

| 호출 지점 | 입력 출처(`source`) | 전달 값 |
|---|---|---|
| PROC-101 `B6` | `ENTRY_FAILURE` | 진입 단계 실패 사유(`EX-SEC-001`·`EX-SEC-004`) |
| PROC-102 `B7` | `RECORD` | 확정된 [`MDL-001`](../datas/model_MDL-001.md) + `isReAnnouncement = true` |
| PROC-102 `B4b` · PROC-103 `B2` | `REASON_CODE` | `EX-SEC-002` 등 실패 사유 |
| PROC-103 `B4` | `RECORD` | 확정된 `MDL-001` + `isReAnnouncement = true` |
| PROC-103 `B8` | `RESULT_CODE` | 이번에 확정된 결과 구분 |

- **진입 조건**: **인증 없음 — `AUTH-001` 인용.** 상위 프로세스 안에서 실행되므로 자체 진입 조건이 없다.
- **사전 검증**: 입력이 위 네 출처 중 하나여야 한다. 어느 것에도 해당하지 않으면 **경로 ③** 으로 안내한다(`SVC-005` F-003).

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 설명 |
|------|--------|------------|------|------|
| 입력 | `source` | string | Y | `ENTRY_FAILURE` · `REASON_CODE` · `RESULT_CODE` · `RECORD` |
| 입력 | `resultCode` | string | N | `RESULT_CODE`·`RECORD` 일 때. 결과 구분 4종 |
| 입력 | `reasonCode` | string | N | `ENTRY_FAILURE`·`REASON_CODE` 일 때. EX 코드 |
| 입력 | `isReAnnouncement` | boolean | N | 확정 결과 재안내 여부(기본 `false`) |
| 출력 | `resultPath` | number(1~4) | - | [`MDL-009`](../datas/model_MDL-007-010.md) |
| 출력 | `isReAnnouncement` | boolean | - | 화면 보조 표시 판단에만 쓴다 |

### 연관 데이터 및 외부 호출

- **호출 API**: 없음.
- **데이터 조회 대상**: 없음. 호출측이 이미 확보한 값만 받는다.
- **데이터 변경 대상(CRUD)**: **없음.** 재안내는 레코드를 갱신하지 않고(`BIZ-002-04`) 지표도 계수하지 않는다(`BIZ-005-03`). **결과 확인 표시(FN-010)를 호출하지 않는다** — 사용자 화면의 재안내는 발송처의 결과 수령이 아니다.

### 실행 제약사항

- **트랜잭션 경계**: **없음.** 영속화가 없는 순수 변환이다.
- **동시성 제어**: 상태를 갖지 않으므로 락·멱등 키가 필요 없다. 같은 입력은 항상 같은 출력을 낸다.
- **성능 요구**: 상수 시간 매핑이다.
- **보안 요구**: 결과 경로 번호 외에 아무것도 응답에 담지 않는다 — **사유 코드·처리 일시·재시도 횟수·내부 단계·추적 키를 담지 않는다**(`SEC-002-05`·`DATA-001-04`). 사유 코드는 오류 응답 엔벨로프의 `code` 로 이미 전달되며 화면이 설명 문구를 고르는 데만 쓴다.

### 로직 실행 순서

#### FE 측 처리 (의사코드)

```
F1. 결과 상태 수신

  진입 트리거: 아래 셋 중 하나
    ① 진입 응답의 초기 상태 stage = 'RESULT'      (PROC-101 F1 에서 넘어옴)
    ② 본인확인 응답 stage = 'RESULT'              (PROC-102 F2)
    ③ 승인·거부 응답 또는 오류 응답 엔벨로프       (PROC-103 F5)
  사용 상태:
    resultPath        = 로컬 상태<1|2|3|4>
    isReAnnouncement  = 로컬 상태<boolean>(기본 false)
    reasonCode        = 로컬 상태<string | null>   // 경로 ③ 의 설명 문구 선택에만 쓴다
  응답 어댑터 변환:
    if (응답이 오류 엔벨로프)
        reasonCode = err.code
        resultPath = (err.code == 'EX-BIZ-002' ? 4 : 3)
        // 502 EX-BIZ-002 도 정상 종료다 — 처리 실패 화면이 아니라 결과 안내다
    else
        resultPath       = res.resultPath
        isReAnnouncement = res.isReAnnouncement
  검증:
    if (resultPath 가 1~4 밖이거나 없다)   resultPath = 3   // 빈 화면·예외 화면을 만들지 않는다

F2. 경로별 패널 렌더 (SCR-004)

  경로 → 아이콘·색·제목·설명·다음 안내는 SCR-004 §결과 4경로가 정본이다
  if (resultPath == 3)   설명 문구를 reasonCode 로 고른다 (제목·아이콘·색은 셋 다 같다)
  if (isReAnnouncement)  배지 `재안내` + 덧붙이는 문장 (제목 바로 아래)
  캐시·전역 상태 갱신: 없다
  표시 금지: 추적 키 · 사유 코드 원문 · 처리 일시 · 재시도 횟수 · 내부 단계

F3. 종료

  UI 전이: 여정의 끝이다 — 화면이 제공하는 이동 수단을 두지 않는다
  정리: 페이지 메모리의 암호값 쌍·생년월일을 폐기한다 (POL DATA-001-03)
  실패 처리: 이 단계에는 서버 호출이 없어 실패 경로가 없다
```

#### BE 측 처리 (의사코드)

```
B1. 결과 확보 (호출 진입)

  엔드포인트·메서드: 없음 — 상위 프로세스 안에서 함수로 실행된다
  인증·인가 검증: 인증 없음 — AUTH-001 인용
  입력 재검증:
    if (source not in ['ENTRY_FAILURE','REASON_CODE','RESULT_CODE','RECORD'])
        → resultPath = 3 로 확정하고 B3 으로 간다        // 매핑되지 않는 상태는 경로 ③
  값 확보:
    if (source == 'RECORD')       resultCode = input.record.resultCode
    if (source == 'RESULT_CODE')  resultCode = input.resultCode
    if (source in ['ENTRY_FAILURE','REASON_CODE'])  resultCode = null

B2. 결과 경로 선택 — POL BIZ-001-02 · BIZ-001-03 (validate)

  // 결과 구분 → 경로 번호 대응은 이 자리 한 곳에만 둔다
  switch (resultCode)
      case 'SUCCESS'          → resultPath = 1
      case 'USER_DENIED'      → resultPath = 2
      case 'DECRYPT_FAILED'   → resultPath = 3
      case 'DELIVERY_FAILED'  → resultPath = 4
      case null               → resultPath = 3     // 진입 단계 실패·규약 위반(추적 레코드 없음)
      default                 → resultPath = 3     // 매핑되지 않는 상태 (SVC-005 F-003)
  // 다섯 번째 경로를 만들지 않는다
  // 결과 구분 값을 변환·별칭화하지 않는다 (POL BIZ-001-03)
  정책 적용 지점: BIZ-004-04 — 확정 후 재연동은 허브가 수행하지 않는다.
                  경로 ②·④ 의 "다음 안내"가 발송처 재요청을 가리키는 근거다

B3. 결과 안내 구성 — POL BIZ-002-04 ③ · SEC-002-05 (mask)

  info = { resultPath, isReAnnouncement: (input.isReAnnouncement ?? false) }
  // 영속화하지 않는다 — 재안내 여부는 안내 구성에만 쓰는 표시 정보다
  // 추적 레코드를 갱신하지 않는다 (보관 기산점이 밀리지 않는다)
  // 지표를 계수하지 않는다 (POL BIZ-005-03)
  // 결과 확인 표시(FN-010)를 호출하지 않는다 — 사용자 재안내는 발송처의 결과 수령이 아니다
  마스킹: FN-015 — 추적 키·복호화 원문·암호값·생년월일·처리 일시를 담지 않는다
  사전 조회 쿼리: 없음 · 영속화 쿼리: 없음
  return info                                      // MDL-009
  후속 이벤트 발행: 없음
```

### 실행 결과

- **정상 결과**: [`MDL-009`](../datas/model_MDL-007-010.md) `{ resultPath, isReAnnouncement }`. **영속화·이벤트 발행 없음.**
- **실패 결과**: 없음 — 본 프로세스에는 실패 경로가 없다. 호출측의 실패는 이미 경로 값으로 표현된다.
- **후속 트리거**: 없음. 사용자 여정의 끝이며, 이후 확인은 발송처의 조회(PROC-201·PROC-202)로 이어진다.

### 의존 프로세스

- **호출 관계**: 없음.
- **선행 관계**: PROC-101 · PROC-102 · PROC-103 · PROC-104 중 하나에서 결과 또는 실패가 확정돼야 한다.
- **이벤트 관계**: 없음.

### 구현 가이드

- **결과 구분 → 경로 대응을 한 곳에만 둔다.** 화면·조회 API·다른 프로세스가 각자 구현하면 같은 연동이 자리마다 다르게 읽힌다([`../datas/model_MDL-007-010.md`](../datas/model_MDL-007-010.md) `MDL-009` 구현 가이드).
- **경로 ③ 은 두 출처를 받는다** — 결과 구분 `DECRYPT_FAILED` 와 추적 레코드가 없는 진입 단계 실패다. 따라서 **결과 구분 값이 없어도 이 경로를 그릴 수 있어야 한다**.
- **재안내에서 아무것도 쓰지 않는다.** `result_confirmed_at` 을 건드리면 보관 기산점이 밀리고(`BIZ-002-04`), 요청 수를 올리면 지표가 중복된다(`BIZ-005-03`).
- **`isReAnnouncement` 를 저장하지 않는다.** 안내 구성에만 쓰는 표시 정보이며 대응 컬럼이 없다.
- **경로 값이 범위를 벗어나면 화면이 아니라 서버가 먼저 보정한다.** 서버가 `1~4` 를 보장해야 화면이 빈 상태를 다루지 않는다.
