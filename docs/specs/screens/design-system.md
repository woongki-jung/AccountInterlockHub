# 디자인 시스템 정의

정본 목록은 [`spec-screens.md`](spec-screens.md). 컴포넌트 카탈로그는 [`design-system-components.md`](design-system-components.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **목적**: 사용자 표면의 색·글자·간격·상태 표현·접근성 기준을 한 곳에서 정하고, 모든 화면이 같은 토큰을 참조하게 한다.
- **적용 범위**: 이 제품의 사용자 표면은 **하나**다 — 발송처 링크로 진입하는 사용자 웹([`../../prd/PRD.md`](../../prd/PRD.md) §프로그램 구성·기술스택·검증 방법). 관리자 표면이 없으므로(`AUTH-001-01`) **표면별 토큰 분기·접두어 체계를 두지 않는다.** 토큰은 한 벌이며 모든 화면이 같은 값을 쓴다.
- 기술 스택은 ReactJS(TypeScript)로 고정돼 있으나([`../../prd/devspec/infra.md`](../../prd/devspec/infra.md) §애플리케이션 구성), 본 문서는 **특정 UI 라이브러리·CSS 프레임워크를 강제하지 않는다.** 토큰은 CSS 사용자 정의 속성 이름으로 적되 구현 수단은 build 단계가 정한다.

## 표면 전제 (설계 판단의 근거)

1. **모바일 우선** — 사용자는 발송처가 보낸 링크를 대개 휴대전화에서 연다. 좁은 폭을 기준으로 설계하고 넓은 폭에서 여백만 늘린다.
2. **로그인·네비게이션이 없다** — 계정·세션이 없으므로(`AUTH-001-02`) 전역 메뉴·사이드바·프로필·로그아웃이 존재하지 않는다. 화면에는 **지금 단계의 내용과 그 단계의 액션만** 둔다.
3. **경로가 하나다** — 진입부터 결과까지 URL 이 바뀌지 않는다([`../functions/spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §프로토콜 확정). 단계 전환은 같은 문서 안에서 일어나므로 **페이지 이동 연출을 두지 않는다.** 결과 뒤의 복귀 이동은 이 여정을 **끝내고 밖으로 나가는** 이동이라 여기에 해당하지 않는다([`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동).
4. **표시할 개인정보가 없다** — 허브는 사용자 정보를 보관·표시하지 않는다(`DATA-001-02`·`DATA-001-04`). 마스킹 규칙이 필요한 표시 항목이 존재하지 않는다.
5. **문구가 상수에서 온다** — 동의 항목·안내 문구는 배포 상수이며 화면이 가공하지 않는다(`DATA-003-05`). 레이아웃은 상수표가 정한 허용 형태를 전제로 짠다(§안내 영역 레이아웃 전제).
6. **여정이 짧다** — 한 사람이 이 표면에 머무는 시간은 몇 분이다. 학습을 요구하는 장치(온보딩·툴팁·설정)를 두지 않는다.

## 타이포그래피

내려받는 웹 글꼴을 쓰지 않는다 — 진입 즉시 읽혀야 하고 외부 요청을 늘리지 않기 위함이다. 운영체제 기본 글꼴을 그대로 쓴다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--font-family-base` | 시스템 UI 글꼴 스택(한국어 포함) | 전체 |
| `--font-size-xs` | `0.8125rem` (13px) | 배지·캡션 |
| `--font-size-sm` | `0.875rem` (14px) | 보조 설명 |
| `--font-size-base` | `1rem` (16px) | 본문·버튼·**입력 필드 최소값** |
| `--font-size-lg` | `1.125rem` (18px) | 강조 문단 |
| `--font-size-xl` | `1.375rem` (22px) | 화면 제목 |
| `--font-size-2xl` | `1.75rem` (28px) | 결과 제목 |
| `--font-weight-regular` / `--font-weight-semibold` / `--font-weight-bold` | `400` / `600` / `700` | 본문 / 강조·버튼 / 제목 |
| `--line-height-tight` / `--line-height-base` | `1.35` / `1.6` | 제목 / 본문 |

- **입력 필드 글자는 `--font-size-base` 미만으로 두지 않는다.** 16px 보다 작으면 일부 모바일 브라우저가 포커스 시 화면을 자동 확대해 레이아웃이 흔들린다.
- 생년월일 입력은 `--font-size-lg`·자간 `0.15em`·고정폭 숫자로 표시해 여섯 자리를 세기 쉽게 한다.
- 줄 길이는 한 줄 최대 40 글자 안팎(카드 최대 폭이 이를 만든다).
- **고정 높이를 주지 않는다** — 글자 간격을 사용자가 키워도 잘리지 않아야 한다(1.4.12).

- `prefers-reduced-motion: reduce` 이면 전환·페이드 시간을 `0ms` 로 둔다. **진행 표시는 정보이므로 없애지 않고** 회전 주기를 1.6초 이상으로 늦춘다.

## 레이아웃

전역 네비게이션·사이드바·푸터 메뉴·브랜드 영역이 **없다.** 화면은 아래 한 벌의 구조를 공유한다.

1. **페이지** — 바탕 `--color-bg`, 좌우 여백 `--space-md`, 상하 여백 `--space-xl`. 세로 중앙 정렬을 쓰지 않는다(내용 높이가 단계마다 달라 흔들린다). 내용은 위에서부터 쌓는다.
2. **카드** — 바탕 `--color-surface`, 모서리 `--radius-lg`, 그림자 `--shadow-card`, 안쪽 여백 `--space-lg`. 최대 폭 `--size-content-max`, 가로 중앙 정렬.
3. **카드 내부 순서** — ① 화면 제목(h1) ② 보조 설명 ③ 본문 영역(폼·목록·결과) ④ 액션 영역. 이 순서를 화면마다 바꾸지 않는다.
4. **액션 영역** — 카드 맨 아래. 버튼이 둘이면 **세로로 쌓고 주 액션을 위에 둔다**(좁은 폭에서 가로 배치는 히트 영역을 깎는다). 버튼 사이 간격 `--space-sm`.

### 반응형 브레이크포인트

기준은 **모바일 우선**이며, 아래 두 지점에서만 값이 바뀐다. 구조(단일 컬럼)는 어느 폭에서도 같다.

| 이름 | 조건 | 변화 |
|---|---|---|
| 기본 | `0`~`479px` | 카드가 좌우 여백을 뺀 폭 전체. 카드 안쪽 여백 `--space-md`, 상하 여백 `--space-lg` |
| `--bp-sm` | `480px` 이상 | 카드 최대 폭 `440px`, 안쪽 여백 `--space-lg`, 좌우 여백 `--space-lg` |
| `--bp-md` | `768px` 이상 | 카드 최대 폭 `--size-content-max`(480px), 상하 여백 `--space-2xl` |

- **가로 스크롤을 만들지 않는다.** 320px 폭에서 모든 화면이 세로 스크롤만으로 동작해야 한다(1.4.10). 확대 400% 에서도 같다.
- 표·고정폭 요소를 쓰지 않는다. 이 표면에는 목록·폼·안내문만 있다.

| **초기** | 문서 수신 직후 | **스켈레톤을 두지 않는다** — 진입 응답이 초기 상태를 함께 실어 주므로(`spec-functions-api-user.md` §연동 요청 진입) 첫 그림에 이미 내용이 있다 |
| **로딩(제출 중)** | **본인확인 요청 응답 대기(SCR-001 하나)** | 눌린 버튼에 스피너 + 문구 교체, 입력 필드 잠금(`aria-busy="true"`). **승인 제출(SCR-002)에는 이 표현이 서지 않는다** — 아래 근거 |
| **오류(입력)** | 형식 위반·재입력 안내·필수 동의 미충족 | 화면의 **알림 영역**에 인라인 알림(위험 계열) + 필드 경계 `--color-danger` + 오류 문구를 필드에 연결. **단계는 바뀌지 않는다** |
| **오류(처리)** | 내부 오류(`EX-BIZ-003`) | **같은 알림 영역**에 인라인 알림 + 액션 버튼 재활성. 사용자가 그대로 다시 제출할 수 있다 |
| **비활성** | 필수 동의 미충족 | 버튼은 `--color-disabled-bg`·`--color-disabled-fg`·**`aria-disabled="true"`**(완전한 `disabled` 가 아니다 — 눌렀을 때 유효성 안내를 읽혀야 한다). **숨기지 않는다** — 무엇을 채워야 눌리는지 보여야 한다 |
| **빈 상태** | 안내 문구 상수가 비었을 때 | **안내 영역을 렌더하지 않는다**(`EXC-BIZ-07`). 빈 자리 표시·대체 문구를 넣지 않는다 |
| **결과** | 결과 3경로 | 결과 패널로 카드 내용을 교체(§결과 3경로의 시각 구분) |

- **제출 중 표현이 서는 화면은 SCR-001 하나다.** 승인 제출은 요청 발신 즉시 카드 내용이 진행 화면(SCR-003)으로 바뀌어 **버튼도 동의 목록도 화면에서 사라지므로**, SCR-002 에는 버튼 스피너도 폼 잠금도 나타나지 않는다([`screen_SCR-002.md`](screen_SCR-002.md) §화면 상태 전이 `SubmittingApprove`). 같은 이유로 스피너를 쓰는 화면은 SCR-001·SCR-003 둘뿐이고 동의 목록에는 **잠금 상태·`disabled` 를 두지 않는다**([`design-system-components.md`](design-system-components.md) §Spinner·§ConsentList). 승인 이후의 대기 표현은 SCR-003 의 진행 패널이 대신한다.
- **인라인 알림의 위치는 오류 유형에 따라 달라지지 않는다** — 화면 사양이 고정한 **알림 영역**(본문 영역 아래·액션 영역이 있으면 그 위) 한 곳에 나타난다([`screen_SCR-001.md`](screen_SCR-001.md) §레이아웃 구성 3 · [`screen_SCR-002.md`](screen_SCR-002.md)·[`screen_SCR-003.md`](screen_SCR-003.md) §레이아웃 구성 4). 입력 오류는 입력 아래, 처리 오류는 카드 위처럼 자리를 나누면 같은 화면에서 알림이 옮겨 다녀 방금 뜬 알림을 놓친다. **화면이 스스로 띄우는 유효성 안내도 같은 자리**다([`screen_SCR-002.md`](screen_SCR-002.md) §조건부 표시 — 화면 게이팅).
- 목록형 빈 상태가 이 표면에 존재하지 않는다 — 조회 화면이 없고 동의 항목은 1건 이상이 보장된다([`../datas/model_MDL-007-010.md`](../datas/model_MDL-007-010.md) `MDL-008`).
- 재시도 버튼·문의 안내를 두지 않는다. 상위 문서에 근거가 없고, 결과 확정 후의 재연동은 발송처가 새 요청을 발행한다(`BIZ-004-04`). **결과 ① 의 복귀 이동 링크는 여기에 해당하지 않는다** — 재시도·문의가 아니라 여정 밖으로 나가는 이동이며 상위 근거가 있다([`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 6 · [`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동).

## 결과 3경로의 시각 구분

경로는 정확히 셋이며 넷째를 만들지 않는다(`BIZ-001-02`). 각 경로는 **색 + 아이콘 + 제목 문구** 셋으로 구분한다 — 색을 못 보아도 아이콘과 문구로 구분된다.

| 경로 | 의미 | 강조색 | 패널 바탕 | 아이콘(뜻) | 제목 |
|---|---|---|---|---|---|
| ① | 연동 완료 | `--color-success` | `--color-success-weak` | 원 안 체크 | 연동이 완료되었습니다 |
| ② | 링크·복호화 오류 | `--color-danger` | `--color-danger-weak` | 원 안 느낌표 | 연동을 진행할 수 없습니다 |
| ③ | 수신처 전달 실패 | `--color-warning` | `--color-warning-weak` | 삼각형 안 느낌표 | 연동을 마치지 못했습니다 |

- **색·아이콘·제목은 사용자 거부 경로가 폐지되기 전 것을 그대로 승계했다**(`BIZ-003-03`) — 번호만 당겨졌고 짝을 새로 짓지 않았다. 중립 계열(`--color-neutral`)만 결과 패널에서 쓰이지 않게 됐고, **그 토큰은 보조 배지(재안내)가 계속 쓴다**(§색 토큰 — 토큰 값·이름을 바꾸지 않았다).
- 아이콘은 **인라인 SVG** 로 넣고 `aria-hidden="true"` 로 감춘다(뜻은 제목 문구가 전달한다). 아이콘 글꼴·외부 이미지를 쓰지 않는다.
- **확정 결과 재안내**는 새 경로가 아니라 위 세 패널 중 하나의 재표시이며, 보조 배지가 함께 붙는다(대상은 ①·③ — [`screen_SCR-004.md`](screen_SCR-004.md) §확정 결과 재안내).
- **연동 완료(①)에는 복귀 안내 영역이 패널 끝에 붙는다** — 색·아이콘·제목은 달라지지 않고 영역 하나가 더해질 뿐이다. 표시 조건·문구·대기 시간의 정본은 [`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동이며, **이 문서는 그 시간 값을 갖지 않는다**(모션 토큰이 아니라 화면 하나의 흐름 규칙이다).

## 안내 영역 레이아웃 전제

동의 안내 문구(`<CONSENT_NOTICE>`)와 동의 항목(`<CONSENT_ITEMS>`)은 배포 상수이며 값은 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §동의 항목 값이 단일 출처다. 레이아웃은 그 절이 정한 **허용 형태**를 전제로 짠다.

1. 안내 문구는 **최대 400자·최대 3단락(빈 줄 구분)·평문**이다. 이 범위 안에서는 값이 바뀌어도 화면 사양을 고치지 않는다.
2. 안내 영역은 **단락을 그대로 문단으로 렌더**한다 — 접기·더 보기·스크롤 영역을 두지 않는다(3단락 400자는 접지 않아도 읽힌다).
3. 서식·링크·HTML 을 해석하지 않는다. 평문으로만 출력한다(`DATA-003-05`).
4. **값이 비면 영역을 렌더하지 않는다.** 제목·구분선·여백도 함께 사라진다.
5. 허용 형태를 벗어나는 문구가 필요해지면 **상수와 화면 사양을 함께 고친다**(`EXC-DATA-08`).
6. 동의 항목은 현재 1건이지만 **항상 목록으로 렌더**한다 — 항목 수가 상수 변경으로 늘 수 있다. 1건일 때도 목록 구조를 그대로 쓰고 특별 취급하지 않는다.

## 접근성 기준

목표는 **WCAG 2.1 AA** 이며 아래를 사양으로 못박는다.

| 항목 | 기준 | 이 표면의 대응 |
|---|---|---|
| 명도 대비 | 본문 4.5:1 · 큰 텍스트/비텍스트 3:1 | §색 대비 검증의 실측값 전건 충족 |
| 색 사용 | 색만으로 의미 전달 금지 | 상태·결과에 아이콘 + 문구 병기 |
| 키보드 | 모든 기능을 키보드로 조작·탭 순서 = 문서 순서 | 조작 요소는 버튼·입력·체크박스뿐이며 커스텀 위젯을 만들지 않는다. 모달이 없어 포커스 가둠도 없다 |
| 포커스 표시 | 항상 보이는 포커스 표시 | `:focus-visible` 에 2px 안쪽 여백(바탕색) + 2px `--color-focus` 링. 채워진 버튼 위에서도 흰 여백이 3:1 이상을 만든다. **포커스를 받는 요소는 모두 이 한 벌의 링을 쓴다** — 프로그램 이동으로만 포커스를 받는 단계 제목(`tabindex="-1"`)도 예외가 아니다(아래) |
| 폼 레이블 | 모든 입력에 보이는 레이블 | `<label for>` 로 연결. 자리표시자를 레이블로 쓰지 않는다 |
| 오류 안내 | 오류를 글로 알리고 입력과 연결 | 오류 문구를 `aria-describedby` 로 필드에 연결하고 `aria-invalid="true"` 를 준다 |
| 상태 알림 | 화면 변화를 소리로도 알림 | 단계가 바뀌면 새 제목(`tabindex="-1"`)으로 포커스를 옮기고 문서 제목을 갱신한다(**옮겨 간 제목에도 위 포커스 링이 그대로 선다**). **단, 그 전환에 필드에 매인 안내가 함께 뜨면 포커스는 그 필드가 가져간다**(아래 — 문서 제목 갱신은 그대로). 진행 중·오류는 `role="status"`(공손) 로 알린다 |
| 히트 영역 | 최소 44x44 CSS px | `--size-hit-min` 을 모든 조작 요소에 적용 |
| 확대·재배치 | 320px 폭·400% 확대에서 가로 스크롤 없음 | 단일 컬럼·상대 단위·고정 높이 금지 |
| 모션 | 감소 설정 존중 | `prefers-reduced-motion` 대응(§간격·크기·모양) |
| 언어 | 문서 언어 선언 | 문서 `lang="ko"` |

- **프로그램 이동으로 받은 포커스에도 같은 링이 선다.** 단계 제목은 `tabindex="-1"` 이라 탭 순서에 없어 **단계 전환의 프로그램 이동이 포커스가 닿는 유일한 경로**인데, 조건을 `:focus-visible` 하나에만 걸고 규칙이 이 제목까지 닿지 않으면 화면에는 사양의 링이 아니라 **브라우저 기본 링(1px)** 이 그려진다(Chrome 실측). 휴리스틱이 매치되지 않는 브라우저에서는 아무 표시도 서지 않는다. 사양이 요구하는 것은 **제목이 포커스를 갖는 동안 위 링이 실제로 보이는 것**이며, 구현은 이 제목에도 같은 링 선언이 닿게 하고 프로그램 이동에서도 조건이 성립하게 한다(예: 이 제목에 한해 `:focus` 로도 같은 규칙을 건다 — **선택자는 예시**이고 수단은 build 가 정한다). 근거: 이 표시가 **다음 `Tab` 이 어디서 시작되는지 알리는 유일한 단서**이고(SCR-003 은 조작 요소가 아예 없다 — [`design-system-components.md`](design-system-components.md) §ProgressPanel), 기본 링은 브라우저·테마마다 굵기·색이 달라 §색 대비 검증이 실측으로 보장한 `--color-focus` 대비(카드 위 7.78:1·페이지 위 7.19:1)가 그 자리에서만 무너진다. 제목이 조작 요소로 오독될 우려보다 포커스 위치를 잃는 손실이 크다 — 링은 '누를 수 있다'가 아니라 **'지금 포커스가 여기'** 라는 뜻이고, 제목에는 밑줄·커서 변화 같은 조작 단서를 두지 않는다.
- **단계 전환과 필드에 매인 안내가 겹치면 포커스는 그 필드가 가져간다.** 위 행의 "새 제목으로 옮긴다"는 전환에 **입력 요소에 매인 InlineAlert**(재입력·형식 안내, 첫 미충족 항목 안내 — [`design-system-components.md`](design-system-components.md) §InlineAlert)가 함께 뜨면 적용하지 않고 **그 안내가 매인 요소로** 포커스를 옮긴다. 해당하는 전환은 둘이며 **도착 상태가 이미 도착지를 정해 두었다** — `BackToIdentity`(SCR-002·SCR-003 → SCR-001 · 400 `EX-AUTH-001`·`EX-AUTH-002`)는 [`screen_SCR-001.md`](screen_SCR-001.md) §화면 상태 전이 `ReEntry` 의 "InlineAlert + 필드 포커스"(불일치는 **값 유지·전체 선택**)로, `BackToConsent` 중 400 `EX-BIZ-001`(SCR-003 → SCR-002)은 [`screen_SCR-002.md`](screen_SCR-002.md) 같은 절 `Blocked` 의 "첫 미충족 항목으로 포커스"로 들어온다. 근거 셋 — ① **같은 오류의 포커스 도착지가 어느 화면에서 제출했는지에 따라 갈리면 안 된다**(`EX-AUTH-002` 는 SCR-001 에서 제출하면 필드로, SCR-002 에서 제출하면 제목으로 가게 된다 — 알림 자리를 오류 유형으로 나누지 않는 §상태 표현과 같은 취지다) ② 사용자의 다음 행동이 그 요소의 수정이라, 제목으로 보내면 `Tab` 이 한 번 더 필요하고 **값 유지·전체 선택**(오타를 즉시 덮어쓰게 하는 확정 설계)이 무의미해진다 ③ 화면이 바뀐 사실은 `role="status"` 인 그 안내가 낭독하며, 옮겨 간 요소가 레이블·값·`aria-describedby` 로 연결된 안내까지 함께 읽혀 위 행의 목적이 오히려 더 채워진다. **문서 제목(`document.title`) 갱신과 제목 문구 교체는 이 예외에서도 그대로 수행한다** — 포커스 이동과 별개 계약이다. 필드에 매인 안내가 없는 전환(SCR-002·SCR-003·SCR-004 도착)은 위 행 그대로 제목으로 옮긴다. 이 예외로 **SCR-001 제목은 제품에서 프로그램 포커스를 받는 자리가 없어진다**(진입은 전환이 아니고 자동 포커스를 주지 않는다 — [`design-system-components.md`](design-system-components.md) §TextField). 그 화면에서 확인할 것은 제목의 링이 아니라 **포커스가 필드로 갔는가**다.
- 스크린리더 지원 수준은 **표준 HTML 시맨틱 + 필요한 최소 ARIA** 다. 사용자 지정 위젯이 없으므로 역할·상태를 직접 구현할 자리가 없다.

## 하지 않는 것

1. **관리자·구성 화면을 만들지 않는다**(`AUTH-001-01`). 연동 구성은 상수 갱신·재배포로만 바뀐다.
2. **로그인·계정·세션 화면을 만들지 않는다**(`AUTH-001-02`).
3. **암호값·생년월일·복호화 원문·추적 키를 화면에 표시하지 않는다**(`DATA-001-04`·[`function_FN-014-015.md`](../functions/function_FN-014-015.md) §금지 항목).
4. **링크 만료·1회성 사용·요청 제한을 나타내는 표시를 두지 않는다**(`OPS-002-05`).
