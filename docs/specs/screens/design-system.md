# 디자인 시스템 정의

정본 목록은 [`spec-screens.md`](spec-screens.md). 컴포넌트 카탈로그는 [`design-system-components.md`](design-system-components.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **목적**: 사용자 표면의 색·글자·간격·상태 표현·접근성 기준을 한 곳에서 정하고, 모든 화면이 같은 토큰을 참조하게 한다.
- **적용 범위**: 이 제품의 사용자 표면은 **하나**다 — 발송처 링크로 진입하는 사용자 웹([`../../prd/PRD.md`](../../prd/PRD.md) §프로그램 구성·기술스택·검증 방법). 관리자 표면이 없으므로(`AUTH-001-01`) **표면별 토큰 분기·접두어 체계를 두지 않는다.** 토큰은 한 벌이며 모든 화면이 같은 값을 쓴다.
- 기술 스택은 ReactJS(TypeScript)로 고정돼 있으나([`../../prd/devspec/infra.md`](../../prd/devspec/infra.md) §애플리케이션 구성), 본 문서는 **특정 UI 라이브러리·CSS 프레임워크를 강제하지 않는다.** 토큰은 CSS 사용자 정의 속성 이름으로 적되 구현 수단은 build 단계가 정한다.

## 표면 전제 (설계 판단의 근거)

1. **모바일 우선** — 사용자는 발송처가 보낸 링크를 대개 휴대전화에서 연다. 좁은 폭을 기준으로 설계하고 넓은 폭에서 여백만 늘린다.
2. **로그인·네비게이션이 없다** — 계정·세션이 없으므로(`AUTH-001-02`) 전역 메뉴·사이드바·프로필·로그아웃이 존재하지 않는다. 화면에는 **지금 단계의 내용과 그 단계의 액션만** 둔다.
3. **경로가 하나다** — 진입부터 결과까지 URL 이 바뀌지 않는다([`../functions/spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §프로토콜 확정). 단계 전환은 같은 문서 안에서 일어나므로 **페이지 이동 연출을 두지 않는다.**
4. **표시할 개인정보가 없다** — 허브는 사용자 정보를 보관·표시하지 않는다(`DATA-001-02`·`DATA-001-04`). 마스킹 규칙이 필요한 표시 항목이 존재하지 않는다.
5. **문구가 상수에서 온다** — 동의 항목·안내 문구는 배포 상수이며 화면이 가공하지 않는다(`DATA-003-05`). 레이아웃은 상수표가 정한 허용 형태를 전제로 짠다(§안내 영역 레이아웃 전제).
6. **여정이 짧다** — 한 사람이 이 표면에 머무는 시간은 몇 분이다. 학습을 요구하는 장치(온보딩·툴팁·설정)를 두지 않는다.

## 타이포그래피

내려받는 웹 글꼴을 쓰지 않는다 — 진입 즉시 읽혀야 하고 외부 요청을 늘리지 않기 위함이다. 운영체제 기본 글꼴을 그대로 쓴다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--font-family-base` | 시스템 UI 글꼴 스택(한국어 포함) | 전체 |
| `--font-size-xs` | `0.8125rem` (13px) | 배지·캡션 |
| `--font-size-sm` | `0.875rem` (14px) | 보조 설명 |
| `--font-size-base` | `1rem` (16px) | 본문·버튼·**입력 필드 최소값** |
| `--font-size-lg` | `1.125rem` (18px) | 강조 문단 |
| `--font-size-xl` | `1.375rem` (22px) | 화면 제목 |
| `--font-size-2xl` | `1.75rem` (28px) | 결과 제목 |
| `--font-weight-regular` / `--font-weight-semibold` / `--font-weight-bold` | `400` / `600` / `700` | 본문 / 강조·버튼 / 제목 |
| `--line-height-tight` / `--line-height-base` | `1.35` / `1.6` | 제목 / 본문 |

- **입력 필드 글자는 `--font-size-base` 미만으로 두지 않는다.** 16px 보다 작으면 일부 모바일 브라우저가 포커스 시 화면을 자동 확대해 레이아웃이 흔들린다.
- 생년월일 입력은 `--font-size-lg`·자간 `0.15em`·고정폭 숫자로 표시해 여섯 자리를 세기 쉽게 한다.
- 줄 길이는 한 줄 최대 40 글자 안팎(카드 최대 폭이 이를 만든다).
- **고정 높이를 주지 않는다** — 글자 간격을 사용자가 키워도 잘리지 않아야 한다(1.4.12).

- **히트 영역 44x44 는 모든 조작 요소에 적용**한다 — 버튼, 체크박스(행 전체가 히트 영역), 링크. 시각 크기가 작아도 여백으로 44 를 채운다.
- `prefers-reduced-motion: reduce` 이면 전환·페이드 시간을 `0ms` 로 둔다. **진행 표시는 정보이므로 없애지 않고** 회전 주기를 1.6초 이상으로 늦춘다.

## 레이아웃

전역 네비게이션·사이드바·푸터 메뉴·브랜드 영역이 **없다.** 화면은 아래 한 벌의 구조를 공유한다.

1. **페이지** — 바탕 `--color-bg`, 좌우 여백 `--space-md`, 상하 여백 `--space-xl`. 세로 중앙 정렬을 쓰지 않는다(내용 높이가 단계마다 달라 흔들린다). 내용은 위에서부터 쌓는다.
2. **카드** — 바탕 `--color-surface`, 모서리 `--radius-lg`, 그림자 `--shadow-card`, 안쪽 여백 `--space-lg`. 최대 폭 `--size-content-max`, 가로 중앙 정렬.
3. **카드 내부 순서** — ① 화면 제목(h1) ② 보조 설명 ③ 본문 영역(폼·목록·결과) ④ 액션 영역. 이 순서를 화면마다 바꾸지 않는다.
4. **액션 영역** — 카드 맨 아래. 버튼이 둘이면 **세로로 쌓고 주 액션을 위에 둔다**(좁은 폭에서 가로 배치는 히트 영역을 깎는다). 버튼 사이 간격 `--space-sm`.

### 반응형 브레이크포인트

기준은 **모바일 우선**이며, 아래 두 지점에서만 값이 바뀐다. 구조(단일 컬럼)는 어느 폭에서도 같다.

| 이름 | 조건 | 변화 |
|---|---|---|
| 기본 | `0`~`479px` | 카드가 좌우 여백을 뺀 폭 전체. 카드 안쪽 여백 `--space-md`, 상하 여백 `--space-lg` |
| `--bp-sm` | `480px` 이상 | 카드 최대 폭 `440px`, 안쪽 여백 `--space-lg`, 좌우 여백 `--space-lg` |
| `--bp-md` | `768px` 이상 | 카드 최대 폭 `--size-content-max`(480px), 상하 여백 `--space-2xl` |

- **가로 스크롤을 만들지 않는다.** 320px 폭에서 모든 화면이 세로 스크롤만으로 동작해야 한다(1.4.10). 확대 400% 에서도 같다.
- 표·고정폭 요소를 쓰지 않는다. 이 표면에는 목록·폼·안내문만 있다.

| **로딩(제출 중)** | 본인확인·승인 요청 응답 대기 | 눌린 버튼에 스피너 + 문구 교체, 폼 전체 입력 잠금(`aria-busy="true"`). 승인 제출은 전용 진행 화면으로 전환한다 |
| **오류(입력)** | 형식 위반·재입력 안내·필수 동의 미충족 | 해당 필드·영역에 인라인 알림(위험 계열) + 필드 경계 `--color-danger` + 오류 문구를 필드에 연결. **단계는 바뀌지 않는다** |
| **오류(처리)** | 내부 오류(`EX-BIZ-003`) | 카드 상단에 인라인 알림 + 액션 버튼 재활성. 사용자가 그대로 다시 제출할 수 있다 |
| **비활성** | 필수 동의 미충족·제출 중 | 버튼 `--color-disabled-bg`·`--color-disabled-fg`, `aria-disabled="true"`. **숨기지 않는다** — 무엇을 채워야 눌리는지 보여야 한다 |
| **빈 상태** | 안내 문구 상수가 비었을 때 | **안내 영역을 렌더하지 않는다**(`EXC-BIZ-07`). 빈 자리 표시·대체 문구를 넣지 않는다 |
| **결과** | 결과 4경로 | 결과 패널로 카드 내용을 교체(§결과 4경로) |

- 목록형 빈 상태가 이 표면에 존재하지 않는다 — 조회 화면이 없고 동의 항목은 1건 이상이 보장된다([`../datas/model_MDL-007-010.md`](../datas/model_MDL-007-010.md) `MDL-008`).
- 재시도 버튼·문의 안내를 두지 않는다. 상위 문서에 근거가 없고, 결과 확정 후의 재연동은 발송처가 새 요청을 발행한다(`BIZ-004-04`).

## 결과 4경로의 시각 구분

경로는 정확히 넷이며 다섯째를 만들지 않는다(`BIZ-001-02`). 각 경로는 **색 + 아이콘 + 제목 문구** 셋으로 구분한다 — 색을 못 보아도 아이콘과 문구로 구분된다.

| 경로 | 의미 | 강조색 | 패널 바탕 | 아이콘(뜻) | 제목 |
|---|---|---|---|---|---|
| ① | 연동 완료 | `--color-success` | `--color-success-weak` | 원 안 체크 | 연동이 완료되었습니다 |
| ② | 사용자 거부 | `--color-neutral` | `--color-neutral-weak` | 원 안 가로줄(중지) | 연동을 진행하지 않았습니다 |
| ③ | 링크·복호화 오류 | `--color-danger` | `--color-danger-weak` | 원 안 느낌표 | 연동을 진행할 수 없습니다 |
| ④ | 수신처 전달 실패 | `--color-warning` | `--color-warning-weak` | 삼각형 안 느낌표 | 연동을 마치지 못했습니다 |

- **거부는 오류가 아니다** — 사용자가 의도한 선택이므로 위험 계열 색·오류 아이콘을 쓰지 않고 중립 계열로 표시한다.
- 아이콘은 **인라인 SVG** 로 넣고 `aria-hidden="true"` 로 감춘다(뜻은 제목 문구가 전달한다). 아이콘 글꼴·외부 이미지를 쓰지 않는다.
- **확정 결과 재안내**는 새 경로가 아니라 위 네 패널 중 하나의 재표시이며, 보조 배지가 함께 붙는다(§보조 표시).

## 안내 영역 레이아웃 전제

동의 안내 문구(`<CONSENT_NOTICE>`)와 동의 항목(`<CONSENT_ITEMS>`)은 배포 상수이며 값은 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §동의 항목 값이 단일 출처다. 레이아웃은 그 절이 정한 **허용 형태**를 전제로 짠다.

1. 안내 문구는 **최대 400자·최대 3단락(빈 줄 구분)·평문**이다. 이 범위 안에서는 값이 바뀌어도 화면 사양을 고치지 않는다.
2. 안내 영역은 **단락을 그대로 문단으로 렌더**한다 — 접기·더 보기·스크롤 영역을 두지 않는다(3단락 400자는 접지 않아도 읽힌다).
3. 서식·링크·HTML 을 해석하지 않는다. 평문으로만 출력한다(`DATA-003-05`).
4. **값이 비면 영역을 렌더하지 않는다.** 제목·구분선·여백도 함께 사라진다.
5. 허용 형태를 벗어나는 문구가 필요해지면 **상수와 화면 사양을 함께 고친다**(`EXC-DATA-08`).
6. 동의 항목은 현재 1건이지만 **항상 목록으로 렌더**한다 — 항목 수가 상수 변경으로 늘 수 있다. 1건일 때도 목록 구조를 그대로 쓰고 특별 취급하지 않는다.

## 접근성 기준

목표는 **WCAG 2.1 AA** 이며 아래를 사양으로 못박는다.

| 항목 | 기준 | 이 표면의 대응 |
|---|---|---|
| 명도 대비 | 본문 4.5:1 · 큰 텍스트/비텍스트 3:1 | §색 대비 검증의 실측값 전건 충족 |
| 색 사용 | 색만으로 의미 전달 금지 | 상태·결과에 아이콘 + 문구 병기 |
| 키보드 | 모든 기능을 키보드로 조작·탭 순서 = 문서 순서 | 조작 요소는 버튼·입력·체크박스뿐이며 커스텀 위젯을 만들지 않는다. 모달이 없어 포커스 가둠도 없다 |
| 포커스 표시 | 항상 보이는 포커스 표시 | `:focus-visible` 에 2px 안쪽 여백(바탕색) + 2px `--color-focus` 링. 채워진 버튼 위에서도 흰 여백이 3:1 이상을 만든다 |
| 폼 레이블 | 모든 입력에 보이는 레이블 | `<label for>` 로 연결. 자리표시자를 레이블로 쓰지 않는다 |
| 오류 안내 | 오류를 글로 알리고 입력과 연결 | 오류 문구를 `aria-describedby` 로 필드에 연결하고 `aria-invalid="true"` 를 준다 |
| 상태 알림 | 화면 변화를 소리로도 알림 | 단계가 바뀌면 새 제목(`tabindex="-1"`)으로 포커스를 옮기고 문서 제목을 갱신한다. 진행 중·오류는 `role="status"`(공손) 로 알린다 |
| 히트 영역 | 최소 44x44 CSS px | `--size-hit-min` 을 모든 조작 요소에 적용 |
| 확대·재배치 | 320px 폭·400% 확대에서 가로 스크롤 없음 | 단일 컬럼·상대 단위·고정 높이 금지 |
| 모션 | 감소 설정 존중 | `prefers-reduced-motion` 대응(§간격·크기·모양) |
| 언어 | 문서 언어 선언 | 문서 `lang="ko"` |

- 스크린리더 지원 수준은 **표준 HTML 시맨틱 + 필요한 최소 ARIA** 다. 사용자 지정 위젯이 없으므로 역할·상태를 직접 구현할 자리가 없다.

## 하지 않는 것

1. **관리자·구성 화면을 만들지 않는다**(`AUTH-001-01`). 연동 구성은 상수 갱신·재배포로만 바뀐다.
2. **로그인·계정·세션 화면을 만들지 않는다**(`AUTH-001-02`).
3. **암호값·생년월일·복호화 원문·추적 키를 화면에 표시하지 않는다**(`DATA-001-04`·[`function_FN-014-015.md`](../functions/function_FN-014-015.md) §금지 항목).
4. **링크 만료·1회성 사용·요청 제한을 나타내는 표시를 두지 않는다**(`OPS-002-05`).
5. **재시도 버튼·문의 채널·상담 링크를 두지 않는다** — 상위 문서에 근거가 없다.
6. **표면별 토큰 접두어를 만들지 않는다** — 표면이 하나다.
