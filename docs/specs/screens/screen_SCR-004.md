# 연동 결과 안내 화면 정의

정본 목록은 [`spec-screens.md`](spec-screens.md). 디자인 토큰·컴포넌트는 [`design-system.md`](design-system.md) · [`design-system-components.md`](design-system-components.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **화면 목적**: 연동이 어떻게 끝났는지를 **세 경로 중 하나로** 알린다. 사용자가 다음에 무엇을 하면 되는지까지 한 문장으로 덧붙인다. **연동 완료**(경로 ①)에서는 결과를 잠시 보여 준 뒤 응답이 실어 준 복귀 주소로 사용자를 돌려보내 **여정을 결과 화면에서 끝내지 않는다**(§복귀 이동). 완료가 아닌 결과(②·③)는 **이동할 주소를 받지 못해** 이 화면에 머문다. 결과가 이미 확정된 링크로 다시 들어와도 **같은 경로를 다시 표시**하고 이미 처리된 요청임을 보조 표시로 알린다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 6 — "결과를 **세 경로**로 구분해 사용자에게 표시한다 — 연동 완료 · 링크·복호화 오류 · 수신처 전달 실패. 결과가 이미 확정된 링크로 다시 진입하면 **그 결과 경로를 그대로 다시 안내**한다(경로를 추가하지 않는다)."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 6 — "**연동 완료 결과만** 결과를 **3초** 보여 준 뒤 **요청 처리 응답이 돌려준 복귀 주소로 자동 이동**한다 … **완료가 아닌 결과는 이동할 주소를 받지 못하므로**(허브가 복귀 주소를 싣지 않는다) 결과 화면에 머문다."

## SCR-004 연동 결과 안내

### 기본 정보

| 항목 | 내용 |
|------|------|
| 화면명 | 연동 결과 안내 |
| 화면 경로 | `<INTERLOCK_ENTRY_PATH>` (쿼리 `encX`·`encY`) — 단계 `RESULT`. 결과 경로마다 URL 을 나누지 않는다 |
| 접근 권한 | `Public` — 결과가 확정된 진행 상태에서 열린다. 링크 형식이 깨진 진입은 이 화면이 **첫 화면**이 된다 |
| 관련 서비스 | [`SVC-005`](../services/service_SVC-005.md) 연동 결과 안내 |
| 트리거 PROC | 없음 — 이 화면의 조작(복귀 이동)은 **서버를 부르지 않는다**. 표시 내용을 정한 것은 PROC-105 다 |
| 선행 화면 | SCR-001 · SCR-002 · SCR-003, 또는 **없음**(진입 판정 실패 시 최초 화면) |
| 관련 IA 항목 | `USR-05`(결과 안내) — 결과는 `USR-01`·`USR-02`·`USR-03`·`USR-04` 어디에서든 흘러든다 |

### 레이아웃 구성

카드 안을 ResultPanel 하나로 채운다. 앞 단계의 폼·목록·안내는 남기지 않는다. 아래 순서와 문구만 이 문서가 정하고, **요소 사이 간격은 [`design-system-components.md`](design-system-components.md) §ResultPanel 이 정본**이다(값을 여기에 옮겨 적지 않는다).

1. **결과 아이콘** — 경로별 아이콘(40px), 경로 강조색.
2. **제목 영역** — StageTitle(결과 변형). 경로별 제목(`--font-size-2xl`).
3. **보조 표시** — Badge `재안내`. **확정 결과 재안내일 때만** 제목 바로 아래에 놓는다(§확정 결과 재안내).
4. **설명 문단** — 경로별 설명 1~2문장.
5. **다음 안내** — 사용자가 다음에 할 일 한 줄(`--color-text-muted`).
6. **복귀 안내 영역** — 다음 안내 아래(패널 맨 끝). 고지 문구 한 줄 + 카운트다운 한 줄 + 수동 이동 링크. **`returnUrl` 이 있고 절대 URL 확인을 통과할 때만** 나타난다(§복귀 이동).

- **버튼을 두지 않는다.** 재시도·문의·복사·공유 요소를 두지 않는다(§조건부 표시). 조작 요소는 복귀 안내 영역의 **수동 이동 링크 하나뿐**이며, 그것은 서버를 부르지 않는 이동 수단이다.
- 복귀 안내 영역이 없을 때 그 자리를 빈 칸·대체 문구로 채우지 않는다 — 영역째 사라진다.

### 결과 3경로

경로 번호는 서버가 정해 준 값이며 화면이 결과 구분에서 다시 계산하지 않는다([`MDL-009`](../datas/model_MDL-007-010.md) 구현 가이드). 색·아이콘 토큰은 [`design-system.md`](design-system.md) §결과 3경로의 시각 구분이 정본이다.

| 경로 | 결과 구분 | 제목 | 설명 | 다음 안내 |
|---|---|---|---|---|
| ① | `SUCCESS` | 연동이 완료되었습니다 | 요청하신 연동이 정상적으로 처리되었습니다. | 이 화면에서 더 하실 일은 없습니다. |
| ② | `DECRYPT_FAILED` 및 추적 레코드가 없는 진입 단계 실패 | 연동을 진행할 수 없습니다 | 사유 코드별 기본 문구를 그대로 쓴다(아래) | 연동을 요청한 서비스에서 새 링크를 받아 다시 진행해 주세요. |
| ③ | `DELIVERY_FAILED` | 연동을 마치지 못했습니다 | 연동 대상 서비스에 전달하지 못했습니다. | 다시 연동하려면 연동을 요청한 서비스에서 새로 요청해 주세요. |

- **제목·설명·다음 안내·아이콘·색은 경로 번호가 바뀌기 전 것을 그대로 승계한다** — 사용자 거부 경로가 폐지되면서(`BIZ-003-03`) 번호만 ③→② · ④→③ 으로 당겨졌고, 문구를 새로 짓지 않았다.
- **경로 ② 의 설명**은 사유 코드가 고른다 — `EX-SEC-001` "연동 링크가 올바르지 않습니다." / `EX-SEC-004` "전달 정보가 허용 크기를 넘었습니다." / `EX-SEC-002` "연동 요청 정보가 규약과 맞지 않습니다." / `EX-OPS-002` "처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요."([`function_FN-014-015.md`](../functions/function_FN-014-015.md) §오류 메시지 기본값). **제목·아이콘·색은 넷 다 같다** — 사유가 달라도 같은 경로이며 경로가 늘어나지 않는다.
- **`EX-OPS-002`(분류되지 않는 내부 처리 실패)도 경로 ② 다** — 진입 접점이 200 화면 + 결과 경로 ② 로 보낸다([`spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §연동 요청 진입 — 에러 처리 · `OPS-003-05`). **그 밖의 사유 코드**가 들어와도 화면이 새 문구를 만들지 않고 위 §오류 메시지 기본값의 문구를 그대로 쓰며, 그 표에도 없는 코드는 `EX-OPS-002` 문구로 안내한다(`FN-014` 가 미상 코드를 `EX-OPS-002` 로 수렴시킨다). **사유 코드가 아예 없는 경우도 같다** — `EX-OPS-002` 문구로 안내한다. 화면은 사유를 추측해 만들어 내지 않으며(`BIZ-001-02`), 미상 코드 수렴 · 미매핑 catch-all([`SVC-005`](../services/service_SVC-005.md) F-003)이라는 선 규칙의 **같은 적용**이지 새 규칙이 아니다. 이 자리에 오는 것은 진입 초기 상태가 부재 판정에 걸린 경우다(PROC-101 `F1` — 그 폴백은 `reasonCode` 를 만들지 않는다).
- **③ 의 다음 안내는 재연동 주체가 발송처라는 규칙에서 나온다**(`BIZ-004-04` — 결과가 확정된 뒤의 재연동은 허브가 하지 않고 발송처가 새 추적 키로 새 요청을 발행한다). 연락처·상담 채널을 적지 않는다 — 상수에 그런 값이 없다.
- 매핑되지 않는 상태는 경로 ② 로 안내한다(**미매핑 catch-all** — [`SVC-005`](../services/service_SVC-005.md) F-003).
- **경로 ① 의 다음 안내는 "창을 닫으라"고 말하지 않는다.** 이 경로는 복귀 주소가 실려 오면 곧 이동하므로 창을 닫으라는 안내와 나란히 설 수 없고, 값이 형식 미달이라 이동하지 않는 경우(§복귀 이동)에도 같은 문장이 그대로 참이어야 한다. "이 화면에서 더 하실 일은 없습니다."는 **이동하든 잔류하든 참**이라 조건 분기 없이 한 문장으로 선다.
- **복귀 안내 영역은 경로가 아니라 `returnUrl` 이 부른다** — 실제로 값이 실리는 경로는 **① 하나**뿐이지만(`BIZ-001-06`) 화면은 그 사실을 조건으로 쓰지 않는다(§복귀 이동).

### 확정 결과 재안내 (보조 표시)

같은 링크로 다시 들어와 이미 확정된 결과를 보는 경우다(`BIZ-002-04` ③). **새 경로를 만들지 않고** 앞의 패널을 그대로 다시 보여 준다.

| 항목 | 확정 내용 |
|---|---|
| 대상 경로 | **①·③ 뿐이다** — 경로 ② 는 재안내 대상이 아니다(아래 근거) |
| 형태 | Badge `재안내`(중립색 바탕 + 되돌림 아이콘 + 글자) |
| 문구 | **"이미 처리된 요청입니다"** |
| 위치 | **결과 제목 바로 아래·설명 문단 위**. 제목보다 앞세우지 않는다 — 사용자가 먼저 알아야 할 것은 결과이고 재안내라는 사실은 보조다 |
| 덧붙이는 문장 | 설명 문단 끝에 한 문장 — "이 연동은 앞서 처리가 끝났고, 지금 보시는 결과가 그때 확정된 결과입니다." |
| 그 밖의 차이 | **없다.** 색·아이콘·제목·다음 안내는 최초 안내와 같다 |

- **경로 ② 는 확정 결과 재안내 대상이 아니다.** 재안내는 추적 레코드에 확정된 결과를 다시 보여 주는 것인데(`BIZ-002-04` ③), ⑴ 레코드의 결과 구분에 `DECRYPT_FAILED` 가 기록되는 경로가 없고(EXC-BIZ-14 — 추적 키는 그 복호화를 통과해야만 얻어진다) ⑵ 진입 단계 실패는 레코드 자체가 없어 재진입해도 매번 새 판정으로 다시 경로 ② 가 된다(`BIZ-002-02` · §이동 경로 마지막 항과 같은 사실). 따라서 배지 `재안내` 가 붙는 경로는 **①·③** 이다.
- 재안내에서도 화면은 아무것도 다시 제출하지 않는다. 서버 역시 레코드를 갱신하지 않고 지표를 계수하지 않는다(`BIZ-002-04`·`BIZ-005-03`).
- **재안내는 복귀 이동을 바꾸지 않는다** — 재안내라도 `returnUrl` 이 실려 오면 그대로 이동한다(§복귀 이동 · `BIZ-002-04` ③).

### 복귀 이동 (연동 완료 결과)

결과를 잠시 보여 준 뒤 사용자를 출발지로 돌려보내는 **후처리**다. **이동 여부를 화면이 판정하지 않는다** — 서버가 실어 준 [`MDL-009`](../datas/model_MDL-007-010.md) `returnUrl` 속성이 **있으면 이동, 없으면 잔류**이며 그것이 유일한 신호다(`BIZ-001-06` · [`SVC-005`](../services/service_SVC-005.md) F-007·F-008). 값이 실리는 경로는 **연동 완료(①) 하나**이므로 실제로 이동하는 결과도 ① 뿐이지만, 그 사실은 **서버가 아는 것**이고 화면은 필드만 본다.

| 항목 | 확정 내용 |
|---|---|
| 이동 신호 | `returnUrl` **속성의 존재 여부**. 경로 번호(`resultPath`)로 다시 판정하지 않는다 |
| **복귀 이동 대기 시간** | **3초** — 결과를 표시한 시점부터 이동까지. **이 문서가 이 값의 정본**이며 다른 절·다른 도메인은 값이 아니라 이 이름으로 참조한다. **예외로 검증 TC 는 기대값 판정을 위해 값을 인용할 수 있다**(기대값을 적지 않으면 검증이 성립하지 않는다 — 인용일 뿐 정본이 되지 않는다) |
| 이동 방식 | **브라우저 이력 치환** — 현재 이력 항목을 복귀 주소로 대체하고 새 항목을 쌓지 않는다 |
| 이동 대상 확인 | 받은 값이 `https://`·`http://` 로 시작하는 **절대 URL** 인지 화면이 **다시 확인**한다. 미달이면 이동하지 않고 복귀 안내 영역도 그리지 않는다(= 잔류) |
| 이동 실패 | **결과가 바뀌지 않는다.** 화면은 그대로 남고 수동 이동 링크가 남는다 — 새 경로·새 예외 코드를 만들지 않는다 |
| 고지 문구 | **"잠시 후 원래 화면으로 자동으로 돌아갑니다."** (`--color-text-muted`) |
| 카운트다운 문구 | **"3초 후 이동합니다"** — 3 → 2 → 1 로 갱신. **시각 표시 전용** |
| 수동 이동 링크 | 라벨 **"지금 돌아가기"**. 주소 문자열을 라벨로 쓰지 않는다(§데이터 표시). 누르면 대기를 취소하고 **자동 이동과 같은 방식(이력 치환)으로 같은 창에서** 즉시 이동한다 — 새 창·새 탭으로 열지 않는다 |

- **대기 시간을 연동 구성 상수표에 두지 않는다** — [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) 의 표는 **배포 시 주입되는 연동 구성**이고(`OPS-001-01`), 3초는 연동 구성이 아니라 PRD 가 직접 정한 **화면 표시 규칙**이다. 주입 상수를 늘리면 기동 검증 대상(`OPS-001-02`)과 확정 관리 대상이 함께 늘어난다.
- **모션 토큰에도 두지 않는다** — `--motion-duration-*` 은 상태 변화·단계 전환의 **지속시간**이며([`design-system.md`](design-system.md) §간격·크기·모양), 3초는 지속시간이 아니라 화면 하나의 흐름 규칙이다. 전역 토큰에 화면 규칙을 얹지 않는다.
- **이력을 치환하는 이유** — ① 뒤로 가기로 결과 화면에 돌아오면 화면은 상태를 잃어 진입부터 다시 시작하고([`spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §프로토콜 확정 3) 암호값이 담긴 URL 이 다시 판정을 탄다. 치환하면 뒤로 가기가 **출발지로** 간다 ② 암호값을 담은 URL 을 브라우저 이력에 덜 남긴다(`DATA-001-04`).
- **화면이 형식을 다시 확인하는 이유** — 값이 지금은 허브 상수에서 오지만 출처가 확정되면 **외부 입력**이 될 수 있다([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑦). `javascript:`·`data:` 등 다른 스킴은 이동 대상이 아니며, 미달이면 카운트다운도 수동 링크도 그리지 않는다.
- **이동 실패를 오류 경로로 올리지 않는 이유** — 결과는 이미 확정됐고 이동은 결과 안내 뒤의 후처리다. 실패해도 사용자가 보는 결과가 바뀌지 않으므로 네 번째 경로도 새 EX 코드도 만들지 않는다([`SVC-005`](../services/service_SVC-005.md) §예외 사항).
- **적용 경로가 확정된 뒤에도 이 절은 바뀌지 않았다** — 적용 경로는 **연동 완료(①) 하나로 확정**됐고([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑩ **확정 종결** · `EXC-BIZ-15`), 그 확정으로 달라진 것은 서버의 동봉 조건 한 곳이다. 화면이 필드 존재 여부만 보는 규칙은 확정 전과 같다 — **판정 지점을 한 곳에 둔다**는 `BIZ-001-06` 이 확정 뒤에도 그대로이기 때문이다.

#### 접근성 (복귀 이동)

1. **자동 이동을 미리 알린다** — 고지 문구는 결과가 도착한 **첫 그림부터** 결과 문구와 **같은 `role="status"` 영역 안**에 있다. 결과와 함께 **한 번만** 읽히며, 예고 없이 화면이 바뀌는 일이 없다.
2. **카운트다운 숫자 영역은 `aria-hidden="true"`** — 남은 초는 시각 표시 전용이다. 라이브 리전(`role="status"`) 안에 있어도 `aria-hidden` 인 요소는 읽히지 않으므로, 1초마다 갱신되는 숫자가 스크린리더를 가로채지 않는다.
3. **`prefers-reduced-motion: reduce` 에서 달라질 것이 없다** — 진행 링·진행 막대 같은 애니메이션을 **애초에 쓰지 않고** 텍스트만 갱신하기 때문이다. **대기 시간은 줄이지 않는다** — 3초는 PRD 가 정한 값이다.
4. **수동 이동 링크는 항상 함께 있다** — 카운트다운 중에도 보이고, 키보드로 이동·실행할 수 있으며, 히트 영역은 `--size-hit-min`(44x44)을 지킨다. 누르면 대기를 취소하고 즉시 이동한다.
5. **링크로 포커스를 옮기지 않는다** — 결과 도착 시 포커스는 제목으로 간다(§구현 가이드). 링크로 옮기면 사용자가 결과 문구를 건너뛴다.
6. **시간 제한에 대한 판단** — 자동 이동은 콘텐츠가 정한 시간 제한이라 WCAG 2.1 **2.2.1(타이밍 조절 가능)** 의 대상이다. 이 화면은 **끄기·연장 수단을 두지 않고** 사전 고지·수동 링크·이동 실패 시 잔류로 완화한다 — 3초 표시와 이동 자체가 PRD 요구사항이기 때문이다(§수행 범위 6). **자동 이동 중지 수단을 둘지는 담당자 확인 사항**으로 남긴다.

### 화면 상태 전이

| 상태 | 진입 조건 | PROC 단계 매핑 | 표시 내용 |
|------|----------|---------------|-----------|
| Result-① | `resultPath = 1` | PROC-105 결과 경로 선택 · 결과 안내 구성 | 완료 패널 |
| Result-② | `resultPath = 2`(진입 초기 상태 포함) | 위와 같다 | 오류 패널 + 사유별 설명 |
| Result-③ | `resultPath = 3`(502 `EX-BIZ-002` 포함) | 위와 같다 | 전달 실패 패널 |
| ReAnnounced | Result-① 또는 Result-③ + `isReAnnouncement = true`(경로 ② 는 대상이 아니다 — §확정 결과 재안내) | PROC-105 결과 안내 구성(BR-009) | 같은 패널 + 배지 + 덧붙이는 문장 |
| Returning | 결과를 표시한 뒤 + `returnUrl` 속성 존재 + 절대 URL 확인 통과(`F1` 에서 판정) | PROC-105 `F2` 렌더 · `F3` 폐기·복귀 이동 | 같은 패널 + 복귀 안내 영역. 대기 시간이 지나면 이력 치환으로 이동한다 |
| Terminal | 결과를 표시한 뒤 위에 해당하지 않는 경우, 또는 `Returning` 에서 이동이 수행되지 않은 경우 | PROC-105 `F3`(잔류) | 상태가 더 바뀌지 않는다. `Returning` 을 거쳤다면 **수동 이동 링크는 남는다**. 새로고침하면 진입부터 다시 시작한다 |

- **502 `EX-BIZ-002` 도 정상 종료다.** 오류 응답 엔벨로프의 `code` 로 경로 ③ 을 고른다 — 처리 실패 화면이 아니라 결과 안내다([`spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §동의·승인 제출 에러 처리).
- **`Returning` 은 복귀 이동 요구로 늘린 유일한 상태다.** 대기 중에는 남은 초가 갱신되고 끝에 이동이 일어나므로 "상태가 더 바뀌지 않는다"는 `Terminal` 의 정의에 조건으로 얹을 수 없었다. 대신 **경로마다 대기 상태를 만들지 않고** 한 상태로 두었다 — 진입 조건이 경로 번호가 아니라 `returnUrl` 존재 여부이기 때문이다(실제로 성립하는 것은 `Result-①` 위에서다).
- **`Returning` 은 `Result-①` 과 그 `ReAnnounced` 어느 쪽에도 얹힌다** — 재안내 여부는 이동을 바꾸지 않는다(§복귀 이동).
- **이동이 막혔는지를 화면이 판정하지 않는다.** 이동이 일어나면 화면 자체가 사라지므로, **화면이 남아 있다는 사실이 곧 `Terminal`** 이다. 막힘을 감지해 알림을 띄우거나 상태를 바꾸는 처리를 두지 않는다.

### 구현 가이드

- **결과 구분 → 경로 번호 대응을 화면이 다시 구현하지 않는다.** 서버가 `resultPath` 로 준 값을 그대로 쓴다 — 대응을 두 곳에 두면 화면과 발송처 조회 결과가 갈린다([`MDL-009`](../datas/model_MDL-007-010.md) 구현 가이드).
- **이동 여부도 화면이 다시 판정하지 않는다** — 같은 정신이다. 화면이 보는 것은 `returnUrl` 속성의 **존재 여부** 하나뿐이며 `resultPath` 를 이동 조건으로 읽지 않는다(`BIZ-001-06`). 실제로 적용 경로가 "완료만 이동"으로 확정됐을 때([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑩ · `EXC-BIZ-15`) **이 판정 규칙은 그대로였고** 서버의 동봉 조건 한 곳만 바뀌었다.
- **이동은 이력 치환으로 수행한다**(§복귀 이동). 특정 API·라이브러리를 강제하지 않으며, 새 이력 항목을 쌓지 않는 이동이면 된다. **수동 링크도 같다** — 링크 요소를 쓰되 눌렸을 때 치환 이동으로 처리한다. 그 처리가 동작하지 않는 환경에서는 링크의 기본 동작이 그대로 이동을 수행한다(이력 항목이 하나 쌓이는 것은 감수한다 — 그 환경에서는 자동 이동도 일어나지 않는다).
- **대기 타이머는 하나만 둔다.** 수동 링크를 누르면 타이머를 취소하고, 이미 이동을 시작했으면 다시 이동하지 않는다. 화면이 사라진 뒤 타이머가 남지 않게 정리한다.
- **이동이 수행되지 않아도 아무것도 되돌리지 않는다** — 결과 표시와 수동 링크를 그대로 유지할 뿐, 알림을 띄우거나 경로를 바꾸지 않는다(§복귀 이동).
- 경로 값이 1~3 밖이거나 없으면 **경로 ②** 로 그린다([`SVC-005`](../services/service_SVC-005.md) F-003 — 미매핑 catch-all). 빈 화면·예외 화면을 만들지 않는다.
- 결과 도착 시 제목으로 포커스를 옮기고 문서 제목을 결과 제목으로 맞춘다. 영역은 `role="status"` 로 둔다 — 경고음처럼 끼어드는 알림(`role="alert"`)을 쓰지 않는다.
- 아이콘은 인라인 SVG 로 넣고 `aria-hidden="true"` 를 준다. 뜻은 제목 문구가 전달한다.
- 결과를 표시한 뒤에도 페이지 메모리의 암호값·생년월일을 계속 들고 있을 이유가 없다 — 폐기한다(`DATA-001-03`). **복귀 이동을 기다리는 동안도 마찬가지다** — 대기는 값을 붙들 이유가 되지 않는다.
