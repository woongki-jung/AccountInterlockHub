# 연동 결과 안내 화면 정의

정본 목록은 [`spec-screens.md`](spec-screens.md). 디자인 토큰·컴포넌트는 [`design-system.md`](design-system.md) · [`design-system-components.md`](design-system-components.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **화면 목적**: 연동이 어떻게 끝났는지를 **네 경로 중 하나로** 알린다. 사용자가 다음에 무엇을 하면 되는지까지 한 문장으로 덧붙이고 여정을 끝낸다. 결과가 이미 확정된 링크로 다시 들어와도 **같은 경로를 다시 표시**하고 이미 처리된 요청임을 보조 표시로 알린다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 6 — "결과를 네 경로로 구분해 사용자에게 표시한다 — 연동 완료 · 사용자 거부 · 링크·복호화 오류 · 수신처 전달 실패. 결과가 이미 확정된 링크로 다시 진입하면 **그 결과 경로를 그대로 다시 안내**한다(경로를 추가하지 않는다)."

## SCR-004 연동 결과 안내

### 기본 정보

| 항목 | 내용 |
|------|------|
| 화면명 | 연동 결과 안내 |
| 화면 경로 | `<INTERLOCK_ENTRY_PATH>` (쿼리 `encX`·`encY`) — 단계 `RESULT`. 결과 경로마다 URL 을 나누지 않는다 |
| 접근 권한 | `Public` — 결과가 확정된 진행 상태에서 열린다. 링크 형식이 깨진 진입은 이 화면이 **첫 화면**이 된다 |
| 관련 서비스 | [`SVC-005`](../services/service_SVC-005.md) 연동 결과 안내 |
| 트리거 PROC | 없음 — 이 화면에는 액션이 없다. 표시 내용을 정한 것은 PROC-105 다 |
| 선행 화면 | SCR-001 · SCR-002 · SCR-003, 또는 **없음**(진입 판정 실패 시 최초 화면) |
| 관련 IA 항목 | `USR-05`(결과 안내) — 결과는 `USR-01`·`USR-02`·`USR-03`·`USR-04` 어디에서든 흘러든다 |

### 레이아웃 구성

카드 안을 ResultPanel 하나로 채운다. 앞 단계의 폼·목록·안내는 남기지 않는다.

1. **결과 아이콘** — 경로별 아이콘(40px), 경로 강조색.
2. **제목 영역** — StageTitle. 경로별 제목(`--font-size-2xl`).
3. **보조 표시** — Badge `재안내`. **확정 결과 재안내일 때만** 제목 바로 아래에 놓는다(§확정 결과 재안내).
4. **설명 문단** — 경로별 설명 1~2문장.
5. **다음 안내** — 사용자가 다음에 할 일 한 줄(`--color-text-muted`).

- 이 화면에는 **버튼이 없다.** 재시도·문의·복사·공유 요소를 두지 않는다(§조건부 표시).

### 결과 4경로

경로 번호는 서버가 정해 준 값이며 화면이 결과 구분에서 다시 계산하지 않는다([`MDL-009`](../datas/model_MDL-007-010.md) 구현 가이드). 색·아이콘 토큰은 [`design-system.md`](design-system.md) §결과 4경로의 시각 구분이 정본이다.

| 경로 | 결과 구분 | 제목 | 설명 | 다음 안내 |
|---|---|---|---|---|
| ① | `SUCCESS` | 연동이 완료되었습니다 | 요청하신 연동이 정상적으로 처리되었습니다. | 이 창은 닫으셔도 됩니다. |
| ② | `USER_DENIED` | 연동을 진행하지 않았습니다 | 동의하지 않으셔서 연동이 취소되었습니다. | 다시 연동하려면 연동을 요청한 서비스에서 새로 요청해 주세요. |
| ③ | `DECRYPT_FAILED` 및 추적 레코드가 없는 진입 단계 실패 | 연동을 진행할 수 없습니다 | 사유 코드별 기본 문구를 그대로 쓴다(아래) | 연동을 요청한 서비스에서 새 링크를 받아 다시 진행해 주세요. |
| ④ | `DELIVERY_FAILED` | 연동을 마치지 못했습니다 | 연동 대상 서비스에 전달하지 못했습니다. | 다시 연동하려면 연동을 요청한 서비스에서 새로 요청해 주세요. |

- **경로 ③ 의 설명**은 사유 코드가 고른다 — `EX-SEC-001` "연동 링크가 올바르지 않습니다." / `EX-SEC-004` "전달 정보가 허용 크기를 넘었습니다." / `EX-SEC-002` "연동 요청 정보가 규약과 맞지 않습니다." / `EX-OPS-002` "처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요."([`function_FN-014-015.md`](../functions/function_FN-014-015.md) §오류 메시지 기본값). **제목·아이콘·색은 넷 다 같다** — 사유가 달라도 같은 경로이며 경로가 늘어나지 않는다.
- **`EX-OPS-002`(분류되지 않는 내부 처리 실패)도 경로 ③ 이다** — 진입 접점이 200 화면 + 결과 경로 ③ 으로 보낸다([`spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §연동 요청 진입 — 에러 처리 · `OPS-003-05`). **그 밖의 사유 코드**가 들어와도 화면이 새 문구를 만들지 않고 위 §오류 메시지 기본값의 문구를 그대로 쓰며, 그 표에도 없는 코드는 `EX-OPS-002` 문구로 안내한다(`FN-014` 가 미상 코드를 `EX-OPS-002` 로 수렴시킨다).
- **②·④ 의 다음 안내는 재연동 주체가 발송처라는 규칙에서 나온다**(`BIZ-004-04` — 결과가 확정된 뒤의 재연동은 허브가 하지 않고 발송처가 새 추적 키로 새 요청을 발행한다). 연락처·상담 채널을 적지 않는다 — 상수에 그런 값이 없다.
- **거부(②)를 오류처럼 보이게 하지 않는다.** 사용자가 의도한 선택이므로 중립 색과 중립 아이콘을 쓴다.
- 매핑되지 않는 상태는 경로 ③ 으로 안내한다([`SVC-005`](../services/service_SVC-005.md) F-003).

### 확정 결과 재안내 (보조 표시)

같은 링크로 다시 들어와 이미 확정된 결과를 보는 경우다(`BIZ-002-04` ③). **새 경로를 만들지 않고** 앞의 패널을 그대로 다시 보여 준다.

| 항목 | 확정 내용 |
|---|---|
| 대상 경로 | **①·②·④ 뿐이다** — 경로 ③ 은 재안내 대상이 아니다(아래 근거) |
| 형태 | Badge `재안내`(중립색 바탕 + 되돌림 아이콘 + 글자) |
| 문구 | **"이미 처리된 요청입니다"** |
| 위치 | **결과 제목 바로 아래·설명 문단 위**. 제목보다 앞세우지 않는다 — 사용자가 먼저 알아야 할 것은 결과이고 재안내라는 사실은 보조다 |
| 덧붙이는 문장 | 설명 문단 끝에 한 문장 — "이 연동은 앞서 처리가 끝났고, 지금 보시는 결과가 그때 확정된 결과입니다." |
| 그 밖의 차이 | **없다.** 색·아이콘·제목·다음 안내는 최초 안내와 같다 |

- **경로 ③ 은 확정 결과 재안내 대상이 아니다.** 재안내는 추적 레코드에 확정된 결과를 다시 보여 주는 것인데(`BIZ-002-04`), ① 레코드의 결과 구분에 `DECRYPT_FAILED` 가 기록되는 경로가 없고(EXC-BIZ-14 — 추적 키는 그 복호화를 통과해야만 얻어진다) ② 진입 단계 실패는 레코드 자체가 없어 재진입해도 매번 새 판정으로 다시 경로 ③ 이 된다(`BIZ-002-02` · §이동 경로 마지막 항과 같은 사실). 따라서 배지 `재안내` 가 붙는 경로는 **①·②·④** 다.
- 재안내에서도 화면은 아무것도 다시 제출하지 않는다. 서버 역시 레코드를 갱신하지 않고 지표를 계수하지 않는다(`BIZ-002-04`·`BIZ-005-03`).

### 이동 경로 (Navigation)

| 이동 대상 | 트리거 | 조건 | 트리거 PROC |
|-----------|--------|------|-------------|
| (없음) | — | 이 화면은 여정의 끝이다. 화면이 제공하는 이동 수단이 없다 | — |
| SCR-001 본인확인 | 새로고침·같은 링크 재진입 | 진입 판정을 통과하면 본인확인부터 다시 시작한다 | (PROC-101 서버 수행) |
| SCR-004(자기 자신) | 같은 링크 재진입 후 본인확인 통과 | 결과가 확정된 추적 키이면 확정 결과 재안내 | PROC-102 → PROC-105 |

- 결과가 확정된 링크라도 **재진입은 본인확인을 다시 거친다** — 확정 여부는 추적 키로만 판정할 수 있고, 추적 키는 복호화해야 얻어지기 때문이다(`BIZ-002-01`·`BIZ-002-03`).
- 진입 단계 실패(경로 ③)는 추적 레코드가 없어 재진입해도 같은 판정으로 다시 경로 ③ 이 된다(`BIZ-002-02`).

### 구현 가이드

- **결과 구분 → 경로 번호 대응을 화면이 다시 구현하지 않는다.** 서버가 `resultPath` 로 준 값을 그대로 쓴다 — 대응을 두 곳에 두면 화면과 발송처 조회 결과가 갈린다([`MDL-009`](../datas/model_MDL-007-010.md) 구현 가이드).
- 경로 값이 1~4 밖이거나 없으면 **경로 ③** 으로 그린다([`SVC-005`](../services/service_SVC-005.md) F-003). 빈 화면·예외 화면을 만들지 않는다.
- 결과 도착 시 제목으로 포커스를 옮기고 문서 제목을 결과 제목으로 맞춘다. 영역은 `role="status"` 로 둔다 — 경고음처럼 끼어드는 알림(`role="alert"`)을 쓰지 않는다.
- 아이콘은 인라인 SVG 로 넣고 `aria-hidden="true"` 를 준다. 뜻은 제목 문구가 전달한다.
- 결과를 표시한 뒤에도 페이지 메모리의 암호값·생년월일을 계속 들고 있을 이유가 없다 — 폐기한다(`DATA-001-03`).
