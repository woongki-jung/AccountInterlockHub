# 화면 정의서 (목록)

AccountInterlockHub 사용자 표면의 단일 출처다. 방향 근거는 [`../../prd/PRD.md`](../../prd/PRD.md), 정보 구조는 [`../../prd/ia/IA.md`](../../prd/ia/IA.md), 준수 규칙은 [`../policies/spec-policies.md`](../policies/spec-policies.md), 서비스 시나리오는 [`../services/spec-services.md`](../services/spec-services.md), 데이터는 [`../datas/spec-models.md`](../datas/spec-models.md), 접점 계약은 [`../functions/spec-functions.md`](../functions/spec-functions.md), 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md) 를 따른다.

본 문서는 **화면 코드 체계·목록·이동 경로·접근 매트릭스·화면을 갖지 않는 IA 노드**를 담는다. 화면 상세는 `screen_<SCR 코드>.md` 가, 디자인 시스템은 아래 두 문서가 갖는다.

- [`design-system.md`](design-system.md) — 디자인 토큰·색 대비 실측·레이아웃·상태 표현·접근성 기준
- [`design-system-components.md`](design-system-components.md) — 공통 컴포넌트 11종

## 이 표면의 형태 (모든 화면의 전제)

1. **표면은 하나다** — 사용자 웹뿐이다. 관리자 화면·구성 화면·로그인 화면이 존재하지 않는다(`AUTH-001-01`·`AUTH-001-02`). 따라서 **디자인 시스템도 하나**이고 표면별 토큰 분기를 두지 않는다.
2. **경로도 하나다** — 진입부터 결과까지 URL 이 바뀌지 않는다([`../functions/spec-functions-api-user.md`](../functions/spec-functions-api-user.md) §프로토콜 확정). 화면 넷은 **같은 경로 위의 네 단계**이며 각자의 URL 을 갖지 않는다. 결과 뒤의 **복귀 이동만 이 경로 밖으로 나가며**, 그것은 단계 전이가 아니라 여정의 종료다([`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동).
3. **단계는 서버 응답이 정한다** — 진입 응답이 실어 주는 초기 상태와 이후 두 접점의 응답이 다음 단계를 지정한다. 화면이 스스로 단계를 건너뛰지 않는다.
4. **새로고침은 처음부터다** — 허브에 세션이 없어(`AUTH-001-02`) 화면 상태가 복원되지 않는다. 사용자는 생년월일을 다시 넣는다.
5. **표시할 개인정보가 없다** — 허브는 사용자 정보를 보관하지 않으므로 되돌려 표시할 값이 없다(§표시 데이터·마스킹 총괄).

## 디자인 시스템 요약

정본은 [`design-system.md`](design-system.md). 핵심 결정만 옮긴다.

- **모바일 우선 반응형** — 단일 컬럼 카드 하나. 브레이크포인트는 `480px`·`768px` 둘뿐이며 구조는 어느 폭에서도 같고 여백·최대 폭만 바뀐다. 본문 최대 폭 480px.
- **접근성 목표는 WCAG 2.1 AA** — 본문 대비 4.5:1, 큰 텍스트·비텍스트 3:1, 히트 영역 최소 44x44 CSS px, 키보드 전 기능 조작, 폼 레이블·오류 연결. **정의한 색 토큰의 실측 대비비를 표로 남겨** 값 변경 시 재측정하게 했다.
- **색만으로 의미를 전달하지 않는다** — 상태·결과는 색 + 아이콘 + 문구 셋으로 구분한다.
- **결과 3경로의 시각 구분** — ① 완료(초록·원 안 체크) ② 링크·복호화 오류(빨강·원 안 느낌표) ③ 전달 실패(황갈색·삼각형 안 느낌표). 사용자 거부 경로가 폐지돼(`BIZ-003-03`) **번호만 당겨졌고 색·아이콘·문구는 승계**했다.
- **전역 네비게이션·브랜드 영역이 없다** — 로그인·메뉴·프로필이 없는 단일 흐름이라 화면에는 지금 단계의 내용과 액션만 둔다.
- **외부 자원을 쓰지 않는다** — 웹 글꼴·아이콘 글꼴·외부 이미지를 두지 않고 시스템 글꼴과 인라인 SVG 로 그린다.

## 화면 코드 체계

- **화면 코드**: `SCR-<순번 3자리>` — 본 문서의 목록이 정본이다.
- **단계 값**: 화면은 접점 응답의 `stage` 값과 1:1 로 대응한다 — `IDENTITY`(SCR-001) · `CONSENT`(SCR-002) · `RESULT`(SCR-004). **`PROCESSING`(SCR-003) 만 화면이 소유한 단계**로, 승인 요청을 보낸 시점에 시작해 응답이 오면 끝난다(서버에 대응 값이 없다).
- **트리거 PROC**: 정책·서비스가 예약한 18종을 그대로 인용한다. **본 도메인의 PROC 추가 채번은 0건**이며 실재 확인은 교차검증 시점이다.
- **인용 코드**: `SVC`·`MDL`·`FN`·`EX`·정책 규칙 ID 를 **인용만** 하고 새로 만들지 않는다. 신설 코드 0건.
- 화면이 부르는 것은 **접점(엔드포인트)** 이며 공통 기능(FN)이 아니다. FN 은 서버 내부에서 공유되는 기능 코드라 화면 인터랙션 표의 호출 대상 칸에는 접점 이름을 적는다.

### 서비스 도메인 예약과의 정합

[`../services/spec-services-codes.md`](../services/spec-services-codes.md) §화면(SCR) 예약 채번의 4종을 **의미 변경 없이 그대로 확정**했다. 통합 0 · 폐기 0 · 추가 0 · 재배치 0.

- 예약이 열어 둔 두 선택지 중 **① `SCR-003` 을 `SCR-002` 의 상태로 통합하는 안을 채택하지 않고 독립 화면으로 유지**했다. 승인 제출 후 대기는 폼·목록이 사라지고 진행 표시만 남는 다른 화면이며, 흐름에 이미 단계 개념이 있어 별도 단계로 두는 편이 정합적이다. **② `SCR-004` 를 경로마다 화면으로 나누지 않고 한 화면의 세 상태로** 두었다 — 경로별로 화면을 나누면 네 번째 경로를 만들기 쉬워진다(`BIZ-001-02`).
- **진입(`USR-01`) 전용 화면을 새로 채번하지 않았다.** 진입 응답은 화면 문서 하나와 초기 상태를 돌려주며, 그 초기 상태가 `IDENTITY` 면 SCR-001 이, `RESULT` 면 SCR-004 가 **첫 화면**이 된다. 진입만을 위한 중간 화면은 사용자가 볼 일이 없다.

## 화면 간 이동 경로 (Navigation Flow)

앞으로 가는 경로와 되돌아오는 경로를 함께 적는다. 모든 전환은 **접점 응답**으로 일어나며 화면이 임의로 단계를 바꾸지 않는다.

1. **발송처 링크 → SCR-001** — 진입 응답의 초기 상태가 `IDENTITY` 일 때(구조 판정 통과).
2. **발송처 링크 → SCR-004(경로 ②)** — 진입 응답의 초기 상태가 `RESULT` 일 때(`EX-SEC-001`·`EX-SEC-004`·`EX-OPS-002`). 추적 레코드가 만들어지지 않은 실패다.
3. **SCR-001 → SCR-002** — 본인확인 제출이 `stage = CONSENT` 를 돌려줄 때(PROC-102).
4. **SCR-001 유지** — `EX-AUTH-001`(형식)·`EX-AUTH-002`(재입력)·`EX-BIZ-003`(재시도 가능). 단계가 바뀌지 않는다.
5. **SCR-001 → SCR-004** — `stage = RESULT`(확정 결과 재안내) 또는 `EX-SEC-001`·`EX-SEC-002`.
6. **SCR-002 → SCR-003** — 승인 제출 요청을 보낸 즉시(PROC-103).
7. **SCR-002 유지** — 화면 게이팅(필수 미동의 상태의 승인 버튼 클릭 — **요청을 보내지 않는다**) · `EX-BIZ-001`(서버 재검증) · `EX-BIZ-003`.
8. **SCR-003 → SCR-004** — 결과 응답(경로 ①·②·③) 또는 `EX-BIZ-002`(경로 ③).
9. **SCR-003 → SCR-002** — `EX-BIZ-001`·`EX-BIZ-003`(되돌아가는 경로).
10. **SCR-003 → SCR-001** — 승인 시점 재복호화의 판정 1·2단계 실패(`EX-AUTH-002`)·형식 위반(`EX-AUTH-001`). **본인확인 재입력으로 되돌아간다**(되돌아가는 경로).
11. **어느 화면에서든 새로고침 → SCR-001** — 진입 응답을 다시 받아 처음부터 시작한다. 결과가 확정된 링크면 본인확인 제출이 다시 SCR-004(재안내)로 데려간다.
12. **SCR-004 → 복귀 주소(허브 밖)** — 응답에 `returnUrl` 이 실려 왔고 절대 URL 확인을 통과할 때, 결과를 보여 준 뒤 **브라우저 이력을 치환하며** 이동한다(실제로 실리는 경로는 **① 하나**). 대기 시간·문구·수동 이동 링크의 정본은 [`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동이다.
13. **SCR-004 → (없음·잔류)** — `returnUrl` 이 없거나 확인 미달일 때(경로 ②·③ 전부 포함). 화면이 제공하는 이동 수단이 없다.

- **미동의로 끝나는 경로가 이 목록에 없다.** 동의하지 않은 사용자는 결과 화면으로 가지 않고(`BIZ-003-03`) **창을 닫아 여정을 떠난다** — 화면 간 이동이 아니므로 이동 경로가 아니다. 그 연동은 결과 미확정으로 남는다.
- **뒤로 가기로 단계를 되돌릴 수 없다** — 리다이렉트를 쓰지 않아 브라우저 이력에 단계가 쌓이지 않는다. 뒤로 가기는 이 여정 밖으로 나간다. 복귀 이동도 **이력을 치환**하므로 뒤로 가기가 결과 화면으로 돌아오지 않는다.
- 되돌아가는 경로(9·10)는 **사용자가 누르는 버튼이 아니라 서버 응답이 만든다.** 화면에 "이전 단계로" 버튼을 두지 않는다.

## 사용자 역할별 화면 접근 권한 매트릭스

역할 정의는 [`../services/spec-services.md`](../services/spec-services.md) §사용자 정의를 따른다.

| 역할 | SCR-001 | SCR-002 | SCR-003 | SCR-004 | 근거 |
|---|---|---|---|---|---|
| **사용자** | ✅ | ✅ | ✅ | ✅ | 발송처가 만든 링크로 진입하는 유일한 화면 이용자 |
| **발송처** | ❌ | ❌ | ❌ | ❌ | 접근 표면이 라이브러리(파일)와 서버 대면 API 다. 결과는 조회 API 로 확인한다([`SVC-005`](../services/service_SVC-005.md) 사용자 정의) |
| **수신처** | ❌ | ❌ | ❌ | ❌ | 접근 표면이 허브의 전달 호출 수신과 완료 콜백 API 다 |
| **허브 운영자** | ❌ | ❌ | ❌ | ❌ | 배포 주체이며 **화면 조작 수단이 없다.** 구성 변경은 상수 갱신·재배포로만 이뤄진다(`AUTH-001-01`) |

- **화면에 인증이 없다.** 링크를 가진 누구나 열 수 있으며 역할을 식별·검증하지 않는다(`AUTH-001-02`·`AUTH-001-03`). 그로 인한 위험은 수용 리스크다(`OPS-002-01`·`OPS-002-02`).
- **역할별 메뉴·버튼 노출 제어가 없다** — 역할 개념이 런타임에 존재하지 않으므로 조건부 노출 규칙도 없다. 화면의 조건부 표시는 전부 **진행 상태와 상수 값**으로만 결정된다.

## 화면을 갖지 않는 IA 노드

IA leaf 17 노드 중 **화면 표면을 갖는 것은 `USR` 영역의 5 노드뿐**이고, 나머지 12 노드는 사용자 화면이 없다. 커버리지 판정에서 누락으로 읽히지 않도록 근거를 남긴다.

| IA 노드 | 화면 | 근거 |
|---|---|---|
| `USR-01` 연동 링크 진입 | SCR-001(판정 통과 시 첫 화면) · SCR-004(판정 실패 시 첫 화면) | 진입 응답이 곧 첫 화면 문서다 |
| `USR-03` 본인확인 | SCR-001 | — |
| `USR-04` 동의·승인 | SCR-002 | — |
| `USR-02` 연동 실행 | SCR-003(대기·진행 표시) | **자체 화면이 아니다.** 승인 제출 이후의 서버 처리이며 사용자에게는 기다림으로만 나타난다 |
| `USR-05` 연동 결과 안내 | SCR-004 | — |
| `LIB-01` 데이터 암호화 · `LIB-02` 요청 URL 생성 | **화면 없음** | 발송처 프로세스 안에서 실행되는 **함수 호출**이다. 허브가 그리는 화면이 아니다 |
| `LIB-03` 배포 패키지 · `LIB-04` 규약 테스트 벡터 | **화면 없음** | 발송처에 파일로 전달하는 **산출물**이다. 내려받기 화면·포털을 두지 않는다(전달 경로는 build 단계 확정 — [`../../prd/devspec/infra.md`](../../prd/devspec/infra.md) §연동 라이브러리 배포) |
| `API-01`~`API-04` | **화면 없음** | 발송처·수신처가 **서버에서 직접 호출**하는 접점이다. 사람이 조작하는 표면이 아니며 관리자 조회 화면을 두지 않는다(`AUTH-001-01`) |
| `BAT-02` 보관정책 배치 | **화면 없음** | 스케줄 실행과 **명령 진입점**으로만 실행한다. 관측은 표준 출력과 종료 코드다(`OPS-003-04`) |
| `BAT-04`·`BAT-05`·`BAT-06` 기록 3종 | **화면 없음** | 내부 기록 기능이다. 조회는 서버 대면 API 가 담당하고 화면·명령 표면이 없다([`../../prd/ia/IA.md`](../../prd/ia/IA.md) `BAT` 영역 주석) |
| `공통`(횡단) | 디자인 시스템 | 화면이 아니라 **모든 화면이 공유하는 규칙**이다([`design-system.md`](design-system.md)) |

## 표시 데이터·마스킹 총괄

- **표시 대상 개인정보가 없다.** 허브는 사용자 정보와 복호화 원문을 보관하지 않으므로(`DATA-001-01`·`DATA-001-02`) 화면에 되돌려 그릴 개인정보가 존재하지 않는다. 개별 화면의 마스킹 규칙 칸은 이 사실과 근거 정책을 적는다.
- 화면이 다루는 값은 넷뿐이다 — ① 사용자가 방금 넣은 **생년월일**(입력 필드 안에서만 보인다) ② URL 쿼리에서 읽어 메모리로만 보유하는 **암호값 쌍**(어디에도 그리지 않는다) ③ 배포 상수에서 온 **동의 항목·안내 문구**(개인정보가 아니다) ④ 결과 응답이 실어 준 **복귀 주소**(개인정보가 아니며 마스킹 대상도 아니지만 **화면에 그리지 않고** 이동 목적지로만 쓴다 — [`screen_SCR-004.md`](screen_SCR-004.md) §데이터 표시).
- **연동 추적 키를 화면에 표시하지 않는다.** 사용자에게 필요 없는 값이라 사용자 표면 응답에 담기지도 않는다([`../functions/function_FN-014-015.md`](../functions/function_FN-014-015.md) §금지 항목).
- **사유 코드·내부 단계·재시도 횟수를 표시하지 않는다**(`SEC-002-05`). 사유 코드는 경로 ② 의 설명 문구를 고르는 데만 쓴다.

## 잠정값·범위 밖의 취급

- **잠정값** — `<CONSENT_NOTICE>`·`<SELFCHECK_PATH>`·`<HUB_BASE_URL_PROD>`·`<HUB_BASE_URL_DEV>`·`<RECEIVER_DELIVERY_URL>`·`<CONSENT_PROOF_RETENTION_MONTHS>`·`<COMPLETION_REDIRECT_URL>` 은 **상수 주입으로만 참조**하고 값을 본문에 복제하지 않는다(단일 출처 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수). 잠정 상태의 운영 배포 금지는 `OPS-001-03` 이 갖는다.
	- `<COMPLETION_REDIRECT_URL>` 은 **화면이 값을 직접 읽지 않는다** — 서버가 응답의 `returnUrl` 에 실어 주고 화면은 그 속성만 본다([`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동). 주소의 **출처 자체가 미확정**이라([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑦) 확정 시 값을 얻는 자리가 바뀔 수 있으나 화면 사양은 그대로 선다.
	- **복귀 이동 대기 시간은 잠정값이 아니다** — PRD 가 직접 정한 요구사항 값이며 상수가 아니라 화면 사양이 정본이다([`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동 — 값은 그 문서만 적는다).
- **성과 지표 목표치**는 상수가 아니므로 수치를 옮겨 적지 않고 [`../../prd/PRD.md`](../../prd/PRD.md) §성과 지표를 참조한다.
- **범위 밖** — 링크 만료(TTL)·1회성 사용·발송처 서명 검증·요청 제한·관리자 화면·결과 푸시 통지에 대응하는 화면 요소·표시를 두지 않는다(`OPS-002-05`).
- **폐지 IA 코드**(`ADM`·`ADM-01`~`ADM-03`·`BAT-01`·`BAT-03`)로는 어떤 화면도 만들지 않는다.
