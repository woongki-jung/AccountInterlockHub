# 공통 컴포넌트 카탈로그

정본은 [`design-system.md`](design-system.md)(토큰·레이아웃·접근성 기준). 화면 목록은 [`spec-screens.md`](spec-screens.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

이 표면이 쓰는 컴포넌트는 **11종**이다. 여기 없는 요소를 화면이 임의로 만들지 않는다 — 필요하면 본 문서를 먼저 고친다. 모든 컴포넌트는 [`design-system.md`](design-system.md) 의 토큰만 참조하고 자기 색·간격 값을 갖지 않는다.

## 목록

| 컴포넌트 | 쓰는 화면 | 한 줄 용도 |
|---|---|---|
| AppShell | 전체 | 페이지 바탕 + 중앙 카드 |
| StageTitle | 전체 | 화면 제목(h1)과 보조 설명. 크기 변형 2종 — ProgressPanel·ResultPanel 도 자기 제목을 따로 두지 않고 이것을 합성한다 |
| TextField | SCR-001 | 한 줄 입력. 생년월일 변형을 갖는다 |
| Button | SCR-001 · SCR-002 | 주 액션·보조 액션 |
| NoticeBlock | SCR-002 | 동의 안내 문구(상수) 표시 |
| ConsentList · ConsentItem | SCR-002 | 동의 항목 목록과 항목별 체크 |
| InlineAlert | SCR-001 · SCR-002 · SCR-003 | 단계를 바꾸지 않는 오류·안내 |
| Spinner | SCR-001 · SCR-003 | 처리 중 표시 |
| ProgressPanel | SCR-003 | 승인 후 대기 화면 본문 |
| ResultPanel | SCR-004 | 결과 3경로 표시 · 복귀 안내 영역 |
| Badge | SCR-002 · SCR-004 | 필수 표시·확정 결과 재안내 보조 표시 |

## AppShell

- **구조**: 페이지(`--color-bg`) > 카드(`--color-surface`·`--radius-lg`·`--shadow-card`) > 내용. 카드는 최대 폭 `--size-content-max`, 가로 중앙.
- **없는 것**: 헤더 바·브랜드 로고·전역 네비게이션·사이드바·푸터 메뉴. 사용자 대면 서비스 표시 명칭 상수가 없으므로 임의 문구를 넣지 않는다.
- **마크업**: 카드는 `<main>`. 페이지에 `<header>`·`<nav>` 를 두지 않는다.
- **반응형**: [`design-system.md`](design-system.md) §반응형 브레이크포인트를 그대로 따른다.

## StageTitle

- **구조**: 제목(`<h1>`·`--font-weight-bold`) + 선택적 보조 설명(`--font-size-sm`·`--color-text-muted`). 제목 → 보조 설명 `--space-2xs`, 블록 아래 여백 `--space-lg`.
- **여백을 갖는 자리는 카드 직계뿐이다**: 위 두 간격은 이 컴포넌트가 **카드의 직계 자식**으로 설 때의 값이다 — [`design-system.md`](design-system.md) §레이아웃 3 이 정한 "①화면 제목 ②보조 설명 → ③본문 영역"의 **블록 경계**이며, SCR-001·SCR-002 가 그 자리다(**두 화면의 간격은 이 규칙으로 달라지지 않는다**). **ProgressPanel·ResultPanel 안에 합성될 때는 자기 여백을 하나도 갖지 않는다** — 제목과 보조 설명이 패널의 직계 요소로 서고(둘을 감싸는 블록을 만들지 않는다) 위·아래·둘 사이 간격을 **전적으로 패널의 간격 모델**이 정한다(§ProgressPanel·§ResultPanel §구조). **두 패널에 같은 규칙이 선다.**
	- 컨테이너 간격과 자식 여백은 **합산**된다 — 두 곳이 각자 값을 가지면 제목 다음 간격만 커지고 **어느 사양에도 없는 합계**가 나온다. 책임을 패널 한쪽에 몰아야 값이 사양에서 결정된다.
	- `--space-lg` 의 용도는 **"블록 간"**([`design-system.md`](design-system.md) §간격·크기·모양)인데 패널 내부는 한 덩어리라 블록 경계가 아니다. ResultPanel 은 배지를 **제목 바로 아래**에 두어야 해([`screen_SCR-004.md`](screen_SCR-004.md) §확정 결과 재안내) 24px 블록 여백과 애초에 양립하지 않는다.
- **크기 변형**: 기본 `--font-size-xl`(화면 제목) / **결과 변형** `--font-size-2xl`(SCR-004 의 결과 제목). **변형은 이 둘뿐이며 그 밖의 크기를 만들지 않는다** — 두 값의 용도는 [`design-system.md`](design-system.md) §타이포그래피가 정본이다("화면 제목"·"결과 제목"). 특히 `--font-size-lg`(용도: 강조 문단) 변형을 만들지 않는다.
- **합성해 쓰는 자리**: 기본 변형은 SCR-001·SCR-002 의 제목 영역과 **ProgressPanel**(SCR-003), 결과 변형은 **ResultPanel**(SCR-004). 두 패널은 자기 제목 글꼴을 따로 규정하지 않고 이 컴포넌트를 합성한다 — 그 제목이 문서의 **유일한 `<h1>`** 이자 단계 전환 시 포커스를 받는 요소라, 계약이 두 곳으로 갈리면 안 된다.
- **상태**: 없음(정적).
- **접근성**: 문서에 `<h1>` 은 하나이며 **단계가 바뀌면 내용이 교체**된다. 교체 시 `tabindex="-1"` 인 이 제목으로 포커스를 옮기고 문서 제목(`document.title`)도 같은 문구로 맞춘다.

## TextField

- **구조**: 레이블(`<label for>`·`--font-size-sm`·`--font-weight-semibold`) + 입력(`--size-control-height`·경계 1px `--color-border`·`--radius-sm`) + 도움말 또는 오류 문구.
- **생년월일 변형**: `type="text"`·`inputmode="numeric"`·`autocomplete="off"`·`maxlength=6`·글자 `--font-size-lg`·자간 `0.15em`·고정폭 숫자. 숫자 외 문자는 입력 시점에 걸러 낸다.
	- **값을 가리지 않는다**(비밀번호형 표시를 쓰지 않는다) — 사용자가 방금 넣은 자기 값이며 오타를 눈으로 고쳐야 한다. 이 값은 필드 밖 어디에도(다른 화면 요소·오류 문구·주소창·브라우저 저장소) 나타나지 않는다([`../datas/model_MDL-004-006.md`](../datas/model_MDL-004-006.md) `MDL-006` 마스킹 규칙).
	- **자동 포커스를 주지 않는다** — 진입 즉시 키보드가 올라오면 안내 문구가 가려진다. 오류로 되돌아올 때만 포커스를 옮긴다.
- **상태**: 기본 / 포커스(포커스 링) / 오류(경계 `--color-danger` + 오류 문구) / 잠금(제출 중·`readonly` 로 값 유지).
- **접근성**: 레이블은 항상 보인다(자리표시자로 대체하지 않는다). 오류 문구는 `aria-describedby` 로 연결하고 필드에 `aria-invalid="true"` 를 준다.

## Button

- **변형**: `primary`(`--color-primary` 바탕·흰 글자) · `secondary`(카드 바탕·1px `--color-border`·`--color-primary` 글자). 이 표면에 위험(빨강) 버튼을 두지 않는다 — **파괴적 조작(삭제·거부 제출)이 하나도 없다.** 각 화면의 액션은 다음 단계로 나아가는 제출 하나뿐이다.
	- **`secondary` 를 쓰는 화면은 현재 없다** — 거부 버튼이 폐지되면서(`BIZ-003-03`) 사용처가 사라졌다. 정의는 남기되 화면이 근거 없이 되살리지 않는다(쓰려면 화면 사양이 먼저 근거를 든다).
- **크기**: 높이 `--size-control-height`, 좌우 여백 `--space-md`, 글자 `--font-size-base`·`--font-weight-semibold`, 모서리 `--radius-md`. 카드 폭을 채우는 전체 폭이 기본이다.
- **상태**: 기본 / 눌림(`--color-primary-strong`) / 포커스(포커스 링) / 비활성(`--color-disabled-bg`·`--color-disabled-fg`·`aria-disabled="true"`) / 처리 중(Spinner + 문구 교체·중복 제출 차단).
	- **`처리 중` 이 서는 자리는 SCR-001 의 확인 버튼 하나다.** SCR-002 의 승인 버튼은 요청 발신 즉시 카드 내용이 진행 화면(SCR-003)으로 바뀌어 **버튼 자체가 화면에서 사라지므로** 이 상태를 거치지 않는다([`screen_SCR-002.md`](screen_SCR-002.md) §화면 상태 전이 `SubmittingApprove`). §목록의 Spinner 사용 화면이 SCR-001·SCR-003 둘뿐인 것과 같은 근거이며, 그래서 승인 제출에는 **폼 전체 잠금도 두지 않는다**(§ConsentList).
- **접근성**: 네이티브 `<button>` 만 쓴다. 비활성은 `disabled` 대신 `aria-disabled="true"` 로 두어 **포커스를 받을 수 있게** 한다 — 왜 못 누르는지 안내를 읽을 수 있어야 한다. **클릭은 제출로 이어지지 않되 무시되지도 않는다** — 그 자리에서 화면 사양이 정한 유효성 안내를 알림 영역에 띄운다([`screen_SCR-002.md`](screen_SCR-002.md) §조건부 표시 — 승인 버튼).
- 액션이 둘이면 세로로 쌓고 주 액션을 위에 둔다.

## NoticeBlock

- **구조**: 약한 바탕(`--color-primary-weak`)·`--radius-md`·안쪽 여백 `--space-md`. 안내 문구 상수의 **단락을 그대로 문단으로** 렌더한다.
- **상태**: 값이 비면 **렌더하지 않는다**(제목·구분선·여백 포함).
- **제약**: 문구를 자르거나 접거나 요약하지 않는다. 서식·링크·HTML 을 해석하지 않는다(`DATA-003-05`). 최대 400자·3단락 전제는 [`design-system.md`](design-system.md) §안내 영역 레이아웃 전제.

## ConsentList · ConsentItem

- **ConsentList**: 항목 1건이어도 **목록 구조로** 렌더한다(항목 수는 상수로 바뀐다). 항목 사이 구분선 `--color-divider`.
- **ConsentItem 구조**: 체크박스 + 항목명(`--font-weight-semibold`) + `필수` 배지(필수 항목만) + 설명(`--font-size-sm`·`--color-text-muted`).
- **히트 영역**: **행 전체가 레이블**이라 어디를 눌러도 체크가 토글된다. 행 최소 높이 `--size-hit-min`.
- **상태**: 미선택 / 선택(체크 표시 `--color-primary`) / 포커스(행에 포커스 링). **잠금(제출 중) 상태를 두지 않는다** — 아래 근거.
	- **잠금 상태가 사라진 이유**: 목록을 잠근 채 응답을 기다리는 흐름은 거부 제출뿐이었는데 그 경로가 폐지됐다(`BIZ-003-03`). 남은 제출은 승인 하나이고, 승인은 요청 발신 즉시 카드 내용이 진행 화면(SCR-003)으로 바뀌어 **목록이 화면에서 사라진다**([`screen_SCR-002.md`](screen_SCR-002.md) §화면 상태 전이 `SubmittingApprove`). 트리거가 없는 상태를 카탈로그에 남기지 않는다.
	- 비활성 토큰 쌍(`--color-disabled-bg`/`--color-disabled-fg`·대비비 **4.82:1**)은 그대로 남아 **승인 버튼의 비활성**에 쓰인다([`design-system.md`](design-system.md) §색 대비 검증). 상태를 지웠을 뿐 토큰을 지우지 않았다.
	- 목록을 흐리게 만들 일이 생기더라도 **불투명도(`opacity`)로 흐리지 않는다** — 전경과 배경을 함께 옅게 만들어 실측 대비비를 무효로 한다. 색 값을 토큰으로 바꿔 대비를 지킨다.
- **접근성**: 네이티브 `<input type="checkbox">` + `<label>` 조합. 목록은 `<ul>`·항목은 `<li>`. 필수 항목에는 `필수` 라는 **글자**를 함께 둔다(별표 하나로 대신하지 않는다). **체크박스를 `disabled` 로 두는 상태가 없다** — 목록은 승인 제출 직전까지 항상 조작 가능하다.
- 항목명·설명·필수 여부는 상수에서 온 값을 그대로 쓴다.

## InlineAlert

- **용도**: 단계를 바꾸지 않는 알림 — 입력 형식 오류, 본인확인 재입력 안내, 필수 동의 미충족, 내부 오류 후 재시도 안내.
- **구조**: 아이콘 + 문구. 위험 계열 바탕 `--color-danger-weak`·글자 `--color-danger-strong`·왼쪽 강조선 3px `--color-danger`. 모서리 `--radius-md`, 안쪽 여백 `--space-sm`~`--space-md`.
- **위치**: 화면 사양이 고정한 **알림 영역** 한 곳 — 본문(입력·목록·진행 표시) 영역 아래이며 액션 영역이 있으면 그 위다([`screen_SCR-001.md`](screen_SCR-001.md) §레이아웃 구성 3 · [`screen_SCR-002.md`](screen_SCR-002.md)·[`screen_SCR-003.md`](screen_SCR-003.md) §레이아웃 구성 4). **오류 유형(입력·처리)에 따라 자리를 옮기지 않는다**([`design-system.md`](design-system.md) §상태 표현).
- **접근성**: `role="status"`(공손) 로 알린다. 필드에 매인 경우 `aria-describedby` 로 연결한다. 알림이 뜬다고 포커스를 빼앗지 않되, 재입력 안내는 해당 필드로 포커스를 옮긴다.
- 문구는 각 화면 사양이 정한 값을 쓴다. 사유 코드·단계 번호·내부 메시지를 노출하지 않는다(`SEC-002-05`).

## Spinner

- **구조**: 원형 진행 표시. 지름 20px(버튼 안) / 32px(진행 화면).
- **SCR-002 는 쓰지 않는다** — 거부 제출 상태(`SubmittingReject`)가 폐지됐고(`BIZ-003-03`), 남은 `SubmittingApprove` 는 카드 내용을 즉시 SCR-003 으로 교체해 이 화면에 처리 중 표시가 서지 않는다([`screen_SCR-002.md`](screen_SCR-002.md) §화면 상태 전이). 쓰는 화면은 **SCR-001(버튼 안 20px)·SCR-003(진행 화면 32px)** 둘이며, 화면이 근거 없이 되살리지 않는다(쓰려면 화면 사양이 먼저 근거를 든다).
- **접근성**: `aria-hidden="true"` 로 두고 **상태는 옆 문구가 전달**한다. 감소 모션 설정에서는 회전 주기를 1.6초 이상으로 늦춘다(없애지 않는다).
- 진행률을 알 수 없으므로 퍼센트·남은 시간을 표시하지 않는다.

## ProgressPanel

- **용도**: 승인 제출 후 결과가 확정되기까지의 대기 표시(SCR-003).
- **구조**: Spinner(32px) + **StageTitle(기본 변형)** + **알림**(InlineAlert·조건부). 제목과 보조 문구는 StageTitle 의 제목·보조 설명이며, 이 패널은 자기 글꼴 크기를 따로 규정하지 않는다([`screen_SCR-003.md`](screen_SCR-003.md) §레이아웃 구성 2·3 이 이미 그 구조다). 세로 가운데 정렬, 위아래 여백 `--space-xl`.
	- **알림은 이 패널의 요소다** — 카드를 이 패널 하나로 채우므로 알림도 패널 안에 서며, **패널의 마지막 요소**다([`screen_SCR-003.md`](screen_SCR-003.md) §레이아웃 구성 4). 자리 자체는 §InlineAlert §위치 그대로다(본문 = 진행 표시 아래이며, 이 화면에는 액션 영역이 없다).
- **간격**: 요소 사이 **`--space-md` 균일** — Spinner ↔ 제목 ↔ 보조 문구 ↔ **(조건부) 알림**. 이 패널 안에서는 합성된 StageTitle 도(§StageTitle) InlineAlert 도 **자기 바깥 여백을 갖지 않아** 간격이 이 한 값으로 결정된다.
	- 알림만 자기 위 여백(`--space-sm`)을 따로 가지면 패널 간격과 **합산돼 28px** 이 되는데, 이는 **어떤 `--space-*` 토큰으로도 표현되지 않는 값**이다. "패널이 간격을 지배한다"(§StageTitle)의 같은 적용이며 새 규칙이 아니다.
- **제약**: 이 상태에는 **조작 요소를 두지 않는다** — 취소 버튼을 두면 이미 진행 중인 서버 처리와 화면이 어긋난다. 뒤로 가기·새로고침은 진입부터 다시 시작한다.
- **접근성**: 영역에 `role="status"`·`aria-live="polite"`·`aria-busy="true"`. 제목의 포커스 이동·문서 제목 일치 계약은 §StageTitle 을 그대로 따른다.
	- **대기가 끝나면 `aria-busy` 를 푼다**(`false` 로 바꾸거나 속성을 지운다) — 결과가 도착해 카드 내용이 다른 화면으로 바뀔 때도, 이 화면에 잔류하는 `Unconfirmed` 로 들어갈 때도 같다([`screen_SCR-003.md`](screen_SCR-003.md) §화면 상태 전이). `aria-busy="true"` 는 라이브 리전에 **"아직 갱신 중이니 지금 읽지 말라"** 는 신호라, 켠 채로 알림을 띄우면 보조기술이 안내를 미루거나 건너뛴다 — `Unconfirmed` 의 재진입 안내는 사용자가 **반드시 읽어야** 하는 문구다. **`role="status"`·`aria-live="polite"` 는 그대로 둔다** — 알림을 그 자리에서 읽혀야 하므로 영역을 라이브 리전에서 내리지 않는다. 푸는 것은 `aria-busy` 하나다.
- 대기 시간 상한은 정책 `BIZ-004-02` 가 정한 전달 재시도 총 소요 상한이 결정한다 — 화면은 **수치를 자체로 정의하지 않는다**.

## ResultPanel

- **용도**: 결과 3경로 표시(SCR-004). 경로별 색·아이콘·제목은 [`design-system.md`](design-system.md) §결과 3경로의 시각 구분이 정본이다.
- **구조**: 경로 아이콘(40px) → **StageTitle(결과 변형)** 제목(`<h1>`·`--font-size-2xl`) → 보조 표시 배지(재안내일 때만) → 설명 문단(`--color-text`) → 다음 안내 한 줄(`--color-text-muted`) → **복귀 안내 영역**(복귀 주소가 실려 왔을 때만). 패널 바탕은 경로별 약한 바탕, 왼쪽 강조선 4px, 안쪽 여백 `--space-lg`.
- **간격**: **균일 간격을 쓰지 않는다** — 배지가 제목에 붙어야 해서 한 값으로 덮을 수 없다. 요소 사이는 아이콘 → 제목 `--space-md` · 제목 → 배지 **`--space-sm`**(제목 바로 아래) · 배지(없으면 제목) → 설명 문단 `--space-md` · 설명 문단 → 다음 안내 `--space-md` · 다음 안내 → 복귀 안내 영역 `--space-md`. 합성된 StageTitle 은 자기 여백을 갖지 않는다(§StageTitle).
- **복귀 안내 영역**: 고지 문구 한 줄(`--font-size-sm`·`--color-text-muted`) + 카운트다운 한 줄(같은 글자 스타일) + **수동 이동 링크**. 표시 조건·문구·대기 시간·이동 방식의 정본은 [`screen_SCR-004.md`](screen_SCR-004.md) §복귀 이동이다.
	- **수동 이동 링크**: 네이티브 `<a>` 하나. 글자 `--color-primary`·`--font-weight-semibold`·`--font-size-base`, **밑줄을 유지**한다(색만으로 구분하지 않는다). 최소 히트 영역 `--size-hit-min` 은 상하 여백으로 채운다. 포커스 표시는 [`design-system.md`](design-system.md) §접근성 기준의 포커스 링 규칙을 그대로 쓴다.
	- **애니메이션을 두지 않는다** — 진행 링·진행 막대 없이 **텍스트만 갱신**한다. 그래서 감소 모션 설정에서 달라질 것이 없고 Spinner 의 회전 주기 규칙도 적용되지 않는다.
- **상태**: 경로 3종 × 재안내 여부(①·③ 에서만) × **복귀 안내 영역 유무**(실제로는 ① 에서만 실린다). 그 밖의 상태를 만들지 않는다.
- **접근성**: 아이콘은 `aria-hidden="true"`. 결과 도착 시 제목으로 포커스를 옮기고, 영역은 `role="status"` 로 둔다(경고음 같은 강한 알림을 쓰지 않는다).
	- **고지 문구는 결과와 함께 첫 그림부터** 이 영역 안에 있어 한 번만 읽힌다. **카운트다운 숫자 영역에는 `aria-hidden="true"`** 를 주어 1초마다의 갱신이 읽히지 않게 한다 — 라이브 리전 안이라도 `aria-hidden` 인 요소는 읽히지 않는다.
	- 링크로 포커스를 옮기지 않는다(포커스는 제목으로 간다). 링크는 탭 순서로 도달한다.
- **제약**: 추적 키·암호값·복호화 원문·사유 코드 원문을 표시하지 않는다. **복귀 주소 문자열도 그리지 않는다** — 링크 라벨은 문구다. **액션 버튼을 두지 않는다** — 수동 이동 링크는 서버를 부르는 액션이 아니라 여정 밖으로 나가는 이동 수단이며, 재시도·문의 요소가 아니다.

## Badge

- **변형**: `필수`(동의 항목용·`--color-primary-weak` 바탕·`--color-primary-strong` 글자) / `재안내`(확정 결과 재안내용·`--color-neutral-weak` 바탕·`--color-neutral` 글자 + 되돌림 아이콘).
- **구조**: `--font-size-xs`·`--radius-pill`·좌우 여백 `--space-xs`. 조작 요소가 아니므로 히트 영역 규칙을 적용하지 않는다.
- **접근성**: 글자를 그대로 읽히게 둔다(아이콘만 쓰지 않는다). 장식 아이콘은 `aria-hidden="true"`.
