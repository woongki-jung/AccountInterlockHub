# 연동 값 데이터 모델 정의 (MDL-004 ~ MDL-006)

정본 목록은 [`spec-models.md`](spec-models.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **모델 목적**: 암호화 연동 규약이 오가게 하는 값 세 가지다 — 발송처가 만든 **암호값 쌍**, 그것을 풀어 얻는 **전달 데이터**, 그리고 나머지 키인 **생년월일**. 셋 다 **어떤 저장소에도 기록되지 않으며**(`DATA-001-02`) 요청 처리 중 메모리에만 존재한다.
- **관련 서비스**: `SVC-001`·`SVC-002`·`SVC-004`(사용자 연동 본체) · `SVC-006`·`SVC-007`(연동 라이브러리) · `SVC-013`(자가진단)

---

## MDL-004 암호값 쌍

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 암호값 쌍 |
| 분류 | 외부 연동(EXT) |
| 사용 서비스 | SVC-001 · SVC-002 · SVC-004 · SVC-006 · SVC-007 · SVC-013 |
| 매핑 엔터티 | **없음(비저장)** |
| 사용 PROC | PROC-101 · PROC-102 · PROC-104 · PROC-204 · PROC-401 · PROC-402 |
| 용도 | 외부 DTO |
| 관련 IA 항목 | `USR-01` · `USR-03` · `USR-02` · `LIB-01` · `LIB-02` · `API-04` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| encX | string | Y | - | Base64URL 문자 집합만(`A-Z a-z 0-9 - _`), 패딩 `=` 없음. 디코드 결과의 길이가 16의 배수(`SEC-001-08`·`SEC-002-02`) | **로그·오류 메시지·응답 본문·화면에 담지 않는다**(`DATA-001-04`) | 전달 데이터를 암호화한 값 |
| encY | string | Y | - | 위와 같다 | 위와 같다 | `encX` 의 키를 생년월일로 암호화한 값 |

- 두 값은 **항상 쌍으로** 다룬다 — 하나만 있으면 복호화 판정이 성립하지 않아 진입 단계에서 구조 위반으로 종결된다(`EX-SEC-001`).
- 규약 값(알고리즘·정규화·인코딩)은 정책이 정본이며 본 모델은 **참조만** 한다(`SEC-001`).

### 엔터티 매핑

**매핑 엔터티 없음** — 저장 대상 셋 중 어디에도 담기지 않는다(`DATA-001-02`). 따라서 `도메인→ENT`·`ENT→도메인` 지점이 존재하지 않는다. 적용되는 변환 지점은 `FE→요청`(진입 URL 파라미터 → 요청)과 `요청→도메인`(Base64URL 디코드)뿐이다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-006 | 전달 데이터 암호화 | 응답 | PROC-401 | 라이브러리 산출 결과 |
| SVC-007 | 연동 요청 URL 생성 | 요청 | PROC-402 | URL 파라미터로 결합 |
| SVC-001 | 연동 링크 진입 | 요청 | PROC-101 | 구조 판정 대상 |
| SVC-002 · SVC-004 | 본인확인 · 연동 실행 | 도메인 | PROC-102 · PROC-104 | 복호화 판정 입력 |
| SVC-013 | 연동 규약 자가진단 | 요청 | PROC-204 | [`MDL-014`](model_MDL-011-015.md) 의 구성 요소 |

### 구현 가이드

- 요청 처리 문맥의 지역 값으로만 다룬다. 세션·캐시·브라우저 저장소에 넣지 않는다.
- Base64URL 로 이미 URL 에 실을 수 있는 형태이므로 **추가 인코딩을 하지 않는다** — 이중 인코딩은 진입 단계 디코드 실패의 대표 원인이다.
- 길이 배수 검사는 디코드 직후에 한다. 복호화를 시도하기 전에 걸러 낼 수 있는 가장 값싼 검사다.

## MDL-005 전달 데이터 X

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 전달 데이터 X |
| 분류 | 외부 연동(EXT) |
| 사용 서비스 | SVC-002 · SVC-004 · SVC-006 |
| 매핑 엔터티 | **없음(비저장)** |
| 사용 PROC | PROC-102 · PROC-104 · PROC-204 · PROC-401 |
| 용도 | 외부 DTO |
| 관련 IA 항목 | `USR-03` · `USR-02` · `LIB-01` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| trackingKey | string | Y | - | 1자 이상 255자 이하, 공백만 불가(`DATA-004-03`·EXC-DATA-11). 부재·형식 위반은 `EX-SEC-002` | - | 연동 추적 키. 허브가 해석하는 **유일한** 필드다 |
| (그 밖의 필드) | 발송처 정의 | N | - | 허브는 검증하지 않는다(`BIZ-004-05`) | **전량 미노출·미저장**(`DATA-001-02`·`DATA-001-04`) | 수신처에 넘길 사용자 키 등 업무 필드. 형상은 발송처·수신처 계약이다 |

- 직렬화 형식은 **UTF-8 JSON** 이며 직렬화 결과가 1,024바이트 이하여야 한다(`SEC-001-02`·`SEC-001-09` → 초과 시 `EX-SEC-004`).
- 허브는 `trackingKey` 만 취하고 **나머지 필드를 해석·검증하지 않는다.** 복호화 원문을 그대로 수신처 전달 페이로드로 삼는다.

### 엔터티 매핑

**매핑 엔터티 없음** — 복호화 원문은 어떤 저장소에도 남기지 않는다(`DATA-001-02`·`DATA-001-03`). 본인확인 단계에서는 `trackingKey` 만 취한 뒤 **즉시 폐기**하고, 승인 시점에 다시 복호화해 얻는다(`BIZ-002-06`). 취해진 `trackingKey` 만 [`MDL-001`](model_MDL-001.md) 을 거쳐 ENT-001 로 간다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-006 | 전달 데이터 암호화 | 요청 | PROC-401 | 암호화 입력([`MDL-016`](model_MDL-016-018.md))의 구성 요소 |
| SVC-002 | 본인확인 | 도메인 | PROC-102 | 복호화 결과 — 추적 키만 취하고 폐기 |
| SVC-004 | 연동 실행 | 도메인 | PROC-104 | 재복호화 결과 — 그대로 전달 페이로드 |
| SVC-013 | 연동 규약 자가진단 | 도메인 | PROC-204 | 판정에만 쓰고 응답에 담지 않는다(`SEC-003-03`) |

### 구현 가이드

- **지역 변수로만 다루고 전역 상태·요청 컨텍스트 저장소에 넣지 않는다.** 재시도 중에도 메모리에만 둔다 — 큐·파일에 적재하면 무저장 원칙이 깨진다.
- 로그 출력 지점에서 이 모델을 걸러 내는 공통 처리를 두면 `DATA-001-04` 를 반복 점검하지 않아도 된다.
- 타입 정의 시 `trackingKey` 만 명시하고 나머지는 열린 형태로 둔다 — 발송처가 필드를 늘려도 허브를 고치지 않아야 한다.

## MDL-006 본인확인 입력

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 본인확인 입력 |
| 분류 | 공통(COM) |
| 사용 서비스 | SVC-002 · SVC-004 |
| 매핑 엔터티 | **없음(비저장)** |
| 사용 PROC | PROC-102 · PROC-104 |
| 용도 | 요청 모델 |
| 관련 IA 항목 | `USR-03` · `USR-02` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| birthDate | string(6) | Y | - | `yyMMdd` 형식의 숫자 6자리 — `^\d{6}$`(`AUTH-002-02` → 위반 시 `EX-AUTH-001`) | **URL·로그·오류 메시지·응답 본문·화면 어디에도 남기지 않는다**(`DATA-001-02`·`DATA-001-04`) | 사용자가 입력한 생년월일. 인증 자격이 아니라 **복호화의 나머지 키**다 |

- 허브는 대조할 원본을 갖고 있지 않다 — 복호화가 되는지로만 판단한다(EXC-AUTH-04). 그래서 저장하지 않고 실패해도 잠그지 않는다(`AUTH-002-04`).

### 엔터티 매핑

**매핑 엔터티 없음** — 어떤 컬럼에도 담기지 않는다(`DATA-001-02`). 적용되는 변환 지점은 `FE→요청`·`요청→도메인` 둘뿐이며, 응답 방향으로는 어떤 지점에도 실리지 않는다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-002 | 본인확인 | 요청 | PROC-102 | 복호화 판정 1·2단계 입력 |
| SVC-004 | 연동 실행 | 요청 | PROC-104 | 승인 시점 재복호화 입력(`BIZ-002-06`) |
| SVC-013 | 연동 규약 자가진단 | 요청 | PROC-204 | [`MDL-014`](model_MDL-011-015.md) 의 구성 요소 |

### 구현 가이드

- 형식 검증은 화면과 서버 양쪽에서 하되 **판정 근거는 서버 검증**이다(`AUTH-002-02`).
- 입력 상태로만 보유한다 — 진행 단계 이동을 위해 값을 URL 파라미터·숨은 필드로 옮기지 않는다.
- 승인 시점의 재복호화에도 같은 값이 필요하다. 요청 사이에 보관하지 않고 **사용자에게 다시 받는 경로**가 성립하도록 화면·기능 도메인이 흐름을 정한다 — 데이터 도메인이 정하는 것은 "저장하지 않는다"까지다.
