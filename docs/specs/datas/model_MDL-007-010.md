# 사용자 연동 진행 데이터 모델 정의 (MDL-007 ~ MDL-010)

정본 목록은 [`spec-models.md`](spec-models.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **모델 목적**: 본인확인 이후 결과 안내까지의 진행에서 오가는 값 넷이다 — 사용자의 **동의·승인 제출**, 상수에서 오는 **동의 항목 구성**, 수신처 **전달 결과**, 그리고 화면이 경로를 고르는 근거인 **결과 안내 정보**. 넷 다 저장되지 않는다.
- **관련 서비스**: `SVC-003`(동의·승인) · `SVC-004`(연동 실행) · `SVC-005`(결과 안내) · `SVC-015`(동의 증적) · `SVC-018`(상수 검증)

## MDL-007 동의·승인 제출

### 기본 정보

| 항목 | 내용 |

| 모델명 | 동의·승인 제출 |
| 분류 | 공통(COM) |
| 사용 서비스 | SVC-003 · SVC-015 |
| 매핑 엔터티 | **없음(비저장)** — 다만 동의 항목 목록은 [`MDL-002`](model_MDL-002.md) 를 거쳐 ENT-002 로 간다 |
| 사용 PROC | PROC-103 · PROC-302 |
| 용도 | 요청 모델 |
| 관련 IA 항목 | `USR-04` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| decision | string | Y | - | 승인·거부 두 값 중 하나. 도메인 표현은 `APPROVE`·`REJECT` | - | 사용자의 제출 의사(BR-004) |
| agreedItemCodes | string[] | Y | 빈 배열 | 각 코드가 [`MDL-008`](#mdl-008-동의-항목-구성) 의 항목 코드에 존재해야 한다. 필수 항목이 모두 포함돼야 승인이 성립한다(`BIZ-003-01`·`BIZ-003-02` → 미충족 시 `EX-BIZ-001`) | - | 사용자가 동의한 항목 코드 목록 |

- 거부 제출이면 `agreedItemCodes` 는 검증 대상이 아니다 — 거부는 곧바로 `USER_DENIED` 로 확정되고 증적을 만들지 않는다(`BIZ-003-03`).
- **전송 표현(필드명·값의 문자열 형태)은 기능·API 도메인이 확정한다**(`BIZ-003` 구현 가이드). 본 모델은 도메인 표현이며, 다르게 확정되면 이 모델의 속성 표기만 따라간다.

### 엔터티 매핑

**매핑 엔터티 없음** — 제출 자체는 저장되지 않는다. `agreedItemCodes` 만 `요청→도메인` 지점을 거쳐 [`MDL-002`](model_MDL-002.md) 의 같은 이름 속성으로 옮겨지고, 거기서 `도메인→ENT` 지점으로 ENT-002 에 담긴다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-003 | 동의·승인 | 요청 | PROC-103 | 서버 재검증 대상(`BIZ-003-02`) |
| SVC-015 | 동의 증적 기록 | 도메인 | PROC-302 | 동의 항목 목록의 출처 |

### 구현 가이드

- 화면 검증은 사용자 편의이고 **판정 근거는 서버 검증**이다. 화면 검증만 두면 `BIZ-003-02` 위반이다.
- 동의한 항목이 **식별 가능한 형태**로 담겨야 서버 재검증과 증적 기록이 함께 성립한다. 단순한 "동의함" 불린 하나로는 어느 항목에 동의했는지 사후에 알 수 없다.

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| version | string(64) | Y | - | 소문자 16진수 64자 — `^[0-9a-f]{64}$` | - | 동의 항목 버전 식별자. 기동 시 산출한다([`data_ENT-002.md`](data_ENT-002.md) §버전 식별자 산출 규칙) |
| notice | string | N | 빈 문자열 | 허용 형태(최대 길이·단락 수·평문 한정)는 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §동의 항목 값이 정본(EXC-DATA-08) | - | `<CONSENT_NOTICE>` 파싱 결과. 비면 안내 영역을 표시하지 않는다(EXC-BIZ-07) |
| items | ConsentItem[] | Y | - | 1건 이상. 항목 코드 오름차순 | - | `<CONSENT_ITEMS>` 파싱 결과 |
| items[].code | string | Y | - | 항목 안에서 유일 | - | 항목 코드 |
| items[].label | string | Y | - | 빈 값 불가 | - | 화면에 그대로 노출하는 항목명 |
| items[].required | boolean | Y | - | - | - | 필수 여부. `true` 인 항목은 모두 동의해야 승인할 수 있다 |
| items[].description | string | Y | - | 빈 값 불가 | - | 화면에 그대로 노출하는 설명 |

- **값을 본 사양에 복제하지 않는다**(`OPS-001-04`) — 상수표가 단일 출처다. 항목·문구가 바뀌면 `version` 도 함께 바뀐다(`DATA-003-03`).
- 항목을 코드·데이터베이스에 따로 두지 않는다(`DATA-003-01`·`DATA-001-05`).

### 엔터티 매핑

**매핑 엔터티 없음** — 구성은 배포 상수이며 데이터베이스에 두지 않는다(`DATA-001-05`). 다만 승인 시점에 이 모델의 `notice`·`items` 가 [`MDL-002`](model_MDL-002.md) 의 `consentSnapshot` 으로, `version` 이 `consentVersion` 으로 복사되어 ENT-002 에 담긴다. 이 복사는 **구성의 저장이 아니라 증적**이다(EXC-DATA-02).

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-018 | 연동 구성 상수 검증 | 도메인 | PROC-901 | 파싱·버전 식별자 산출의 산출물 |
| SVC-003 | 동의·승인 | 도메인 | PROC-103 | 화면 노출·서버 재검증 기준 |
| SVC-015 | 동의 증적 기록 | 도메인 | PROC-302 | 스냅샷·버전 식별자의 출처 |

### 구현 가이드

- 기동 시 한 번 파싱해 불변 값으로 보유한다. 요청마다 다시 파싱하면 배포 중 값이 흔들릴 여지가 생긴다.
- **화면이 문구를 가공하지 않는다**(`DATA-003-05`) — 화면 노출과 증적 스냅샷이 같은 모델에서 나와야 둘이 어긋나지 않는다.
- 항목 정렬(코드 오름차순)을 이 모델에서 한 번만 수행하면 버전 식별자 산출과 스냅샷이 자동으로 같은 순서를 갖는다.

## MDL-009 연동 결과 안내 정보

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 연동 결과 안내 정보 |
| 분류 | 서비스(SVC) |
| 사용 서비스 | SVC-005 |
| 매핑 엔터티 | **없음(비저장)** |
| 사용 PROC | PROC-105 |
| 용도 | 도메인 모델 |
| 관련 IA 항목 | `USR-05` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| resultPath | number | Y | - | `1`·`2`·`3`·`4` 중 하나 — `BIZ-001-02` 가 정한 네 경로의 번호. 다섯 번째 값을 만들지 않는다 | - | 안내할 결과 경로. ① 연동 완료 ② 사용자 거부 ③ 링크·복호화 오류 ④ 수신처 전달 실패 |
| isReAnnouncement | boolean | Y | false | - | - | 확정 결과 재안내 여부. `true` 면 "이미 처리된 요청"임을 보조 표시한다(`BIZ-002-04` ③) |

- **결과 구분 값을 그대로 싣지 않고 경로 번호로 옮긴다** — 경로 ③ 은 결과 구분이 없는 진입 단계 실패도 받아야 하므로, 결과 구분만으로는 경로를 표현할 수 없다(`BIZ-001-02`·EXC-BIZ-01).
- 어느 값에도 매핑되지 않는 상태는 경로 `3` 으로 안내한다(`SVC-005` F-003).
- 각 경로를 몇 개의 화면으로 그릴지는 화면 도메인이 정한다 — 본 모델은 **어떤 결과가 어느 경로인지**만 담는다.

### 엔터티 매핑

**매핑 엔터티 없음** — 재안내 여부는 안내 구성 단계에서만 쓰는 표시 정보이며 저장 대상이 아니다(`SVC-005` 구현 가이드). [`MDL-001`](model_MDL-001.md) 의 `resultCode` 또는 진입 단계 실패 사유에서 `ENT→도메인`·`도메인→응답` 지점을 거쳐 산출된다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-005 | 연동 결과 안내 | 도메인 | PROC-105 | 경로 선택·보조 표시의 근거 |

### 구현 가이드

- 결과 구분 → 경로 번호 대응은 한 곳에만 둔다. 화면마다 대응을 다시 쓰면 경로가 갈린다.
- 안내에 복호화 원문·암호값·생년월일·키를 담지 않는다(`DATA-001-04`·`SEC-002-05`). 이 모델에 그런 속성이 없는 것이 1차 방어다.
- 재안내 흐름에서 추적 레코드를 갱신하거나 지표를 계수하지 않는다(`BIZ-002-04`·`BIZ-005-03`).

## MDL-010 수신처 전달 결과

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 수신처 전달 결과 |
| 분류 | 서비스(SVC) |
| 사용 서비스 | SVC-004 |
| 매핑 엔터티 | **없음(비저장)** |
| 사용 PROC | PROC-104 |
| 용도 | 도메인 모델 |
| 관련 IA 항목 | `USR-02` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| isDelivered | boolean | Y | false | - | - | 전달 성공 여부(BR-006). 성공 판정 기준은 기능·API 도메인이 확정한다 |
| attemptCount | number(정수) | Y | 0 | 1 이상, 규약이 정한 총 시도 횟수 이하(`BIZ-004-02`) | - | 최초 시도를 포함한 전달 시도 횟수 |
| isRetryExhausted | boolean | Y | false | `isDelivered = false` 일 때만 `true` 가 될 수 있다 | - | 즉시 재시도 소진 여부(BR-007) |

- **수신처 응답 본문을 담지 않는다** — 성공·실패 판정 결과만 남긴다. 응답 본문에는 전달한 원문이 되비칠 수 있어 담지 않는 것이 안전하다(`DATA-001-04`).
- 재시도 횟수·간격·대기 상한 값은 정책이 정본이며 본 모델은 참조만 한다(`BIZ-004-02`).

### 엔터티 매핑

**매핑 엔터티 없음** — 전달 결과 자체는 저장되지 않는다. 판정 결과가 [`MDL-001`](model_MDL-001.md) 의 `resultCode` 로 옮겨져(`isDelivered = true` → `SUCCESS`, `isRetryExhausted = true` → `DELIVERY_FAILED`) `도메인→ENT` 지점에서 ENT-001 에 기록된다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-004 | 연동 실행 | 도메인 | PROC-104 | 전달 판정·재시도 판정의 상태 |

### 구현 가이드

- 성공·실패 판정이 결과 구분과 **1:1 로 이어지게** 한다 — 중간 상태를 결과 구분으로 승격시키지 않는다(`BIZ-004` 구현 가이드).
- 재시도 중에도 전달 데이터는 메모리에만 둔다. 재시도를 위해 큐·파일에 적재하면 무저장 원칙이 깨진다(`DATA-001-03`).
- 결과가 확정된 뒤 허브가 자동으로 다시 전달하지 않는다(`BIZ-004-04`). 이 모델에 재예약을 나타내는 속성을 두지 않은 이유다.
