# 데이터 정의서 (목록)

AccountInterlockHub 가 저장하는 데이터의 단일 출처다. 상위 고정값은 [`../../prd/devspec/database.md`](../../prd/devspec/database.md), 방향 근거는 [`../../prd/PRD.md`](../../prd/PRD.md), 정보 구조는 [`../../prd/ia/IA.md`](../../prd/ia/IA.md), 준수 규칙은 [`../policies/spec-policies.md`](../policies/spec-policies.md), 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md) 를 따른다.

본 문서는 **설계 원칙·코드 체계·엔터티 목록·관계 요약·인덱스 전략**을 담고, 컬럼 수준 정의는 `data_<ENT 코드>.md` 가 갖는다. 응용 계층의 데이터 모델은 [`spec-models.md`](spec-models.md) 가 갖는다.

## 데이터 설계 원칙 및 기본 방향

1. **저장 대상은 셋뿐이다**(`DATA-001-01`) — 연동 추적 레코드 · 동의 증적 · 연동 지표 집계. 그 밖의 어떤 데이터도 저장하지 않는다. 세션·사용자·감사 로그·보안 이벤트·실행 이력·구성 테이블을 만들지 않는다(`OPS-003-01`·`OPS-003-02`·`OPS-003-04`·`DATA-001-05`).
2. **저장하지 않는 값을 먼저 못박는다**(`DATA-001-02`) — `encX`·`encY`·복호화 원문 X·사용자가 입력한 생년월일·발송처키는 어떤 컬럼에도 담기지 않는다. 예외는 **연동 추적 키**뿐이며, 추적 키는 불투명 문자열이고 개인정보 원문이 아니다(`DATA-004-01`).
3. **연동 구성은 데이터베이스에 두지 않는다**(`DATA-001-05`) — 배포 시점 상수가 단일 출처다([`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수). 구성 엔터티가 존재하지 않는 것이 이 제품의 설계다.
4. **하드 삭제만 쓴다** — 보관 정책의 목적이 **삭제**이므로(`DATA-002-01`·`DATA-002-02`) 논리 삭제 컬럼(`deleted_at`)을 두지 않는다. 남겨 두는 삭제는 목적에 반한다.
5. **감사 컬럼은 생성 일시 하나뿐이다** — 수정 시각은 사건별 일시 컬럼(결과 확정·결과 확인·완료 콜백)이 이미 정확히 보존하므로 범용 수정 일시 컬럼을 두지 않는다. **생성자·수정자 컬럼도 두지 않는다** — 인증이 없어(`AUTH-001-01`~`AUTH-001-03`) 식별할 행위자가 존재하지 않는다.
6. **파생값을 저장하지 않는다** — 결과 구분에서 결정되는 처리 성공 여부, 일시 컬럼의 존재로 결정되는 결과 확인 여부·콜백 수신 여부, 카운터에서 계산되는 성공률은 컬럼으로 두지 않고 읽는 시점에 산출한다(3NF · `BIZ-005-01`). 두 값이 어긋날 여지를 구조적으로 없앤다.
7. **정규화 기준은 3NF** 이며 의도적 비정규화는 동의 증적의 **항목 스냅샷 하나뿐**이다(§ENT-002). 스냅샷은 성능이 아니라 **사후 입증**을 위한 시점 보존이라 정규화 대상이 아니다.
8. **DBMS 는 PostgreSQL 16**([`../../prd/devspec/database.md`](../../prd/devspec/database.md) §데이터베이스). 타입·제약은 그 기준으로 적되 특정 ORM·프레임워크를 강제하지 않는다.

## 코드 체계·명명 규칙

- **엔터티 코드**: `ENT-<순번 3자리>` — 본 문서의 목록이 정본이다.
- **물리 테이블명**: `tbl_<도메인>_<대상>` 소문자 snake_case. PostgreSQL 은 따옴표 없는 식별자를 소문자로 접으므로 대문자 표기를 쓰지 않는다.
- **컬럼명**: 소문자 snake_case. 일시 컬럼은 `_at` 접미어로 끝낸다.
- **인덱스명**: `idx_<테이블>_<대상 컬럼>` — 기본 키 인덱스는 PostgreSQL 이 자동 생성하므로 별도로 이름 짓지 않는다.
- **데이터 모델 코드**(`MDL-nnn`)는 [`spec-models.md`](spec-models.md) 가 갖는다.

## 엔터티 관계 요약

| 기준 엔터티 | 대상 엔터티 | 관계 유형 | 카디널리티 | 연결 값 | FK |
|---|---|---|---|---|---|
| ENT-001 | ENT-002 | 논리 참조 | 1 : 0..1 (같은 보존 창 안에서) | `tracking_key` 값 일치 | **두지 않는다** |
| ENT-001 | ENT-003 | 관계 없음 | — | — | — |
| ENT-002 | ENT-003 | 관계 없음 | — | — | — |

**물리 FK 를 하나도 두지 않는다.** 근거는 셋이다.

1. **보존 기간이 다르다** — 동의 증적은 추적 레코드가 삭제된 뒤에도 남는다(`DATA-002-02`·EXC-DATA-09). FK 를 걸면 부모 삭제 시 증적을 함께 지우거나(`CASCADE`) 추적 레코드를 지우지 못하게(`RESTRICT`) 되어 두 보관 규칙이 모두 깨진다.
2. **같은 추적 키의 증적이 둘 이상 존재할 수 있다** — 보관 기간이 지나 추적 레코드가 삭제된 뒤 같은 키가 다시 들어오면 새 레코드가 만들어지고(EXC-BIZ-04) 그 승인은 새 증적을 남긴다. 이때 앞선 증적은 아직 보존 기간 안이다. 따라서 증적의 `tracking_key` 는 유일하지 않다.
3. **지표 집계는 추적 키를 담지 않는다**(`DATA-002-03`) — 개별 연동으로 환원되지 않으므로 참조할 대상 자체가 없다.

- 양방향 추적은 값 수준으로 성립한다 — 추적 레코드에서 증적으로는 `tracking_key` 로, 증적에서 추적 레코드로는 같은 값으로 찾는다. 삭제 시점 차이 때문에 한쪽이 없을 수 있는 것이 정상 상태다.
- ON DELETE / ON UPDATE 규칙은 **해당 없음**이다(FK 미설정). 삭제는 전적으로 보관 배치(`PROC-304`)가 대상별로 수행한다.

## 엔터티 간 주요 의존관계

1. **ENT-001 이 먼저 생긴다** — 본인확인 최초 성공 시점에 만들어지며(`BIZ-002-01`), 그 이전 단계의 실패는 어떤 엔터티에도 행을 남기지 않는다(`BIZ-002-02`).
2. **ENT-002 는 ENT-001 이 있어야 생긴다** — 승인 확정은 본인확인 통과 이후에만 일어나므로 증적 생성 시점에는 항상 같은 키의 추적 레코드가 있다(`BIZ-003-04`).
3. **ENT-003 은 앞의 둘과 독립이다** — 추적 레코드 최초 생성·추적 키 미확보 실패·결과 확정이라는 **사건**에만 반응하고 행 참조가 없다(`BIZ-005-02`·`BIZ-005-04`).
4. **삭제 순서 제약이 없다** — FK 가 없으므로 보관 배치는 대상별로 독립 삭제하며 순서를 지키지 않아도 된다(`DATA-002-04` 멱등).

## 인덱스 전략

조회 패턴은 둘뿐이다 — **추적 키 단건 조회**와 **보관 기간 경과분 범위 조회**. 두 패턴 밖의 인덱스를 만들지 않는다.

| 인덱스 | 대상 엔터티 | 대상 컬럼 | 유형 | 카디널리티 추정 | 사용 PROC |
|---|---|---|---|---|---|
| 기본 키 | ENT-001 | `tracking_key` | UNIQUE BTREE | 높음(near-unique) | PROC-102 · PROC-201 · PROC-202 · PROC-203 · PROC-301 · PROC-304 |
| `idx_interlock_tracking_result_confirmed_at` | ENT-001 | `result_confirmed_at` (부분 — NOT NULL 행만) | BTREE | 높음(시각) | PROC-304 |
| `idx_interlock_tracking_created_at` | ENT-001 | `created_at` | BTREE | 높음(시각) | PROC-304 |
| `idx_consent_proof_consented_at` | ENT-002 | `consented_at` | BTREE | 높음(시각) | PROC-304 |
| 기본 키 | ENT-003 | `metric_date` | UNIQUE BTREE | 높음(일자당 1행) | PROC-303 |

- **인덱스 신설 기준**: 조건절·정렬·조인에 그 컬럼을 쓰는 PROC 가 1개 이상 실재해야 한다. 위 5개는 모두 충족하며, **사용 PROC 0건인 인덱스는 두지 않는다** — 그래서 ENT-002 의 `tracking_key` 에는 인덱스를 두지 않았다(증적을 추적 키로 조회하는 PROC 가 없다. 사후 입증은 저장분 직접 확인이다).
- **추적 레코드 삭제는 두 기준을 각각의 인덱스로 분리 산정**한다(`DATA-002-01`). 하나의 조건절에 두 기준을 `OR` 로 묶으면 계획이 흔들리므로, 기준별로 대상을 뽑아 합집합을 지운다. 두 번 실행해도 결과가 같아 멱등성이 유지된다(`DATA-002-04`).
- **지표 집계에는 삭제용 인덱스가 없다** — 삭제 대상이 아니기 때문이다(`DATA-002-03`). 지표 산출의 기간 조회도 기본 키가 그대로 처리한다.
- 데이터 규모 전제: 성과 지표의 요청 건수 규모([`../../prd/PRD.md`](../../prd/PRD.md) §성과 지표 — **수치는 그 문서를 참조한다**)에서 추적 레코드는 최대 보관 상한 기간분만 남고 지표 집계는 하루 1행이다. 파티셔닝·특수 인덱스가 필요한 규모가 아니므로 도입하지 않는다.

## 확정 사항 (선행 도메인이 데이터로 위임한 판단)

| 항목 | 확정값 | 근거·정본 |
|---|---|---|
| 연동 추적 키 컬럼 길이 | **`VARCHAR(255)`**(문자 수 기준) — 정책이 잠정 확정한 1~255자와 **같은 값**이라 정책 개정이 필요하지 않다 | `DATA-004-03`·EXC-DATA-10. X 평문 상한 안에서 넉넉하며 PostgreSQL `varchar(n)` 은 문자 수 기준이라 정책 표현과 정확히 일치한다 |
| 동의 항목 버전 식별자 생성 방식 | **상수 값의 결정적 해시** — SHA-256 다이제스트의 소문자 16진수 64자. 산출 규칙은 [`data_ENT-002.md`](data_ENT-002.md) §버전 식별자 산출 규칙 | `DATA-003-03` 이 자동으로 지켜진다. 수동 채번은 사람이 갱신을 잊으면 같은 식별자가 다른 내용을 가리키는 위반이 조용히 발생한다 |
| 지표 집계의 일자 경계 시간대 | **`Asia/Seoul`(UTC+09:00) 고정** | 지표를 읽는 주체가 국내 운영 주체이고 목표가 월 단위 사람 해석 단위다. 한국은 서머타임이 없어 경계가 흔들리지 않는다. 저장 일시가 모두 `TIMESTAMPTZ` 라 변환이 결정적이다 |
| 지표 카운터 구성 (진입 게이트 🟡 G-05) | **요청 수 1 + 결과 구분 4종 각각 1 = 5개 카운터 분리 저장.** 파생 비율 미저장 | `BIZ-005-01`. 두 성공률 정의(전체 / 사용자 거부 제외)를 **모두 산출 가능**하게 한다. 어느 정의를 목표치 판정에 쓸지는 **담당자 이월**이며 본 사양은 정하지 않는다(`BIZ-005-06`) |
| 처리 성공 여부의 저장 여부 | **저장하지 않는다** — 결과 구분에서 결정되는 파생값이라 읽는 시점에 산출한다 | 정보 손실이 없다(`SUCCESS` = 성공 / 나머지 3종 = 실패). 두 컬럼이 어긋날 여지를 없앤다 |

## 잠정값·범위 밖의 취급

- **잠정값** — `<CONSENT_PROOF_RETENTION_MONTHS>` 등 잠정 상수는 **참조만** 하고 수치를 본문에 복제하지 않는다. 확정은 상수 값 교체로 끝나며 본 사양은 개정되지 않는다(EXC-DATA-06). 잠정 상태의 운영 배포 금지는 `OPS-001-03` 이 갖는다.
- **성과 지표 목표치** — 상수표에 없는 값이라 [`../../prd/PRD.md`](../../prd/PRD.md) §성과 지표를 참조하고 수치를 옮겨 적지 않는다.
- **범위 밖** — 관리자·구성·세션·감사 로그·보안 이벤트·배치 실행 이력은 저장 대상이 아니므로 엔터티를 두지 않는다. [`../../prd/ia/IA.md`](../../prd/ia/IA.md) §사용하지 않는 코드에 실린 코드로는 어떤 엔터티·모델도 만들지 않는다.
