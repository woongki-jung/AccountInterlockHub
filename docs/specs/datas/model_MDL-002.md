# 동의 증적 데이터 모델 정의

정본 목록은 [`spec-models.md`](spec-models.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **모델 목적**: 승인 확정 시점에 남기는 동의 사실의 응용 계층 표현이다. 개인정보를 담지 않으면서도 **어느 시점의 어떤 항목에 동의했는지**를 사후에 그대로 재현할 수 있어야 한다.
- **관련 서비스**: `SVC-015`(기록 주체) · `SVC-003`(유일한 기록 계기) · `SVC-017`(삭제 대상)
- **관련 법규**: 개인정보 보호법 제17조(개인정보의 제공) — 제3자 제공 동의의 입증 수단이다(`DATA-003`).

## MDL-002 동의 증적

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 동의 증적 |
| 분류 | 공통(COM) |
| 사용 서비스 | SVC-003 · SVC-015 · SVC-017 |
| 매핑 엔터티 | [`ENT-002`](data_ENT-002.md) |
| 사용 PROC | PROC-103 · PROC-302 · PROC-304 |
| 용도 | 도메인 모델 |
| 관련 IA 항목 | `BAT-05` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| consentProofId | string(UUID) | Y | 생성 시 발급 | UUID 형식 | - | 증적 식별자(대리 키) |
| trackingKey | string | Y | - | 1자 이상 255자 이하, 공백만 불가 | - | 연동 추적 키. 증적과 사용자를 잇는 유일한 값이다 |
| consentedAt | datetime | Y | 승인 확정 시각 | - | - | 동의 일시. 보존 기간 기산점이며 생성 시각과 같다 |
| consentVersion | string(64) | Y | - | 소문자 16진수 64자 — `^[0-9a-f]{64}$` | - | 동의 항목 버전 식별자([`data_ENT-002.md`](data_ENT-002.md) §버전 식별자 산출 규칙) |
| consentSnapshot | object | Y | - | `notice`(문자열, 빈 값 허용) · `items`(항목 배열, 항목 코드 오름차순) | - | 그 시점 노출 내용의 스냅샷 |
| consentSnapshot.notice | string | Y | 빈 문자열 | 허용 형태는 상수표가 정본 | - | 그 시점 동의 안내 문구 원문 |
| consentSnapshot.items | ConsentItem[] | Y | - | 각 항목은 [`MDL-008`](model_MDL-007-010.md) 의 항목 구조와 같다 | - | 그 시점 동의 항목 정의 |
| agreedItemCodes | string[] | Y | - | 각 코드가 `consentSnapshot.items` 의 항목 코드에 존재해야 한다 | - | 사용자가 실제로 동의한 항목 코드. 선택 항목의 동의 여부도 여기서 드러난다 |

- **개인정보를 담을 속성이 없다**(`DATA-003-02`) — 추적 키 외의 사용자 식별 값을 넣을 자리를 만들지 않는다.
- **생성 후 불변**이다 — 어떤 PROC 도 이 모델을 갱신하지 않는다. 사후 입증 수단이 나중에 바뀌면 증적으로 성립하지 않는다.

### 엔터티 매핑 (PROC 데이터 변환 흐름과 정합)

| 모델 속성 | 엔터티(ENT) | 엔터티 속성 | 변환 지점 | 변환 규칙 |
|-----------|-------------|-------------|-----------|-----------|
| consentProofId | ENT-002 | consent_proof_id | ENT→도메인 | 직접 매핑(INSERT 시 데이터베이스 기본값) |
| trackingKey | ENT-002 | tracking_key | 도메인→ENT / ENT→도메인 | 직접 매핑(무변형 — `DATA-004-01`) |
| consentedAt | ENT-002 | consented_at | 도메인→ENT / ENT→도메인 | 직접 매핑 |
| consentVersion | ENT-002 | consent_version | 도메인→ENT / ENT→도메인 | 직접 매핑. 값은 기동 시 산출된 것을 가져다 쓴다 |
| consentSnapshot | ENT-002 | consent_snapshot | 도메인→ENT / ENT→도메인 | JSON 직렬화·역직렬화. 항목은 항목 코드 오름차순 |
| agreedItemCodes | ENT-002 | agreed_item_codes | 도메인→ENT / ENT→도메인 | JSON 배열 직렬화·역직렬화 |

- `MDL-007`(동의·승인 제출)의 동의 항목 목록이 `요청→도메인` 지점에서 `agreedItemCodes` 로, `MDL-008`(동의 항목 구성)이 같은 지점에서 `consentVersion`·`consentSnapshot` 으로 들어온다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-015 | 동의 증적 기록 | 도메인 | PROC-302 | 승인 확정 시점에만 1건 생성(`DATA-003-04`) |
| SVC-003 | 동의·승인 | 도메인 | PROC-103 · PROC-302 | 승인 확정과 같은 처리 경계에서 만들어진다 |
| SVC-017 | 보관정책 배치 | 도메인 | PROC-304 | 동의 일시 기산으로 삭제(`DATA-002-02`) |

### 구현 가이드

- **스냅샷은 화면이 실제로 노출한 내용과 같아야 한다**(`DATA-003-05`) — 화면이 문구를 가공하면 증적과 실제 노출이 어긋난다. 노출과 스냅샷이 같은 구성 모델(`MDL-008`)에서 나오게 한다.
- **버전 식별자를 증적 기록 시점에 다시 계산하지 않는다** — 기동 시 산출된 값을 그대로 쓴다. 재계산은 배포 중 값이 흔들릴 여지를 만든다.
- `agreedItemCodes` 와 스냅샷 항목 코드의 정합은 응용 계층에서 확인한다([`data_ENT-002.md`](data_ENT-002.md) §구현 가이드).
- 이 모델을 응답·화면에 싣는 경로가 없다 — 조회 API·화면이 정의되지 않았으므로 직렬화 대상은 저장뿐이다. 조회 요구가 생기면 요구사항으로 되돌려 판단한다(EXC-OPS-08).
- 타입 정의 시 스냅샷과 동의 목록을 읽기 전용 구조로 둔다. 생성 후 불변이라는 성질을 타입으로 강제하면 갱신 코드가 생기지 않는다.
