# 서버 대면 API 데이터 모델 정의 (MDL-011 ~ MDL-015)

정본 목록은 [`spec-models.md`](spec-models.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **모델 목적**: 발송처·수신처가 허브와 주고받는 서버 대면 API 의 요청·응답 모델이다. 넷 중 셋(처리상태 확인·연동 완료 확인·완료 콜백)은 **추적 키 하나만** 입력으로 받고, 자가진단은 암호값 쌍과 생년월일을 받는다. 다섯 모델 모두 저장되지 않는다.
- **관련 서비스**: `SVC-010`(처리상태 확인) · `SVC-011`(연동 완료 확인) · `SVC-012`(완료 콜백 수신) · `SVC-013`(연동 규약 자가진단)
- **인증이 없다** — 어떤 모델에도 인증 자격 속성을 두지 않는다(`AUTH-001-03`). 자격이 담긴 요청이 와도 검증하지 않고 무시한다.

## MDL-011 추적 키 입력

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 추적 키 입력 |
| 분류 | 외부 연동(EXT) |
| 사용 서비스 | SVC-010 · SVC-011 · SVC-012 |
| 매핑 엔터티 | **없음(비저장)** — ENT-001 조회 조건으로만 쓰인다 |
| 사용 PROC | PROC-201 · PROC-202 · PROC-203 |
| 용도 | 요청 모델 |
| 관련 IA 항목 | `API-01` · `API-02` · `API-03` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| trackingKey | string | Y | - | 1자 이상 255자 이하, 빈 값·공백만 불가(`DATA-004-03` → 위반 시 400 `EX-DATA-002`) | - | 조회·통지 대상 연동 추적 키 |

- 세 API 가 **같은 형식 기준**을 쓴다. API 마다 다른 상한을 두지 않는다.
- 통지 요청에 추적 키 외의 값이 실려 와도 저장하지 않는다(`SVC-012` 구현 가이드) — 이 모델에 담을 속성을 만들지 않는 것이 그 보장이다.

### 엔터티 매핑

**매핑 엔터티 없음** — 입력은 저장되지 않고 ENT-001 의 기본 키 조회 조건으로만 쓰인다. 적용 지점은 `요청→도메인` 하나이며, 값을 **파싱·정규화하지 않는다**(`DATA-004-01`).

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-010 | 처리상태 확인 | 요청 | PROC-201 | 대상 없음 시 404 `EX-DATA-001` |
| SVC-011 | 연동 완료 확인 | 요청 | PROC-202 | 위와 같다 |
| SVC-012 | 완료 콜백 수신 | 요청 | PROC-203 | 레코드가 없으면 새로 만들지 않는다 |

### 구현 가이드

- 형식 검증에서 **길이는 문자 수 기준**으로 센다. 저장 컬럼도 문자 수 기준이라 두 판정이 어긋나지 않는다.
- 삭제된 레코드와 미진입을 구별하지 않는다(`DATA-002-05`) — 이 모델의 처리 결과가 두 상태를 합친 하나의 응답으로 이어진다.

## MDL-012 처리상태 확인 응답

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 처리상태 확인 응답 |
| 분류 | 외부 연동(EXT) |
| 사용 서비스 | SVC-010 |
| 매핑 엔터티 | **없음(비저장)** — [`ENT-001`](data_ENT-001.md) 에서 파생 |
| 사용 PROC | PROC-201 |
| 용도 | 응답 모델 |
| 관련 IA 항목 | `API-01` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| trackingKey | string | Y | - | 입력값과 같아야 한다 | - | 입력 추적 키를 **변형 없이** 그대로 되돌린다(`DATA-004-01`) |
| isSuccess | boolean \| null | N | null | 결과 미확정이면 null | - | 처리 성공 여부 |
| resultCode | string \| null | N | null | 결과 구분 4종 중 하나 또는 null(`BIZ-001-01`) | - | 결과 구분. 값 변환·별칭을 만들지 않는다(`BIZ-001-03`) |
| isResultConfirmed | boolean | Y | false | - | - | 결과 확인 여부 |
| resultAt | datetime \| null | N | null | - | - | 처리 일시 |
| resultConfirmedAt | datetime \| null | N | null | - | - | 결과 확인 일시 |

- **암호값·복호화 원문·생년월일을 담지 않는다**(`DATA-001-04`) — 담을 속성이 없다.
- 응답에 담기는 값의 범위는 개발사양이 정한 것과 같다([`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §4).

### 엔터티 매핑

| 모델 속성 | 엔터티(ENT) | 엔터티 속성 | 변환 지점 | 변환 규칙 |
|-----------|-------------|-------------|-----------|-----------|
| trackingKey | ENT-001 | tracking_key | ENT→도메인 / 도메인→응답 | 직접 매핑(무변형) |
| isSuccess | ENT-001 | result_code | ENT→도메인 / 도메인→응답 | `result_code = 'SUCCESS'` 로 산출. NULL 이면 null |
| resultCode | ENT-001 | result_code | ENT→도메인 / 도메인→응답 | 직접 매핑 |
| isResultConfirmed | ENT-001 | result_confirmed_at | ENT→도메인 / 도메인→응답 | `result_confirmed_at IS NOT NULL` 로 산출 |
| resultAt | ENT-001 | result_at | ENT→도메인 / 도메인→응답 | 직접 매핑 |
| resultConfirmedAt | ENT-001 | result_confirmed_at | ENT→도메인 / 도메인→응답 | 직접 매핑 |

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-010 | 처리상태 확인 | 응답 | PROC-201 | 응답 구성과 결과 확인 표시를 같은 처리 경계에 둔다 |

### 구현 가이드

- **응답 구성과 결과 확인 표시를 같은 처리 경계에 둔다** — 응답은 갔는데 표시가 남지 않는 상태가 생기지 않게 한다. 이 표시가 보관 기간 기산을 시작시킨다(`DATA-002-01` ①).
- 결과 확인 표시를 할지의 판단 기준("결과를 담아 응답했는가")은 기능·API 도메인이 확정한다(`SVC-010` 예외 사항). 데이터 모델은 두 경우를 모두 표현할 수 있게 열어 둔다.
- 오류 응답 코드 집합에 401·403 을 넣지 않는다(`AUTH-001-03`).

## MDL-013 연동 완료 확인 응답

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 연동 완료 확인 응답 |
| 분류 | 외부 연동(EXT) |
| 사용 서비스 | SVC-011 · SVC-012 |
| 매핑 엔터티 | **없음(비저장)** — [`ENT-001`](data_ENT-001.md) 에서 파생 |
| 사용 PROC | PROC-202 · PROC-203 |
| 용도 | 응답 모델 |
| 관련 IA 항목 | `API-02` · `API-03` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| trackingKey | string | Y | - | 입력값과 같아야 한다 | - | 입력 추적 키를 변형 없이 되돌린다 |
| isCallbackReceived | boolean | Y | false | - | - | 수신처 완료 콜백 수신 여부 — 수신처 처리완료 판정의 **유일한 근거** |
| callbackReceivedAt | datetime \| null | N | null | 미수신이면 null | - | 콜백 일시 |

- **결과 구분을 담지 않는다** — 허브의 처리 결과는 [`MDL-012`](#mdl-012-처리상태-확인-응답) 가 답한다. 두 응답을 합치면 발송처가 판단 대상을 혼동한다.

### 엔터티 매핑

| 모델 속성 | 엔터티(ENT) | 엔터티 속성 | 변환 지점 | 변환 규칙 |
|-----------|-------------|-------------|-----------|-----------|
| trackingKey | ENT-001 | tracking_key | ENT→도메인 / 도메인→응답 | 직접 매핑(무변형) |
| isCallbackReceived | ENT-001 | callback_received_at | ENT→도메인 / 도메인→응답 | `callback_received_at IS NOT NULL` 로 산출 |
| callbackReceivedAt | ENT-001 | callback_received_at | ENT→도메인 / 도메인→응답 | 직접 매핑 |

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-011 | 연동 완료 확인 | 응답 | PROC-202 | 조회 처리에서 레코드를 갱신하지 않는다 |
| SVC-012 | 완료 콜백 수신 | 응답 | PROC-203 | **기록 직후 상태 에코** — 기능·API 가 이 모델의 재사용으로 확정했다(새 모델 미신설). `isCallbackReceived` 는 항상 `true` |

- **두 서비스가 같은 형상을 쓴다** — 완료 콜백 API 의 응답은 통지 직후의 상태를 그대로 되돌려 주는 자리이므로 전용 모델을 만들지 않는다([`../functions/spec-functions-api-server.md`](../functions/spec-functions-api-server.md) §완료 콜백 API §응답 형상 확정).

### 구현 가이드

- 판정은 콜백 수신 여부 하나만 본다. 결과 구분·처리 성공 여부를 함께 보고 판단하지 않는다.
- **연동 완료 확인 조회는 레코드를 갱신하지 않는다** — 보관 기간 기산을 시작시키는 것은 처리상태 확인뿐이다(`SVC-011` F-006). 완료 콜백 수신은 콜백 일시를 기록한 **뒤** 이 모델로 응답하며, 중복 통지에도 최초 수신 일시를 그대로 돌려준다(BR-012 멱등).
- 전달이 실패한 연동에도 응답할 수 있다. 그때는 콜백이 올 수 없으므로 (완료 확인 조회에서) 항상 미수신으로 답한다.

## MDL-014 자가진단 요청

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 자가진단 요청 |
| 분류 | 외부 연동(EXT) |
| 사용 서비스 | SVC-013 |
| 매핑 엔터티 | **없음(비저장)** |
| 사용 PROC | PROC-204 |
| 용도 | 요청 모델 |
| 관련 IA 항목 | `API-04` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| encX | string | Y | - | [`MDL-004`](model_MDL-004-006.md) 와 같은 기준 | **로그·응답·오류 메시지에 담지 않는다** | 발송처가 만든 암호값 |
| encY | string | Y | - | 위와 같다 | 위와 같다 | 발송처가 만든 암호값 |
| birthDate | string(6) | Y | - | [`MDL-006`](model_MDL-004-006.md) 와 같은 기준(`^\d{6}$`) | 위와 같다 | 판정에 쓸 생년월일 |

- 셋 중 하나라도 **없으면** 판정을 수행하지 않는다(`SEC-003-04` → 400 `EX-SEC-003`). **형식 위반은 다른 코드가 맡는다** — 생년월일 형식은 `AUTH-002-02`(400 `EX-AUTH-001`), 암호값 구조는 판정이 수행된 결과이므로 200 부적합 사유 `EX-SEC-001`(`SEC-002-02`)이다.
- 발송처가 **이미 아는 값**만 입력된다 — 자기가 만든 암호값과 자기가 아는 생년월일이다.

### 엔터티 매핑

**매핑 엔터티 없음** — 자가진단은 연동이 아니므로 추적 레코드·동의 증적·지표 집계 **어느 것도 만들지 않는다**(`SEC-003-03`). `요청→도메인` 지점만 존재한다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-013 | 연동 규약 자가진단 | 요청 | PROC-204 | 비공개 경로에서만 받는다(`SEC-003-02`) |

### 구현 가이드

- 판정 절차는 본인확인·연동 실행과 **같은 절차를 공유**한다. 경로마다 다른 판정을 쓰면 자가진단이 통과한 값이 연동에서 실패한다.
- 경로 값(`<SELFCHECK_PATH>`)을 이 모델에 담지 않는다 — 라우팅 설정 값이며 요청 본문의 일부가 아니다.
- **운영 환경에도 노출한다 — 담당자 확인 대기 항목이며 기본안을 적용했다**(PRD §미결·확인 필요 ⑧).

## MDL-015 자가진단 응답

### 기본 정보

| 항목 | 내용 |
|------|------|
| 모델명 | 자가진단 응답 |
| 분류 | 외부 연동(EXT) |
| 사용 서비스 | SVC-013 |
| 매핑 엔터티 | **없음(비저장)** |
| 사용 PROC | PROC-204 |
| 용도 | 응답 모델 |
| 관련 IA 항목 | `API-04` |

### 속성 정의

| 속성명 | 데이터 타입 | 필수 | 기본값 | 유효성 규칙 | 마스킹 규칙 | 설명 |
|--------|-----------|------|--------|-------------|-------------|------|
| isConform | boolean | Y | - | - | - | 규약 적합 판정 결과(BR-013) |
| reasonCode | string \| null | N | null | 정책 예외 코드 카탈로그의 값만 쓴다. 적합이면 null | - | 부적합 사유 코드. 라이브러리 오류 사유 코드와 **같은 값**이다 |
| protocolVersion | string | Y | - | `<MAJOR>.<MINOR>` 문자열(`SEC-001-11`) | - | 허브의 규약 버전. 발송처가 라이브러리 상수와 대조한다(BR-017) |

- **복호화 원문·키·중간 값을 담지 않는다**(`SEC-003-03`·`SEC-002-05`·`DATA-001-04`) — 담을 속성이 없다.
- **판정 실패는 결과 구분이 아니다** — `SUCCESS`·`DECRYPT_FAILED` 같은 값을 만들지 않는다(EXC-BIZ-02).
- 새 예외 코드를 만들지 않는다 — 정책 카탈로그를 참조만 한다.

### 엔터티 매핑

**매핑 엔터티 없음** — 자가진단 호출은 어떤 기록도 남기지 않는다(`SEC-003-03`). 어느 카운터에도 계수하지 않는다(EXC-BIZ-11). `도메인→응답` 지점만 존재한다.

### 사용처

| SVC 코드 | 기능 | 용도 (요청/응답/도메인) | 사용 PROC | 비고 |
|----------|------|------------------------|----------|------|
| SVC-013 | 연동 규약 자가진단 | 응답 | PROC-204 | 판정 결과·사유 코드·규약 버전만 담는다 |

### 구현 가이드

- 판정 단계 번호는 내부 실패 사유로 유지하되 **응답에는 사유 코드만** 싣는다(`SEC-002-05`).
- 부적합 판정의 응답 형태(HTTP 상태·필드 구성)는 기능·API 도메인이 확정한다. 본 모델이 정하는 것은 담기는 값의 범위다.
- 규약 버전을 빠뜨리면 발송처의 호환 판정 근거가 사라진다(`SEC-001-11`).
