# 데이터 모델 정의서 (목록)

AccountInterlockHub 응용 계층 데이터 모델(DTO·도메인 모델)의 단일 출처다. DB 영속화 구조는 [`spec-datas.md`](spec-datas.md), 준수 규칙은 [`../policies/spec-policies.md`](../policies/spec-policies.md), 서비스 시나리오는 [`../services/spec-services.md`](../services/spec-services.md), 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md) 를 따른다.

본 문서는 **설계 원칙·분류 기준·모델 목록**을 담고, 속성 수준 정의는 개별 `model_*.md` 가 갖는다.

## 데이터 모델 설계 원칙

1. **ENT 와 MDL 의 책임을 나눈다** — ENT 는 저장 구조, MDL 은 응용 계층이 주고받는 값이다. **MDL 22종 중 저장되는 것은 셋뿐**이고(`MDL-001`~`MDL-003`) 나머지 19종은 요청 처리 중 메모리에만 존재한다(`DATA-001-01`·`DATA-001-03`).
2. **비저장 모델은 요청 처리가 끝나면 사라진다** — 암호값·복호화 원문·생년월일·발송처키를 담는 모델은 어떤 저장소·세션·캐시에도 넣지 않는다(`DATA-001-02`).
3. **마스킹은 모델이 책임진다** — 금지 값을 담는 모델에는 "로그·오류 메시지·응답 본문·화면에 담지 않는다"를 마스킹 규칙으로 명시한다(`DATA-001-04`·`SEC-002-05`).
4. **값 체계를 새로 만들지 않는다** — 결과 구분은 정책 열거형 4종(`BIZ-001-01`), 예외 코드는 [`../policies/spec-policies.md`](../policies/spec-policies.md) §예외(EX) 코드 카탈로그를 **참조만** 한다(코드 개수·구성은 정책이 단일 출처이므로 본 문서에 옮겨 적지 않는다). 별칭·부분집합·확장을 만들지 않는다(`BIZ-001-03`).
5. **상수 값을 복제하지 않는다** — 상수에서 오는 모델은 플레이스홀더로만 참조한다(`OPS-001-04`).
6. **속성명은 camelCase** 로 통일한다(DB 컬럼은 snake_case — [`spec-datas.md`](spec-datas.md) §코드 체계·명명 규칙).

## 분류 기준

모델은 셋 중 하나로 분류하며, **EXT 가 COM·SVC 보다 우선**한다 — 외부 계약에 묶인 형상은 내부 공유 여부보다 강한 제약이기 때문이다.

- **외부 연동(EXT)** — 발송처 라이브러리·수신처·서버 대면 API 호출자와 경계를 넘어 오가는 모델. 형상을 허브가 임의로 바꿀 수 없다.
- **공통(COM)** — 허브 내부에서 2개 이상의 서비스가 공유하는 모델.
- **서비스(SVC)** — 특정 서비스 내부에서만 쓰는 모델.

## 코드 체계

- **모델 코드**: `MDL-<순번 3자리>` — 본 문서의 목록이 정본이다. 서비스 도메인이 예약 채번한 `MDL-001`~`MDL-022` 의 **의미를 그대로 이어받아 확정**했다([`../services/spec-services-codes.md`](../services/spec-services-codes.md) §데이터 모델(MDL) 예약 채번).
- **예약 대비 변경**: 통합 0건 · 폐기 0건 · 추가 0건. 재배치도 없다 — 같은 코드가 같은 의미를 유지한다.
- 개별 파일은 `model_<MDL 코드>.md` 가 원칙이며, 밀접하게 묶이는 소형 모델은 코드 구간 파일 하나로 묶었다(§모델 목록의 정의 문서 열이 실제 경로다).

## 엔터티 매핑·변환 지점 규약

각 모델의 **엔터티 매핑** 표는 프로세스 도메인의 데이터 변환 흐름 6 지점(FE→요청 / 요청→도메인 / 도메인→ENT / ENT→도메인 / 도메인→응답 / 응답→FE)과 1:1 정합해야 한다.

- **저장 모델 3종**(`MDL-001`~`MDL-003`)만 `도메인→ENT`·`ENT→도메인` 지점을 갖는다. 나머지 19종은 매핑 엔터티가 없으므로 그 두 지점이 존재하지 않는다.
- **파생 속성**은 `ENT→도메인` 지점에서 산출한다 — 처리 성공 여부·결과 확인 여부·완료 콜백 수신 여부·결과 확정 여부가 여기에 해당하며, 컬럼으로 저장되지 않는다([`spec-datas.md`](spec-datas.md) §데이터 설계 원칙 6).
- **응답에 실리는 추적 키는 입력값을 변형 없이 그대로 되돌린다**(`DATA-004-01`) — 어떤 지점에서도 정규화·파싱하지 않는다.

## 모델을 두지 않는 것

아래는 의도적으로 모델을 만들지 않은 항목이다. 필요해지면 요구사항으로 되돌려 판단한다.

1. **완료 콜백 API 전용 응답 모델** — 기능·API 도메인이 **[`MDL-013`](model_MDL-011-015.md) 재사용**으로 확정했다(새 모델을 만들지 않는다). 수신 결과만 돌려주면 되는 자리라 같은 형상으로 충분하다([`../functions/spec-functions-api-server.md`](../functions/spec-functions-api-server.md) §완료 콜백 API).
2. **오류 응답 엔벨로프** — 예외 코드는 정책이 정본이고 응답 형태는 기능·API 도메인이 확정한다. 데이터 도메인이 형상을 선점하지 않는다.
3. **세션·사용자·구성·감사·실행 이력 모델** — 대응하는 저장 대상이 없다(`DATA-001-01`·`DATA-001-05`·`OPS-003-01`·`OPS-003-04`).
4. **성공률 등 파생 지표 모델** — 카운터에서 읽는 시점에 계산한다. 정의가 담당자 이월 상태이므로 값을 고정하는 모델을 만들지 않는다(`BIZ-005-06`).

## 잠정값·범위 밖의 취급

- **잠정값** — `<RECEIVER_DELIVERY_URL>`·`<HUB_BASE_URL_PROD>`·`<HUB_BASE_URL_DEV>`·`<SELFCHECK_PATH>`·`<CONSENT_NOTICE>`·`<CONSENT_PROOF_RETENTION_MONTHS>` 는 **상수 주입으로만 참조**하고 값을 모델 정의에 복제하지 않는다(단일 출처 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수).
- **성과 지표 목표치** — [`../../prd/PRD.md`](../../prd/PRD.md) §성과 지표를 참조하고 수치를 옮겨 적지 않는다.
- **담당자 확인 대기 — 기본안 적용** — 수신처 전달 실패 후의 재시도 경로(`MDL-010`)와 자가진단 API 의 운영 환경 노출(`MDL-014`·`MDL-015`)은 PRD §미결·확인 필요 ⑦·⑧ 의 **기본안대로** 모델화했다. 다르게 정해지면 해당 모델만 개정한다.
- **범위 밖** — 링크 만료(TTL)·1회성 사용·발송처 서명 검증·요청 제한에 대응하는 속성을 어떤 모델에도 두지 않는다(`OPS-002-05`).
