# 횡단 관심사 기능 정의 (FN-014 ~ FN-015)

정본 목록은 [`spec-functions.md`](spec-functions.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **기능 목적**: 모든 표면이 같은 모양으로 실패를 알리고(**오류 응답 엔벨로프**), 어떤 경로로도 금지 값이 새어 나가지 않게 한다(**민감값 제거**). 이 제품은 감사 로그 저장소를 두지 않으므로(`OPS-003-01`) 횡단 관심사는 이 둘뿐이다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §시스템 제약사항 — "**데이터 원칙**: 허브는 사용자 정보·복호화 원문(X)을 지속 보관하지 않는다."
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §미결 — "각 접점의 구체 요청·응답 필드, 오류 규약 … 은 spec 단계에서 확정한다."
- 데이터 도메인이 **오류 응답 엔벨로프의 형상 확정을 기능·API 도메인에 위임**했다([`spec-models.md`](../datas/spec-models.md) §모델을 두지 않는 것 2). 따라서 엔벨로프는 MDL 을 두지 않고 본 문서가 정본이다.

### 시그니처

```
function FN-014 (
  code: string,             // 정책 예외 코드 카탈로그의 EX 코드·필수
  details: FieldReason[],   // 선택·기본값 빈 배열. { field, reason } 목록
): ErrorResponse            // { code, message, details? }
  throws 없음               // 오류 응답 구성 중에는 새 예외를 만들지 않는다
```

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 제약 | 설명 |
|------|--------|------------|------|------|------|
| 입력 | code | string | Y | [`spec-policies.md`](../policies/spec-policies.md) §예외(EX) 코드 카탈로그의 값 | 카탈로그 밖 값은 `EX-OPS-002` 로 대체한다 |
| 입력 | details | FieldReason[] | N | 각 항목 `{ field: string, reason: 'REQUIRED'\|'FORMAT'\|'LENGTH' }` | 입력 형식 위반의 필드별 사유. **값 자체는 담지 않는다** |
| 출력 | code | string | - | 입력과 같다 | 호출측이 분기에 쓴다 |
| 출력 | message | string | - | 한 문장 | §오류 메시지 기본값 표 |
| 출력 | details | FieldReason[] | - | 비어 있으면 필드를 생략한다 | 진단 보조 |

### 처리 흐름 (의사코드)

```
1. 코드 유효성 판정 — 정책 예외 코드 카탈로그 (validate)
   if (code 가 카탈로그에 없다)   code = 'EX-OPS-002'      // 인터페이스 수준의 마지막 방어

2. 메시지 선택 — §오류 메시지 기본값 (transform)
   message = MESSAGE_OF(code)

3. 상세 정제 — FN-015 · POL SEC-002-05 · DATA-001-04 (mask)
   safeDetails = []
   for each d in details:
       safeDetails += { field: d.field, reason: d.reason }   // 값·길이·내부 사유는 버린다

4. 본문 구성
   body = { code: code, message: message }
   if (LENGTH(safeDetails) > 0)   body.details = safeDetails

5. 반환 (HTTP 상태는 카탈로그가 정한 값을 그대로 쓴다)
   return body
```

| 항목 | 내용 |
|------|------|
| 엔드포인트 | 해당 없음 — 모든 접점의 실패 응답 본문을 만든다 |
| HTTP 메서드 | 해당 없음 |
| 인증 요구 | `Public` (인증을 두지 않는다 — `AUTH-001-03`) |
| 요청 DTO | 해당 없음 |
| 응답 DTO (200) | 해당 없음 |

### 오류 메시지 기본값

응답 본문 `message` 의 기본값이다. **화면이 사용자에게 노출하는 문구·표시 형식은 화면 도메인이 정한다** — 화면은 이 값을 그대로 쓰거나 자기 문구로 대체할 수 있다.

| EX 코드 | HTTP | message 기본값 |
|---|---|---|
| `EX-AUTH-001` | 400 | 생년월일을 여섯 자리 숫자로 입력해 주세요. |
| `EX-AUTH-002` | 400 | 입력하신 생년월일로 확인되지 않았습니다. 다시 확인해 주세요. |
| `EX-SEC-001` | 400 | 연동 링크가 올바르지 않습니다. |
| `EX-SEC-002` | 400 | 연동 요청 정보가 규약과 맞지 않습니다. |
| `EX-SEC-003` | 400 | 요청 값이 올바르지 않습니다. |
| `EX-SEC-004` | 400 | 전달 정보가 허용 크기를 넘었습니다. |
| `EX-BIZ-001` | 400 | 필수 동의 항목에 모두 동의해 주세요. |
| `EX-BIZ-002` | 502 | 연동 대상 서비스에 전달하지 못했습니다. |
| `EX-BIZ-003` | 500 | 처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. |
| `EX-DATA-001` | 404 | 해당 연동 추적 키로 진입한 요청이 없습니다. |
| `EX-DATA-002` | 400 | 연동 추적 키 형식이 올바르지 않습니다. |
| `EX-OPS-002` | 500 | 처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요. |

- **표의 문구를 사용자 표면 기준으로 다시 쓰지 않는다 (확정).** `EX-SEC-002` 의 "규약", `EX-SEC-004` 의 "전달 정보"는 발송처·허브 사이의 개념이라 사용자에게 설명력이 낮다. 그럼에도 여기서 바꾸지 않는 근거는 셋이다 — ⑴ 이 표는 **응답 본문 `message` 의 기본값**이고 사용자가 보는 문구의 정본은 화면 도메인이다(위 머리말) ⑵ 두 문구는 **행동 안내를 담지 않으며**, 사용자가 할 일은 화면의 다음 안내가 전담한다([`../screens/screen_SCR-004.md`](../screens/screen_SCR-004.md) §결과 3경로 — 경로 ② 는 사유가 달라도 같은 안내로 수렴한다) ⑶ 문구를 계약 기본값에서 바꾸면 이를 인용한 기능·화면·검증 사양이 함께 흔들린다. **사용자 표면에서 다른 표현이 필요하면 화면이 자기 문구로 대체한다** — 머리말이 이미 그 경로를 열어 두었고, 대체 여부는 화면 도메인의 결정이다.
- **`EX-DATA-001`·`EX-DATA-002` 의 "연동 추적 키"는 그대로 둔다.** 이 둘은 **서버 대면 API 3종**(처리상태 확인·연동 완료 확인·완료 콜백)에서만 응답되고 사용자 표면 어디에도 나타나지 않는다([`spec-functions-api-server.md`](spec-functions-api-server.md) §공통 요청 형상 · `SCR-004` §결과 3경로의 사유 코드 4종에 없다). 발송처는 요청 속성 `trackingKey` 로 이 개념을 이미 쓴다.
- `EX-OPS-001`(필수 상수 미주입)은 **기동 중단 사유**라 HTTP 응답이 없다. 본 기능의 대상이 아니며 표준 출력으로만 알린다(`OPS-001-02`).
- **401·403 을 정의하지 않는다**(`AUTH-001-03`). 인증 자격이 담긴 요청이 와도 검증하지 않고 무시한다.
- 정의되지 않은 경로는 **본문 없는 일반 404** 로 응답한다 — 자가진단 경로만 특별해 보이지 않게 하기 위함이며, 이 응답에는 EX 코드를 담지 않는다(`SEC-003-02`).

### 구현 가이드

- **성공 응답은 감싸지 않는다.** 성공은 각 접점의 응답 모델을 본문 최상위에 그대로 싣고, 실패만 이 엔벨로프를 쓴다. 성공·실패는 HTTP 상태로 이미 갈린다([`spec-functions-api.md`](spec-functions-api.md) §공통 응답 포맷).
- **`details` 에 값을 담지 않는다.** 필드명과 사유 상수만 남긴다 — 어떤 값이 왜 틀렸는지를 되돌려 주면 반복 시도의 판정 수단이 된다(`OPS-002-03`).
- **단계 번호·내부 스택·중간 값을 담지 않는다**(`SEC-002-05`). 내부 실패 사유는 유지하되 응답에는 EX 코드만 싣는다.
- **복귀 주소(`returnUrl`)를 담지 않는다.** 엔벨로프는 위 세 필드로 닫혀 있고, 복귀 주소는 **연동 완료 결과(경로 ①)의 정상 응답에만** 실린다(`BIZ-001-06` · [`spec-functions-api-user.md`](spec-functions-api-user.md) §복귀 주소 응답 규약). 502 `EX-BIZ-002` 가 결과 경로 ③을 함께 안내한다고 해서 예외가 되지 않는다.
- 오류 응답 구성을 한 곳으로 모으면 `DATA-001-04` 를 접점마다 다시 점검하지 않아도 된다.

## FN-015 민감값 제거·기록 통제

### 기본 정보

| 항목 | 내용 |
|------|------|
| 기능명 | 민감값 제거·기록 통제 |
| 분류 | CRS |
| 사용 서비스 | 전 서비스 |
| 호출 PROC | 전 PROC |
| 연관 정책 | `DATA-001-02` · `DATA-001-04` · `SEC-002-05` · `SEC-003-02` · `SEC-003-03` · `OPS-003-03` · `DATA-004-01` |
| 참조 데이터 | [`MDL-004`](../datas/model_MDL-004-006.md) · [`MDL-005`](../datas/model_MDL-004-006.md) · [`MDL-006`](../datas/model_MDL-004-006.md) · [`MDL-016`](../datas/model_MDL-016-018.md) · [`MDL-022`](../datas/model_MDL-019-022.md) |
| 관련 IA 항목 | 공통 |

### 시그니처

```
function FN-015 (
  value: any,               // 응답 본문·로그 항목 등 내보내기 직전의 값·필수
): any                      // 금지 항목이 제거된 사본
  throws 없음
```

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 제약 | 설명 |
|------|--------|------------|------|------|------|
| 입력 | value | any | Y | 구조 제한 없음 | 응답 본문·로그 레코드·예외 메시지 컨텍스트 |
| 출력 | (사본) | any | - | 금지 항목이 제거된 상태 | 원본을 바꾸지 않는다 |

### 금지 항목 (전량 미노출)

| 금지 항목 | 근거 |
|---|---|
| `encX` · `encY` (암호값 쌍) | `DATA-001-02` · `DATA-001-04` |
| 복호화 원문 X 의 **모든 필드**(`trackingKey` 포함 여부는 아래 예외 참조) | `DATA-001-02` · `SEC-003-03` |
| 사용자가 입력한 생년월일 | `DATA-001-02` |
| 발송처키 | `DATA-001-02` |
| 정규화 키 · 초기화 벡터 · 복호화 중간 값 | `SEC-002-05` |
| 자가진단 경로 값(`<SELFCHECK_PATH>`) | `SEC-003-01` · `SEC-003-02` |
| 연동 요청 URL 전체(암호값을 포함한다) | `MDL-018` 마스킹 규칙 |

- **예외 — 연동 추적 키**: 추적 키는 금지 항목이 아니다. 불투명 문자열이며 개인정보 원문이 아니라(`DATA-004-01`) 조회·통지 응답에 **입력값 그대로** 실린다. 다만 사용자 화면·진입 응답에는 싣지 않는다(사용자가 알 필요가 없는 값이다).
- **예외 — 복귀 주소(`returnUrl`)**: 복귀 주소도 금지 항목이 아니다. 개인정보·비밀 값이 아니라 상수 `<COMPLETION_REDIRECT_URL>` 에서 온 URL 이고, **사용자 화면이 이동에 써야 하는 값**이라 **연동 완료 결과(경로 ①)의 안내 응답**에 그대로 실린다([`MDL-009`](../datas/model_MDL-007-010.md) 속성 정의 · `BIZ-001-06`). 다만 주소의 출처가 확정돼 **외부 입력이 되면**(PRD §미결·확인 필요 ⑦) 형식 검증(`https`·`http` 절대 URL)을 통과한 값만 싣는다.

### 처리 흐름 (의사코드)

```
1. 금지 항목 탐색 — POL DATA-001-04 (mask)
   targets = §금지 항목 표의 이름·경로에 해당하는 모든 속성

2. 제거 (부분 마스킹·길이 노출도 하지 않는다)
   for each t in targets:
       value 사본에서 t 를 **속성째 제거**한다
       // 앞뒤 몇 자만 남기는 부분 마스킹도 하지 않는다 —
       // 노출된 일부가 오프라인 전수대입의 탐색 공간을 좁힌다 (POL OPS-002-01)

3. 추적 키 보존 — POL DATA-004-01
   value 사본의 연동 추적 키는 변형 없이 그대로 둔다

4. 반환 (원본을 바꾸지 않는다)
   return 사본
```

### 구현 가이드

- **로그 출력 지점을 한 곳으로 모은다**(`DATA-001` 구현 가이드). 출력 지점이 흩어지면 `DATA-001-04` 를 반복 점검해야 한다.
- **금지 항목을 담는 모델에 애초에 속성을 두지 않는 것이 1차 방어**이고, 본 기능은 2차 방어다(`MDL-012`·`MDL-015` 속성 정의).
- 운영 로그는 두되(EXC-DATA-03) **요청 처리의 기술적 실패**만 남기고 금지 항목을 담지 않는다(`OPS-003-03`). 감사 로그 저장소·보안 이벤트 기록은 도입하지 않는다(`OPS-003-01`·`OPS-003-02`).
- 진입 요청 URL 자체가 암호값을 담고 있으므로, **요청 URL 을 통째로 기록하는 접근 로그를 켜지 않는다.** 필요하면 경로만 남긴다.
- 예외 메시지에도 같은 규칙을 적용한다 — 라이브러리 예외 메시지 포함([`spec-functions-lib.md`](spec-functions-lib.md) §오류 처리).
