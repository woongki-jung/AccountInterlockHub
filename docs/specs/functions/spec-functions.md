## 공통 기능 설계 원칙 및 기본 방향

1. **두 곳 이상이 쓰는 것만 공통 기능으로 만든다** — 2개 이상의 서비스에서 재사용되는 로직만 FN 으로 둔다. 단일 서비스 전용 로직은 해당 서비스와 프로세스가 갖는다(§공통 기능으로 두지 않은 것).
2. **규약을 구현하는 조각은 반드시 공유한다** — 라이브러리(암호화)와 허브(복호화)가 같은 결과를 내야 하고, 본인확인·연동 실행·자가진단이 같은 판정을 써야 한다. 판정이 갈리면 자가진단이 통과시킨 값이 연동에서 실패한다(`SEC-002` 구현 가이드).
3. **값 체계를 새로 만들지 않는다** — 결과 구분은 정책 열거형 4종(`BIZ-001-01`), 예외 코드는 정책 카탈로그를 **참조**한다. 인터페이스 수준에서 꼭 필요한 신규 예외는 정책 카탈로그에 등록한 뒤 쓴다(§신규 예외 코드).
4. **기록은 조건부 갱신으로 만든다** — 결과 확정·결과 확인·콜백 기록은 모두 "아직 비어 있을 때만 채운다"는 같은 형태다. 조회 후 응용 코드에서 판정하면 동시 요청에서 값이 덮인다.
5. **금지 값은 담을 자리를 만들지 않는다** — 모델에 속성을 두지 않는 것이 1차 방어이고 마스킹(FN-015)이 2차 방어다(`DATA-001-04`).
6. **없는 것을 만들지 않는다** — 인증 계층·요청 제한·감사 저장소·구성 API 를 두지 않는다. 부재는 누락이 아니라 결정이다(`AUTH-001`·`OPS-002`·`OPS-003`).
7. **상수 값을 복제하지 않는다** — 경로·주소·기간은 플레이스홀더로만 참조한다(`OPS-001-04`).

### 공통 기능의 반환 구조와 MDL 의 경계

FN 이 주고받는 값 중 **서비스·외부 경계를 넘는 것**만 데이터 모델(MDL)을 인용한다. 정규화 키·디코딩된 암호문·조회 분기 판정·계수 계기처럼 **요청 처리 문맥 안에서만 존재하는 계산 중간 값**은 MDL 을 두지 않고 각 기능의 입력/출력 표가 형상을 정의한다. 데이터 도메인의 MDL 은 응용 계층이 주고받는 값을 다루므로(`spec-models.md` §설계 원칙 1) 함수 내부 중간 값까지 모델로 승격시키면 저장 대상 셋과의 경계가 흐려진다.

## 공통 기능 코드 체계

- **기능 코드**: `FN-<순번 3자리>` — 본 문서의 목록이 정본이다.
- **분류**: `POL`(정책 구현) · `DAT`(데이터 처리) · `EXT`(외부 연동) · `CRS`(횡단 관심사) 중 하나.
- **예외 코드**: `EX-<그룹>-<순번 3자리>` — **정책이 정본**이며 본 도메인은 참조한다([`../policies/spec-policies.md`](../policies/spec-policies.md) §예외(EX) 코드 카탈로그).
- **프로세스 코드**: 정책·서비스가 예약한 18종(`PROC-101`~`105`·`201`~`204`·`301`~`304`·`401`~`404`·`901`)을 그대로 인용한다. **본 도메인의 추가 채번은 0건**이며, 실재 확인은 교차검증 시점이다.
- 개별 파일은 `function_<FN 코드>.md` 가 원칙이며, 밀접하게 묶이는 소형 기능은 코드 구간 파일 하나로 묶었다(§공통 기능 목록의 정의 문서 열이 실제 경로다).

### 신규 예외 코드

인터페이스 수준의 **마지막 방어** 하나를 정책 카탈로그에 등록했다.

| EX 코드 | HTTP | 의미 | 정의 규칙 |
|---|---|---|---|
| `EX-OPS-002` | 500 | 예상치 못한 내부 처리 오류 — 정책이 정의한 다른 EX 로 분류되지 않는 요청 처리의 기술적 실패 | `OPS-003-05` |

- 등록처는 [`../policies/spec-policies.md`](../policies/spec-policies.md) §예외(EX) 코드 카탈로그이며, 그 표가 EX 의 단일 출처다.
- **`EX-FN-nnn` 같은 새 그룹을 만들지 않았다.** 기존 그룹 체계를 그대로 이어 채번했다.

### 담당자 확인 대기 — 기본안 적용

- **수신처 전달 실패 후의 재시도 경로**(PRD §미결·확인 필요 ⑦) — 진입 중 즉시 재시도 + 확정 후 재연동은 발송처가 새 추적 키로 새 요청을 발행하는 **기본안**을 적용했다.
- **자가진단 API 의 운영 환경 노출**(같은 문서 ⑧) — **운영 환경에도 노출**하되 비공개 경로를 유지하는 **기본안**을 적용했다.
- 다르게 정해지면 해당 접점 정의만 개정한다.

## 공통 기능으로 두지 않은 것

아래는 **단일 서비스 전용 로직**이라 FN 으로 만들지 않았다. 각 프로세스 정의서가 자기 의사코드로 담고, 인터페이스 계약이 필요한 것은 하위 문서가 정의한다.

1. **결과 경로 선택**(`SVC-005`) — 결과 구분 → 경로 번호 대응은 `PROC-105` 안에 둔다. 대응을 여러 곳에 두면 경로가 갈린다([`MDL-009`](../datas/model_MDL-007-010.md) 구현 가이드).
2. **필수 동의 서버 재검증**(`SVC-003`) — 승인 제출 접점에서만 쓰인다.
3. **수신처 전달 호출·재시도**(`SVC-004`) — 유일한 외부 호출이며 한 서비스만 쓴다. 계약은 전달 접점 정의가 갖는다.
4. **기동 시 상수 로드·형식 검증·버전 식별자 산출**(`SVC-018`) — `PROC-901` 한 곳에서만 수행한다.
5. **보관 배치 삭제 대상 산정·삭제 수행**(`SVC-017`) — 스케줄과 수동 실행이 같은 로직을 공유하지만 서비스는 하나다.
6. **라이브러리 암호화·요청 URL 생성**(`SVC-006`·`SVC-007`) — 별도 배포 단위의 공개 계약이라 [`spec-functions-lib.md`](spec-functions-lib.md) 가 정의한다. 다만 규약 조각(FN-001·FN-002)은 허브와 **같은 규칙**을 구현한다.

## 잠정값·범위 밖의 취급

- **잠정값** — `<RECEIVER_DELIVERY_URL>`·`<HUB_BASE_URL_PROD>`·`<HUB_BASE_URL_DEV>`·`<SELFCHECK_PATH>`·`<CONSENT_NOTICE>`·`<CONSENT_PROOF_RETENTION_MONTHS>` 는 **상수 주입으로만 참조**하고 값을 본문에 복제하지 않는다(단일 출처 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수). 잠정 상태의 운영 배포 금지는 `OPS-001-03` 이 갖는다.
- **성과 지표 목표치** — 상수표에 없는 값이므로 수치를 옮겨 적지 않고 [`../../prd/PRD.md`](../../prd/PRD.md) §성과 지표를 참조한다.
- **범위 밖** — 링크 만료(TTL)·1회성 사용·발송처 서명 검증·요청 제한·관리자 경로·결과 푸시 통지·Delphi 직접 호출에 대응하는 기능·파라미터·응답 필드를 두지 않는다(`OPS-002-05`).
- **폐지 IA 코드**(`ADM`·`ADM-01`~`ADM-03`·`BAT-01`·`BAT-03`)로는 어떤 기능·접점도 만들지 않는다.
