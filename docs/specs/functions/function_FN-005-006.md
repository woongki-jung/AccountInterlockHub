# 입력 형식 판정 기능 정의 (FN-005 ~ FN-006)

정본 목록은 [`spec-functions.md`](spec-functions.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **기능 목적**: 값을 쓰기 전에 **형식만으로 걸러 낼 수 있는 것**을 한 곳에서 판정한다 — 생년월일과 연동 추적 키 둘이다. 두 값 모두 여러 접점이 같은 기준으로 받아야 하므로, 접점마다 정규식을 다시 쓰면 상한·공백 처리가 곧 어긋난다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §서비스 이용 대상 3 — "사용자 … 발송처가 전달한 링크로 진입해 **생년월일을 입력**하고 …"
	- [`../../prd/devspec/database.md`](../../prd/devspec/database.md) §데이터 원칙 — "연동 추적 키는 전달 데이터(X) 내부의 지정 필드값으로 … 불투명 문자열, 개인정보 원문 아님."

## FN-005 생년월일 형식 검증

### 기본 정보

| 항목 | 내용 |
|------|------|
| 기능명 | 생년월일 형식 검증 |
| 분류 | POL |
| 사용 서비스 | SVC-002 · SVC-004 · SVC-013 |
| 호출 PROC | PROC-102 · PROC-104 · PROC-204 |
| 연관 정책 | `AUTH-002-02` · `AUTH-002-01` · `SEC-003-04` |
| 참조 데이터 | [`MDL-006`](../datas/model_MDL-004-006.md) |
| 관련 IA 항목 | `USR-03` · `USR-02` · `API-04` |

### 시그니처

```
function FN-005 (
  birthDate: string,        // 사용자가 넣은 생년월일·필수
): void
  throws BirthDateFormatError { code: EX-AUTH-001, http: 400 }
```

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 제약 | 설명 |
|------|--------|------------|------|------|------|
| 입력 | birthDate | string | Y | `^\d{6}$` — `yyMMdd` 형식의 숫자 6자리 | 복호화의 나머지 키 |
| 출력 | — | — | - | - | 통과하면 아무것도 반환하지 않는다 |

### 처리 흐름 (의사코드)

```
1. 존재 검사 — POL AUTH-002-02 (validate)
   if (birthDate == null OR birthDate 가 문자열이 아니다)  → throw EX-AUTH-001 (400)

2. 형식 검사 — POL AUTH-002-02 (validate)
   if (!MATCH(birthDate, "^[0-9]{6}$"))                   → throw EX-AUTH-001 (400)

3. 통과 (달력 유효성은 검사하지 않는다)
   return
```

### API 인터페이스

해당 없음 — 본인확인 제출·동의 승인 제출·자가진단 요청 세 접점이 입력 검증 단계에서 호출한다.

### 에러 처리 (에러 코드 카탈로그)

| HTTP status | EX 코드 | 발생 조건 | 사용자 메시지 | 개발자 노트 |
|-------------|---------|-----------|---------------|-------------|
| 400 | `EX-AUTH-001` | 값 부재·숫자 6자리가 아님 | "생년월일을 여섯 자리 숫자로 입력해 주세요." | 복호화를 시도하지 않는다. 결과 미확정(`AUTH-002-02`). 입력 값을 응답·로그에 담지 않는다(`DATA-001-02`) |

### 의존 기능

없음.

### 구현 가이드

- **달력 유효성(예: 존재하지 않는 월·일)을 검사하지 않는다.** 생년월일은 인증 자격이 아니라 **복호화의 나머지 키**이며(EXC-AUTH-04), 값이 맞는지는 복호화 성공 여부로만 판단한다. 달력 검증을 넣으면 발송처가 실제로 키 원문에 쓴 값과 허브의 판정 기준이 갈린다.
- **형식 검증은 화면과 서버 양쪽에서 수행하되 판정 근거는 서버 검증이다**(`AUTH-002-02`). 화면 검증만 두면 정책 위반이다.
- 값은 요청 처리 문맥에만 두고 URL·숨은 필드·로그·저장소 어디에도 남기지 않는다(`DATA-001-02`). 승인 시점의 재복호화에 필요한 값은 승인 요청이 다시 실어 온다([`spec-functions-api-user.md`](spec-functions-api-user.md) §생년월일 재수신 규약).
- **재입력 횟수를 세지 않는다**(`AUTH-002-04`). 본 기능은 상태를 갖지 않는다.

## FN-006 연동 추적 키 형식 판정

### 기본 정보

| 항목 | 내용 |
|------|------|
| 기능명 | 연동 추적 키 형식 판정 |
| 분류 | POL |
| 사용 서비스 | SVC-010 · SVC-011 · SVC-012 · SVC-002 · SVC-004 · SVC-013 |
| 호출 PROC | PROC-201 · PROC-202 · PROC-203 · PROC-102 · PROC-104 · PROC-204 |
| 연관 정책 | `DATA-004-03` · `DATA-004-01` · `SEC-002-03` |
| 참조 데이터 | [`MDL-011`](../datas/model_MDL-011-015.md) · [`MDL-005`](../datas/model_MDL-004-006.md) · [`ENT-001`](../datas/data_ENT-001.md) |
| 관련 IA 항목 | 공통 |

### 시그니처

```
function FN-006 (
  trackingKey: any,         // 판정 대상 값. null·비문자열도 그대로 받는다
): boolean                  // 형식 충족 여부
  throws 없음               // 예외를 던지지 않는다 — 호출측이 판정 결과로 EX 를 고른다
```

### 입력/출력 정의

| 구분 | 항목명 | 데이터 타입 | 필수 | 제약 | 설명 |
|------|--------|------------|------|------|------|
| 입력 | trackingKey | any | N | 제약 없음(판정 대상) | 조회·통지 입력값 또는 복원된 X 의 `trackingKey` 필드값 |
| 출력 | (판정) | boolean | - | - | `true` = 1자 이상 255자 이하이며 공백만이 아님 |

### 처리 흐름 (의사코드)

```
1. 타입·존재 검사 — POL DATA-004-03 (validate)
   if (trackingKey == null OR trackingKey 가 문자열이 아니다)  → return false

2. 공백 검사 (값 자체는 변형하지 않는다 — POL DATA-004-01)
   if (TRIM(trackingKey) == "")                              → return false

3. 길이 검사 (문자 수 기준 — ENT-001 tracking_key 와 같은 단위)
   if (CHAR_LENGTH(trackingKey) > 255)                       → return false

4. 판정 반환
   return true
```

### API 인터페이스

해당 없음 — 세 서버 대면 API 의 입력 검증과 복호화 판정 4단계가 이 기능을 공유한다.

### 에러 처리 (에러 코드 카탈로그)

본 기능은 예외를 던지지 않는다. **판정 결과 `false` 를 어떤 EX 로 바꿀지는 호출측이 정한다** — 같은 형식 기준을 쓰되 실패의 의미가 다르기 때문이다(EXC-DATA-11).

| 호출 지점 | HTTP status | EX 코드 | 발생 조건 | 사용자 메시지 | 개발자 노트 |
|-----------|-------------|---------|-----------|---------------|-------------|
| PROC-201 · PROC-202 · PROC-203 (조회·통지 입력) | 400 | `EX-DATA-002` | 판정 `false` | "연동 추적 키 형식이 올바르지 않습니다." | 조회·기록을 수행하지 않고 종료(`DATA-004-03`) |
| PROC-102 · PROC-104 · PROC-204 (복호화 판정 4단계) | 400 | `EX-SEC-002` | 판정 `false` | "연동 요청 정보가 규약과 맞지 않습니다." | 발송처 페이로드의 규약 위반 → `DECRYPT_FAILED`(`SEC-002-03`) |

### 의존 기능

없음.

### 구현 가이드

- **값을 변형하지 않는다**(`DATA-004-01`). 공백 검사에 쓰는 `TRIM` 은 판정용 임시 결과이며, 저장·조회·응답에는 항상 원본 문자열을 쓴다.
- **길이는 문자 수로 센다.** 저장 컬럼이 문자 수 기준(`VARCHAR(255)`)이라 바이트 수로 세면 두 판정이 어긋난다([`data_ENT-001.md`](../datas/data_ENT-001.md) §속성 정의).
- **상한 값을 본 기능에만 둔다.** 세 API 와 복호화 판정이 같은 상수를 참조해야 API 마다 다른 상한이 생기지 않는다(`MDL-011` 구현 가이드).
- 판정에 실패해도 **허브가 유일성을 강제하지 않는다**(`DATA-004-02`). 본 기능은 형식만 본다.
