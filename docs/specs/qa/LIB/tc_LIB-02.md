# 연동 요청 URL 생성(연동 라이브러리) 테스트 케이스 정의

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).

## 개요

- **검증 목적**: 라이브러리가 만든 연동 요청 URL 이 **그대로 허브 진입 경로로 성립**하는지, 길이 상한을 넘긴 URL 이 **발행되지 않는지** 확인한다. 여기서 만든 URL 이 곧 사용자가 여는 링크이므로, 인코딩이 한 번 더 겹치거나 상한을 넘으면 연동이 시작조차 되지 않는다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §목표 — "발송처가 **라이브러리 호출만으로** 연동 요청 URL을 만들 수 있게 해, 규약 문서 해석·자체 구현 없이 통합을 마치게 한다." · [`../../../prd/ia/IA.md`](../../../prd/ia/IA.md) `LIB-02`.
- **관련 IA 항목**: `LIB-02` (본 파일의 전 TC 공통)
- **검증 방법(qa 케이스)**: **CLI·배치** (C# 콘솔 호출 하네스). 생성된 URL 의 실제 진입 확인 1건만 웹·SPA UI 절차를 병용한다.
- **공통 전제**: `ENV-LIB` 구성 · `SEED-VEC`(규약 테스트 벡터 파일)
- **공통 판정 기준**: **Pass** = 모든 단계의 기대 결과 일치 / **Fail** = 하나 이상 불일치(불일치 항목 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록).
- **매핑 PROC 단계**: [`../../processes/process_PROC-402.md`](../../processes/process_PROC-402.md) 의 라벨(`C1`~`C3` · `L1`~`L5`)을 인용한다.
