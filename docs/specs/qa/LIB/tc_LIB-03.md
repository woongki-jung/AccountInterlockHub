# 배포 패키지 테스트 케이스 정의

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).

## 개요

- **검증 목적**: 발송처가 받는 **제공 단위**가 약속한 다섯 구성으로 정확히 채워지고, 무결성을 표준 도구로 확인할 수 있으며, 사용 안내만으로 통합을 마칠 수 있는지 확인한다. 패키지에 자가진단 경로 값이 섞이면 이 제품의 유일한 완화 장치가 사라지므로 그 부재도 함께 검증한다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §수행 범위 3 — "발송처에 전달하는 **배포 패키지**(라이브러리 파일·호출 샘플·규약 버전 표기)와 **규약 적합성 테스트 벡터**를 함께 제공한다." · §제공 가치 — "**통합 부담 없는 발송처 연동**".
- **관련 IA 항목**: `LIB-03` (본 파일의 전 TC 공통)
- **검증 방법(qa 케이스)**: **CLI·배치** (패키지 파일 검사와 표준 체크섬 도구 실행)
- **공통 전제**: `SEED-PKG`(배포 패키지 산출물 1벌) · `ENV-LIB` 구성
- **공통 판정 기준**: **Pass** = 모든 단계의 기대 결과 일치 / **Fail** = 하나 이상 불일치(불일치 항목 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록).
- **매핑 PROC 단계**: [`../../processes/process_PROC-403.md`](../../processes/process_PROC-403.md) 의 라벨(`L1`~`L4` · `C1`~`C4`)을 인용한다.

|---|---|---|---|---|---|
| INTG · Boundary | `SEC-001-11` · 라이브러리 §규약 버전 호환 판단 | PROC-403 · PROC-204 | BR-017(MAJOR 불일치) | 높음 | 자동 |

- **전제**: `SEED-PKG` · `ENV-API` 자가진단 경로 · 허브 규약 버전을 MAJOR 가 다른 값으로 바꾼 구성 1벌
- **단계**: ① 라이브러리의 `ProtocolVersion` 공개 상수를 읽는다 `C4` ② 자가진단 응답의 `protocolVersion` 을 읽는다(PROC-204 `B6`) ③ MAJOR 가 다른 상태에서 대조 → **비호환** 판정 · 새 배포 패키지 수령·재배포가 필요하다는 결론 ④ 이 상태에서도 **허브가 연동 요청을 버전으로 거절하지는 않는지** 확인(버전 값이 요청에 실리지 않아 런타임 분기가 아니다)
- **판정**: 공통 판정 기준

### LIB-03_008 잠정값 배포 게이트 — 운영 배포 전 확인

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 |
|---|---|---|---|---|---|
| INTG · Negative | `OPS-001-03` · EXC-OPS-01 · PROC-403 `C2` | PROC-403 | BR-024(선행) | 높음 | 수동 |

- **전제**: `CLAUDE.env.md` §연동 구성 상수의 잠정 표기 목록
- **단계**: ① 패키지 전달 직전 절차 확인 `C2` → 잠정 표기 항목이 실제 값으로 교체됐는지 확인하는 **체크리스트 항목**이 배포 절차에 존재한다 ② 미교체 항목이 있는 상태에서 운영 배포 절차를 진행하면 **중단**되는지 확인 ③ 애플리케이션이 잠정 여부를 자동 판별하지 **않음**을 확인(자동 판별 수단을 만들지 않는다 — `OPS-001` 구현 가이드) ④ 개발·검증 환경 기동은 잠정값으로도 막히지 않음을 확인
- **판정**: 공통 판정 기준. 본 TC 는 배포 절차 통제의 존재를 확인하는 것이며 잠정값 자체를 결함으로 올리지 않는다.
