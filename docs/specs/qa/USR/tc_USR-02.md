# 연동 실행(복호화·수신처 전달) 테스트 케이스 정의

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).

## 개요

- **검증 목적**: 승인 확정 후 허브가 **다시 복호화해** 전달 데이터를 수신처로 보내는 구간이 규약대로 동작하는지, 실패 시 **사용자가 진입해 있는 동안에만** 정해진 횟수로 재시도하고 소진 시 `DELIVERY_FAILED` 로 확정하는지 확인한다. 전달 성공 판정은 결과 구분과 1:1 이어야 하며 중간 상태가 결과로 승격되면 안 된다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §수행 범위 5 — "**연동 실행 (복호화·전달)**: 승인 시 허브가 생년월일로 복호화해 X를 얻고, 상수로 고정된 수신처(B) 주소로 전달한다." · §시스템 제약사항 — "복호화는 **연동 실행 시점에 메모리 상에서만** 수행하고 전달 후 폐기한다."
- **관련 IA 항목**: `USR-02` (본 파일의 전 TC 공통)
- **검증 방법(qa 케이스)**: **API·서버** (진행 화면 확인만 웹·SPA UI 절차 병용)
- **공통 전제**: `ENV-API` · `ENV-WEB` 기동 · `ENV-DB` 시드 투입 완료 · **`MOCK-RCV` 모의 수신처 필수**(`<RECEIVER_DELIVERY_URL>` 잠정값이 문서용 예약 도메인이라 실 호스트로 연결되지 않는다 — [`../spec-qa.md`](../spec-qa.md) §모킹 전략)
- **공통 판정 기준**: **Pass** = 모든 단계의 기대 결과 일치 / **Fail** = 하나 이상 불일치(불일치 항목 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록).
- **매핑 PROC 단계**: [`../../processes/process_PROC-104.md`](../../processes/process_PROC-104.md) 의 라벨(`B1`~`B8` · `F1`·`F2`)을 인용한다.

- **전제**: `SEED-VEC-01`(파일) · 본인확인·승인 선행 · `MOCK-RCV` 200 모드

- **데이터 검증**: 당일 `success_count` +1 · 다른 결과 카운터 무변화 · `request_count` 무변화(본인확인 시점에 이미 계수)

### USR-02_014 잠정 전달 주소 상태의 정상 동작 확인

- **단계**: ① 승인까지 진행 `B4` → 예약 도메인이 실 호스트로 연결되지 않아 전달이 실패한다 ② 재시도 소진 후 `B6` → `DELIVERY_FAILED` 확정 · 502 · 경로 ③ ③ 이 결과가 **결함이 아니라 정상 동작**임을 판정 근거에 기록한다 ④ 외부로 데이터가 나가지 않았음을 네트워크 로그로 확인

### USR-02_015 SCR-003 진행 화면 — 조작 요소 없음·`Unconfirmed`

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 |
|---|---|---|---|---|---|
| UI · 상태전이 | SCR-003 §화면 상태 전이·§조건부 표시 · `SEC-002-05` · `BIZ-001-02` · 디자인 시스템 §ProgressPanel §접근성 | PROC-104 | BR-006 · BR-007 | 높음 | 자동 |

- **전제**: `ENV-WEB` · `MOCK-RCV` 지연 응답 모드
- **단계**: ① 승인 제출 직후 화면 `F1` → SCR-003 렌더(Spinner · "연동을 진행하고 있습니다" · 보조 문구) · **취소·재시도 버튼 없음** · 진행률·재시도 횟수·내부 단계 미표시 ② 대기 중 문구가 바뀌지 않는지 확인(화면 자체 타임아웃 없음) ③ 전송 계층을 끊어 응답을 못 받게 한다 → `Unconfirmed` InlineAlert "처리 결과를 확인하지 못했습니다. …" · **진행 영역의 `aria-busy` 가 풀려 있다**(`false` 이거나 속성 자체가 없다) · `role="status"`·`aria-live="polite"` 는 **그대로 남는다** — 대기가 끝났는데 `aria-busy` 를 켠 채 두면 라이브 리전에 "아직 갱신 중이니 지금 읽지 말라"는 신호가 남아 **보조기술이 재진입 안내를 미루거나 건너뛴다**(그 안내를 읽어야 결과를 볼 수 있다) ④ 같은 링크로 재진입 → 서버가 확정한 결과가 재안내된다(네 번째 경로를 만들지 않는다)
- **화면 검증**: 진행 영역에 `role="status"`·`aria-live="polite"` — **대기·`Unconfirmed` 양쪽 시점 모두 유지**(라이브 리전에서 내리지 않는다) · `aria-busy="true"` 는 **대기(`Waiting`) 시점에 한정**하며 대기가 끝나면 푼다(③ 에서 관측) · 감소 모션 설정에서 진행 표시가 사라지지 않는다
- **판정**: 공통 판정 기준
