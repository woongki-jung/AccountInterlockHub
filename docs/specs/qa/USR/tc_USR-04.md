# 동의·승인 테스트 케이스 정의

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).

## 개요

- **검증 목적**: 사용자가 **상수로 고정된 동의 항목을 그대로 보고** 스스로 동의 여부를 결정하는지, **전 항목 동의 게이팅**이 화면(1차 방어)과 서버(재검증) **양쪽**에서 성립하는지, 그리고 **승인 확정 시에만 동의 증적 1건**이 만들어지는지 확인한다. 증적 없는 전달이 생기지 않는 것이 이 단계의 안전 조건이며, **거부를 제출하는 경로가 어디에도 없다**는 것이 이번 노드의 추가 검증 축이다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §제공 가치 — "**전 항목 동의가 진행 조건**이므로 동의 없이 연동이 실행되는 경로가 없다." · §수행 범위 4 — "… 상수로 고정된 동의 항목 노출, **전 항목 동의를 조건으로 승인 제출**. 동의하지 않은 채 제출하면 동의 화면의 **유효성 안내**로 막고 결과 단계로 보내지 않는다 — **사용자 거부는 결과 경로가 아니다**. 동의하지 않으려는 사용자의 종료 수단은 창을 닫는 것이며, 그 연동은 결과 미확정으로 남아 보관 기한에 삭제된다."
- **관련 IA 항목**: `USR-04` (본 파일의 전 TC 공통)
- **검증 방법(qa 케이스)**: **웹·SPA UI** (제출 접점의 HTTP 계약 확인은 API·서버 절차를 병용)
- **공통 전제**: `ENV-WEB` · `ENV-API` 기동 · `ENV-DB` 시드 투입 완료 · `SEED-CONST-OK` 상수 주입 · `MOCK-RCV`(모의 수신처) 200 응답 모드
- **공통 판정 기준**: **Pass** = 모든 단계의 기대 결과 일치 / **Fail** = 하나 이상 불일치(불일치 항목 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록).
- **매핑 PROC 단계**: [`../../processes/process_PROC-103.md`](../../processes/process_PROC-103.md) 의 라벨(`B1`~`B4`·`B5b`·`B6`~`B8` · `F1`~`F3`·`F5` — **`F4`·`B5a` 는 삭제되어 결번**이며 뒤 라벨을 당기지 않는다)과 [`../../processes/process_PROC-302.md`](../../processes/process_PROC-302.md) 의 라벨을 인용한다.
- **결번 TC**: `USR-04_008` (거부 제출의 `agreedItemCodes` 미검증 경계 — 거부 제출 경로 폐지로 전제가 사라졌다. 번호를 다른 뜻으로 재사용하지 않는다).

### USR-04_004 화면 게이팅 상태 판정 — 승인 버튼 활성 전이·`필수` 배지·단계 제목 포커스 표시

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 |
|---|---|---|---|---|---|
| UI · Positive | `BIZ-003-01` · SCR-002 §조건부 표시·§입력 폼 정의·§레이아웃 구성 1 · 디자인 시스템 §Button · 디자인 시스템 §접근성 기준(포커스 표시 — "2px 안쪽 여백(바탕색) + 2px `--color-focus` 링" · **"포커스를 받는 요소는 모두 이 한 벌의 링을 쓴다 — 프로그램 이동으로만 포커스를 받는 단계 제목(`tabindex="-1"`)도 예외가 아니다"** / 상태 알림 — "단계가 바뀌면 새 제목으로 포커스를 옮기고 … **옮겨 간 제목에도 위 포커스 링이 그대로 선다**") · §StageTitle §접근성 | PROC-103 | BR-004 | 보통 | 자동 |

- **전제**: `ENV-WEB` · 본인확인 선행(⑥ 관측을 위해 **화면에서 실제로 제출**해 `stage = CONSENT` 전환이 일어나게 한다 — 상태를 직접 주입해 SCR-002 를 그리면 전환 시점이 사라져 ⑥~⑧ 을 관측할 수 없다)
- **단계**: ① SCR-002 진입 직후 `F1` → 필수 항목 미체크 상태에서 승인 버튼이 **비활성 표시 + `aria-disabled="true"`**(속성 `disabled` 를 쓰지 않는다) ② 액션 영역의 버튼이 **"동의하고 연동하기" 하나뿐**임을 확인 ③ 필수 항목 체크 `F2` → 승인 버튼 활성 ④ 체크 해제 → 다시 `aria-disabled` ⑤ `필수` 배지가 `required = true` 항목에만 표시되는지 확인 ⑥ **단계 전환 시점의 제목 포커스** — 본인확인 제출이 `stage = CONSENT` 를 돌려줘 카드가 SCR-002 로 교체되는 순간을 관측한다 `F1` → `document.activeElement` 가 교체된 **`<h1>`**(StageTitle 기본 변형 · "연동 동의")이고 문서 제목도 그 문구와 같다 ⑦ **그 제목에 사양의 링이 실제로 보인다** — 포커스를 가진 동안 제목 경계 바깥으로 **바탕색 2px → `--color-focus` `#0B4FA8` 2px** 순서의 띠가 **렌더 픽셀에** 나타난다. 세 값(두께 2px·색 `#0B4FA8`·안쪽 여백 2px) 중 하나라도 어긋나면 Fail이며, **두께 1px·안쪽 여백 0·브라우저 기본색이면 브라우저 기본 링**이라 Fail이다(`:focus-visible` 에만 조건을 건 구현이 여기로 떨어진다). **아무 표시도 서지 않는 경우도 Fail** — 사양은 조건이 아니라 결과를 요구한다("제목이 포커스를 갖는 동안 위 링이 실제로 보이는 것"). 어떤 선택자·속성으로 그렸는지는 묻지 않는다(성립 수단은 build 가 정한다) ⑧ **제목은 탭 순서에 없다** — `tabindex="-1"` 이라 `Tab`·`Shift+Tab` 으로는 제목에 포커스를 줄 수 없고(⑥ 직후 첫 `Tab` 은 제목을 건너뛰어 **첫 조작 요소인 동의 체크박스**로 간다 — §레이아웃 구성 1→3), 단계 전환의 프로그램 이동이 포커스가 닿는 유일한 경로임을 확인한다. 표시가 없으면 **다음 `Tab` 이 어디서 시작되는지 알리는 단서를 잃는다**
- **화면 검증**: 체크박스 히트 영역 44x44 CSS px 이상 · 키보드 탭 순서에 승인 버튼이 **비활성 상태에서도 남아 있다** · **단계 제목(`<h1>`)은 그 탭 순서에 없고**(`tabindex="-1"`) 포커스는 프로그램 이동으로만 온다(⑧) · 키보드로 체크·제출 가능 · 색만으로 필수 여부를 전달하지 않는다(배지 문구 병기)
- **판정**: 공통 판정 기준

### USR-04_008 (결번)
