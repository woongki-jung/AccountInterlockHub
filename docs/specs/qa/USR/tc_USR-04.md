# 동의·승인 테스트 케이스 정의

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).

## 개요

- **검증 목적**: 사용자가 **상수로 고정된 동의 항목을 그대로 보고** 스스로 승인·거부를 결정하는지, 필수 동의 게이팅이 화면과 서버 **양쪽**에서 성립하는지, 그리고 **승인 확정 시에만 동의 증적 1건**이 만들어지는지 확인한다. 증적 없는 전달이 생기지 않는 것이 이 단계의 안전 조건이다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §제공 가치 — "**동의 기반 투명성**: 사용자가 어떤 항목에 동의하는지 화면에서 확인하고 스스로 승인·거부를 결정한다." · §수행 범위 4 — "… 상수로 고정된 **동의 항목 노출·동의 후 승인 또는 거부**."
- **관련 IA 항목**: `USR-04` (본 파일의 전 TC 공통)
- **검증 방법(qa 케이스)**: **웹·SPA UI** (제출 접점의 HTTP 계약 확인은 API·서버 절차를 병용)
- **공통 전제**: `ENV-WEB` · `ENV-API` 기동 · `ENV-DB` 시드 투입 완료 · `SEED-CONST-OK` 상수 주입 · `MOCK-RCV`(모의 수신처) 200 응답 모드
- **공통 판정 기준**: **Pass** = 모든 단계의 기대 결과 일치 / **Fail** = 하나 이상 불일치(불일치 항목 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록).
- **매핑 PROC 단계**: [`../../processes/process_PROC-103.md`](../../processes/process_PROC-103.md) 의 라벨(`B1`~`B8` · `F1`~`F5`)과 [`../../processes/process_PROC-302.md`](../../processes/process_PROC-302.md) 의 라벨을 인용한다.
