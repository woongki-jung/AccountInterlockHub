# 연동 링크 진입 테스트 케이스 정의

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).

## 개요

- **검증 목적**: 발송처가 만든 연동 요청 URL 로 들어온 요청이 **생년월일 입력 이전에 판정할 수 있는 구조 위반**을 정확히 걸러 내는지, 그리고 판정 결과와 무관하게 **언제나 화면 문서**로 응답하는지 확인한다. 이 단계의 실패는 추적 키를 알 수 없으므로 레코드를 만들지 않고 지표에만 계수되어야 한다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §수행 범위 4 — "발송처 링크로 고정 진입 경로에 진입, 생년월일 입력, …" · [`../../../prd/ia/IA.md`](../../../prd/ia/IA.md) `USR-01` — "발송처가 만든 링크로 고정 진입 경로에 진입해 `encX`·`encY`를 받고 형식을 판정(무효 링크는 결과 안내로 분기)".
- **관련 IA 항목**: `USR-01` (본 파일의 전 TC 공통)
- **검증 방법(qa 케이스)**: **웹·SPA UI** (진입 응답의 HTTP 계약 확인은 API·서버 절차를 병용)
- **공통 전제**: `ENV-WEB` 기동 · `ENV-DB` 시드 투입 완료 · `SEED-CONST-OK` 상수 주입([`../spec-qa.md`](../spec-qa.md) §테스트 환경 · §시드 데이터 카탈로그)
- **공통 판정 기준**: **Pass** = 모든 단계의 기대 결과 일치 / **Fail** = 하나 이상 불일치(불일치 항목 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록). 실행 단계의 세분 판정 5종은 [`../../../../ai/strategies/qa-execution.md`](../../../../ai/strategies/qa-execution.md) §공통 원칙.
- **매핑 PROC 단계**: [`../../processes/process_PROC-101.md`](../../processes/process_PROC-101.md) 의 라벨(`B1`~`B7` · `F1`~`F3`)을 그대로 인용한다.

### USR-01_001 정상 링크 진입 — 구조 판정 통과 후 본인확인 단계

|---|---|---|---|---|---|
| E2E · Positive | SVC-001 · FN-002 · FN-003 · SCR-001 · `SEC-001-08` | PROC-101 | BR-001(통과) | 높음 | 자동 |

- **전제**: `SEED-VEC-01` 의 기대 요청 URL(파일)
- **단계**: ① 벡터 01 의 요청 URL 로 진입 `B1`~`B4` → HTTP 200 · `Content-Type: text/html; charset=utf-8` ② 초기 상태 판독 `B6`·`B7`·`F1` → 본문에 `{"stage":"IDENTITY"}` 주입, `resultPath` 부재 ③ 화면 확인 `F2`·`F3` → SCR-001 렌더(제목 "본인 확인" · 생년월일 필드 · 확인 버튼 활성)
- **데이터 검증**: `tbl_interlock_tracking` 에 어떤 행도 추가되지 않는다(`BIZ-002-02`) · `tbl_interlock_metric_daily` 무변화
- **판정**: 공통 판정 기준
