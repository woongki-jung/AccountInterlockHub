# 완료 콜백 API 테스트 케이스 정의

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).

## 개요

- **검증 목적**: 수신처가 자기 처리를 마쳤음을 통지하는 접점이 **멱등**하게 동작하고(중복 통지에도 최초 수신 일시 유지), **결과 구분을 건드리지 않으며**, 없는 레코드를 되살리지 않는지 확인한다. 인증이 없어 위조 통지를 막을 수단이 없다는 점은 수용 리스크로 확인 대상이다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §서비스 이용 대상 2 — "수신처 … 처리 완료를 허브에 콜백으로 통지한다." · §시스템 제약사항 — "완료 콜백도 추적 키를 아는 쪽이면 통지할 수 있다."
- **관련 IA 항목**: `API-03` (본 파일의 전 TC 공통)
- **검증 방법(qa 케이스)**: **API·서버**
- **공통 전제**: `ENV-API` 기동 · `ENV-DB` 시드 투입 완료 · `SEED-CONST-OK` 상수 주입
- **공통 판정 기준**: **Pass** = 모든 단계의 기대 결과 일치 / **Fail** = 하나 이상 불일치(불일치 항목 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록).
- **매핑 PROC 단계**: [`../../processes/process_PROC-203.md`](../../processes/process_PROC-203.md) 의 라벨(`C1`·`C2` · `B1`~`B5`)을 인용한다.
- **엔드포인트**: `POST /api/interlock/callback` — 요청 `MDL-011` · 응답 `MDL-013`

### API-03_001 최초 콜백 수신 → 기록·200

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 |
|---|---|---|---|---|---|
| INTG · Positive | SVC-012 · FN-011 · MDL-011 · MDL-013 · ENT-001 | PROC-203 · PROC-301 | BR-012(최초) · BR-002(`FIXED`) | 높음 | 자동 |

- **전제**: `SEED-TRK-FIXED-SUCCESS`(SQL — `callback_received_at IS NULL`)
- **단계**: ① `{"trackingKey":"<키>"}` 로 POST `C1`·`B1` → 200 ② 데이터 확인 `B4` → `callback_received_at` 이 채워진다 ③ 응답 `B5` → `isCallbackReceived = true` · `callbackReceivedAt` 이 방금 기록된 값과 일치 ④ 이후 연동 완료 확인 API(`API-02`)가 같은 값을 돌려주는지 대조
- **판정**: 공통 판정 기준

### API-03_002 중복 콜백 — 최초 수신 일시 유지(멱등)

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 |
|---|---|---|---|---|---|
| DATA · 상태전이 | FN-011 · 인터페이스 §응답 형상 확정 · ENT-001 §구현 가이드 | PROC-203 · PROC-301 | BR-012(중복) | 높음 | 자동 |

- **전제**: API-03_001 을 수행해 `callback_received_at` 이 채워진 상태
- **단계**: ① 같은 키로 콜백을 3회 더 발신 `B4` → 매회 200 ② 데이터 확인 → `callback_received_at` 이 **최초 값 그대로** ③ 응답의 `callbackReceivedAt` 이 매회 같은 최초 값인지 확인 → 수신처가 자기 통지가 이미 반영됐음을 알 수 있다 ④ 조건부 UPDATE(`callback_received_at IS NULL`)로 구현됐는지 동시 발신으로 재확인
- **판정**: 공통 판정 기준

### API-03_003 결과 확정 레코드에 콜백 — 결과 구분 불변

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 |
|---|---|---|---|---|---|
| DATA · 상태전이 | `BIZ-001-04` · FN-011 · PROC-301 `B6` | PROC-203 · PROC-301 | BR-021 · BR-012 | 높음 | 자동 |

- **전제**: `SEED-TRK-FIXED-SUCCESS`·`SEED-TRK-FIXED-DELIVERY`(SQL)
- **단계**: ① 두 레코드에 각각 콜백을 발신 `B4` → 200 ② 데이터 확인 → `result_code`·`result_at` **불변**(콜백만 이어 쓴다) ③ `DELIVERY_FAILED` 레코드도 콜백이 기록되는지 확인(허브는 통지 자격을 판단하지 않는다) ④ 결과 확정 이후에도 콜백을 이어 쓸 수 있음을 확인 ⑤ 지표 카운터 무변화 확인
- **판정**: 공통 판정 기준

### API-03_007 인증·출처 검증 부재 — 위조 통지 수용 리스크

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 |
|---|---|---|---|---|---|
| POL · 권한/인증 | `AUTH-001-03` · `OPS-002-02` · EXC-OPS-07 | PROC-203 | BR-012 | 높음 | 자동 |

- **전제**: `SEED-TRK-FIXED-SUCCESS`(SQL)
- **단계**: ① 수신처가 아닌 임의 출처에서 인증 없이 콜백 발신 `B1` → 200 · 정상 기록(출처를 검증하지 않는다) ② 임의 자격을 실어 발신 → 검증 없이 같은 결과 ③ 401·403 이 응답 코드 집합에 없음을 확인 ④ 이 상태가 **수용 리스크이며 결함이 아님**을 판정 근거에 기록 ⑤ 발송처 서명 검증·IP 제한이 도입되지 않았음을 확인(도입됐다면 범위 밖 — `OPS-002-05`)
- **판정**: 공통 판정 기준. **AUTH 치환** — 위조 통지 차단 수단이 **설계상 없음**을 확인한다.
