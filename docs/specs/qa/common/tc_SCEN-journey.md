# 횡단 시나리오 테스트 케이스 정의 — 사용자 여정·규약 왕복

정본 목록은 [`../spec-qa.md`](../spec-qa.md). 용어는 [`../../../../wiki/WIKI.md`](../../../../wiki/WIKI.md).
같은 횡단 식별자의 플랫폼 계층 시나리오는 [`tc_SCEN-platform.md`](tc_SCEN-platform.md).

## 개요

- **검증 목적**: 여러 IA 노드를 가로지르는 **사용자 여정**과, 라이브러리·허브가 같은 규약의 양쪽임을 증명하는 **규약 대칭(왕복) 검증**을 담는다. 기능단위 TC 가 이미 검증한 세부 동작은 다시 확인하지 않고 **노드 간 연계와 흐름**에 집중한다.
- **관련 PRD 요구사항**: [`../../../prd/PRD.md`](../../../prd/PRD.md) §프로그램 구성·기술스택·검증 방법 — "**규약 대칭(왕복) 검증**은 별도 통합 검증 항목으로 둔다 — 라이브러리가 암호화한 값을 허브가 복호화해 원문이 복원되는지 대조한다."
- **관련 IA 항목**: `공통` (횡단). 각 TC 의 표에 걸치는 노드를 적는다.
- **검증 방법(qa 케이스)**: 여정 TC 는 **웹·SPA UI** 를 주 절차로 하고 API·서버·CLI·배치 절차를 구간별로 병용한다. 왕복 TC 는 **CLI·배치**(하네스) + **API·서버**(허브 복호화) 조합이다.
- **공통 전제**: `ENV-WEB` · `ENV-API` · `ENV-LIB` · `ENV-DB` · `MOCK-RCV` 전부 기동 · `SEED-CONST-OK` 상수 주입
- **공통 판정 기준**: **Pass** = **전 단계 Pass**(모든 단계의 확인 항목 일치) / **Fail** = 하나 이상 불일치(불일치 단계 기록) / **Block** = 전제 조건 미충족으로 실행 불가(사유 기록).
- 각 단계는 **행동 → 확인 항목** 쌍으로 적는다.

### SCEN_001 발송처 통합 담당자 — 첫 연동을 성공시키는 전 여정

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| E2E · Positive | SVC-006~009 · SVC-001~005 · SVC-010·011·014·015·016 | PROC-401·402·403·404·101·102·103·104·105·201·301·302·303 | BR-001·BR-002①·BR-004·BR-005·BR-006·BR-008·BR-025·BR-010·BR-018·BR-020·BR-023·BR-024 | 높음 | 반자동 | `LIB-01`~`04` · `USR-01`~`05` · `API-01` · `BAT-04`~`06` |

- **페르소나·목적**: 발송처 통합 담당자가 배포 패키지를 처음 받아, 자기 회원 1명을 서비스 B 와 연동시키고 결과를 조회하기까지.
- **전제**: `SEED-PKG` · `MOCK-RCV` 200 모드 · `ENV-DB` 초기화
- **단계**:
	1. 배포 패키지를 받아 체크섬을 대조 `PROC-403 C3` → 전건 일치
	2. 사용 안내의 환경별 기준 URL 기재란을 읽는다 `PROC-403 C4` → 개발·로컬 기준 URL 확보
	3. 테스트 벡터로 하네스를 실행 `PROC-404 C1` → `passed = total` · 종료 코드 0
	4. 라이브러리 `ProtocolVersion` 과 자가진단 응답의 `protocolVersion` 을 대조 `PROC-204 C2` → MAJOR 일치(호환)
	5. 회원 1명의 X·발송처키·생년월일로 `Encrypt` 호출 `PROC-401 L8` → 암호값 쌍 반환
	6. `BuildRequestUrl` 호출 `PROC-402 L5` → 연동 요청 URL 반환(길이 상한 이내)
	7. 그 URL 로 자가진단 호출 `PROC-204 B6` → `isConform = true`
	8. 사용자가 그 URL 로 진입 `PROC-101 F3` → SCR-001 렌더
	9. 생년월일 입력·확인 `PROC-102 B8` → SCR-002 렌더 · 추적 레코드 1건 생성 · `request_count` +1
	10. 필수 동의 체크 후 승인 `PROC-103 B6` → SCR-003 진행 화면 · 동의 증적 1건
	11. 허브가 수신처에 전달 `PROC-104 B4` → **모의 수신처가 X 를 실제로 수신**(바이트 일치)
	12. 결과 확정·안내 `PROC-104 B6`·`PROC-105 F2`·`F3` → `SUCCESS` · SCR-004 경로 ① · `success_count` +1 · 응답에 `returnUrl` 이 실려 복귀 안내 영역이 뜨고 3초 뒤 이력 치환으로 복귀 주소로 이동
	13. 발송처가 처리상태 확인 API 호출 `PROC-201 B6` → `resultCode = "SUCCESS"` · 이 시점에 `result_confirmed_at` 채워짐
	14. 발송처가 연동 완료 확인 API 호출 `PROC-202 B5` → `isCallbackReceived = false`(수신처 통지 전)
- **판정**: 공통 판정 기준

### SCEN_002 사용자 — 동의하지 않기로 결정하는 여정

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| E2E · Negative | SVC-001~003 · SVC-014 · SVC-016 | PROC-101·102·103·301·303 | BR-001 · BR-002①② · BR-004(미충족) · BR-022(미충족) | 높음 | 자동 | `USR-01`·`USR-03`·`USR-04` · `BAT-04`·`BAT-06` |

- **페르소나·목적**: 링크를 받은 사용자가 동의 내용을 확인하고 **제공하지 않기로** 결정한다. 거부를 제출하는 경로가 없으므로 이 여정은 **결과 화면에 도달하지 않고** 결과 미확정으로 끝난다(`BIZ-003-03`).
- **전제**: `SEED-VEC-01`(파일) · `MOCK-RCV` 요청 로그 초기화 · 네트워크 로그 수집 · 당일 카운터 사전 기록
- **단계**:
	1. 링크로 진입 `PROC-101 F3` → SCR-001
	2. 생년월일 입력·확인 `PROC-102 B8` → SCR-002 · 추적 레코드 생성 · `request_count` +1
	3. 안내 문구와 동의 항목을 읽는다 `PROC-103 F1` → 상수 값 그대로 노출
	4. 화면의 종료 수단을 찾는다 `PROC-103 F1` → **거부·취소 버튼·링크·닫기 아이콘이 없고** 액션은 "동의하고 연동하기" 하나뿐이다
	5. 체크하지 않은 채 승인 버튼을 누른다 `PROC-103 F2`·`F3` → **요청을 보내지 않고**(네트워크 요청 0건) 알림 영역에 "모든 항목에 동의해 주셔야 합니다" · 첫 미충족 항목으로 포커스 · 단계 유지
	6. 창(탭)을 닫는다 → 종료를 알리는 요청이 **0건**이며 허브는 이탈을 인지하지 못한다(`EXC-BIZ-05`)
	7. 데이터 확인 → 추적 레코드는 남아 있고 `result_code IS NULL`(**결과 미확정**) · **증적 0건** · **모의 수신처 요청 0건** · 결과 구분 카운터 3종 무변화
	8. 같은 링크로 재진입해 본인확인 통과 `PROC-102 B7` → 결과가 확정되지 않아 **재안내가 아니라 동의 화면으로 이어진다**(`BIZ-002-03` ②) · `request_count` 무변화
	9. 이 레코드가 **생성 기산 보관 상한**의 삭제 대상으로 남는지 확인(`DATA-002-01` ②) — 결과 확인 기산은 시작되지 않는다
- **판정**: 공통 판정 기준

### SCEN_003 수신처 장애 → 발송처가 새 추적 키로 재요청하는 여정

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| E2E · Positive | SVC-004 · SVC-005 · SVC-006·007 · SVC-014·016 | PROC-104·105·301·303·401·402 | BR-006(실패) · BR-007(소진) · BR-008③ · BR-025(미동봉) · BR-002③ | 높음 | 자동 | `USR-02`·`USR-05` · `LIB-01`·`LIB-02` · `BAT-04`·`BAT-06` |

- **페르소나·목적**: 수신처 장애로 전달이 실패한 뒤, 발송처가 **새 추적 키로 새 요청을 발행해** 연동을 다시 성립시킨다(허브는 자동 재전달을 하지 않는다).
- **전제**: `SEED-VEC-01`(파일) · `MOCK-RCV` 연결 거부 모드
- **단계**:
	1. 사용자가 링크로 진입해 승인까지 진행 `PROC-103 B7` → SCR-003 진행 화면
	2. 허브가 전달을 시도하고 재시도를 소진 `PROC-104 B5` → 정책이 정한 횟수·간격·총 소요 상한 이내
	3. 결과 확정 `PROC-104 B6` → `DELIVERY_FAILED` · 502 `EX-BIZ-002` · `delivery_failed_count` +1
	4. 결과 안내 `PROC-105 F2` → SCR-004 경로 ③ · 다음 안내 "다시 연동하려면 연동을 요청한 서비스에서 새로 요청해 주세요." · **`returnUrl` 없음 → 화면 잔류**(복귀 안내 영역 미표시)
	5. 수신처를 200 모드로 복구하고 10분 관찰 → **허브가 재전달을 시도하지 않는다**(모의 수신처 요청 0건)
	6. 같은 링크로 재진입해 본인확인 통과 `PROC-102 B7` → 경로 ③ 재안내(무갱신) · 재안내라도 경로 ③ 이므로 여전히 이동하지 않는다
	7. 발송처가 **새 추적 키**로 X 를 만들어 `Encrypt`·`BuildRequestUrl` 호출 `PROC-401`·`PROC-402` → 새 요청 URL
	8. 사용자가 새 링크로 진입해 승인 `PROC-104 B6` → 전달 성공 · `SUCCESS` · 경로 ① · 이번에는 `returnUrl` 이 실려 복귀 이동이 일어난다
	9. 데이터 확인 → 추적 레코드 2건(각기 다른 키)·증적 2건 · `request_count` +2 · `delivery_failed_count` +1 · `success_count` +1
- **판정**: 공통 판정 기준

### SCEN_004 사용자 — 깨진 링크로 진입해 새 링크를 받는 여정

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| E2E · Negative | SVC-001 · SVC-005 · SVC-016 | PROC-101·105·303 | BR-001(위반) · BR-008② · BR-025(미동봉) · BR-018(추적 키 미확보) | 높음 | 자동 | `USR-01`·`USR-05` · `BAT-06` |

- **페르소나·목적**: 메신저 전달 과정에서 잘린 링크로 진입한 사용자가 무엇을 해야 하는지 안내받고, 새 링크로 연동을 마친다.
- **전제**: `SEED-URL-B64BAD`(파일 — 뒷부분이 잘린 `encX`) · `SEED-VEC-01`(정상 링크)
- **단계**:
	1. 잘린 링크로 진입 `PROC-101 B4` → 구조 판정 실패
	2. 화면 확인 `PROC-105 F2` → **SCR-004 가 첫 화면**(경로 ②) · 설명 "연동 링크가 올바르지 않습니다." · 초기 상태에 `returnUrl` 속성이 없어 잔류한다
	3. 데이터 확인 → 추적 레코드 0건 · `request_count` +1 · `decrypt_failed_count` +1
	4. 다음 안내 확인 → "연동을 요청한 서비스에서 새 링크를 받아 다시 진행해 주세요."
	5. 같은 잘린 링크로 재진입 → **같은 판정으로 다시 경로 ②**(레코드가 없어 재안내가 아니다 — 배지가 붙지 않는다)
	6. 정상 링크로 진입해 연동을 완료 `PROC-104 B6` → 경로 ① · `success_count` +1
	7. 데이터 확인 → 3·5 단계의 미확보 실패가 **시도마다 계수**됐음을 확인(수용 한계)
- **판정**: 공통 판정 기준

### SCEN_005 사용자 — 생년월일을 여러 번 틀린 뒤 연동을 마치는 여정

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| E2E · 상태전이 | SVC-002~005 · SVC-014·015·016 | PROC-102·103·104·105·301·302·303 | BR-003 · BR-002① · BR-004(충족) · BR-008① | 높음 | 자동 | `USR-03`~`USR-05` · `USR-02` · `BAT-04`~`BAT-06` |

- **페르소나·목적**: 생년월일을 헷갈린 사용자가 여러 번 다시 입력해 결국 연동을 마친다(잠금·차단이 없다).
- **전제**: `SEED-VEC-01`(파일) · `MOCK-RCV` 200 모드
- **단계**:
	1. 링크로 진입 `PROC-101 F3` → SCR-001
	2. 잘못된 생년월일로 5회 제출 `PROC-102 B4a` → 매회 재입력 안내 · 입력 값 유지·전체 선택 · **시도 횟수 미표시**
	3. 데이터 확인 → 추적 레코드 0건 · 카운터 4종 **전부 무변화**
	4. 형식이 깨진 값(5자리)으로 1회 제출 → 형식 안내(다른 문구) · 복호화 미시도
	5. 올바른 값으로 제출 `PROC-102 B8` → SCR-002 · 레코드 1건 생성 · `request_count` **+1**(누적 6회 시도였지만 1)
	6. 승인 제출 `PROC-103 B6`·`PROC-104 B6` → 증적 1건 · 전달 성공 · `SUCCESS`
	7. 결과 확인 `PROC-105 F2` → SCR-004 경로 ① · `success_count` +1
	8. 새로고침 `PROC-101 B1` → 진입부터 다시 시작(세션 없음) → 본인확인 통과 시 경로 ① 재안내
- **판정**: 공통 판정 기준

### SCEN_006 수신처 완료 통지까지 이어지는 여정

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| E2E · 상태전이 | SVC-004 · SVC-010·011·012 · SVC-014 | PROC-104·201·202·203·301 | BR-006 · BR-010 · BR-011 · BR-012 · BR-021 | 높음 | 자동 | `USR-02` · `API-01`~`API-03` · `BAT-04` |

- **페르소나·목적**: 연동이 완료된 뒤 수신처가 자기 처리를 마치고 허브에 통지하며, 발송처가 그 사실을 확인한다.
- **전제**: `SEED-VEC-01`(파일) · `MOCK-RCV` 200 모드
- **단계**:
	1. 연동을 완료해 `SUCCESS` 를 확정 `PROC-104 B6`
	2. 발송처가 연동 완료 확인 API 호출 `PROC-202 B5` → `isCallbackReceived = false` · **레코드 무갱신**
	3. 수신처가 완료 콜백 발신 `PROC-203 B4` → 200 · `callback_received_at` 채워짐 · `result_code` 불변
	4. 수신처가 같은 콜백을 재발신 `PROC-203 B4` → 200 · **최초 수신 일시 그대로**(멱등)
	5. 발송처가 연동 완료 확인 API 재호출 `PROC-202 B4` → `isCallbackReceived = true` + 최초 수신 일시
	6. 발송처가 처리상태 확인 API 호출 `PROC-201 B5` → `resultCode = "SUCCESS"` · 이 시점에 결과 확인 표시 · 보관 기산 개시
	7. 처리상태 확인을 재호출 → `result_confirmed_at` 불변
	8. 데이터 확인 → 레코드 1건에 진입·결과·결과 확인·콜백이 **모두 이어져** 기록됐다
- **판정**: 공통 판정 기준

### SCEN_007 규약 대칭 왕복 검증 — 라이브러리 암호화 → 허브 복호화

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| INTG · Positive | `SEC-001-01`~`SEC-001-08` · SVC-006 · SVC-009 F-004 · SVC-004 | PROC-401·402·404·101·102·104 | BR-020 · BR-024 · BR-001 · BR-006 | 높음 | 자동 | `LIB-01`·`LIB-02`·`LIB-04` · `USR-01`~`USR-03` · `USR-02` |

- **검증 목적**: 라이브러리가 암호화한 값을 허브가 복호화해 **원문이 그대로 복원**되는지 대조한다. 근거 데이터는 규약 테스트 벡터다.
- **전제**: `ENV-LIB` + `ENV-API` + `MOCK-RCV` 200 모드 · `SEED-VEC`
- **단계**:
	1. 벡터 각 항목으로 `Encrypt` 호출 `PROC-401 L8` → 암호값 쌍 산출
	2. `BuildRequestUrl` 호출 `PROC-402 L5` → 요청 URL 산출
	3. 산출값이 벡터 기대 출력과 일치 `PROC-404 C1` → 전건 일치
	4. 같은 암호값을 자가진단에 넣는다 `PROC-204 B6` → 전건 `isConform = true`
	5. 같은 URL 로 실제 진입·본인확인·승인을 수행 `PROC-102 B5`·`PROC-104 B3`
	6. **모의 수신처가 받은 본문 바이트열**과 벡터의 원본 X UTF-8 바이트열을 비교 `PROC-404 C2` → **완전 일치**(필드 순서·공백·이스케이프·숫자 표현·다국어 코드 포인트 불변)
	7. 복호화된 X 의 `trackingKey` 와 추적 레코드의 `tracking_key` 가 일치하는지 확인
	8. 전 항목에 대해 1~7 을 반복하고 실패 항목이 0 임을 확인

### SCEN_008 왕복 검증 — 경계 6종 전건

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| INTG · Boundary | `SEC-001-03`·`SEC-001-08`·`SEC-001-09`·`SEC-001-02` · 라이브러리 §반드시 덮는 경계 | PROC-401·402·404·102·104 | BR-020 · BR-023 · BR-024 | 높음 | 자동 | `LIB-01`·`LIB-02`·`LIB-04` · `USR-03`·`USR-02` |

- **검증 목적**: 규약의 경계값에서도 대칭이 유지되는지 확인한다. 정규화 경계에서 어긋나면 특정 발송처키 길이에서만 연동이 실패하는 사고가 난다.
- **전제**: `SEED-VEC`(6 경계 항목) · `ENV-LIB` + `ENV-API` + `MOCK-RCV`
- **단계**:
	1. 키 원문 32바이트 **미만** 항목으로 왕복 → 원문 복원 일치
	2. 키 원문 **정확히 32바이트** 항목으로 왕복 → 일치
	3. 키 원문 32바이트 **초과** 항목으로 왕복 → 일치
	4. Base64URL **치환 문자(`-`·`_`) 출현** 항목으로 왕복 → 퍼센트 인코딩 없이 URL 이 성립하고 일치
	5. X 평문이 **크기 상한 바로 아래** 항목으로 왕복 → 일치 · 요청 URL 이 길이 상한 이내
	6. X 에 **다국어 문자 포함** 항목으로 왕복 → 코드 포인트 손실·정규화 변형 0
	7. 6 항목 전부에 대해 자가진단 `isConform = true` 확인
	8. 한 항목이라도 불일치면 어긋난 항목의 `caseId` 로 원인을 좁힌다

### SCEN_009 규약 버전 대조 — 라이브러리·벡터·허브 3자 일치

| 계층·유형 | 검증 대상 | 검증 PROC | 검증 분기/예외 | 우선순위 | 자동화 | IA |
|---|---|---|---|---|---|---|
| INTG · Positive | `SEC-001-11` · `SEC-001-12` · SVC-008 · SVC-013 | PROC-403·404·204 | BR-017 · BR-024 | 높음 | 자동 | `LIB-03`·`LIB-04` · `API-04` |

- **검증 목적**: 규약 버전이 세 곳에서 같은 값을 말하는지 확인한다. 한 곳이라도 어긋나면 호환 판정 자체를 신뢰할 수 없다.
- **전제**: `SEED-PKG` · `ENV-API` 자가진단 경로
- **단계**:
	1. 라이브러리 `ProtocolVersion` 공개 상수를 읽는다 `PROC-403 C4` → 값 A
	2. 벡터 파일의 `protocolVersion` 을 읽는다 `PROC-404 L3` → 값 B
	3. 자가진단 응답의 `protocolVersion` 을 읽는다 `PROC-204 B6` → 값 C
	4. A = B = C 확인
	5. 사용 안내 §규약 버전 표기의 값도 같은지 확인 `PROC-403 L2`
	6. 형식이 `<MAJOR>.<MINOR>` 문자열인지 확인
	7. 규약을 바꾸면 라이브러리·허브를 **함께 배포**하고 벡터를 재생성·대조 통과시키는 것이 배포 전제임을 절차에서 확인
- **판정**: 공통 판정 기준
