AccountInterlockHub 의 품질 검증 케이스 단일 출처다. 방향 근거는 [`../../prd/PRD.md`](../../prd/PRD.md), 정보 구조는 [`../../prd/ia/IA.md`](../../prd/ia/IA.md), 준수 규칙은 [`../policies/spec-policies.md`](../policies/spec-policies.md), 서비스는 [`../services/spec-services.md`](../services/spec-services.md), 데이터는 [`../datas/spec-datas.md`](../datas/spec-datas.md), 접점은 [`../functions/spec-functions.md`](../functions/spec-functions.md), 화면은 [`../screens/spec-screens.md`](../screens/spec-screens.md), 프로세스는 [`../processes/spec-process.md`](../processes/spec-process.md), 검증 활동 기본 지침은 [`../../../ai/strategies/qa-execution.md`](../../../ai/strategies/qa-execution.md) 를 따른다.

본 문서는 **전략·환경 요약·채번 체계·유형 분포·미해소 카탈로그·문서 목록**을 담고, 상세는 아래 두 하위 문서와 개별 TC 파일이 갖는다.

- [`spec-qa-seed.md`](spec-qa-seed.md) — 테스트 환경 상세 · **시드 데이터 카탈로그** · 모킹 전략

## 테스트 전략 요약

1. **사양이 기준이다** — TC 는 선행 도메인 6종의 사양을 근거로만 도출했다. 사양에 없는 동작을 검증 대상으로 만들지 않았고, 사양과 어긋난 TC 는 결함이 아니라 **TC 결함**으로 분류한다.
2. **없는 것의 부재를 검증한다** — 이 제품은 인증·요청 제한·관리자 표면·감사 저장소를 **두지 않기로 결정**했다. 그 결정이 지켜졌는지 확인하는 TC 를 두되, 부재 자체를 결함으로 올리지 않는다(§AUTH 치환 · §수용 리스크의 취급).
3. **규약 대칭이 최우선 검증 축이다** — 라이브러리(암호화)와 허브(복호화)가 같은 결과를 내지 못하면 제품이 성립하지 않는다. 규약 테스트 벡터를 근거로 한 **왕복 검증**을 별도 통합 항목으로 두었다(`SCEN_007`·`SCEN_008`).
4. **결과 체계의 단일성을 반복 확인한다** — 결과 구분 **3종**·화면 경로 **3개**·지표 카운터 **4개**(요청 수 1 + 결과 구분 3)가 같은 값 체계를 쓰는지, **네 번째가 만들어지지 않는지**를 여러 계층에서 교차 확인한다. **미동의로 끝난 연동에는 결과 구분도 결과 경로도 부여되지 않는다**는 사실(`BIZ-003-03`)도 같은 축에서 확인한다.
5. **무저장 원칙은 구조로 확인한다** — 금지 값이 저장되지 않는지를 값 검사뿐 아니라 **스키마에 자리가 없는지**로 확인한다.
6. **우선순위** — 핵심 시나리오(Happy Path) → 정책 위반 → 예외·오류 → 경계값 순으로 도출했다.

## 테스트 환경 요약

상세·시드 카탈로그는 [`spec-qa-seed.md`](spec-qa-seed.md).

| 환경 ID | 대상 | 요지 |
|---|---|---|
| `ENV-WEB` | 사용자 웹 | 배포 산출물 기동(NestJS 가 React 정적 빌드를 서빙). 브라우저 자동화로 조작·관측 |
| `ENV-API` | 백엔드 API | 같은 배포 단위. HTTP 클라이언트로 접점 직접 호출 |
| `ENV-CLI` | 보관 배치 | 같은 배포 단위 안의 명령 진입점 실행. 표준 출력·표준 오류 분리 수집 |
| `ENV-LIB` | 연동 라이브러리 | 라이브러리 빌드 산출물 + **C# 콘솔 호출 하네스** |
| `ENV-DB` | PostgreSQL 16 | 마이그레이션 → 시드 투입 → 검증 쿼리. 접속 정보는 문서에 적지 않고 참조만 한다 |
| `MOCK-RCV` | 모의 수신처 | **필수** — `<RECEIVER_DELIVERY_URL>` 잠정값이 문서용 예약 도메인이라 실 호스트로 연결되지 않는다 |
| `MOCK-RESP` | 응답 변조 프록시 | 화면이 **서버가 낼 수 없는 값**(범위 밖 `resultPath`·형식 미달 `returnUrl`·**진입 문서의 초기 상태 블록**)을 받았을 때의 방어를 확인한다. 용도 전량은 [`spec-qa-seed.md`](spec-qa-seed.md) §모킹 전략 |

- **접속 비밀번호·키·자가진단 경로 운영 값을 본 문서군에 직접 적지 않는다.** 상수는 플레이스홀더로만 참조한다(단일 출처 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수).
	- **상수 실값의 검증 TC 예외** — 사양 본문은 상수의 값을 복제하지 않지만(`OPS-001-04`), **검증 TC 는 기대값 판정을 위해 상수 실값을 인용할 수 있다.** 기대값을 적지 않으면 무엇과 대조할지가 서지 않아 검증이 성립하지 않기 때문이다. **인용일 뿐 정본이 되지 않는다** — 단일 출처는 여전히 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) 이고, 값이 바뀌면 TC 를 따라 고친다. 화면 사양의 복귀 이동 대기 시간 예외([`../screens/screen_SCR-004.md`](../screens/screen_SCR-004.md) §복귀 이동)·목업의 상수 실값 예외(`mockup/INDEX.md` §디자인 근거)와 같은 성질의 예외다. 현재 이 예외를 쓰는 자리는 `<CONSENT_ITEMS>` 의 항목 코드다([`USR/tc_USR-04.md`](USR/tc_USR-04.md) `_005`·`_006` — 실재하는 코드와 실재하지 않는 코드의 대비가 판정 자체라 코드를 적지 않으면 TC 가 성립하지 않는다).
	- **비공개여야 하는 값은 이 예외의 대상이 아니다.** `<SELFCHECK_PATH>` 처럼 **경로를 모르게 두는 것이 유일한 완화 장치인 값**(`SEC-003-01`·`SEC-003-02`·`OPS-002`)은 TC 에도 적지 않고 플레이스홀더로만 참조한다 — 한 번 적으면 저장소 기록에 남아 비공개가 깨지고, 그 순간 완화 장치 자체가 사라진다. 이 값을 쓰는 TC 는 **주입값과 응답·동작의 일치 여부**로만 판정한다([`API/tc_API-04.md`](API/tc_API-04.md) §엔드포인트).
- **fault 주입 하네스**(DB 연결 차단·UPDATE 실패·암호 기능 초기화 실패)·**동시 요청 하네스**·**응답 변조 프록시(`MOCK-RESP`)**·**초기 상태 값 주입 하네스**(주입 이스케이프 관측)·**복귀 이동 차단 관측 절차(`CHK-NAVBLOCK`)**·**스크린리더 관측 수단**이 필요한 TC 는 전제에 명시했다. 미구축 상태면 해당 TC 는 🟠 Block 으로 등재한다.

## 테스트 케이스 코드 체계

- **기능단위 TC**: `{ia-code}_{3자리}` — 예 `USR-03_001`. 일련번호는 노드별 001 부터 순차 채번한다. IA 맵이 곧 명명 SSOT 이므로 별도 접두어 매핑표를 두지 않는다.
- **횡단 TC**: 주제별 전용 식별자. **본 산출물이 사용하는 횡단 식별자는 `SCEN_` 하나**이며 `SCEN_001` 부터 순차 채번한다. IA 좌표는 `공통`.
- **`MIG_` 는 사용하지 않는다** — §데이터 이관 범위 참조.
- **폐지 IA 코드**(`ADM`·`ADM-01`~`ADM-03`·`BAT-01`·`BAT-03`)로는 어떤 TC 도 채번하지 않았다(사용 0건).
- **선행 도메인 코드는 인용만** 한다 — SVC·FN·MDL·ENT·SCR·PROC·정책 규칙 ID·EX·BR 의 신설 0건.
- **결번을 둔다** — 전제가 사라진 TC 는 삭제 후 그 번호를 비워 두고 **다른 뜻으로 재사용하지 않는다**. 현재 결번은 `USR-04_008`(거부 제출의 `agreedItemCodes` 미검증 경계)·`USR-05_002`(사용자 거부 패널) 2건이며, 각 파일 §개요에 결번 사유를 적었다.
- **PROC 단계 라벨**은 프로세스 도메인이 확정한 체계(`F` FE · `B` BE · `C` 호출측 · `L` 라이브러리 내부, 레이어별 1부터, 분기는 접미 문자)를 그대로 인용한다.

## 테스트 유형별 케이스 분포

| 유형 | 목표 비율 | 실제 | 비율 | 판정 |
|---|--:|--:|--:|---|
| Positive | ~40% | 79 | 32.6% | 목표보다 낮음(아래 근거) |
| Negative | ~30% | 70 | 28.9% | 목표 부합 |
| Boundary | ~15% | 33 | **13.6%** | **20% 상한 충족** |
| 권한/인증 | ~5% | 12 | 5.0% | 목표 부합(치환 적용 — §AUTH 치환) |
| 상태전이 | ~5% | 22 | 9.1% | 목표보다 높음(아래 근거) |
| 시스템예외 | ~3% | 18 | 7.4% | 목표보다 높음(아래 근거) |
| 조합경계값 | ~2% | 8 | 3.3% | 목표 부합 |

- **상태전이가 높은 이유** — 이 제품의 핵심 규칙 셋(결과 구분 **1회 확정** · 확정 결과 **재안내 무갱신** · 결과 확인·콜백의 **조건부 UPDATE 멱등**)이 전부 상태 전이 성질이다. 이 흐름을 Positive 로 접으면 "덮이지 않는다"는 사실이 검증되지 않는다.
- **시스템예외가 높은 이유** — 저장 3종 갱신이 상위 요청과 **같은 트랜잭션 경계**에 있어, 되돌림 동작을 각 계기마다 확인해야 한다(`EX-BIZ-003` 9건 · `EX-OPS-002` 6건).
- **Positive 가 낮은 이유** — 위 둘로 흡수된 만큼 줄었다. 정상 경로 자체는 여정 TC(`SCEN_001`~`SCEN_006`)와 각 노드의 Happy Path 로 전부 덮인다. 거부 경로 폐지로 Positive 1건(거부 제출)이 Negative(화면 게이팅)로 옮겨 간 것도 한몫한다.

## 이 제품 고유의 TC 설계 제약

만들지 않은 TC 와 그 근거다. 누락이 아니라 **범위 밖이라는 판단**이다.

| 만들지 않은 TC | 근거 |
|---|---|
| 토큰·권한 검사 TC | 인증이 없다(`AUTH-001`). §AUTH 치환으로 대체 |
| 레이트 리밋 TC | 요청 제한을 두지 않는다([`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 — 제외). 반복 호출이 차단되지 않는다는 **수용 리스크 확인 TC**(`SCEN_019`)만 둔다 |
| "N회 실패 후 잠금" TC | 본인확인 재입력 횟수 제한이 없다(`AUTH-002-04`). 제한 없음을 확인하는 `USR-03_006` 으로 대체 |
| 개인정보 마스킹 TC | 표시 대상 개인정보가 없다. **금지 값이 저장·응답·표준 출력 어디에도 남지 않음**을 확인하는 TC 로 대체(`SCEN_015`·`SCEN_016`·`USR-03_012`·`USR-03_013` 등) |
| 성과 지표 목표치 판정 TC | 목표치가 잠정값이며 확정 전까지 미달을 결함으로 다루지 않는다. **카운터 누적 정확성** TC(`BAT-06_001`~`_013`)로 대체 |
| 데이터 이관(`MIG_`) TC | §데이터 이관 범위 참조 |
| 네 번째 결과 경로 TC | 경로는 정확히 3개다. **네 번째가 만들어지지 않음**을 확인하는 `USR-05_005` 를 둔다 |
| 사용자 거부 결과 TC | 거부가 결과 경로에서 폐지됐다(`BIZ-003-03`). **거부 제출·거부 결과 구분·거부 카운터의 부재**를 확인하는 TC(`USR-04_016`·`BAT-04_005`·`BAT-06_006`·`USR-05_005`)로 대체한다 |
| 복귀 이동 실패의 오류 TC | 이동 실패는 예외가 아니다(EX 코드·네 번째 경로를 만들지 않는다). **잔류 + 수동 링크 유지**를 확인하는 `USR-05_015` 로 대체한다 |

### AUTH 치환

템플릿의 "권한/인증 ~5%"·"AUTH-* 정책 적용 화면마다 권한 미충족 케이스"는 이 제품에 그대로 적용할 수 없다. 인증이 **설계상 없기** 때문이다(`AUTH-001-01`~`AUTH-001-03`). 아래 12건으로 치환했고, 각 TC 본문에 치환 사실과 근거를 적었다.

| 치환 형태 | TC | 근거 |
|---|---|---|
| 서버 대면 API 4종이 **인증 없이 호출 가능**함(설계된 부재의 Positive 검증) | `API-01_006`·`API-02_005`·`API-03_007`·`API-04_011` | `AUTH-001-03` |
| **자격이 담긴 요청도 검증 없이 처리**(401·403 미정의) | `API-01_007` | `AUTH-001-03` · EXC-AUTH-01 |
| **관리자 경로·화면·구성 API 가 존재하지 않음** | `SCEN_017` | `AUTH-001-01` |
| **사용자 계정·세션이 존재하지 않음**(새로고침은 처음부터) | `SCEN_018` | `AUTH-001-02` |
| **본인확인(생년월일 복호화)이 유일한 신원 확인 수단** | `USR-03_016` | `AUTH-002-01` · EXC-AUTH-04 |
| **자가진단이 비공개 경로에서만 응답**(다른 경로·메서드는 일반 404) | `API-04_009`·`API-04_010` | `SEC-003-01`·`SEC-003-02` |
| **요청 제한 부재**로 반복 호출이 차단되지 않음(수용 리스크) | `SCEN_019` | `OPS-002-03` |
| **조회로 인한 보관 기산 개시**를 누구든 시작시킬 수 있음(수용 리스크) | `SCEN_021` | `OPS-002-04` |

### 수용 리스크의 취급

`OPS-002` 의 네 리스크(기밀성·무결성/출처·반복 시도·조회로 인한 보관 기산 개시)는 **결함이 아니라 수용된 성질**이다(EXC-OPS-07). 리스크가 실제로 존재함을 확인하는 TC 는 두되(`SCEN_019`·`SCEN_020`·`SCEN_021`·`API-03_007`) **실패로 판정하지 않는다**. 결정적 IV 한계도 같다(EXC-SEC-01 → `SCEN_020`).

### 데이터 이관 범위

**이관 범위가 없다.** 구 `docs/specs`·`apps`·`mockup` 은 directing 단계에서 전량 폐기됐고([`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 — 제외 "기존 구현·사양의 승계"), 데이터베이스 스키마도 이전 구성을 승계하지 않고 새로 설계했다([`../../prd/devspec/database.md`](../../prd/devspec/database.md) §데이터 원칙). 따라서 **이관 대상 정리표와 `MIG_` TC 를 작성하지 않았다.** 구 TC 재검증도 범위 밖이다.

## 검증 절차·판정 기준

- **자동 207건 · 반자동 31건 · 수동 4건.** 반자동은 fault 주입·동시 요청·저장소 전수 점검·시각 제어처럼 **사전 준비가 필요한 관측**을 뜻하고, 수동은 문서·절차 확인(배포 게이트·사용 안내·벡터 실 데이터 점검)이다.
- **TC 사양의 판정 기준**은 세 값이다 — **Pass**(모든 단계의 기대 결과 일치) / **Fail**(하나 이상 불일치, 불일치 항목 기록) / **Block**(전제 조건 미충족으로 실행 불가, 사유 기록).
- **실행 단계의 실제 판정은 5종**으로 세분된다(🟢 Pass / 🔵 Pass-Mock / 🟣 Pass-Static / 🔴 Fail / 🟠 Block) — 정본 [`../../../ai/strategies/qa-execution.md`](../../../ai/strategies/qa-execution.md) §공통 원칙. **`MOCK-RCV` 를 쓰는 전달 검증은 🔵 Pass-Mock** 으로 분리 기록해 실 Pass 와 섞지 않는다.
- **결함 기록** — 재현 절차·기대값·실제값·환경 정보를 함께 남긴다. 사양과 어긋난 TC 는 결함이 아니라 TC 결함(사양 동기화)으로 분류한다.
