# 보안 정책 정의

정본 목록은 [`spec-policies.md`](spec-policies.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

암호화 연동 규약 자체(`SEC-001`)는 분량이 커서 [`policy_SEC-crypto.md`](policy_SEC-crypto.md) 로 분기했다. 본 문서는 그 규약을 **판정에 쓰는 절차**(`SEC-002`)와 **자가진단 경로의 취급 기준**(`SEC-003`)을 담는다.

## 개요

- **정책 목적**: 복호화 성공·실패를 누구나 같은 기준으로 판정하게 하고, 실패를 "사용자가 다시 시도할 일"과 "구조적으로 불가능한 일"로 갈라 결과 구분·화면 경로가 흔들리지 않게 한다. 아울러 자가진단 API 의 유일한 완화 장치인 **경로 비공개**를 운영 규칙으로 못박는다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §제공 가치 — "전달 데이터는 이중 암호화(encX/encY)되어 전달되고 **사용자의 생년월일 입력으로만 복원**된다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 8 — "**연동 규약 자가진단 API**: … 노출 경로는 상수로 고정한 **비공개 경로**다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §시스템 제약사항 — "**경로가 알려지면 이 완화는 사라진다** — 경로 값은 비공개로 취급하고 … 유출이 확인되면 경로를 교체·재배포한다."

### 정책 규칙

| 규칙 ID | 규칙 내용 | 적용 조건 | 적용 지점 | 위반 시 처리 (HTTP·EX 코드) |
|---------|-----------|-----------|-----------|----------------------------|
| SEC-002-01 | 복호화 성공은 아래 **4단계를 모두 통과**한 것만 뜻한다. ① 생년월일 정규화 키로 `encY` 복호화(패딩 검증 포함) → 32바이트 키 획득 ② 획득한 키로 `encX` 복호화(패딩 검증 포함) → X 바이트열 획득 ③ X 를 UTF-8 JSON 으로 파싱 ④ 필수 필드 `trackingKey` 존재·형식 검증. 허브와 자가진단이 같은 절차를 쓴다 | 생년월일이 주어진 모든 복호화 | 검증 | 단계별 처리는 `SEC-002-02`~`SEC-002-04` 를 따른다 |
| SEC-002-02 | **생년월일 입력 이전에 판정 가능한 구조 위반**(암호 파라미터 부재·빈 값·Base64URL 디코드 실패·암호문 길이가 16의 배수 아님·URL 길이 상한 초과)은 복호화를 시도하지 않고 즉시 실패로 확정한다 | 링크 진입 시 | 검증 | 400 `EX-SEC-001`(URL 길이 초과는 `EX-SEC-004`) + 결과 경로 "링크·복호화 오류". 추적 레코드 미생성, 지표 집계만 계수(`BIZ-005-02`) |
| SEC-002-03 | **판정 3·4단계 실패**(X JSON 파싱 실패, `trackingKey` 부재·형식 위반)는 발송처 페이로드의 규약 위반으로 분류하고 결과 구분 `DECRYPT_FAILED` 로 확정한다 | 1·2단계 통과 후 | 검증 | 400 `EX-SEC-002` + 결과 경로 "링크·복호화 오류". 추적 키를 알 수 없어 추적 레코드는 만들지 않는다 |
| SEC-002-04 | **판정 1·2단계 실패**는 생년월일 불일치와 구별할 수 없으므로 **전부 본인확인 실패로 분류**한다. 결과 구분을 확정하지 않고 재입력 안내로 되돌린다 | 생년월일 입력 후 | 검증 | 400 `EX-AUTH-002` + 재입력 안내. 결과 미확정·미기록(`BIZ-001-05`) |
| SEC-002-05 | 실패 응답은 **어느 단계에서 왜 실패했는지 이상의 정보를 담지 않는다**. 복호화 원문·키·중간 값·내부 스택을 응답과 로그에 담지 않는다 | 모든 실패 응답 | 결과 마스킹 | 위반 시 응답 필드·로그 항목 제거(사양 반려). 노출된 값이 있으면 `DATA-001-04` 위반으로 처리 |

### 예외 사항

- **EXC-SEC-05 (1·2단계 통과 후 3·4단계 실패의 판정 근거)**: 1·2단계를 통과했다는 것은 생년월일에서 파생한 키로 두 겹의 PKCS#7 패딩이 모두 맞았다는 뜻이다. 잘못된 생년월일이 두 겹의 패딩 검증을 연달아 통과할 확률은 무시할 수준이므로, 이후의 파싱·필드 실패는 **사용자 입력 문제가 아니라 발송처 페이로드 문제**로 본다. 이 경계가 `EX-AUTH-002`(재입력)와 `EX-SEC-002`(`DECRYPT_FAILED`)를 가르는 유일한 기준이다.
- **EXC-SEC-06 (자가진단의 판정 범위)**: 자가진단은 `SEC-002-01` 의 4단계를 그대로 수행하되 **판정 결과와 사유 코드만** 응답한다. 결과 구분 확정·추적 레코드·동의 증적·지표 집계·수신처 전달을 하지 않는다(`SEC-003-03`).
- **EXC-SEC-07 (승인 시점의 재복호화)**: 본인확인에서 이미 복호화에 성공했더라도 승인 시점에 다시 복호화한다(`BIZ-002-06`). 이때 4단계가 실패하면 `SEC-002-03`·`SEC-002-04` 를 다시 적용한다.

|---------|----------|-------------------------------|--------------------------------|

| SEC-002-03 | PROC-102 · PROC-104 · PROC-204 | 복호화 판정 3·4단계 | 검증 |
| SEC-002-04 | PROC-102 | 복호화 판정 1·2단계 | 검증 |
| SEC-002-05 | PROC-101 · PROC-102 · PROC-104 · PROC-204 | 응답 구성 | 결과 마스킹 |

### 구현 가이드

- 판정 4단계는 **하나의 함수로 묶어 허브·자가진단이 공유**한다. 두 경로가 다른 코드를 쓰면 자가진단이 통과한 값이 연동에서 실패하는 사고가 난다.
- 단계 번호를 내부 실패 사유로 유지하되 응답에는 EX 코드만 싣는다(`SEC-002-05`).
- 암호문 길이의 16 배수 검사는 디코드 직후 수행한다 — 복호화를 시도하기 전에 걸러 낼 수 있는 가장 값싼 검사다.

## SEC-003 자가진단 경로 취급

### 기본 정보

| 항목 | 내용 |
|------|------|
| 정책명 | 자가진단 경로 취급 |
| 분류 | SEC |
| 적용 범위 | 연동 규약 자가진단 API 의 노출 경로와 그 경로 값의 관리 |
| 우선순위 | 높음 |
| 관련 정책 | `OPS-001`(상수 주입) · `OPS-002`(접근 통제 없음) · `SEC-002`(판정 절차) |
| 적용 PROC | PROC-204 · PROC-901 |
| 관련 IA 항목 | `API-04` |

### 정책 규칙

| 규칙 ID | 규칙 내용 | 적용 조건 | 적용 지점 | 위반 시 처리 (HTTP·EX 코드) |
|---------|-----------|-----------|-----------|----------------------------|
| SEC-003-01 | 자가진단 API 의 **운영 값 경로는 git 으로 관리되는 상수표에 적지 않고, 배포 시점에 주입되는 비밀 값으로 다룬다**. 상수표([`CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수)에는 `<SELFCHECK_PATH>` 의 **형식과 잠정값**만 남는다 | 상시 | 검증 | 운영 값이 저장소·공개 문서에 기록되면 그 경로는 즉시 유출로 간주하고 `SEC-003-05` 를 적용한다 |
| SEC-003-02 | 경로 값을 공개 문서·클라이언트 코드·응답 본문·오류 메시지에 담지 않는다. 자가진단 경로가 아닌 요청에는 **경로의 존재를 드러내지 않는 일반 404** 로 응답한다 | 상시 | 결과 마스킹 | 404(별도 EX 코드 없음). 경로 힌트를 담은 응답은 사양 반려 |
| SEC-003-03 | 자가진단 호출은 **연동으로 취급하지 않는다** — 수신처 전달·추적 레코드·동의 증적·지표 집계 어느 것도 만들지 않고 복호화 원문을 응답에 담지 않는다 | 자가진단 요청 처리 | 검증 | 기록·전달이 발생하면 `DATA-001-01` 위반. 원문 노출은 `DATA-001-04` 위반 |
| SEC-003-04 | 자가진단 요청은 `encX`·`encY`·생년월일 셋을 모두 받는다. **셋 중 하나라도 없으면** 판정을 수행하지 않는다(본문을 JSON 으로 해석할 수 없는 경우도 부재와 같이 다룬다) | 자가진단 요청 진입 | 검증 | 400 `EX-SEC-003` |
| SEC-003-05 | 경로 값의 **유출이 확인되면 새 경로로 교체하고 재배포**한다. 교체 전까지는 유출 상태를 수용 리스크로 기록한다(`OPS-002`). 운영 값은 최초 배포 시점에 새로 지정한다 | 유출 확인 시 · 최초 운영 배포 시 | 검증 | 배포 절차 중단·경로 재지정(절차 통제 — 애플리케이션 분기 아님) |

- **`SEC-003-04` 의 경계 — 부재만 다룬다.** 입력이 있는데 **형식이 어긋나는 경우는 본 규칙이 다루지 않는다.** 생년월일 형식은 `AUTH-002-02`(400 `EX-AUTH-001`), 암호값 구조는 `SEC-002-02`(자가진단에서는 판정이 수행된 결과이므로 200 부적합 · 사유 `EX-SEC-001`)가 각각 맡는다. 따라서 `EX-SEC-003` 를 형식 위반에 쓰지 않는다.

### 예외 사항

- **EXC-SEC-08 (운영 환경 노출 — 기본안 적용)**: 자가진단 API 는 **운영 환경에도 노출**한다. 발송처가 운영 통합 시점에 규약을 확인할 수 있어야 자가진단의 목적이 성립하기 때문이다. [`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑧ 의 **담당자 확인 대기 항목이며 기본안을 적용**했다. 다르게 정해지면 본 예외만 개정한다.
- **EXC-SEC-09 (요청 제한 없음)**: 자가진단은 규약 적합성을 즉시 알려 주므로 반복 시도의 판정 수단이 될 수 있으나, 요청 제한을 두지 않는 것이 이 제품의 결정이다(`OPS-002`). 경로 비공개가 유일한 완화 장치이며 그래서 `SEC-003-01`·`SEC-003-05` 가 필요하다.
- **EXC-SEC-10 (잠정값 상태)**: 상수표의 현재 `<SELFCHECK_PATH>` 값은 잠정값이고 저장소에 기록돼 있으므로 **비공개로 볼 수 없다**. 개발·검증 환경 기동에는 쓰되 이 값 그대로 운영 배포하지 않는다(`OPS-001-03`).

### 구현 가이드

- 경로는 **애플리케이션 설정 값 하나로 주입**받아 라우팅에 쓴다. 소스·정적 자산·프런트엔드 번들 어디에도 값을 넣지 않는다.
- 배포 파이프라인·비밀 관리 수단의 구체 형태는 build 단계에서 정한다([`../../prd/devspec/infra.md`](../../prd/devspec/infra.md) §미결). 정책이 요구하는 것은 "저장소에 남지 않고 배포 시 주입된다"는 성질뿐이다.
- 운영 값은 추측하기 어려운 무작위 구간을 포함한다. 잠정값의 형식(경로 접두 + 무작위 문자열)을 그대로 따르면 형식 검증이 통과한다.
- 자가진단 응답에는 판정 결과·사유 코드와 **허브의 규약 버전**을 담는다(`SEC-001-11` 의 호환 판정 근거).
