# 정책 정의서 (목록)

AccountInterlockHub 가 준수하는 정책의 단일 출처다. 방향 근거는 [`../../prd/PRD.md`](../../prd/PRD.md), 정보 구조는 [`../../prd/ia/IA.md`](../../prd/ia/IA.md), 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md) 를 따른다.

본 문서는 정책의 **설계 방향·코드체계·분류·목록**을 담고, 규칙 본문은 그룹별 하위 정의서가 갖는다.

## 정책 설계 규칙 및 기본 방향

1. **상수 참조 원칙** — 연동 구성 값을 본문에 옮겨 적지 않고 플레이스홀더로만 참조한다. 값의 단일 출처는 [`CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수이며, 값이 바뀌어도 정책 개정이 필요하지 않다.
2. **없는 것을 만들지 않는다** — 관리자 인증·사용자 계정 인증·서버 대면 API 인증·요청 제한·발송처 서명 검증·링크 만료는 이 제품이 **두지 않기로 결정한** 항목이다. 정책은 그 부재를 명시적으로 선언하고 수용 리스크를 기록하되, 대체 장치를 새로 도입하지 않는다.
3. **측정 가능성** — 모든 규칙은 값·조건·임계값으로 판정할 수 있어야 한다. 판정할 수 없는 규칙은 두지 않는다.
4. **단일 열거형** — 결과 구분·예외(EX) 코드처럼 여러 도메인이 공유하는 값 집합은 정책이 정본이고 다른 도메인은 참조만 한다(별칭·부분집합·확장 금지).
5. **무저장 우선** — 저장이 필요한지 먼저 묻고, 필요하면 저장 대상 셋(추적 레코드·동의 증적·지표 집계) 중 하나에 담는다. 셋 밖의 저장은 정책 위반이다.

## 코드체계

- **정책 코드**: `<그룹>-<순번 3자리>` — 예 `SEC-001`.
- **규칙 ID**: `<그룹>-<순번 3자리>-<리비전 2자리>` — 예 `SEC-001-01`. 마지막 2자리는 정책 안에서의 규칙 자리이자 리비전 자리다. 초회는 `01` 부터 차례로 부여하고, 규칙을 개정하면 **미사용 번호를 새로 부여**한다. 한 번 부여된 규칙 ID 는 재사용하지 않는다.
- **예외 ID**: `EXC-<그룹>-<순번 2자리>` — 예 `EXC-SEC-01`. 프로세스 의사코드에서 인용한다.
- **그룹 코드**: `AUTH`(인증·인가) · `DATA`(데이터) · `BIZ`(비즈니스 규칙) · `SEC`(보안) · `OPS`(운영).

## 적용 지점 분류

모든 규칙은 아래 넷 중 하나 이상을 갖는다.

- **검증(validate)** — 요청 진입 시 입력값·상태를 사전 검증. 런타임 분기가 없는 설계 제약·배포 절차 통제도 여기에 넣고 "사양·구현 게이트"·"배포 절차"임을 단계명에 밝힌다.
- **입력 가공(transform)** — 검증 통과 후 도메인 값으로 변환할 때 적용(정규화·인코딩·기본값 보충).
- **결과 마스킹(mask)** — 응답·화면·로그를 만들 때 값 제거·변환.
- **감사 로그(audit)** — 트랜잭션 종료 후 감사 로그 기록. **이 제품은 감사 로그 저장소를 두지 않으므로 어떤 규칙도 이 분류를 쓰지 않는다**(`OPS-003-01`). 사후 관측 수단은 추적 레코드의 결과 구분·지표 집계·동의 증적 셋뿐이다.

## 우선순위 및 충돌 해결 원칙

정책이 서로 다른 결론을 낼 때는 아래 순서로 판단한다. 위 항목이 아래 항목을 이긴다.

1. **개인정보 보호·무저장**(`DATA-001`) — 저장·노출을 늘리는 해석은 언제나 진다.
2. **암호화 연동 규약의 대칭**(`SEC-001`) — 라이브러리와 허브가 같은 결과를 내야 한다. 한쪽만 바꾸는 해석은 진다.
3. **결과·값 체계의 단일성**(`BIZ-001`) — 도메인 편의를 위한 값 추가·별칭은 진다.
4. **사용자 진행 가능성** — 위 셋과 충돌하지 않는 범위에서 사용자가 연동을 마칠 수 있는 해석을 택한다.
5. **운영 단순성**(`OPS`) — 위 넷이 갈리지 않을 때의 최종 기준이다.

- 정책과 개발사양이 어긋나면 개발사양([`../../prd/devspec/`](../../prd/devspec/))이 상위다. 정책은 그 미확정 세부를 채울 뿐 상위 규약과 충돌하는 값을 만들지 않는다.
- 정책과 후행 도메인 사양이 어긋나면 정책이 상위다. 후행 도메인은 규칙 ID 를 인용만 하고 값을 복제하지 않는다.

## 예외(EX) 코드 카탈로그

정책 위반의 응답 코드다. **자가진단 API 의 사유 코드와 연동 라이브러리의 오류 사유 코드도 같은 값을 쓴다** — 발송처가 라이브러리·자가진단 두 경로에서 같은 진단을 얻게 하기 위함이다. 후행 도메인은 본 표를 참조만 하고 코드를 새로 만들지 않는다.

| EX 코드 | HTTP | 의미 | 정의 규칙 |
|---|---|---|---|
| `EX-AUTH-001` | 400 | 생년월일 입력 형식 위반(`yyMMdd` 6자리 숫자 아님) | `AUTH-002-02` |
| `EX-AUTH-002` | 400 | 본인확인 실패 — 복호화 판정 1·2단계 실패. 결과 미확정·재입력 안내 | `AUTH-002-03` |
| `EX-SEC-001` | 400 | 연동 요청 암호 파라미터 부재·형식 위반(생년월일 입력 이전 구조 판정 실패) | `SEC-002-02` |
| `EX-SEC-002` | 400 | 규약 위반 — 복호화 판정 3·4단계 실패(X JSON 파싱 실패·`trackingKey` 부재·형식 위반) | `SEC-002-03` |
| `EX-SEC-003` | 400 | 자가진단 요청 입력 부재·형식 위반 | `SEC-003-04` |
| `EX-SEC-004` | 400 | 크기 상한 위반(X 평문 상한 초과 · 연동 요청 URL 길이 상한 초과) | `SEC-001-09`·`SEC-001-10` |
| `EX-BIZ-001` | 400 | 필수 동의 미충족 상태의 승인 제출 | `BIZ-003-02` |
| `EX-BIZ-002` | 502 | 수신처 전달 실패(즉시 재시도 소진) | `BIZ-004-03` |
| `EX-BIZ-003` | 500 | 연동 처리 중 내부 오류(동의 증적 기록 실패 등) — 결과 미확정·재시도 가능 | `BIZ-003-04` |
| `EX-DATA-001` | 404 | 조회·통지 대상 추적 레코드 없음 | `BIZ-002-05` |
| `EX-DATA-002` | 400 | 연동 추적 키 형식 위반(조회·콜백 입력) | `DATA-004-03` |
| `EX-OPS-001` | — | 필수 상수 미주입·형식 위반 → 기동 중단(HTTP 응답 없음) | `OPS-001-02` |
| `EX-OPS-002` | 500 | 예상치 못한 내부 처리 오류 — 위 코드 어느 것으로도 분류되지 않는 요청 처리의 기술적 실패. 결과 미확정 | `OPS-003-03` |

- 자가진단 경로가 아닌 경로로 온 자가진단 요청은 별도 EX 코드 없이 일반 404 로 처리한다(경로의 존재를 드러내지 않기 위함 — `SEC-003-02`).
- `EX-OPS-002` 는 **인터페이스 수준의 마지막 방어**다. 위 코드로 분류되는 실패에는 쓰지 않으며, 응답에 내부 사유·스택·중간 값을 담지 않는다(`SEC-002-05`).

## 잠정값·미결 항목의 취급

- **잠정값** — `<RECEIVER_DELIVERY_URL>`·`<HUB_BASE_URL_PROD>`·`<HUB_BASE_URL_DEV>`·`<SELFCHECK_PATH>`·`<CONSENT_NOTICE>`·`<CONSENT_PROOF_RETENTION_MONTHS>` 와 성과 지표 목표치는 잠정값이다. 정책은 이 값들을 참조만 하며 수치를 본문에 복제하지 않는다. 잠정 상태의 운영 배포 금지는 `OPS-001-03` 이 규칙으로 갖는다.
- **담당자 확인 대기(기본안 적용)** — 수신처 전달 실패 후의 재시도 경로(`BIZ-004`)와 자가진단 API 의 운영 환경 노출(`SEC-003`)은 [`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요의 **기본안대로** 사양화했다. 다르게 정해지면 해당 규칙만 개정한다.
- **범위 밖** — 링크 만료(TTL)·1회성 사용·발송처 서명 검증·요청 제한·Delphi 지원은 이번 범위가 아니므로 정책을 두지 않는다. 그 부재로 남는 리스크는 `OPS-002` 가 수용 리스크로 기록한다.
