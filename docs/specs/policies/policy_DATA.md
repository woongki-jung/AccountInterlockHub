# 데이터 정책 정의

정본 목록은 [`spec-policies.md`](spec-policies.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **정책 목적**: 허브가 **무엇을 남기고 무엇을 남기지 않는지**, 남긴 것을 언제 지우는지를 확정한다. 이 제품의 핵심 가치가 "사용자 정보를 지속 보관하지 않는 중개"이므로, 저장 범위가 한 줄이라도 넓어지면 제품 정의가 무너진다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §시스템 제약사항 — "**데이터 원칙**: 허브는 사용자 정보·복호화 원문(X)을 지속 보관하지 않는다. 복호화는 **연동 실행 시점에 메모리 상에서만** 수행하고 전달 후 폐기한다. 저장 대상은 **연동 추적 레코드 · 동의 증적 · 연동 지표 집계 셋**이며 …"
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 10 — "**동의 증적 기록**: 사용자가 **어느 시점의 어떤 동의 항목에 동의했는지**를 개인정보 없이 남긴다."
	- [`../../prd/devspec/database.md`](../../prd/devspec/database.md) §데이터 원칙 · §동의 증적 · §보관 정책.
- **관련 법규**: 개인정보 보호법 제17조(개인정보의 제공) — 제3자 제공 시 정보주체 동의. 동의 항목·증적 정책(`DATA-003`)의 근거다.

### 예외 사항

- **EXC-DATA-01 (추적 키는 예외)**: 연동 추적 레코드와 동의 증적이 갖는 **연동 추적 키값**은 저장한다. 추적 키는 불투명 문자열이며 개인정보 원문이 아니다(`DATA-004-01`).
- **EXC-DATA-02 (동의 항목 스냅샷)**: 동의 증적이 보존하는 항목 내용은 **연동 구성의 저장이 아니라 증적**이다. 서비스가 참조하는 구성은 언제나 배포된 상수다(`DATA-003-02`).
- **EXC-DATA-03 (운영 로그)**: 요청 처리의 기술적 실패(연결 오류·시간 초과 등)를 남기는 운영 로그는 두되, `DATA-001-04` 의 금지 항목을 담지 않는다. 로깅 구성의 구체 형태는 build 단계가 정한다([`../../prd/devspec/infra.md`](../../prd/devspec/infra.md) §미결).

### 구현 가이드

- 저장 계층은 세 저장 대상에 대응하는 접근 경로만 갖는다. 그 밖의 저장 경로를 만들지 않으면 규칙 위반이 구조적으로 어려워진다.
- 복호화 결과는 지역 변수로만 다루고 전역 상태·요청 컨텍스트 저장소에 넣지 않는다.
- 로그 출력 지점에서 금지 항목을 걸러 내는 공통 처리를 두면 `DATA-001-04` 를 반복 점검하지 않아도 된다.

### 예외 사항

- **EXC-DATA-04 (결과 확인이 보관 기산을 시작시킨다)**: 처리상태 확인 API 가 결과를 담아 응답한 시점에 그 레코드는 결과 확인 완료가 되고 `<RETENTION_MONTHS>` 기산이 시작된다([`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §처리상태 확인 API). 인증이 없으므로 추적 키를 아는 누구든 이 기산을 시작시킬 수 있다 — 수용 리스크다(`OPS-002-04`).
- **EXC-DATA-05 (확정 결과 재안내)**: 확정 결과 재안내는 레코드를 갱신하지 않으므로 보관 기산점을 밀지 않는다(`BIZ-002-04`).
- **EXC-DATA-06 (잠정 보존 기간)**: `<CONSENT_PROOF_RETENTION_MONTHS>` 는 잠정값이며 법령·계약 확인 후 확정한다. 확정은 상수 값 교체로 끝나고 본 정책은 개정하지 않는다.

### 구현 가이드

- 기간 값은 상수 주입으로 받아 실행 시점에 기준 일시를 계산한다. 값이 코드에 박히면 확정 시 재작성이 필요해진다.
- 수동 실행 진입점은 스케줄 실행과 **같은 삭제 로직을 공유**하고 진입 경로만 다르다. 처리 결과 요약(대상별 삭제 건수·기준 일시)을 표준 출력으로, 성공·실패를 종료 코드로 내보낸다.
- 삭제는 대상별로 분리해 세고, 요약에 각 건수를 담는다(검증의 관측 지점).

### 예외 사항

- **EXC-DATA-07 (안내 문구 확정 주체)**: `<CONSENT_NOTICE>` 는 잠정 문구다. 개인정보 제3자 제공 고지는 통상 **제공받는 자·제공 항목·보유 기간·거부 시 불이익**을 담으므로 실문구는 그 관점에서 검토해 확정하며, **검토 주체는 담당자**이고 법적 판단이 필요하면 법무 확인을 거친다([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ④). 사양은 상수를 참조하므로 문구 확정 시 개정이 필요하지 않다.
- **EXC-DATA-08 (허용 형태 범위)**: 안내 문구는 상수표가 정한 허용 형태(최대 길이·단락 수·평문 한정) 범위 안에서만 값 교체로 반영된다. 범위를 벗어나면 화면 사양을 함께 고쳐야 한다.
- **EXC-DATA-09 (증적의 존속)**: 동의 증적은 추적 레코드보다 오래 남는다 — 사후 입증이 목적이기 때문이다(`DATA-002-02`).

### 구현 가이드

- 버전 식별자는 상수 값(`<CONSENT_ITEMS>` + `<CONSENT_NOTICE>`)에서 **결정적으로 산출**하면 `DATA-003-03` 이 자동으로 지켜진다. 산출 방식(값 해시·수동 채번 등)의 확정은 데이터 도메인 소관이다.
- 스냅샷은 그 시점 항목의 노출 내용을 그대로 담는다 — 버전 식별자만으로는 사후에 내용을 알 수 없기 때문이다.
- 동의 증적에는 추적 키 외의 어떤 사용자 식별 값도 넣지 않는다. 사용자 신원 확인은 발송처가 추적 키로 수행한다.

- **EXC-DATA-10 (형식 상한의 근거)**: X 평문 상한이 1,024바이트(`SEC-001-09`)이므로 추적 키는 그보다 짧다. 255자는 그 안에서 넉넉한 상한이며 데이터 도메인이 정하는 컬럼 길이와 **같은 값**을 쓴다. 값이 달라지면 데이터 도메인 값을 따르고 본 규칙을 개정한다.
- **EXC-DATA-11 (복호화 단계의 형식 검증)**: 복호화 판정 4단계의 `trackingKey` 형식 검증도 같은 상한을 쓰되, 실패는 `EX-SEC-002`(규약 위반)로 분류한다(`SEC-002-03`). 조회·통지 입력의 형식 위반(`EX-DATA-002`)과 구별한다.
