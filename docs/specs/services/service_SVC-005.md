# 연동 결과 안내 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 연동이 어떻게 끝났는지를 **네 경로 중 하나로** 사용자에게 알린다. 결과가 이미 확정된 링크로 다시 들어와도 같은 경로를 다시 보여 주어, 사용자가 보는 결과와 발송처가 조회하는 결과가 어긋나지 않게 한다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 6 — "결과를 네 경로로 구분해 사용자에게 표시한다 — 연동 완료 · 사용자 거부 · 링크·복호화 오류 · 수신처 전달 실패. 결과가 이미 확정된 링크로 다시 진입하면 **그 결과 경로를 그대로 다시 안내**한다(경로를 추가하지 않는다)."
	- [`../../prd/devspec/database.md`](../../prd/devspec/database.md) §추적 키 중복 수신 3.

### 사용자 정의

- **사용자** — 안내를 받는 유일한 주체다. 안내는 사용자가 다음에 무엇을 해야 하는지 판단할 수 있는 수준까지만 담는다.
- **발송처** — 결과 안내 화면을 보지 않는다. 결과는 서버 대면 API 로 조회한다(푸시 통지 경로는 두지 않는다).

### 관련 서비스

- `SVC-001`·`SVC-002`·`SVC-003`·`SVC-004` — 결과·실패를 넘겨준다.
- `SVC-010` — 발송처가 같은 결과 구분을 조회로 확인한다. 두 표면이 같은 값 체계를 쓴다.
- `SVC-014` — 확정 결과의 출처가 되는 레코드를 보유한다.

### 예외 사항

- **다섯 번째 경로를 만들지 않는다.** 확정 결과 재안내도 새 경로가 아니라 기존 경로의 재표시 + 보조 표시다.
- **경로 ③ 은 두 출처를 받는다** — 추적 레코드가 없는 진입 단계 실패와 `DECRYPT_FAILED`. 따라서 결과 구분 값이 없어도 이 경로를 그릴 수 있어야 한다.
- **보관 기간이 지나 레코드가 삭제된 뒤의 재진입**은 확정 결과를 알 수 없으므로 새 연동으로 시작한다. 재안내가 아니다.
- 결과 안내의 문구·표시 형식·경로를 화면으로 어떻게 나눌지는 화면 도메인이 정한다. 본 사양은 **어떤 결과가 어느 경로로 가는지**만 정한다.

### 구현 가이드

- 결과 구분은 문자열 상수 네 개로 한 곳에 정의하고 화면·API·집계가 그 정의를 가져다 쓴다. 화면에서 별칭·대소문자 변형을 만들지 않는다.
- "결과 확정" 판정은 결과 구분 값의 존재 여부로 한다.
- 재안내 여부는 안내 구성 단계에서만 쓰는 표시 정보이며 저장 대상이 아니다.
