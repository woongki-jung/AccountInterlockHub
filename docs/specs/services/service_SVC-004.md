# 연동 실행 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 승인이 확정된 연동에 대해 **전달 데이터를 다시 복원해 수신처에 넘긴다**. 제품의 핵심 가치가 성립하는 지점이며, 원문을 저장하지 않기 위해 복호화를 여기서 한 번 더 수행하고 전달 직후 폐기한다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 5 — "**연동 실행 (복호화·전달)**: 승인 시 허브가 생년월일로 복호화해 X를 얻고, 상수로 고정된 수신처(B) 주소로 전달한다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §시스템 제약사항 — "복호화는 **연동 실행 시점에 메모리 상에서만** 수행하고 전달 후 폐기한다."

### 사용자 정의

- **사용자** — 승인으로 이 서비스를 발화시키지만 전달 자체에는 관여하지 않는다. 전달이 끝날 때까지 화면에서 기다린다.
- **수신처** — 전달을 받는 대상이다. 전달 성공 판정의 근거가 되는 응답을 돌려준다.
- 전달은 **서버 간 호출**로만 수행한다. 브라우저를 경유하면 복호화 원문이 사용자 단말에 노출된다.

### 관련 서비스

- `SVC-003` — 승인 확정을 넘겨준다.
- `SVC-005` — 확정된 결과를 경로 ①·②·③ 으로 받는다.
- `SVC-012` — 수신처가 이후 완료를 통지한다.
- `SVC-014`·`SVC-016` — 결과를 기록·계수한다.

### 예외 사항

- **재시도 경로는 담당자 확인 대기 항목이며 기본안을 적용했다**([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑧). ① 허브는 사용자가 진입해 있는 동안에만 재시도하고 ② 결과가 확정된 뒤의 재연동은 발송처가 **새 추적 키로 새 요청을 발행**해 수행한다. 다르게 정해지면 이 서비스의 F-004·예외 흐름만 개정한다.
- **잠정 전달 주소 상태에서는 전달이 항상 실패한다.** 상수의 잠정값이 문서용 예약 도메인이라 실 호스트로 연결되지 않기 때문이며, `DELIVERY_FAILED` 로 끝나는 것이 그 상태의 정상 동작이다. 이 상태로 운영 배포하지 않는다.
- **전달 성공 판정의 구체 기준**(수신처 응답의 어느 범위를 성공으로 볼지)은 기능·API 도메인이 확정한다. 서비스가 요구하는 것은 성공·실패 판정이 결과 구분과 1:1 로 이어지는 것뿐이다.
- **허브는 요청의 출처를 검증하지 않는다.** 규약대로 만든 암호값이면 출처와 무관하게 복호화·중개된다 — 수용 리스크다(`OPS-002-02`).

### 구현 가이드

- 재시도 중에도 전달 데이터는 메모리에만 둔다. 재시도를 위해 큐·파일에 적재하면 무저장 원칙이 깨진다.
- 총 소요 상한은 사용자가 화면에서 기다리는 시간이다. 회당 대기 상한과 간격의 합이 상한을 넘지 않도록 구성한다.
- 결과 확정·카운터 갱신은 같은 트랜잭션 경계에서 처리해 이중 계수·누락을 막는다.
- 전달 대상 주소는 상수 하나로 주입받는다. 연동이 1:1 고정이라 대상 선택 로직이 없다.
