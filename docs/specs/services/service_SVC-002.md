# 본인확인 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 사용자가 넣은 생년월일로 전달 데이터가 복원되는지를 확인해 **본인 여부를 판정**한다. 이 제품의 유일한 신원 확인 수단이며, 복원에 성공한 이 시점이 허브가 연동을 추적 키로 식별하게 되는 최초 시점이라 **연동 추적 레코드도 여기서 만들어진다**.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §제공 가치 — "전달 데이터는 이중 암호화(encX/encY)되어 전달되고 **사용자의 생년월일 입력으로만 복원**된다. 허브는 값을 저장하지 않고 연동 실행 시점에만 복호화한다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 9 — "연동 추적 키 기준 **단일 추적 레코드**를 **사용자가 진입한 시점에 생성**하고 …"

### 사용자 정의

- **사용자** — 생년월일을 넣는 유일한 주체다. 생년월일은 인증 자격이 아니라 **복호화의 나머지 키**이며, 허브는 대조할 원본을 갖고 있지 않다.
- 본인확인에 성공해도 계정·세션이 만들어지지 않는다. 이후 단계는 같은 연동 요청의 처리 문맥으로만 이어진다.

### 관련 서비스

- `SVC-001` — 구조 판정을 통과한 진입을 넘겨준다.
- `SVC-003` — 판정 통과 후 이어받는다.
- `SVC-005` — 판정 3·4단계 실패와 확정 결과 재안내를 받는다.
- `SVC-014` — 추적 레코드의 생성·이어쓰기를 수행한다.
- `SVC-016` — 요청 수를 계수한다.
- `SVC-013` — 같은 복호화 판정 절차를 기록 없이 수행한다.

### 예외 사항

- **판정 1·2단계 실패와 생년월일 불일치는 구별되지 않는다.** 두 겹의 패딩 검증을 잘못된 생년월일이 연달아 통과할 확률이 무시할 수준이라, 1·2단계 실패는 전부 본인확인 실패로 다룬다. 이 경계가 재입력과 `DECRYPT_FAILED` 를 가르는 유일한 기준이다.
- **재입력을 막는 장치가 없다.** 생년월일은 경우의 수가 작고 요청 제한도 없으므로 온라인 반복 시도가 가능하다 — 수용 리스크다(`OPS-002-01`·`OPS-002-03`).
- **보관 기간이 지나 레코드가 삭제된 뒤 같은 추적 키가 들어오면** 허브는 중복을 알 수 없어 새 레코드를 만든다. 유일성 책임이 발송처에 있다는 전제에서 수용한다.
- 본인확인에서 복호화한 원문은 승인 시점에 **다시 복호화**해 얻는다. 요청 사이에 남기지 않기 위한 의도된 중복 수행이다.

### 구현 가이드

- 판정 4단계는 하나의 절차로 묶어 `SVC-004`·`SVC-013` 이 **같은 절차를 공유**한다. 경로마다 다른 판정을 쓰면 자가진단이 통과한 값이 연동에서 실패하는 사고가 난다.
- 사전 조회 → 3분기 판정 → 생성·이어쓰기·재안내를 한 곳에서 처리한다. 분기가 흩어지면 확정 결과가 덮이는 사고가 난다.
- 형식 검증은 화면과 서버 양쪽에서 하되 판정 근거는 서버 검증이다.
- 생년월일은 입력 상태로만 보유하고 URL·로그·저장소 어디에도 남기지 않는다.
