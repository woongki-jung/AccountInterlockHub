# 동의·승인 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 사용자가 **자기 정보가 누구에게 어떤 항목으로 제공되는지 확인한 뒤 스스로 동의 여부를 결정**하게 한다. **필수 항목에 모두 동의해야만** 승인을 제출할 수 있고 그 승인으로만 연동이 진행되며, 동의한 사실은 개인정보를 담지 않는 증적으로 남는다. **동의하지 않은 제출을 결과 단계로 보내는 경로는 없다.**
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §제공 가치 — "**동의 기반 투명성**: 사용자가 어떤 항목에 동의하는지 화면에서 확인하고 스스로 동의 여부를 결정한다. **전 항목 동의가 진행 조건**이므로 동의 없이 연동이 실행되는 경로가 없다. 동의 사실은 개인정보를 담지 않는 **동의 증적**으로 남는다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 4 — "… 상수로 고정된 동의 항목 노출, **전 항목 동의를 조건으로 승인 제출**. 동의하지 않은 채 제출하면 동의 화면의 **유효성 안내**(…)로 막고 결과 단계로 보내지 않는다 — **사용자 거부는 결과 경로가 아니다**. 동의하지 않으려는 사용자의 종료 수단은 창을 닫는 것이며, 그 연동은 결과 미확정으로 남아 보관 기한에 삭제된다."

- **BR-004 와 BR-005 는 같은 조건을 두 곳에서 판정한다** — BR-004 는 화면(사용자 경험), BR-005 는 서버(실제 게이트). 화면 판정만 두고 서버 판정을 생략하면 `BIZ-003-02` 위반이다.

### 사용자 정의

- **사용자** — 동의 여부를 결정하는 유일한 주체다. 어떤 역할도 사용자를 대신해 동의할 수 없고, 동의하지 않으면 연동은 진행되지 않는다.
- **발송처·수신처** — 동의 항목의 내용에 관여하지 않는다. 항목은 허브의 배포 상수가 정본이다.
- **허브 운영자** — 상수를 바꿔 항목·문구를 갱신할 수 있으나 화면 조작 수단은 없다. 항목·문구가 바뀌면 버전 식별자도 함께 바뀐다.

### 관련 서비스

- `SVC-002` — 본인확인을 통과한 연동을 넘겨준다.
- `SVC-004` — 승인 확정을 이어받아 전달을 수행한다.
- `SVC-005` — 본 서비스는 결과 경로를 만들지 않는다. 미동의로 끝난 연동은 결과 단계로 넘어가지 않는다(`BIZ-003-03`).
- `SVC-015` — 동의 증적을 기록한다.
- `SVC-014` — 승인 사실을 레코드에 이어 쓴다. 미동의로 끝난 연동은 **결과 미확정**으로 남는다.
- `SVC-018` — 동의 항목 상수를 파싱하고 버전 식별자를 산출한다.

### 예외 사항

- **선택 항목은 승인을 막지 않는다.** 현재 상수의 항목은 필수 1건이지만, 상수가 바뀔 수 있으므로 필수·선택 구분을 전제로 판정한다.
- **안내 문구가 비어 있어도 승인은 가능하다.** 문구 부재는 안내 영역 미표시일 뿐 게이팅 조건이 아니다.
- **미동의 이탈은 결과가 아니다.** 동의하지 않은 채 창을 닫으면 그 연동은 **결과 미확정**으로 남았다가 생성 기산 보관 상한에 삭제된다(`EXC-BIZ-05` · `DATA-002-01` ②). 같은 링크로 다시 들어오면 확정 결과 재안내가 아니라 미확정 레코드를 이어 써 동의 흐름을 계속한다(`BIZ-002-03` ②).
- 동의 안내 문구는 잠정값이며 실문구 확정은 담당자 소관이다(필요 시 법무 확인). 사양은 상수를 참조하므로 문구 확정으로 개정되지 않는다.

### 구현 가이드

- 동의 항목은 기동 시 파싱한 상수를 그대로 쓴다. 항목을 데이터베이스에 두지 않는다.
- 승인 요청에는 사용자가 동의한 항목이 **식별 가능한 형태**로 담겨야 서버 재검증과 증적 기록이 함께 성립한다. 구체 필드 형태는 기능·API 도메인이 정한다.
- 화면 검증은 사용자 편의이고 판정 근거는 서버 검증이다. 화면 검증만 두면 `BIZ-003-02` 위반이다.
- **진행 의사 값으로 결과를 가르는 분기를 두지 않는다.** 거부 제출 경로가 없어 승인 요청의 진행 의사가 하나뿐이므로, 승인 성립 조건은 **필수 동의 충족**으로 일원화한다(`BIZ-003-01`). 요청 필드 구성은 기능·API 도메인 소관이지만 도달 불가 분기를 계약에 남기지 않는다.
- 증적 기록과 승인 확정을 같은 처리 경계에 두어, 증적이 없는 승인이나 승인 없는 증적이 생기지 않게 한다.
