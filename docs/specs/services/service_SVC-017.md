# 보관정책 배치 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 보관 기간이 지난 기록을 **일 단위로 지워** 개인정보를 지속 보관하지 않는다는 제품 원칙을 실제로 유지시킨다. 스케줄만으로는 실행 결과를 관측할 수 없으므로 **수동 실행 진입점**을 함께 두어 같은 로직을 명령으로도 돌릴 수 있게 한다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 9 — "일 단위 배치로 보관 기간 경과분을 삭제한다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §프로그램 구성·기술스택·검증 방법 — "보관 배치는 인앱 스케줄 작업이라 명령 실행·종료 코드로 관측할 수 없으므로, **수동 실행 진입점 제공을 요구사항으로 둔다**(선택 사항이 아니다)."

### 사용자 정의

- **허브 운영자** — 수동 실행의 유일한 주체다. 배포 단위 안의 명령 진입점으로 실행하며 화면·HTTP 경로를 통하지 않는다.
- 사용자·발송처·수신처는 이 기능을 호출할 수단이 없다.

### 관련 서비스

- `SVC-014`·`SVC-015` — 삭제 대상 저장분을 만든다.
- `SVC-010` — 결과 확인 표시로 기산점을 시작시킨다.
- `SVC-016` — 삭제 대상이 아니며, 삭제 이후에도 지표를 낼 수 있게 한다.
- `SVC-018` — 보관 기간 상수를 주입·검증한다.

### 예외 사항

- **왜 관리 HTTP 경로가 아닌가** — 관리자 경로·관리자 인증을 두지 않기로 했고 공개 표면을 사용자 진입 경로와 서버 대면 API 로 한정했다. 인증 없는 삭제 트리거를 공개 표면에 추가하면 그 결정과 정면 충돌한다. 명령 진입점은 배포 단위 안에 있으면서 외부 표면을 늘리지 않는다.
- **동의 증적 보존 기간은 잠정값이다.** 확정은 상수 값 교체로 끝나며 이 사양은 개정되지 않는다.
- **삭제된 레코드에 대한 조회는 미진입과 구별하지 않는다.** 삭제 사실을 드러내지 않기 위해서다.
- **확정 결과 재안내는 보관 기산점을 밀지 않는다.** 레코드를 갱신하지 않기 때문이다.
- **실행 명령의 구체 이름·실행 방식**은 기능·API 도메인이 확정한다. 본 사양이 정하는 것은 진입 경로가 둘이라는 것과 관측 계약(표준 출력 요약 + 종료 코드)이다.

### 구현 가이드

- 기간 값은 상수 주입으로 받아 실행 시점에 기준 일시를 계산한다. 값이 코드에 박히면 확정 시 재작성이 필요해진다.
- 수동 실행 진입점은 스케줄 실행과 같은 삭제 로직을 호출하고 진입 경로만 다르게 둔다. 로직이 갈라지면 두 경로의 결과가 달라진다.
- 삭제는 대상별로 분리해 세고 요약에 각 건수를 담는다. 요약은 고정된 키·값 구조로 내보내 검증 절차가 그대로 파싱할 수 있게 한다.
- 종료 코드는 0 과 0 이외만 구분한다. 세부 사유는 요약에 담는다.
