# 연동 추적 기록 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 연동 1건의 진행과 결과를 **추적 키 기준 단일 레코드 하나**에 모은다. 화면 표시·발송처 조회·수신처 통지가 모두 이 레코드를 근거로 같은 사실을 말하게 하는 것이 목적이다. 화면·명령 표면은 없지만 발송처·수신처에 제공하는 조회의 근거이므로 제공 기능단위로 둔다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 9 — "연동 추적 키 기준 **단일 추적 레코드**를 **사용자가 진입한 시점에 생성**하고, 승인·거부·복호화 결과·수신처 전달 결과·결과 확인·완료 콜백을 같은 레코드에 이어 기록한다."
	- [`../../prd/devspec/database.md`](../../prd/devspec/database.md) §연동 추적 레코드 · §추적 키 중복 수신.

### 사용자 정의

- **허브 운영자** — 이 기록의 소유 주체지만 조회·조작 화면을 갖지 않는다. 기록을 읽는 수단은 서버 대면 API 와 보관 배치뿐이다.
- **발송처** — `SVC-010`·`SVC-011` 로 이 레코드를 읽는다.
- **수신처** — `SVC-012` 로 이 레코드에 완료 사실을 남긴다.
- **사용자** — 이 기록을 직접 보지 않는다. 결과 안내로만 접한다.

### 관련 서비스

- `SVC-002` — 레코드 생성 계기(본인확인 최초 성공)를 만든다.
- `SVC-003`·`SVC-004` — 거부·전달 결과로 결과 구분을 확정시킨다.
- `SVC-010`·`SVC-011`·`SVC-012` — 이 레코드를 읽거나 이어 쓴다.
- `SVC-016` — 같은 경계에서 갱신되는 집계다.
- `SVC-017` — 보관 기간이 지난 레코드를 지운다.

### 예외 사항

- **거부·전달 실패도 레코드가 이미 있다.** 둘 다 본인확인을 통과한 뒤에 일어나므로 결과 구분만 확정해 이어 쓴다.
- **보관 기간이 지나 삭제된 뒤 같은 키가 다시 들어오면** 중복을 알 수 없어 새 레코드를 만든다. 유일성 책임이 발송처에 있다는 전제에서 수용한다.
- **완료 콜백은 결과 확정 이후에도 이어 쓴다.** 결과 구분과 완료 콜백은 다른 사실이라 확정 1회성 규칙의 대상이 아니다.
- **감사 로그·보안 이벤트 저장소를 두지 않는다.** 사후 관측 수단은 추적 레코드의 결과 구분·지표 집계·동의 증적 셋뿐이다.

### 구현 가이드

- 사전 조회 → 3분기 판정 → 생성·이어쓰기·재안내를 한 곳에서 처리한다. 분기가 흩어지면 확정 결과가 덮이는 사고가 난다.
- "결과 확정" 판정은 결과 구분 값의 존재 여부로 한다.
- 레코드의 물리 키 설계·인덱스·컬럼 타입은 데이터 도메인이 정한다. 본 사양은 무엇을 언제 기록하는지만 정한다.
- 기록과 지표 갱신을 같은 트랜잭션 경계에 두어 이중 계수·누락을 막는다.
