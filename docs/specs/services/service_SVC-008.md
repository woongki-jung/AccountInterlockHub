# 배포 패키지 제공 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 발송처가 라이브러리를 **받아서 바로 쓸 수 있는 하나의 묶음**으로 제공한다. 파일만 던져 주면 발송처는 호출 방법·규약 버전·기준 URL 을 스스로 찾아야 하므로, 이 서비스가 그 정보를 함께 담아 통합 소요를 줄인다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 3 — "발송처에 전달하는 **배포 패키지**(라이브러리 파일·호출 샘플·규약 버전 표기)와 **규약 적합성 테스트 벡터**를 함께 제공한다."
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §1 — "**배포 무결성** — 발송처가 받은 파일이 허브가 낸 산출물인지 확인할 수 있어야 한다."

### 사용자 정의

- **허브 운영자** — 패키지를 구성하고 전달하는 주체다. 서비스 이용 대상이 아니라 배포 주체이며 화면을 갖지 않는다.
- **발송처** — 수령·확인·통합의 주체다. 기준 URL 을 자기 환경에 맞게 고르는 책임도 여기에 있다.
- 배포 전달 경로(파일을 어떤 수단으로 전달할지)는 build 단계에서 확정한다.

### 관련 서비스

- `SVC-006`·`SVC-007` — 패키지가 담는 라이브러리 기능이다.
- `SVC-009` — 패키지에 동봉되는 테스트 벡터를 제공한다.
- `SVC-013` — 허브의 규약 버전을 알려 주어 호환 판정의 근거가 된다.

### 예외 사항

- **무결성 수단으로 체크섬을 택했다.** 어셈블리 서명은 코드 서명 인증서의 조달·갱신이 필요해 이번 범위의 비용 균형에 맞지 않는다. 서명 도입은 후속 보완 사안이다.
- **자가진단 경로 값은 패키지에 담지 않는다.** 경로 비공개가 유일한 완화 장치이므로 공개 문서·클라이언트 코드·배포 안내 어디에도 값을 넣지 않는다. 발송처에 경로를 알리는 수단은 배포 안내가 아닌 별도 비공개 전달이며, 그 절차는 배포 절차가 정한다.
- **기준 URL 기재란은 값을 문서에 박기 위한 것이 아니다.** 상수 단일 출처에서 그 시점의 확정 값을 가져와 채우는 자리이며, 값이 바뀌면 안내만 갱신한다.
- 라이브러리 빌드 환경(빌드 도구·빌드 PC)은 허브 애플리케이션과 다르며 build 착수 시점에 점검한다.

### 구현 가이드

- 패키지 구성 파일 목록과 체크섬 파일은 같은 절차에서 만들어 항상 동기 상태를 유지한다.
- 호출 샘플은 콘솔 형태로 두어 발송처가 복사해 바로 실행할 수 있게 한다. 검증용 호출 하네스와 같은 형태를 쓰면 산출물이 하나로 줄어든다.
- 사용 안내는 규약 버전·공개 진입점 두 개·오류 사유 코드 목록·기준 URL 기재란을 담는다. 규약 세부 값은 정책 문서를 참조하게 하고 안내에 복제하지 않는다.
- 소스 위치·산출물명·대상 런타임은 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 라이브러리 식별자가 단일 출처다.
