# 연동 규약 자가진단 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 발송처가 만든 암호값이 허브 규약에 맞는지 **연동 전에** 확인하게 한다. 규약 이탈을 운영 트래픽이 아니라 통합 시점에 발견하는 것이 목적이며, 그래서 실제 연동과 같은 판정을 쓰되 전달·기록은 하지 않는다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 8 — "**연동 규약 자가진단 API**: 발송처가 만든 암호값의 규약 적합성만 판정해 응답한다. 수신처 전달·기록을 하지 않고 복호화 원문도 반환하지 않는다. 노출 경로는 상수로 고정한 **비공개 경로**다."
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §7 — "**입력** — 발송처가 만든 `encX`·`encY` 와 **판정에 쓸 생년월일**을 함께 받는다 … **판정 범위** — 복호화 성공 여부, X의 필수 필드 존재 여부, 연동 추적 키의 형식."

#### 예외 흐름

| 코드 | 발생 조건 | 처리 방식 | 사용자 응답 |
|------|----------|----------|-------------|
| `EX-SEC-003` | `encX`·`encY`·생년월일 중 하나라도 **부재**(요청 본문을 해석할 수 없는 경우 포함) | 판정을 수행하지 않고 종료한다 | 입력 오류 응답 |
| `EX-AUTH-001` | 생년월일이 `yyMMdd` 6자리 숫자가 아님 | 판정을 수행하지 않는다 | 입력 오류 응답 |
| `EX-SEC-001` | 암호값의 구조 위반(디코드 실패·암호문 길이가 16의 배수 아님) | 부적합으로 판정하고 사유 코드를 담는다 | 사유 코드 `EX-SEC-001` |
| `EX-AUTH-002` | 판정 1·2단계 실패(키 불일치) | 부적합으로 판정한다. 연동에서는 재입력 대상이 되는 상태임을 사유 코드로 알린다 | 사유 코드 `EX-AUTH-002` |
| `EX-SEC-002` | 판정 3·4단계 실패(X 파싱 실패·`trackingKey` 부재·형식 위반) | 부적합으로 판정한다. 발송처 페이로드의 규약 위반이다 | 사유 코드 `EX-SEC-002` |
| `EX-SEC-004` | 전달 데이터 평문 크기 상한 초과 | 부적합으로 판정한다 | 사유 코드 `EX-SEC-004` |

- **세 코드의 경계** — 요청 자체가 성립하지 않는 경우만 입력 오류다. **입력 부재**는 `EX-SEC-003`(`SEC-003-04`), **생년월일 형식 위반**은 `EX-AUTH-001`(`AUTH-002-02`)이며, **암호값 구조 위반**은 판정이 수행된 결과이므로 입력 오류가 아니라 **부적합 사유 `EX-SEC-001`**(`SEC-002-02`)이다. 한 사유를 두 코드로 답하지 않는다.
- 부적합 판정의 응답 형태(HTTP 상태·필드 구성)는 기능·API 도메인이 확정한다. 본 사양이 정하는 것은 **판정 결과와 사유 코드만 응답한다**는 범위다.

### 사용자 정의

- **발송처** — 유일한 호출 주체다. 자기가 만든 값과 자기가 아는 생년월일로 자기 환경을 점검한다.
- **허브 운영자** — 경로 값을 배포 시점에 지정하고 유출 시 교체한다. 경로 값은 배포 비밀로 다룬다.
- 사용자·수신처는 이 기능과 관계없다.

### 관련 서비스

- `SVC-006` — 진단 대상 암호값을 만든다. 두 기능이 같은 사유 코드 체계를 쓴다.
- `SVC-002`·`SVC-004` — 같은 판정 절차를 쓰되 이쪽은 기록·전달을 수행한다.
- `SVC-008` — 규약 버전 대조의 다른 한쪽(라이브러리 상수)을 제공한다.
- `SVC-009` — 값 대조로 같은 확인을 하는 오프라인 경로다.
- `SVC-018` — 경로 상수를 주입하고 형식을 검증한다.

### 예외 사항

- **운영 환경에도 노출한다 — 담당자 확인 대기 항목이며 기본안을 적용했다**([`../../prd/PRD.md`](../../prd/PRD.md) §미결·확인 필요 ⑧). 발송처가 운영 통합 시점에 규약을 확인할 수 있어야 자가진단의 목적이 성립하기 때문이다. 다르게 정해지면 이 항목만 개정한다.
- **경로 비공개가 유일한 완화 장치다.** 요청 제한이 없는 환경에서 규약 적합성 판정은 반복 시도의 판정 수단이 될 수 있다. 그래서 경로 값을 공개 문서·클라이언트 코드·응답 어디에도 담지 않고, 유출이 확인되면 교체·재배포한다.
- **상수표의 현재 경로 값은 잠정값이며 저장소에 기록돼 있어 비공개로 볼 수 없다.** 개발·검증 환경 기동에는 쓰되 이 값 그대로 운영 배포하지 않는다.
- **판정 실패는 결과 구분이 아니다.** 자가진단은 연동이 아니므로 `SUCCESS`·`DECRYPT_FAILED` 같은 값을 만들지 않는다.

### 구현 가이드

- 판정 절차는 `SVC-002`·`SVC-004` 와 **같은 절차를 공유**한다. 두 경로가 다른 코드를 쓰면 자가진단이 통과한 값이 연동에서 실패하는 사고가 난다.
- 경로는 애플리케이션 설정 값 하나로 주입받아 라우팅에 쓴다. 소스·정적 자산·프런트엔드 산출물 어디에도 값을 넣지 않는다.
- 운영 경로 값은 추측하기 어려운 무작위 구간을 포함하고, 상수표에 남은 형식을 따르면 기동 시 형식 검증을 통과한다.
- 단계 번호는 내부 실패 사유로 유지하되 응답에는 사유 코드만 싣는다.
