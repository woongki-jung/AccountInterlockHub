# 연동 구성 상수 검증 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 이 제품은 관리자 화면·구성 저장소 없이 **배포 시점 상수만으로** 움직인다. 그래서 상수가 제대로 주입됐는지가 곧 서비스 정상성이며, 하나라도 빠지면 서비스를 여는 대신 **기동을 중단**해 누락 구성으로 잘못 동작하는 일을 막는다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §시스템 제약사항 — "**연동 구성 = 배포 시점 상수**: 연동 구성 값은 … 단일 출처이며, 값 변경은 **재배포**로만 반영된다. 런타임 변경 수단을 두지 않는다."
	- [`../../prd/devspec/infra.md`](../../prd/devspec/infra.md) §연동 구성 상수 주입 — "애플리케이션은 기동 시 필수 상수의 존재·형식을 확인하고, 충족하지 않으면 기동을 중단한다."

### 사용자 정의

- **허브 운영자(배포 주체)** — 상수를 주입하고 기동 결과를 확인하는 유일한 주체다. 화면·API 로 구성을 바꾸는 수단은 없다.
- 사용자·발송처·수신처는 이 기능과 직접 관계하지 않지만, 기동이 되지 않으면 어떤 서비스도 이용할 수 없다.

### 관련 서비스

- 나머지 17개 서비스 전부의 선행 조건이다.
- `SVC-003`·`SVC-015` — 동의 항목 구성과 버전 식별자를 소비한다.
- `SVC-013` — 자가진단 경로 값을 소비한다.
- `SVC-004`·`SVC-017` — 수신처 전달 주소·보관 기간 상수를 소비한다.
- `SVC-001`·`SVC-007` — 진입 경로 상수를 공유한다.

### 예외 사항

- **자가진단 경로의 운영 값은 상수표에 적지 않는다.** 저장소에 남으면 비공개 완화가 사라지므로 배포 시 주입되는 비밀 값으로 다룬다. 상수표에는 형식과 잠정값만 남는다.
- **허브 기준 URL 은 검증 대상이 아니다.** 허브에 주입되는 값이 아니라 발송처가 라이브러리 호출 인자로 넘기는 값이라 소유 주체가 다르다.
- **잠정값은 형식 검증을 통과한다.** 그래서 개발·검증 환경 기동을 막지 않으며, 운영 배포 차단은 절차로만 이뤄진다.
- **기동 중단에는 HTTP 응답이 없다.** 사유는 코드로 식별하되 표면에 실리지 않는다.

### 구현 가이드

- 기동 검증은 모든 미충족 항목을 모아 한 번에 보고한 뒤 중단한다. 하나씩 실패시키면 배포자가 여러 번 재시도해야 한다.
- 버전 식별자를 상수 값에서 결정적으로 산출하면 항목·문구 변경 시 식별자가 자동으로 따라간다. 산출 방식의 확정은 데이터 도메인 소관이다.
- 상수는 애플리케이션 설정 값으로만 주입받고, 값이 필요한 자리에는 플레이스홀더로 참조한다.
- 배포 절차의 잠정값 확인은 체크리스트 항목으로 둔다. 자동 판별 수단을 만들지 않는다.
