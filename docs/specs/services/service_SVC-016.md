# 연동 지표 집계 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 추적 레코드가 보관 기간이 지나 지워진 뒤에도 **사용량·성공률을 낼 수 있게** 개인정보 없는 일자별 건수만 따로 쌓는다. 추적 키를 담지 않아 개별 연동으로 환원되지 않으므로 삭제 대상이 아니다. 화면·명령 표면은 없지만 성과 지표 제공의 근거이므로 제공 기능단위로 둔다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 11 — "**연동 지표 집계**: 일자 단위 요청·성공·실패 건수만 누적한다. 추적 키를 포함하지 않아 개별 연동으로 환원되지 않으며 보관 기간 삭제의 영향을 받지 않는다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §성과 지표 — 지표 정의와 목표치(**본 사양은 수치를 옮겨 적지 않고 참조한다**).

### 사용자 정의

- **허브 운영자** — 카운터를 읽어 지표를 산출하는 주체다. 조회 화면·조회 API 를 두지 않으며 저장분을 직접 확인한다.
- **발송처·수신처·사용자** — 이 집계를 보지 않는다. 개별 연동으로 환원되지 않으므로 어느 역할에도 개별 정보를 제공하지 않는다.

### 관련 서비스

- `SVC-002` — 레코드 최초 생성 계기와 추적 키 미확보 실패 계기를 만든다.
- `SVC-001` — 진입 단계 실패로 추적 키 미확보 계수를 유발한다.
- `SVC-004` — 결과 확정 계기(전달 성공·전달 실패)를 만든다. `SVC-003` 의 승인은 결과를 확정하지 않아 계수 계기가 아니다.
- `SVC-014` — 같은 처리 경계에서 함께 갱신된다.
- `SVC-017` — 이 집계는 삭제 대상이 아니다.

### 예외 사항

- **추적 키를 알 수 없는 실패는 시도마다 계수된다.** 같은 요청인지 판정할 수단이 없어 생기는 중복이며 수용 한계로 기록한다. 검증에서 결함으로 올리지 않는다.
- **성공률의 분모·분자 정의는 담당자 이월 사항이다.** 집계는 결과 미확정으로 끝난 요청을 분모에 **포함한 정의**와 **제외한 정의**를 모두 산출할 수 있는 형태로만 보장하고, 어느 정의를 목표치 판정에 쓸지는 정하지 않는다(`BIZ-005-06`).
- **결과 구분 3종의 합이 요청 수보다 작은 것은 정상이다.** 미동의 이탈·본인확인 미완료 이탈처럼 결과가 확정되지 않고 끝난 요청이 있기 때문이며(`BIZ-005-04`), 이 차이를 결함으로 다루지 않는다.
- **목표치는 잠정값이며 본 사양에 수치를 옮겨 적지 않는다.** 확정 전까지 미달 자체를 결함으로 다루지 않는다.
- **집계는 삭제되지 않는다.** 보관 정책의 대상이 아니며, 이 성질이 추적 레코드 삭제 이후에도 지표를 낼 수 있게 하는 근거다.

### 구현 가이드

- 카운터 갱신은 결과 확정·레코드 생성과 같은 트랜잭션 경계에서 처리해 이중 계수·누락을 막는다.
- 일자 경계는 하나의 기준 시간대로 고정한다. 구체 기준은 데이터 도메인이 확정한다.
- 카운터 컬럼 구성은 데이터 도메인이 정본이며, 본 사양은 무엇을 언제 세는지만 정한다.
- 파생 비율을 저장하지 않으면 정의가 바뀌어도 과거 데이터를 다시 만들 필요가 없다.
