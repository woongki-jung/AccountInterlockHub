# 연동 링크 진입 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 발송처가 만든 연동 요청 URL 로 들어온 사용자를 받아, **생년월일을 묻기 전에 판정할 수 있는 구조 위반만** 먼저 걸러 낸다. 규약을 지키지 않은 링크로 사용자가 생년월일을 넣는 헛수고를 막고, 추적 키를 알 수 없는 실패를 여기서 종결시킨다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §수행 범위 4 — "**사용자 진입·본인확인·동의·승인**: 발송처 링크로 고정 진입 경로에 진입 …"
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §2 — "발송처가 §연동 라이브러리로 만든 URL로 **사용자를 진입**시킨다. 진입 경로는 상수로 고정된다 … 연동이 1:1로 고정이므로 경로에 발송처 식별 구간을 두지 않는다."

### 사용자 정의

- **사용자** — 진입의 유일한 주체다. 링크 없이는 이 경로에 도달할 수단이 없다.
- **발송처** — 진입을 발생시키는 주체지만 이 서비스를 직접 호출하지는 않는다. URL 을 만들어 사용자를 보낼 뿐이다.
- 허브는 진입 요청이 정당한 발송처에서 왔는지 **검증하지 않는다**(`OPS-002-02` 수용 리스크).

### 관련 서비스

- `SVC-007` — 이 서비스가 받는 URL 을 만든다.
- `SVC-002` — 판정을 통과한 진입을 이어받는다.
- `SVC-005` — 판정에 실패한 진입을 결과 경로 ③ 으로 받는다.
- `SVC-016` — 추적 키를 알 수 없는 실패를 계수한다.

### 예외 사항

- **링크를 확보한 누구든 진입할 수 있다.** 링크 만료(TTL)·1회성 사용·발송처 서명 검증을 두지 않기로 했으므로(`OPS-002-05`) 진입 자체를 막는 장치가 없다. 이는 수용 리스크이며 이 서비스가 완화 장치를 추가하지 않는다.
- **같은 링크로 몇 번이든 다시 진입할 수 있다.** 재진입의 처리는 추적 키를 확보한 뒤 `SVC-002`·`SVC-005` 가 판정한다.
- **진입 단계 실패는 시도마다 계수된다.** 같은 요청인지 판정할 수단이 없어 생기는 중복이며 수용 한계로 기록한다(`BIZ-005-05`).

### 구현 가이드

- 암호문 길이의 16 배수 검사는 Base64URL 디코드 직후에 수행한다 — 복호화를 시도하기 전에 걸러 낼 수 있는 가장 값싼 검사다.
- 암호값은 요청 처리 문맥의 지역 값으로만 다루고 세션·캐시·브라우저 저장소에 넣지 않는다.
- 진입 경로 값은 상수 주입으로 받는다. 경로에 발송처 식별 구간이 없으므로 라우팅 분기도 없다.
- 실패 응답은 어느 단계에서 실패했는지 이상의 정보를 담지 않는다.
