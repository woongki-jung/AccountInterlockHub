# 연동 요청 URL 생성 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 발송처가 진입 경로·파라미터 이름·인코딩 규칙을 직접 조립하지 않고 **호출 한 번으로** 사용자를 보낼 링크를 얻게 한다. 조립 실수로 진입이 실패하는 일을 없애고, URL 길이 한계를 만들기 전에 알려 준다.
- **관련 PRD 요구사항**:
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §1 — "**요청 URL 생성**(`LIB-02`) — 허브 진입 경로에 `encX`·`encY`를 결합한 연동 요청 URL을 산출한다. 허브 진입 기준 URL은 환경(운영·개발)마다 다르므로 **호출 시 입력으로 받는다**."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §목표 — "발송처가 **라이브러리 호출만으로** 연동 요청 URL을 만들 수 있게 해 …"

### 사용자 정의

- **발송처** — 유일한 호출 주체이며, 자기 환경(운영·개발)에 맞는 기준 URL 을 고르는 책임도 발송처에 있다.
- **사용자** — 결과물인 URL 로 진입하는 주체지만 이 기능을 호출하지 않는다.
- 기준 URL 값은 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수 — 발송처 호출 입력 값이 단일 출처이며, 발송처는 배포 패키지의 사용 안내에 기재된 값을 쓴다.

### 관련 서비스

- `SVC-006` — 이 기능이 결합할 암호값 쌍을 만든다.
- `SVC-001` — 이 기능이 만든 URL 로 사용자가 진입한다.
- `SVC-008` — 환경별 기준 URL 을 발송처에 전달하는 경로다.
- `SVC-009` — 요청 URL 의 기대 출력을 테스트 벡터로 고정한다.

### 예외 사항

- **기준 URL 은 잠정값이다.** 운영·개발 기준 URL 이 확정되면 상수 값 교체로 반영되며 이 사양은 개정되지 않는다. 잠정 상태의 운영 배포는 금지된다.
- **URL 길이 상한을 넘기는 경우가 실무에서 드물지 않다.** 전달 데이터가 클수록 암호값이 길어지므로, 발송처는 평문 크기 상한과 URL 길이 상한을 함께 고려해 전달 데이터를 구성해야 한다.
- **링크에는 만료·1회성 표시가 없다.** 링크 만료·1회성 사용을 두지 않기로 했으므로 URL 에 그런 파라미터를 추가하지 않는다.

### 구현 가이드

- 기준 URL 의 끝 구분자 유무에 관계없이 같은 결과가 나오도록 결합한다. 발송처마다 다른 형태로 값을 넘겨도 결과가 흔들리지 않아야 한다.
- 암호값은 이미 URL 에 그대로 실을 수 있는 형태이므로 추가 인코딩을 하지 않는다. 이중 인코딩은 진입 단계 디코드 실패의 대표 원인이다.
- 파라미터 이름은 허브의 진입 파싱과 **정확히 같은 이름**을 써야 한다. 이름의 확정은 기능·API 도메인 소관이며 라이브러리와 허브가 같은 값을 공유한다.
- 길이 판정은 조립을 마친 최종 문자열 기준으로 한다.
