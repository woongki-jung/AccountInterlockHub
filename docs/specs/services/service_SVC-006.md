# 전달 데이터 암호화 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: 발송처가 암호화 규약을 직접 구현하지 않고 **호출 한 번으로** 규약에 맞는 암호값을 얻게 한다. 규약 해석 차이로 연동이 실패하는 일을 통합 단계에서 없애는 것이 목적이다.
- **관련 PRD 요구사항**:
	- [`../../prd/PRD.md`](../../prd/PRD.md) §제공 가치 — "**통합 부담 없는 발송처 연동**: 발송처는 암호화 규약을 구현하지 않고 **연동 라이브러리 호출**로 암호값과 요청 URL을 얻는다."
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §1 — "**데이터 암호화**(`LIB-01`) — 전달 데이터 X·발송처키·사용자 생년월일을 입력받아 §암호화 연동 규약대로 `encX`·`encY`를 산출한다."

### 사용자 정의

- **발송처** — 유일한 호출 주체다. 발송처키를 자기 책임으로 보관하고 호출 시 넘긴다.
- **허브** — 이 기능의 반대 방향(복호화)을 구현한다. 두 구현은 같은 규약의 양쪽이므로 규약이 바뀌면 함께 바뀐다.
- 사용자·수신처는 이 기능을 직접 호출하지 않는다.

### 관련 서비스

- `SVC-007` — 이 기능의 출력을 받아 연동 요청 URL 을 만든다.
- `SVC-002`·`SVC-004` — 이 기능이 만든 암호값을 복호화한다.
- `SVC-009` — 이 기능의 출력이 규약과 일치하는지 대조할 기준을 제공한다.
- `SVC-013` — 같은 사유 코드 체계로 규약 적합성을 알려 준다.

### 예외 사항

- **같은 키·같은 평문은 항상 같은 암호값이 된다.** 초기화 벡터가 키에서 결정적으로 파생되기 때문이며, 상위 규약이 정한 한계로 수용 리스크에 포함된다. 결함으로 다루지 않으며 난수 초기화 벡터 도입은 이번 범위가 아니다.
- **암호값은 URL 파라미터로 노출되고 생년월일은 경우의 수가 작다.** 링크와 암호값을 확보한 자의 오프라인 전수대입은 막지 못한다 — 수용 리스크다.
- **허브는 발송처키를 갖지 않는다.** 그래서 허브는 `encX` 의 키를 직접 만들 수 없고 항상 `encY` 복호화로 얻은 키를 쓴다.
- 공개 진입점은 암호화와 요청 URL 생성 둘뿐이다. 내부 정규화·인코딩 도구를 공개하지 않는다.

### 구현 가이드

- **정규화 순서를 지킨다** — 이어 붙이기 → 정규화. 각각 정규화한 뒤 이어 붙이면 다른 키가 나온다.
- 대상 런타임과 소스 위치·산출물명은 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 라이브러리 식별자가 단일 출처다. 사양에 값을 복제하지 않는다.
- 오류는 .NET 관용에 맞춰 예외 기반으로 알리되, 라이브러리 전용 예외 타입을 두어 호출측이 규약 위반과 런타임 오류를 구별할 수 있게 한다.
- 특정 암호 라이브러리를 강제하지 않는다. 대상 런타임의 표준 암호 기능만으로 성립하는 조합이다.
