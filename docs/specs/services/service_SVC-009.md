# 규약 테스트 벡터 제공 기능 정의

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

## 개요

- **서비스 목적**: "이 값을 넣으면 이 값이 나와야 한다"를 미리 고정해, **라이브러리와 허브가 같은 규약을 구현했는지 값으로 증명**한다. 발송처는 자기 환경에서 결과 일치를 확인하고, 허브는 규약 대칭(왕복) 검증의 근거로 삼는다.
- **관련 PRD 요구사항**:
	- [`../../prd/devspec/external-apis.md`](../../prd/devspec/external-apis.md) §1 — "**규약 테스트 벡터**(`LIB-04`) — 알려진 입력과 기대 출력(`encX`·`encY`·요청 URL)의 대조 표. 발송처가 자기 환경에서 결과 일치를 확인할 수 있고, 허브의 규약 대칭(왕복) 검증도 이 벡터를 근거로 삼는다."
	- [`../../prd/PRD.md`](../../prd/PRD.md) §프로그램 구성·기술스택·검증 방법 — "**규약 대칭(왕복) 검증**은 별도 통합 검증 항목으로 둔다."

### 사용자 정의

- **발송처** — 자기 환경의 결과가 규약과 맞는지 스스로 확인하는 주체다. 벡터는 허브에 요청하지 않고도 확인할 수 있는 유일한 수단이다.
- **허브 운영자** — 벡터를 만들고 왕복 검증을 수행하는 주체다.
- 사용자·수신처는 이 기능과 관계없다.

### 관련 서비스

- `SVC-006`·`SVC-007` — 벡터의 기대 출력을 만드는 대상 기능이다.
- `SVC-008` — 벡터를 동봉해 전달한다.
- `SVC-013` — 발송처가 값 대조 대신 **허브에 직접 물어** 확인하는 다른 경로다. 두 경로가 같은 사유 코드 체계를 쓴다.
- `SVC-002`·`SVC-004` — 왕복 검증에서 복호화 쪽을 담당한다.

### 예외 사항

- **벡터의 입력은 예시 값이다.** 실제 사용자 생년월일·실 발송처키·실 회원 정보를 벡터에 넣지 않는다. 벡터는 배포 패키지에 담겨 저장소·발송처 양쪽에 남는 문서이기 때문이다.
- **벡터가 통과해도 연동 성공을 보장하지는 않는다.** 벡터는 규약 구현의 일치만 증명하며, 수신처 전달·기준 URL·전달 주소 등 환경 값의 정확성은 별도 확인 대상이다.
- **같은 입력은 항상 같은 출력을 낸다.** 초기화 벡터가 키에서 파생되는 규약이라 벡터가 성립한다. 난수 초기화 벡터를 쓰는 규약이라면 값 대조 방식 자체가 불가능해진다.

### 구현 가이드

- 벡터는 사람이 읽고 기계가 파싱할 수 있는 형태로 둔다. 발송처의 자체 확인과 검증 절차가 같은 파일을 쓴다.
- 각 항목에 어떤 경계를 덮는 사례인지 표시해 두면 규약 개정 시 어느 항목을 다시 만들어야 하는지 판단하기 쉽다.
- 왕복 검증은 라이브러리 산출물과 허브가 모두 준비된 뒤 수행하는 통합 검증 항목이다. 어느 한쪽만으로는 성립하지 않는다.
- 검증용 호출 하네스는 벡터를 입력으로 받아 결과를 표준 출력·종료 코드로 내보내, 명령 실행 절차를 그대로 적용할 수 있게 한다.
