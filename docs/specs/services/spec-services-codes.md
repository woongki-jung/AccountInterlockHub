# 서비스 코드 카탈로그

정본 목록은 [`spec-services.md`](spec-services.md). 용어는 [`../../../wiki/WIKI.md`](../../../wiki/WIKI.md).

본 문서는 서비스 시나리오가 쓰는 **분기(BR)·예외(EX)·데이터 모델(MDL)·화면(SCR)·프로세스(PROC)** 코드를 한곳에 모아 후행 도메인이 같은 값을 이어받게 한다.

## 예외(EX) 사용 매핑

EX 코드의 **정의는 정책이 정본**이다([`../policies/spec-policies.md`](../policies/spec-policies.md) §예외(EX) 코드 카탈로그). 아래는 어느 서비스가 어떤 코드를 쓰는지의 매핑일 뿐이며, 서비스는 코드를 새로 만들지 않는다.

| EX 코드 | 사용 SVC |
|---|---|
| `EX-AUTH-001` | SVC-002 · SVC-013 |
| `EX-AUTH-002` | SVC-002 · SVC-004 · SVC-013 |
| `EX-SEC-001` | SVC-001 · SVC-013 |
| `EX-SEC-002` | SVC-002 · SVC-004 · SVC-006 · SVC-009 · SVC-013 |
| `EX-SEC-003` | SVC-013 |
| `EX-SEC-004` | SVC-001 · SVC-006 · SVC-007 · SVC-013 |
| `EX-BIZ-001` | SVC-003 |
| `EX-BIZ-002` | SVC-004 |
| `EX-BIZ-003` | SVC-003 · **SVC-004** · SVC-014 · SVC-015 · SVC-016 |
| `EX-DATA-001` | SVC-010 · SVC-011 · SVC-012 · **SVC-014** |
| `EX-DATA-002` | SVC-010 · SVC-011 · SVC-012 |
| `EX-OPS-001` | SVC-017 · SVC-018 |
| `EX-OPS-002` | SVC-005 |

- 매핑 13행 = 정책 EX 카탈로그 13종 전건. `EX-OPS-002` 는 **인터페이스 수준의 마지막 방어**라 어느 시나리오에서나 일어날 수 있지만, 시나리오 사양이 예외 흐름으로 명시해 다루는 곳은 SVC-005 다(진입 처리 중 분류되지 않는 내부 실패를 **경로 ②** 로 안내한다 — [`service_SVC-005.md`](service_SVC-005.md) §예외 흐름 · `OPS-003-05`).
- **EX 코드를 갖지 않는 실패**가 셋 있다. ① 자가진단 경로가 아닌 요청의 일반 404(`SEC-003-02`) ② 배포 패키지 무결성·테스트 벡터 대조 불일치(배포 절차 중단 — 런타임 응답이 아니다) ③ 보관 배치의 삭제 실패(요약의 `failureReason` 과 **CLI 경로의** 종료 코드로 구분 — `OPS-003-04`. 스케줄 경로에는 종료 코드가 없다).

## 데이터 모델(MDL) 예약 채번

데이터 도메인이 아직 작성 전이라 **예약 채번**한다. 아래 의미를 데이터 도메인이 그대로 이어받아 확정하며, 컬럼·타입·인덱스는 데이터 도메인 소관이다. 저장 대상은 `MDL-001`~`MDL-003` **셋뿐**이고 나머지는 전부 비저장(요청 처리 중 메모리 전용)이다(`DATA-001-01`).

| MDL 코드 | 의미 | 저장 여부 |
|---|---|---|
| MDL-001 | 연동 추적 레코드 — 추적 키·처리 성공 여부·결과 구분·처리 일시·결과 확인 여부·결과 확인 일시·완료 콜백 수신 여부·콜백 일시·생성 일시 | 저장 |
| MDL-002 | 동의 증적 — 추적 키·동의 일시·동의 항목 버전 식별자·그 시점 항목 내용 스냅샷 | 저장 |
| MDL-003 | 연동 지표 집계 — 일자·요청 수·결과 구분 3종 각각의 건수(거부 카운터 없음) | 저장 |
| MDL-004 | 암호값 쌍 — `encX`·`encY`(Base64URL 문자열). 진입 파라미터·라이브러리 출력·자가진단 입력이 공유하는 값 쌍 | 비저장 |
| MDL-005 | 전달 데이터 X — 복호화한 원문(JSON). `trackingKey` 필드를 포함하며 수신처 전달 페이로드로 그대로 쓰인다 | 비저장 |
| MDL-006 | 본인확인 입력 — 사용자가 넣은 생년월일(`yyMMdd` 6자리) | 비저장 |
| MDL-007 | 동의·승인 제출 — 사용자가 동의한 항목의 식별자 목록(진행 의사 값을 별도로 받지 않는다 — `BIZ-003-01`) | 비저장 |
| MDL-008 | 동의 항목 구성 — `<CONSENT_ITEMS>` 파싱 결과·`<CONSENT_NOTICE>`·동의 항목 버전 식별자 | 비저장(상수 유래) |
| MDL-009 | 연동 결과 안내 정보 — 선택된 결과 경로와 확정 결과 재안내 여부, 연동 완료(경로 ①)에만 실리는 복귀 주소 | 비저장 |
| MDL-010 | 수신처 전달 결과 — 전달 시도의 성공·실패 판정과 재시도 소진 여부 | 비저장 |
| MDL-011 | 추적 키 입력 — 처리상태 확인·연동 완료 확인·완료 콜백이 공통으로 받는 입력 | 비저장 |
| MDL-012 | 처리상태 확인 응답 — 추적 키·처리 성공 여부·결과 구분·결과 확인 여부·처리 일시·결과 확인 일시 | 비저장 |
| MDL-013 | 연동 완료 확인 응답 — 추적 키·완료 콜백 수신 여부·콜백 일시 | 비저장 |
| MDL-014 | 자가진단 요청 — `encX`·`encY`·판정에 쓸 생년월일 | 비저장 |
| MDL-015 | 자가진단 응답 — 판정 결과·사유 코드·허브의 규약 버전 | 비저장 |
| MDL-016 | 라이브러리 암호화 입력 — 전달 데이터 X·발송처키·사용자 생년월일 | 비저장 |
| MDL-017 | 요청 URL 생성 입력 — 허브 기준 URL·암호값 쌍 | 비저장 |

| MDL-019 | 규약 테스트 벡터 항목 — 입력(발송처키·생년월일·X)과 기대 출력(`encX`·`encY`·요청 URL)의 한 쌍 | 비저장(배포 산출물) |
| MDL-020 | 배포 패키지 구성 — 라이브러리 파일·호출 샘플·사용 안내·테스트 벡터·체크섬 파일의 묶음 | 비저장(배포 산출물) |
| MDL-021 | 보관 배치 실행 결과 요약 — 기준 일시·대상별 삭제 건수 | 비저장 |
| MDL-022 | 연동 구성 상수 집합 — 기동 시 주입·검증되는 상수의 묶음 | 비저장(상수 유래) |

데이터 모델 22종(저장 3 · 비저장 19).

## 화면(SCR) 예약 채번

화면 도메인이 아직 작성 전이라 **예약 채번**한다. 화면 구성·표시 형식은 화면 도메인 소관이며, 서비스는 어느 시나리오가 어느 화면을 참조하는지만 정한다. 사용자 표면 밖의 역할(발송처·수신처·허브 운영자)은 화면을 갖지 않는다.

| SCR 코드 | 의미 | 참조 SVC |
|---|---|---|
| SCR-001 | 본인확인 — 연동 요청 URL 로 진입했을 때 처음 표시되는 생년월일 입력 화면 | SVC-001 · SVC-002 |
| SCR-002 | 동의·승인 — 동의 항목·안내 문구를 노출하고 **전 항목(필수) 동의를 조건으로** 승인을 받는 화면. 미충족 제출은 유효성 안내로 막는다(거부 제출 수단을 두지 않는다) | SVC-003 |
| SCR-003 | 연동 진행 안내 — 승인 제출 후 결과가 확정되기까지의 대기 표시. 화면 도메인이 `SCR-002` 의 한 상태로 통합해도 된다 | SVC-004 |
| SCR-004 | 연동 결과 안내 — 결과 3경로를 표시하는 화면. 경로를 3개 화면으로 나눌지 한 화면의 3상태로 둘지는 화면 도메인이 정한다 | SVC-005 |
