# 정보 구조 (IA)

AccountInterlockHub의 정보 구조다. 서비스 제공 기능단위(leaf)까지 담으며, 세부 구현기능은 spec 단계가 다룬다. 각 노드는 `ia-code`로 식별하며, 사양·이력·티켓이 이 코드로 IA를 가리킨다(정책 [`ia.md`](../../../ai/strategies/ia.md)).

**우선순위 등급의 의미** — `높음` = 이 기능이 없으면 제품의 핵심 가치(연동 중개)가 성립하지 않는다. `보통` = 없으면 운영·통합이 불편하나 핵심 가치는 성립한다. 영역의 등급은 하위 leaf 중 가장 높은 등급이다. **착수 순서**는 등급이 아니라 [`../PRD.md`](../PRD.md) §우선순위가 정한다.

| ia-code | 노드 | 깊이 | 우선순위 | 설명 |
| ------- | ---- | ---- | ---- | ---- |
| USR | 사용자 연동 | 영역 | 높음 | 사용자 진입·본인확인·동의·승인·복호화 전달·결과 안내 |
| USR-01 | 연동 링크 진입 | leaf | 높음 | 발송처가 만든 링크로 고정 진입 경로에 진입해 `encX`·`encY`를 받고 형식을 판정(무효 링크는 결과 안내로 분기) |
| USR-03 | 본인확인 | leaf | 높음 | 사용자가 생년월일을 입력하고, 그 값으로 전달 데이터가 복원되는지로 본인을 확인(복원 실패 시 재입력) |
| USR-04 | 동의·승인 | leaf | 높음 | 상수로 고정된 동의 항목을 노출하고 동의·거부를 받아 승인을 제출. 동의 사실은 `BAT-05`로 남는다 |
| USR-02 | 연동 실행 | leaf | 높음 | 승인 시 복원한 전달 데이터를 상수로 고정된 수신처(B)에 전달(허브는 원문을 저장하지 않음) |
| USR-05 | 연동 결과 안내 | leaf | 높음 | 결과를 네 경로로 구분해 사용자에게 표시 — 연동 완료 · 사용자 거부 · 링크·복호화 오류 · 수신처 전달 실패 |
| LIB | 연동 라이브러리 | 영역 | 높음 | 발송처(서비스 A)에 제공하는 암호화·요청 URL 생성 라이브러리. C#(.NET) 프로젝트에서 호출 |
| LIB-01 | 데이터 암호화 | leaf | 높음 | 전달 데이터 X와 발송처키·생년월일로 encX·encY 산출(허브 복호화와 대칭 규약) |
| LIB-02 | 요청 URL 생성 | leaf | 높음 | 허브 진입 경로에 encX·encY를 결합한 연동 요청 URL 산출 |
| LIB-03 | 배포 패키지 | leaf | 보통 | 발송처가 받는 제공 단위 — 라이브러리 파일·호출 샘플·규약 버전 표기의 묶음 |
| LIB-04 | 규약 테스트 벡터 | leaf | 보통 | 알려진 입력과 기대 출력의 대조 벡터. 발송처의 자체 확인과 규약 대칭(왕복) 검증의 근거 |
| API | 서비스 연동 API | 영역 | 보통 | 발송처·수신처 대면 서버 인터페이스 |
| API-01 | 처리상태 확인 API | leaf | 보통 | 발송처가 연동 추적 키 기준 처리·결과 확인 상태 조회 |
| API-02 | 연동 완료 확인 API | leaf | 보통 | 발송처가 연동 추적 키 기준 수신처의 처리완료 여부 확인 |
| API-03 | 완료 콜백 API | leaf | 보통 | 수신처가 정보연계 완료를 전달받은 추적 키 기준으로 허브에 통지 |
| API-04 | 연동 규약 자가진단 API | leaf | 보통 | 발송처가 만든 암호값의 규약 적합성만 판정해 응답(무전달·무기록·원문 미반환). 비공개 경로로 노출하며 라이브러리 배포와 함께 제공 |
| BAT | 기록·보관 | 영역 | 보통 | 연동 추적·동의 증적·지표 집계 기록과 보관 정책 |
| BAT-04 | 연동 추적 기록 | leaf | 보통 | 연동 추적 키 기준 단일 레코드에 진입·처리 결과·결과 확인·수신처 완료 콜백을 기록 |
| BAT-05 | 동의 증적 기록 | leaf | 보통 | 동의 시점·동의 항목 버전을 추적 키와 함께 보존(개인정보 미포함). 추적 레코드와 보존 기간이 다르다 |
| BAT-06 | 연동 지표 집계 | leaf | 보통 | 일자 단위 요청·성공·거부·실패 건수만 누적(추적 키 미포함). 보관 기간 삭제 이후의 성과 지표 산출 근거 |
| BAT-02 | 보관정책 배치 | leaf | 보통 | 일 배치: 보관 기간 경과분 삭제 |
| 공통 | (횡단) | — | — | 무저장·개인정보 최소(복호화 원문 미저장) 원칙, 암호화 연동 규약(라이브러리·허브 공유 계약), 연동 구성 상수화, 접근 통제 없음(수용 리스크), 단일 App Service 배포·기술스택 |

- `BAT` 영역의 세 기록 노드(`BAT-04`·`BAT-05`·`BAT-06`)는 사용자 화면을 갖지 않는 내부 기록 기능이지만, **발송처·수신처에 제공하는 조회·증적·지표의 근거**가 되므로 제공 기능단위로 둔다. 기록 항목·보관 규칙은 [`../devspec/database.md`](../devspec/database.md)가 정본이다.

## 사용하지 않는 코드

`ia-code`는 발급 후 불변이며 재사용하지 않는다([`ia.md`](../../../ai/strategies/ia.md) §`ia-code` 규칙). 현재 제품 구성에 대응 노드가 없는 코드는 아래와 같으며, 새 노드에 다시 배정하지 않는다.

- `ADM`·`ADM-01`·`ADM-02`·`ADM-03` — 관리자 영역.
- `BAT-01`·`BAT-03` — 처리상태 저장·연동이력 저장. 두 기능은 `BAT-04` 단일 노드가 담당한다.

`USR-01`·`USR-02`는 담당 범위가 좁아진 노드다 — `USR-01`은 링크 진입만, `USR-02`는 연동 실행(복호화·전달)만 담당하고, 분리된 기능은 `USR-03`·`USR-04`·`USR-05`가 새 코드로 갖는다. 코드의 의미가 다른 기능으로 바뀐 것이 아니라 축소된 것이므로 재사용에 해당하지 않는다.

이 코드로 남아 있는 노드별 작업 이력(`history/`)은 그대로 보존한다([`ia-history.md`](../../../ai/strategies/ia-history.md)).
