# 정보 구조 (IA)

AccountInterlockHub의 정보 구조다. 서비스 제공 기능단위(leaf)까지 담으며, 세부 구현기능은 spec 단계가 다룬다. 각 노드는 `ia-code`로 식별하며, 사양·이력·티켓이 이 코드로 IA를 가리킨다(정책 [`ia.md`](../../../ai/strategies/ia.md)).

| ia-code | 노드 | 깊이 | 우선순위 | 설명 |
| ------- | ---- | ---- | ---- | ---- |
| USR | 사용자 연동 | 영역 | 높음 | 사용자 진입·본인확인·동의·승인·복호화 전달·결과 안내 |
| USR-01 | 진입·동의·승인 | leaf | 높음 | 발송처 링크로 고정 진입 경로에 진입, 생년월일 입력, 상수로 고정된 동의 항목 노출·동의/거부·승인 |
| USR-02 | 연동 실행·결과 안내 | leaf | 높음 | 승인 시 생년월일로 encY→키→encX→X 복호화 → 상수로 고정된 수신처(B)로 전달 → 결과(완료·거부·오류) 화면 표시 |
| LIB | 연동 라이브러리 | 영역 | 높음 | 발송처(서비스 A)에 제공하는 암호화·요청 URL 생성 라이브러리. Delphi·C# 프로젝트에서 호출 |
| LIB-01 | 데이터 암호화 | leaf | 높음 | 전달 데이터 X와 발송처키·생년월일로 encX·encY 산출(허브 복호화와 대칭 규약) |
| LIB-02 | 요청 URL 생성 | leaf | 높음 | 허브 진입 경로에 encX·encY를 결합한 연동 요청 URL 산출 |
| API | 서비스 연동 API | 영역 | 보통 | 발송처·수신처 대면 서버 인터페이스 |
| API-01 | 처리상태 확인 API | leaf | 높음 | 발송처가 연동 추적 키 기준 처리·결과 확인 상태 조회 |
| API-02 | 연동 완료 확인 API | leaf | 높음 | 발송처가 연동 추적 키 기준 수신처의 처리완료 여부 확인 |
| API-03 | 완료 콜백 API | leaf | 높음 | 수신처가 정보연계 완료를 전달받은 추적 키 기준으로 허브에 통지 |
| BAT | 기록·보관 | 영역 | 보통 | 연동 추적 기록·보관 정책 |
| BAT-04 | 연동 추적 기록 | leaf | 높음 | 연동 추적 키 기준 단일 레코드에 요청·처리 결과·결과 확인·수신처 완료 콜백을 기록 |
| BAT-02 | 보관정책 배치 | leaf | 보통 | 일 배치: 보관 기간 경과분 삭제 |
| 공통 | (횡단) | — | — | 무저장·개인정보 최소(복호화 원문 미저장) 원칙, 암호화 연동 규약(라이브러리·허브 공유 계약), 연동 구성 상수화, 단일 App Service 배포·기술스택 |

## 사용하지 않는 코드

`ia-code`는 발급 후 불변이며 재사용하지 않는다([`ia.md`](../../../ai/strategies/ia.md) §`ia-code` 규칙). 현재 제품 구성에 대응 노드가 없는 코드는 아래와 같으며, 새 노드에 다시 배정하지 않는다.

- `ADM`·`ADM-01`·`ADM-02`·`ADM-03` — 관리자 영역.
- `BAT-01`·`BAT-03` — 처리상태 저장·연동이력 저장(현재는 `BAT-04` 단일 노드가 담당).

이 코드로 남아 있는 노드별 작업 이력(`history/`)은 그대로 보존한다([`ia-history.md`](../../../ai/strategies/ia-history.md)).
