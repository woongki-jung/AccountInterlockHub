# 개발사양 — 데이터베이스 지침

AccountInterlockHub의 데이터베이스 고정값이다. spec·build·qa가 단일 출처로 참조한다. 방향 근거는 [`../PRD.md`](../PRD.md) §시스템 제약사항. 용어는 [`wiki/WIKI.md`](../../../wiki/WIKI.md).

## 데이터베이스

- **PostgreSQL 16**을 사용한다.
	- 운영: Azure의 PostgreSQL 서비스(Azure Database for PostgreSQL).
	- 개발·로컬: 별도로 구축한 PostgreSQL 서버.

## 데이터 원칙

- 허브는 **사용자 정보를 지속 보관하지 않는다**. 발송처가 전달한 암호값(encX/encY)과 복호화한 원문(X)은 **연동 실행 시점에 메모리 상에서만** 다루고 전달 후 폐기한다 — 어느 것도 저장하지 않는다. 예외는 **연동 추적 레코드와 동의 증적이 갖는 추적 키값**이며, 추적 키는 개인정보 원문이 아니다.
- **연동 구성은 데이터베이스에 두지 않는다**. 연동 구성 값은 배포 시점 상수이며 단일 출처는 [`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수다.
- 저장 대상은 **셋**이다. 그 외 어떤 데이터도 저장하지 않는다.
	1. **연동 추적 레코드** — 연동 1건이 레코드 1건에 대응한다(§연동 추적 레코드).
	2. **동의 증적** — 동의 사실의 사후 입증 수단. 개인정보를 담지 않는다(§동의 증적).
	3. **연동 지표 집계** — 일자별 건수 카운터. 개별 연동으로 환원되지 않는다(§연동 지표 집계).
- **동의 항목 스냅샷은 연동 구성의 저장이 아니다** — 동의 증적이 보존하는 항목 내용은 그 사용자가 동의한 시점의 **증적**이며, 서비스가 참조하는 구성은 언제나 배포된 상수다(§동의 증적).
- **보안 이벤트를 별도로 기록하지 않는다.** 복호화 실패·전달 실패는 추적 레코드의 결과 구분으로, 발생 건수는 지표 집계로 남는다.
- 스키마는 **이전 구성을 승계하지 않고** 위 세 저장 대상 기준으로 새로 설계한다.
- 연동 추적 키는 전달 데이터(X) 내부의 지정 필드값으로, 발송처와 수신처가 공유하는 조회·통지 기준이다(불투명 문자열, 개인정보 원문 아님).

## 연동 추적 레코드

**연동 추적 키** 기준으로 사용자 진입부터 수신처(B) 완료 콜백까지를 **한 레코드**에 기록한다. 처리상태 확인·연동 완료 확인 API([`external-apis.md`](external-apis.md))의 근거 데이터이며, 사용자 정보·복호화 원문은 포함하지 않는다.

- **생성 시점** — 사용자가 진입 경로로 들어와 연동 요청이 허브에 인지된 시점에 레코드를 만든다. 허브는 그 전의 연동 요청을 알 수 없으므로, **조회 시 레코드가 없다는 것은 해당 추적 키로 진입한 사용자가 없었다는 뜻**이다.
- **갱신** — 승인·거부, 복호화 결과, 수신처 전달 결과, 결과 확인, 완료 콜백을 같은 레코드에 이어 기록한다.

기록 항목은 다음 범위다.

- 연동 추적 키
- 처리 성공 여부 · **결과 구분** · 처리 일시
- 결과 확인 여부 · 결과 확인 일시
- 수신처 완료 콜백 수신 여부 · 콜백 일시

- **결과 구분**은 발송처가 후속 조치를 판단할 수 있도록 최소한 사용자 거부·복호화 실패·수신처 전달 실패를 서로 구별한다. 구분 값 목록은 spec 단계에서 확정한다.
- **결과 확인**의 의미(발송처가 처리상태 확인 API로 결과를 받아 간 것)는 [`external-apis.md`](external-apis.md) §처리상태 확인 API가 정의한다.
- 구체 컬럼·타입·인덱스·키 설계는 spec 단계에서 확정한다.

### 추적 키 중복 수신

추적 키의 유일성은 **발송처가 책임진다**([`../PRD.md`](../PRD.md) §시스템 제약사항 — 신뢰 위임). 허브는 보관 중인 레코드로 판정할 수 있는 범위에서 다음과 같이 동작한다.

1. **같은 키의 레코드가 없다** — 새 레코드를 만든다(정상 진입).
2. **같은 키의 레코드가 있고 결과가 아직 확정되지 않았다** — 같은 레코드를 이어 쓴다. 사용자의 새로고침·재진입, 본인확인 재시도가 정상 동작한다.
3. **같은 키의 레코드가 있고 결과가 이미 확정됐다**(처리 성공·거부·실패가 기록된 상태) — 새 연동으로 받아들이지 않고, **이미 확정된 결과를 그대로 안내**한다. 확정된 결과가 덮여 발송처가 다른 연동의 결과를 보는 일을 막는다.
	- 안내는 [`../ia/IA.md`](../ia/IA.md) `USR-05` 의 **네 경로 중 그 레코드의 결과에 해당하는 경로**를 다시 표시하는 것이다. **다섯 번째 결과 경로를 만들지 않는다.** "이미 처리된 요청"임을 알리는 문구는 그 경로의 **보조 표시**로 둔다(문구·표시 위치는 spec 확정).
	- 이 재진입은 새 연동 요청이 아니므로 **연동 지표 집계의 요청 수에 계수하지 않는다**(§연동 지표 집계).
	- 추적 레코드를 갱신하지 않는다 — 결과·일시·결과 확인 상태가 모두 그대로 유지된다(보관 기산점도 밀리지 않는다).

- 보관 기간이 지나 레코드가 삭제된 뒤 같은 키가 다시 들어오면 허브는 중복을 알 수 없다(1번으로 동작한다). 이 한계는 유일성 책임이 발송처에 있다는 전제에서 수용한다.
- **수신처 전달 실패 후의 재시도** — 전달 실패도 확정된 결과이므로 같은 링크로 다시 진입하면 3번(확정 결과 재안내)이 적용된다. 재시도 경로의 기본안은 둘이다(담당자 확인 대기 — [`../PRD.md`](../PRD.md) §미결·확인 필요).
	1. 허브는 **사용자가 진입해 있는 동안**에만 전달을 재시도한다(즉시 재시도 횟수·간격은 spec 확정).
	2. 결과가 확정된 뒤의 재연동은 발송처가 **새 추적 키로 새 요청을 발행**해 수행한다.

## 동의 증적

사용자가 **어느 시점의 어떤 동의 항목에 동의했는지**를 남긴다([`../ia/IA.md`](../ia/IA.md) `BAT-05`). 개인정보를 담지 않으며, 사용자 신원의 확인은 추적 키로 발송처가 수행한다.

기록 항목은 다음 범위다.

- 연동 추적 키
- 동의 일시
- 동의한 동의 항목의 **버전 식별자**와 그 시점의 항목 내용(상수 값의 스냅샷)

- 동의 항목은 상수라 배포에 따라 바뀔 수 있으므로, **버전 식별자만으로는 사후에 내용을 알 수 없다** — 동의 시점의 항목 내용을 함께 남긴다.
- 보존 기간은 추적 레코드와 **다르다**. `<CONSENT_PROOF_RETENTION_MONTHS>`로 상수화하며 현재 값은 잠정이다([`../PRD.md`](../PRD.md) §미결·확인 필요).
- 버전 식별자의 생성 방식(상수 값의 해시·수동 채번 등)은 spec 단계에서 확정한다.

## 연동 지표 집계

성과 지표를 추적 레코드 삭제 이후에도 산출할 수 있게 하는 **일자 단위 카운터**다([`../ia/IA.md`](../ia/IA.md) `BAT-06`). 추적 키를 포함하지 않아 개별 연동으로 환원되지 않는다.

- 집계 단위는 **일자**이며, 누적 항목은 요청 수와 결과 구분별 건수(성공·사용자 거부·복호화 실패·전달 실패)다.
- 결과 구분은 추적 레코드의 결과 구분과 같은 값 체계를 쓴다(§연동 추적 레코드).
- 개인정보·추적 키를 담지 않으므로 **보관 기간 삭제 대상이 아니다**.

## 보관 정책

**일 단위 배치 작업**으로 보관 기간이 지난 데이터를 삭제한다([`../ia/IA.md`](../ia/IA.md) `BAT-02`). 대상별 규칙은 다음과 같고, 기간 값은 모두 상수로 고정한다([`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수).

| 대상 | 삭제 기준 |
|---|---|
| 연동 추적 레코드 | 아래 두 기준 중 **먼저 도달한 쪽** |
| 동의 증적 | 동의 일시 기산 `<CONSENT_PROOF_RETENTION_MONTHS>` 경과분 |
| 연동 지표 집계 | 삭제하지 않는다 |

추적 레코드의 두 기준은 다음과 같다.

1. **결과 확인 완료 기산** — 결과 확인이 완료된 뒤 `<RETENTION_MONTHS>`(기본 3개월)이 지난 레코드.
2. **생성 기산 절대 상한** — 결과 확인 여부와 무관하게 생성 후 `<RETENTION_MAX_MONTHS>`(기본 6개월)이 지난 레코드. 발송처가 조회하지 않은 레코드가 영구히 남는 것을 막는다.

- 동의 증적은 추적 레코드가 삭제된 뒤에도 남는다 — 사후 입증이 목적이므로 보존 기간이 더 길다.
- 배치는 애플리케이션(NestJS 스케줄 작업)에 포함된다([`infra.md`](infra.md) §애플리케이션 구성).
