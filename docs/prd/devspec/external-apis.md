# 개발사양 — 외부 API·인터페이스

AccountInterlockHub가 외부와 주고받는 인터페이스의 고정값(계약 수준)이다. 구체 필드·프로토콜 상세는 spec 단계에서 확정한다. 방향 근거는 [`../PRD.md`](../PRD.md).

허브의 외부 접점은 여섯이다 — 발송처에 제공하는 **연동 라이브러리**, 사용자 **진입**, 수신처 **전달**, **처리상태 확인**·**연동 완료 확인**·**완료 콜백** API.

## 암호화 연동 규약 (공통 전제)

발송처가 전달 데이터를 이중 암호화해 전달하고, 허브가 사용자 생년월일로 복호화한다. 암호화는 §연동 라이브러리가, 복호화는 허브가 수행하며 **양쪽은 같은 규약의 반대 방향**이다.

- **X** — 전달할 데이터(JSON). 수신처(B)에 넘길 사용자 키와 **연동 추적 키 필드**를 포함한다. 발송처는 연동 추적 키를 X의 `trackingKey` 필드에 담는다(불투명 문자열·개인정보 원문 아님·발송처와 수신처가 공유).
- **encX** = `AES256(X, 키 = 발송처키 + 사용자 생년월일(yyMMdd))`. IV는 암호화 키값을 첫 자리부터 필요한 만큼 잘라 쓰고, 권장 길이보다 짧으면 나머지를 `_`로 채운다.
- **encY** = `AES(encX 암호화에 쓴 키, 키 = 사용자 생년월일)`. 전송되는 것은 encX·encY 뿐이고, 이를 풀 나머지 키(생년월일)는 전송하지 않는다(사용자가 진입 화면에서 입력).
- **복호화(허브)** — 사용자 생년월일로 `encY` 복호화 → encX 복호화용 키 복원 → `encX` 복호화 → X 획득.
- 블록 모드·키 32바이트 정규화·패딩·encX 전달 형식(URL 길이 한계) 등 세부는 spec에서 확정한다. **확정값은 라이브러리와 허브 양쪽 구현의 단일 출처**가 된다.
- **보안 강도 한계**: encX·encY는 URL로 노출되고 생년월일은 경우의 수가 작아 오프라인 전수대입에 취약하다. 링크 만료·1회성·발송처 서명 검증 등 강화는 후속 보완 항목이다([`../PRD.md`](../PRD.md) §미결·확인 필요).

## 1. 연동 라이브러리 (허브 → 발송처 제공)

허브가 발송처(서비스 A)에 **파일로 배포**하는 라이브러리다([`../ia/IA.md`](../ia/IA.md) `LIB`). 발송처의 **Delphi·C# 프로젝트에서 모두 호출 가능**해야 한다는 제약이 형태를 규정한다 — 기본안은 **C 호출 규약으로 함수를 내보내는 네이티브 라이브러리**다(관리 코드 전용 어셈블리는 Delphi에서 직접 호출할 수 없어 제약을 만족하지 못한다).

제공 기능은 둘이다.

1. **데이터 암호화**(`LIB-01`) — 전달 데이터 X·발송처키·사용자 생년월일을 입력받아 §암호화 연동 규약대로 `encX`·`encY`를 산출한다.
2. **요청 URL 생성**(`LIB-02`) — 허브 진입 경로에 `encX`·`encY`를 결합한 연동 요청 URL을 산출한다. 허브 진입 기준 URL은 환경(운영·개발)마다 다르므로 **호출 시 입력으로 받는다**.

- 함수 시그니처·문자열 인코딩(UTF-8)·버퍼 소유권·오류 코드 체계, 대상 플랫폼(32/64비트), 동봉 산출물(호출 래퍼·샘플·헤더) 범위는 spec 단계에서 확정한다.
- 라이브러리와 허브는 같은 규약을 구현하므로 **규약이 바뀌면 양쪽을 함께 갱신**해야 한다. 버전 표기·호환 판단 방법은 spec 단계에서 확정한다.

## 2. 발송처 → 허브 (연동 요청 진입)

- 발송처가 §연동 라이브러리로 만든 URL로 **사용자를 진입**시킨다. 진입 경로는 상수로 고정된다([`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수).
- 전달 대상 수신처(B) 주소와 사용자에게 노출할 동의 항목도 같은 상수에서 결정된다.
- 사용자가 진입 화면에서 **생년월일 입력·동의·승인**을 마치면 허브가 복호화를 수행한다(§암호화 연동 규약).

## 3. 허브 → 수신처 B (연동 전달)

- 사용자의 승인·복호화가 완료되면, 허브는 상수로 고정된 **수신처(B) 전달 주소**로 복호화한 **X**를 전달한다.
- 수신처 B는 전달받은 사용자 키로 회원 여부를 판단하고 적절한 서비스를 제공한다.
- 허브는 전달 후 복호화 원문(X)을 보관하지 않는다([`database.md`](database.md) §데이터 원칙).

## 4. 처리상태 확인 API (허브 → 발송처 조회 응답)

- 발송처가 **연동 추적 키**를 기준으로 연동 요청의 처리·결과 확인 상태를 조회하는 서버 대면 API다([`../ia/IA.md`](../ia/IA.md) `API-01`).
- 응답에 포함되는 상태는 처리 성공 여부·결과 확인 여부·처리 일시·결과 확인 일시 범위다([`database.md`](database.md) §연동 추적 레코드).

## 5. 연동 완료 확인 API (허브 → 발송처 조회 응답)

- 발송처가 **연동 추적 키**를 기준으로 수신처(B)의 정보연계 처리완료 여부를 확인하는 서버 대면 API다([`../ia/IA.md`](../ia/IA.md) `API-02`).
- 판단 근거는 같은 추적 레코드의 완료 콜백 수신 여부다.

## 6. 완료 콜백 API (수신처 B → 허브 통지)

- 수신처 B가 정보연계 처리를 완료한 뒤, **전달받은 연동 추적 키**를 기준으로 완료를 허브에 통지하는 서버 대면 API다([`../ia/IA.md`](../ia/IA.md) `API-03`).
- 허브는 수신한 완료 통지를 추적 레코드에 기록한다.

## 미결

- 각 접점의 구체 요청·응답 필드, 인증·서명 방식, 오류 규약, 프로토콜(리다이렉트·서버 호출 등)은 spec 단계에서 확정한다.
- 복호화 실패(잘못된 생년월일)·수신처 전달 실패 시의 오류 응답·사용자 화면·재시도 규약은 spec 단계에서 확정한다.
- 연동 라이브러리의 구현 언어·대상 플랫폼·배포 구성은 담당자 확정 대기다([`../PRD.md`](../PRD.md) §미결·확인 필요).
