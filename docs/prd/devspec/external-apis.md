# 개발사양 — 외부 API·인터페이스

AccountInterlockHub가 외부와 주고받는 인터페이스의 고정값(계약 수준)이다. 구체 필드·프로토콜 상세는 spec 단계에서 확정한다. 방향 근거는 [`../PRD.md`](../PRD.md). 용어는 [`wiki/WIKI.md`](../../../wiki/WIKI.md).

허브의 외부 접점은 일곱이다 — 발송처에 제공하는 **연동 라이브러리**, 사용자 **진입**, 수신처 **전달**, **처리상태 확인**·**연동 완료 확인**·**완료 콜백**·**연동 규약 자가진단** API.

## 암호화 연동 규약 (공통 전제)

발송처가 전달 데이터를 이중 암호화해 전달하고, 허브가 사용자 생년월일로 복호화한다. 암호화는 §연동 라이브러리가, 복호화는 허브가 수행하며 **양쪽은 같은 규약의 반대 방향**이다.

- **X** — 전달할 데이터(JSON). 수신처(B)에 넘길 사용자 키와 **연동 추적 키 필드**를 포함한다. 발송처는 연동 추적 키를 X의 `trackingKey` 필드에 담는다(불투명 문자열·개인정보 원문 아님·발송처와 수신처가 공유). 필드명은 spec 단계에서 확정하며 여기서는 잠정 표기다.
- **encX** = `AES256(X, 키 = 발송처키 + 사용자 생년월일(yyMMdd))`. IV는 암호화 키값을 첫 자리부터 필요한 만큼 잘라 쓰고, 권장 길이보다 짧으면 나머지를 `_`로 채운다.
- **encY** = `AES(encX 암호화에 쓴 키, 키 = 사용자 생년월일)`. 전송되는 것은 encX·encY 뿐이고, 이를 풀 나머지 키(생년월일)는 전송하지 않는다(사용자가 진입 화면에서 입력).
- **복호화(허브)** — 사용자가 입력한 생년월일로 다음 순서를 수행한다.
	1. 생년월일을 키로 `encY`를 복호화해 encX 복호화용 키를 복원한다.
	2. 복원한 키로 `encX`를 복호화해 X를 얻는다.
- 블록 모드·키 32바이트 정규화·패딩·encX 전달 형식(URL 길이 한계) 등 세부는 spec에서 확정한다. **확정값은 라이브러리와 허브 양쪽 구현의 단일 출처**가 된다.
- **보안 강도 한계**: encX·encY는 URL로 노출되고 생년월일은 경우의 수가 작아 오프라인 전수대입에 취약하다. 인증·요청 제한·발송처 서명 검증을 두지 않으므로 온라인 반복 시도를 막는 장치도 없다. 이 수준은 수용 대상이며 강화는 후속 보완 항목이다([`../PRD.md`](../PRD.md) §시스템 제약사항·§미결·확인 필요).

## 1. 연동 라이브러리 (허브 → 발송처 제공)

허브가 발송처(서비스 A)에 **파일로 배포**하는 라이브러리다([`../ia/IA.md`](../ia/IA.md) `LIB`). 발송처의 **C# 프로젝트에서 호출**하므로 **.NET 클래스 라이브러리**(대상 런타임 .NET Framework 4.8)로 만든다. Delphi 프로젝트에서의 직접 호출은 이번 범위가 아니다([`../PRD.md`](../PRD.md) §수행 범위 — 제외).

제공 기능은 둘이다.

1. **데이터 암호화**(`LIB-01`) — 전달 데이터 X·발송처키·사용자 생년월일을 입력받아 §암호화 연동 규약대로 `encX`·`encY`를 산출한다.
2. **요청 URL 생성**(`LIB-02`) — 허브 진입 경로에 `encX`·`encY`를 결합한 연동 요청 URL을 산출한다. 허브 진입 기준 URL은 환경(운영·개발)마다 다르므로 **호출 시 입력으로 받는다**.

발송처에 전달하는 산출물은 다음을 포함한다.

- **배포 패키지**(`LIB-03`) — 라이브러리 파일, C# 호출 샘플, 규약 버전 표기.
- **규약 테스트 벡터**(`LIB-04`) — 알려진 입력과 기대 출력(`encX`·`encY`·요청 URL)의 대조 표. 발송처가 자기 환경에서 결과 일치를 확인할 수 있고, 허브의 규약 대칭(왕복) 검증도 이 벡터를 근거로 삼는다([`../PRD.md`](../PRD.md) §프로그램 구성·기술스택·검증 방법).

비기능 요구는 계약 수준에서 다음을 만족한다(상세는 spec 위임).

- **스레드 안전** — 공개 진입점은 동시 호출에 안전해야 한다(호출 간 상태를 공유하지 않는다).
- **의존 런타임** — .NET Framework 4.8 외의 런타임 구성요소를 추가로 요구하지 않는다.
- **배포 무결성** — 발송처가 받은 파일이 허브가 낸 산출물인지 확인할 수 있어야 한다(어셈블리 서명 또는 체크섬 제공 — 방식은 spec 확정).
- **비밀 값 미포함** — 라이브러리는 발송처키를 내장하지 않는다. 발송처키는 호출 시 입력받는다.

- 공개 API 시그니처·문자열 인코딩(UTF-8)·오류 처리 방식, 동봉 산출물 범위는 spec 단계에서 확정한다.
- 라이브러리와 허브는 같은 규약을 구현하므로 **규약이 바뀌면 양쪽을 함께 갱신**해야 한다. 버전 표기·호환 판단 방법은 spec 단계에서 확정한다.

## 2. 발송처 → 허브 (연동 요청 진입)

- 발송처가 §연동 라이브러리로 만든 URL로 **사용자를 진입**시킨다. 진입 경로는 상수로 고정된다([`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수). 연동이 1:1로 고정이므로 경로에 발송처 식별 구간을 두지 않는다.
- 전달 대상 수신처(B) 주소와 사용자에게 노출할 동의 항목도 같은 상수에서 결정된다.
- 사용자가 진입 화면에서 **생년월일 입력·동의·승인**을 마치면 허브가 복호화를 수행한다(§암호화 연동 규약).
- 진입 시점에 연동 추적 레코드를 만든다. 같은 추적 키가 다시 진입했을 때의 동작은 [`database.md`](database.md) §추적 키 중복 수신이 정한다.
- **결과 확정 후 복귀** — 오류가 아닌 결과(연동 완료·사용자 거부)에서는 허브가 요청 처리 응답에 **사용자 복귀 주소**를 함께 실어 주고, 사용자 화면이 결과를 3초 보여 준 뒤 그 주소로 이동한다([`../PRD.md`](../PRD.md) §수행 범위 6). 현재는 상수 `<COMPLETION_REDIRECT_URL>` 을 그대로 돌려주는 **개발용 더미**이며 주소의 실제 출처는 미확정이다(§미결). 응답 필드명·전달 방식은 spec 이 확정한다.

## 3. 허브 → 수신처 B (연동 전달)

- 사용자의 승인·복호화가 완료되면, 허브는 상수로 고정된 **수신처(B) 전달 주소**로 복호화한 **X**를 전달한다.
- 수신처 B는 전달받은 사용자 키로 회원 여부를 판단하고 적절한 서비스를 제공한다.
- 허브는 전달 후 복호화 원문(X)을 보관하지 않는다([`database.md`](database.md) §데이터 원칙).
- 현재 전달 응답에서 **사용자 복귀 주소를 받지 않는다** — 복귀 주소의 출처가 수신처 응답으로 정해지면 이 접점의 응답 규약이 함께 정해진다(§미결).

## 4. 처리상태 확인 API (허브 → 발송처 조회 응답)

- 발송처가 **연동 추적 키**를 기준으로 연동 요청의 처리·결과 확인 상태를 조회하는 서버 대면 API다([`../ia/IA.md`](../ia/IA.md) `API-01`).
- 응답에 포함되는 상태는 처리 성공 여부·**결과 구분**·결과 확인 여부·처리 일시·결과 확인 일시 범위다([`database.md`](database.md) §연동 추적 레코드).
- **결과 확인** — 발송처가 본 API로 결과를 받아 간 것을 뜻한다. 허브는 결과를 담아 응답한 시점에 그 레코드를 결과 확인 완료로 표시하고 확인 일시를 남긴다. 이 시점이 보관 기간의 기산점이다([`database.md`](database.md) §보관 정책).

## 5. 연동 완료 확인 API (허브 → 발송처 조회 응답)

- 발송처가 **연동 추적 키**를 기준으로 수신처(B)의 정보연계 처리완료 여부를 확인하는 서버 대면 API다([`../ia/IA.md`](../ia/IA.md) `API-02`).
- 판단 근거는 같은 추적 레코드의 완료 콜백 수신 여부다.
- 처리상태 확인 API와 통합하지 않는다 — 발송처의 호출 시점과 판단 대상(허브의 처리 vs 수신처의 처리)이 다르다.

## 6. 완료 콜백 API (수신처 B → 허브 통지)

- 수신처 B가 정보연계 처리를 완료한 뒤, **전달받은 연동 추적 키**를 기준으로 완료를 허브에 통지하는 서버 대면 API다([`../ia/IA.md`](../ia/IA.md) `API-03`).
- 허브는 수신한 완료 통지를 추적 레코드에 기록한다.

## 7. 연동 규약 자가진단 API (허브 → 발송처 응답)

발송처가 라이브러리로 만든 암호값이 허브 규약에 맞는지 **연동 전에 확인**하는 서버 대면 API다([`../ia/IA.md`](../ia/IA.md) `API-04`).

- **입력** — 발송처가 만든 `encX`·`encY` 와 **판정에 쓸 생년월일**을 함께 받는다(복호화 성공 여부를 판정하려면 나머지 키가 필요하다). 발송처 자신이 만든 값으로 자기 환경을 점검하는 용도이므로 발송처가 이미 아는 값만 입력된다.
- **판정 범위** — 복호화 성공 여부, X의 필수 필드 존재 여부, 연동 추적 키의 형식. 판정 결과와 사유 코드만 응답한다.
- **하지 않는 것** — 수신처(B) 전달, 추적 레코드·동의 증적·지표 집계 기록, 복호화 원문의 응답 포함. 자가진단 호출은 연동으로 취급하지 않는다.
- **노출 경로** — 상수로 고정한 **비공개 경로**로만 노출한다(`<SELFCHECK_PATH>`). 요청 제한이 없는 환경에서 규약 적합성 판정이 반복 시도의 수단이 되는 것을 경로 비공개로 낮춘다([`../PRD.md`](../PRD.md) §시스템 제약사항). **운영 환경에도 노출한다** — 발송처가 운영 통합 시점에 규약을 확인해야 목적이 성립한다. 경로가 알려지면 완화가 사라지므로 경로 값은 공개 문서·클라이언트 코드에 담지 않고, 유출이 확인되면 경로를 교체·재배포한다. 상수에 현재 들어 있는 값은 **잠정값**이며 저장소에 기록돼 있어 비공개로 볼 수 없다 — **운영 값은 배포 시점에 새로 지정**한다([`../../../CLAUDE.env.md`](../../../CLAUDE.env.md) §연동 구성 상수).
- 입력 전달 방식(본문·헤더)과 사유 코드 체계는 spec 단계에서 확정한다.

## 미결

- **복귀 주소의 출처** — 오류가 아닌 결과에서 사용자를 돌려보낼 주소를 어디서 얻을지 정해지지 않았다. 후보는 ① 수신처(B) 전달 응답이 돌려주는 값 ② 발송처가 전달 데이터 X에 담아 보내는 값 ③ 상수 유지 셋이며, 어느 것을 고르느냐에 따라 §3 전달 응답 규약 또는 §암호화 연동 규약의 X 필드가 함께 바뀐다. 확정 전까지는 상수 더미를 반환한다([`../PRD.md`](../PRD.md) §미결·확인 필요 7).
- 각 접점의 구체 요청·응답 필드, 오류 규약, 프로토콜(리다이렉트·서버 호출 등)은 spec 단계에서 확정한다.
- 복호화 실패(잘못된 생년월일)·수신처 전달 실패 시의 오류 응답·사용자 화면·재시도 규약은 spec 단계에서 확정한다.
- 서버 대면 API에 인증을 두지 않으므로 인증·서명 방식은 다루지 않는다([`../PRD.md`](../PRD.md) §수행 범위 — 제외).
