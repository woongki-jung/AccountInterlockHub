## 제품 정의 (한 줄)

**하나의 발송처와 하나의 수신처 사이에 고정된 1:1 사용자 연동**을, 발송처가 암호화해 전달한 값을 **사용자 동의·본인확인(생년월일)으로 복원**해 중개하는 단일 서비스. 연동 구성은 **배포 시점 상수**로 고정하고, 발송처가 쓸 **암호화·요청 URL 생성 라이브러리(C#)**를 함께 제공한다. 허브는 사용자 정보를 **지속 보관하지 않는다**.

## 목적·배경

- 개인정보를 지속 보관하지 않고 운영되는 B2B 솔루션(이하 '서비스 A')의 **회원 식별 정보**를, 지정된 외부 서비스(이하 '서비스 B')와 연동해야 한다.
- 연동 대상이 **하나로 고정**되어 있으므로, 연동을 런타임에 구성·변경하는 장치(관리자 화면·구성 저장소)는 서비스가 감당할 가치보다 비용·공격면이 크다. 구성을 **배포 시점 상수**로 고정해 서비스를 단순화한다.
- 발송처가 암호화 규약을 매번 직접 구현하면 통합 비용과 규약 이탈 위험이 크다. 허브가 **암호화·요청 URL 생성을 수행하는 라이브러리**를 제공해 발송처의 통합 부담을 없앤다.
- 전달 값의 기밀성은 **단일 암호화 JSON + 사용자 본인확인(생년월일)** 결합으로 확보한다.
- 전제: 발송처는 연동 대상 회원의 **생년월일을 이미 보유·처리**한다(라이브러리 호출 입력). 발송처의 무보관 원칙은 개인정보의 **장기 축적**을 두지 않는다는 뜻이며, 연동 요청 시점에 회원 정보를 다루는 것과 배타적이지 않다.

## 목표

- 서비스 A의 회원을 서비스 B와 연동하는 과정을, **관리자 조작 없이** 배포된 상수 구성만으로 안정적으로 수행한다.
- 발송처가 **라이브러리 호출만으로** 연동 요청 URL을 만들 수 있게 해, 규약 문서 해석·자체 구현 없이 통합을 마치게 한다.
- 연동 중개 과정에서 **사용자 정보를 보관하지 않고**(복호화한 원문 포함 미저장), 추적·증적에 필요한 최소 기록만 한시적으로 남긴다.
- 저장 구조·구성 요소를 **연동 1건 단위로 단순화**해 운영 비용을 낮춘다.

## 서비스 이용 대상

1. **발송처 (서비스 A 운용사 · 연동 요청 주체)** — 전달 데이터(X)를 만들고, 허브가 제공한 **연동 라이브러리**로 암호화·요청 URL 생성을 수행해 사용자를 허브로 유도한다. 이후 처리 상태·완료 여부를 서버 대면 API로 조회한다.
2. **수신처 (서비스 B 운용사 · 연동 대상)** — 허브가 전달한 사용자 키로 회원 여부를 판단해 자체 서비스에 연결하고, 처리 완료를 허브에 콜백으로 통지한다.
3. **사용자 (서비스 A의 고객)** — 발송처가 전달한 링크로 진입해 **생년월일을 입력**하고, 동의 항목을 확인한 뒤 연동을 승인하거나 거부한다.

> 허브 운영자는 서비스 이용 대상이 아니라 **배포 주체**다. 연동 구성 변경은 화면 조작이 아니라 상수 갱신·재배포로 이뤄진다(§시스템 제약사항).

## 제공 가치

- **구성 없는 운용**: 연동 대상이 고정이므로 운영 중 구성 조작이 필요 없다. 관리자 화면·구성 저장소·관리자 인증이 없어 운영 부담과 공격면이 함께 줄어든다.
- **통합 부담 없는 발송처 연동**: 발송처는 암호화 규약을 구현하지 않고 **연동 라이브러리 호출**로 암호값과 요청 URL을 얻는다. 라이브러리는 발송처의 **C#(.NET) 프로젝트**에서 그대로 호출한다.
- **통합 시점의 규약 확인**: 발송처는 **자가진단 API**로 자신이 만든 암호값이 규약에 맞는지 연동 전에 확인한다. 규약 이탈을 운영 트래픽이 아니라 통합 시점에 발견한다.
- **암호화 전송 + 본인확인**: 전달 데이터는 이중 암호화(encX/encY)되어 전달되고 **사용자의 생년월일 입력으로만 복원**된다. 허브는 값을 저장하지 않고 연동 실행 시점에만 복호화한다.
- **동의 기반 투명성**: 사용자가 어떤 항목에 동의하는지 화면에서 확인하고 스스로 승인·거부를 결정한다. 동의 사실은 개인정보를 담지 않는 **동의 증적**으로 남는다.
- **처리 추적**: 발송처가 연동 추적 키로 처리·결과 확인·수신처 완료 여부를 조회할 수 있다.

## 성과 지표

각 지표의 산출 근거를 함께 정한다 — 추적 레코드는 보관 기간이 지나면 삭제되므로, 삭제 이후에도 지표를 낼 수 있는 근거로 **연동 지표 집계**(개인정보 미포함 일자별 카운터)를 둔다([`devspec/database.md`](devspec/database.md) §연동 지표 집계).

| 지표 | 정의 | 산출 근거 |
|---|---|---|
| 서비스 사용량 | 기간 내 연동 처리 요청 건수 | 연동 지표 집계(일자별 요청 수) |
| 연동 성공률 | 연동 요청 대비 정상 복호화·전달·완료 비율 | 연동 지표 집계(결과 구분별 건수) |
| 발송처 통합 소요 | 발송처가 라이브러리를 받아 첫 연동 요청을 성공시키기까지 걸린 기간 | 발송처 통합 기록(수기) |

- 지표의 **목표 수치는 정하지 않고 진행**한다. 목표치는 운영 데이터가 없는 상태에서 정하면 근거가 없으므로, 배포 전까지 기준선을 관측해 확정한다(§미결·확인 필요).
- 목표 "운영 비용을 낮춘다"는 수치 지표를 두지 않고 **구조로 확인**한다 — 저장 대상 종류(추적 레코드·동의 증적·지표 집계 셋)와 배포 단위(App Service 하나 + 라이브러리 파일)가 이 방향의 결과다.

## 수행 범위

### 포함

1. **연동 구성 상수화**: 연동 구성 값을 [`CLAUDE.env.md`](../../CLAUDE.env.md) §연동 구성 상수를 단일 출처로 고정하고, 배포 시점에 애플리케이션 설정으로 주입한다(값 목록은 그 절이 유일한 열거처다).
2. **암호화 연동 규약 (허브 정의)**: 전달 데이터 X(JSON) → `encX`·`encY` 이중 암호화 규약을 정의한다. 이 규약은 **연동 라이브러리(암호화)와 허브(복호화)가 공유하는 단일 계약**이다. 상세 [`devspec/external-apis.md`](devspec/external-apis.md).
3. **연동 라이브러리 (발송처 제공)**: 발송처의 C# 프로젝트에서 호출하는 **.NET 클래스 라이브러리**로 **데이터 암호화**와 **연동 요청 URL 생성**을 제공한다. 발송처에 전달하는 **배포 패키지**(라이브러리 파일·호출 샘플·규약 버전 표기)와 **규약 적합성 테스트 벡터**를 함께 제공한다.
4. **사용자 진입·본인확인·동의·승인**: 발송처 링크로 고정 진입 경로에 진입, 생년월일 입력, 상수로 고정된 동의 항목 노출·동의 후 승인 또는 거부.
5. **연동 실행 (복호화·전달)**: 승인 시 허브가 생년월일로 복호화해 X를 얻고, 상수로 고정된 수신처(B) 주소로 전달한다.
6. **연동 결과 안내**: 결과를 네 경로로 구분해 사용자에게 표시한다 — 연동 완료 · 사용자 거부 · 링크·복호화 오류 · 수신처 전달 실패.
7. **처리상태 확인 API · 연동 완료 확인 API · 완료 콜백 API**: 발송처의 상태·완료 조회와 수신처의 완료 통지.
8. **연동 규약 자가진단 API**: 발송처가 만든 암호값의 규약 적합성만 판정해 응답한다. 수신처 전달·기록을 하지 않고 복호화 원문도 반환하지 않는다. 노출 경로는 상수로 고정한 **비공개 경로**다.
9. **연동 추적 기록·보관**: 연동 추적 키 기준 **단일 추적 레코드**를 **사용자가 진입한 시점에 생성**하고, 승인·거부·복호화 결과·수신처 전달 결과·결과 확인·완료 콜백을 같은 레코드에 이어 기록한다. 일 단위 배치로 보관 기간 경과분을 삭제한다.
10. **동의 증적 기록**: 사용자가 **어느 시점의 어떤 동의 항목에 동의했는지**를 개인정보 없이 남긴다(추적 키·동의 시각·동의 항목 버전). 추적 레코드와 별도 보존 기간을 갖는다.
11. **연동 지표 집계**: 일자 단위 요청·성공·거부·실패 건수만 누적한다. 추적 키를 포함하지 않아 개별 연동으로 환원되지 않으며 보관 기간 삭제의 영향을 받지 않는다(§성과 지표).

### 제외

- **연동 구성의 런타임 변경** — 관리자 화면·구성 저장소·관리자 인증을 두지 않는다. 구성 변경은 상수 갱신·재배포로만 이뤄진다.
- **다중 연동** — 복수 발송처·복수 수신처 구성, 연동 추가 절차는 다루지 않는다.
- **사용자 정보·복호화 원문의 지속 보관** — 허브는 사용자 정보와 복호화한 전달 데이터(X) 원문을 저장하지 않는다(추적 레코드의 추적 키값은 예외).
- **서버 대면 API의 인증** — 처리상태 확인·연동 완료 확인·완료 콜백·자가진단 API에 인증을 두지 않는다. 이로 인한 리스크는 수용 대상이다(§시스템 제약사항).
- **요청 제한** — 진입 경로·서버 대면 API에 과부하·반복 시도 제한을 두지 않는다. 이로 인한 리스크는 수용 대상이다(§시스템 제약사항).
- **보안 이벤트 기록** — 복호화 실패·전달 차단 등의 보안 이벤트를 별도로 남기지 않는다. 결과 구분은 추적 레코드에, 건수는 지표 집계에 남는다.
- **연동 결과의 발송처 푸시 통지** — 발송처는 조회 API로 결과를 확인한다. 통지 경로는 두지 않는다.
- **Delphi 프로젝트에서의 직접 호출** — 이번 범위는 C# 호출만 지원한다. Delphi 지원은 별건으로 다룬다(§미결·확인 필요).
- **기존 구현·사양의 승계** — 이전 데이터 구성·화면·사양을 승계하지 않고 본 문서의 요건 기준으로 새로 설계한다.
- **암호화 키(발송처키)의 생성·배포·관리** — 발송처키의 생성·보관은 발송처 소관이다. 허브는 규약과 라이브러리를 제공한다.
- **전달 데이터(X)의 업무적 유효성 판단** — 허브는 규약대로 복호화·중개하되 X 내용의 업무 신뢰성은 판단하지 않는다.
- **보안 강화 기능** — 링크 만료(TTL)·1회성 사용·발송처 서명 검증은 이번 범위에서 다루지 않는다(§미결·확인 필요).

## 우선순위

암호화 규약은 연동 라이브러리와 허브가 함께 구현하는 공유 계약이므로 **모든 작업의 선행 조건**이다. 규약 확정 이후는 다음 순서를 따른다.

1. **사용자 연동 본체** — 상수 기반 진입, 본인확인·동의·승인, 복호화·수신처 전달, 결과 안내. 제품의 핵심 가치가 여기서 성립한다.
2. **연동 라이브러리** — 발송처의 통합 수단. 1과 동일 규약의 반대 방향(암호화)을 구현하므로 1의 규약 확정에 의존한다. 배포 패키지·테스트 벡터를 함께 낸다.
3. **연동 API·기록·보관 배치** — 연동 실행 이후의 조회·통지·자가진단·기록 정리. 자가진단 API는 라이브러리 배포 시점에 필요하므로 2와 함께 준비한다.

## 시스템 제약사항

- **기술 스택**: 백엔드 NestJS(API) + 프런트엔드 ReactJS, 기본 언어 TypeScript. 연동 라이브러리는 **C#(.NET Framework 4.8)** 클래스 라이브러리로 별도 스택이다(§프로그램 구성·기술스택·검증 방법). 상세 [`devspec/infra.md`](devspec/infra.md).
- **배포 형태**: ReactJS 정적 빌드를 NestJS가 정적 콘텐츠로 서빙해 **하나의 Azure App Service**로 배포한다. 연동 라이브러리는 발송처에 **파일로 배포**되며 App Service 배포 단위에 포함되지 않는다.
- **연동 구성 = 배포 시점 상수**: 연동 구성 값은 [`CLAUDE.env.md`](../../CLAUDE.env.md) §연동 구성 상수가 단일 출처이며, 값 변경은 **재배포**로만 반영된다. 런타임 변경 수단을 두지 않는다.
- **공개 표면**: 사용자 진입 경로와 서버 대면 API만 외부에 노출된다. 관리자 경로·관리자 인증·IP 기반 접속 제한은 두지 않는다. 자가진단 API는 상수로 고정한 비공개 경로로만 노출한다.
- **데이터 원칙**: 허브는 사용자 정보·복호화 원문(X)을 지속 보관하지 않는다. 복호화는 **연동 실행 시점에 메모리 상에서만** 수행하고 전달 후 폐기한다. 저장 대상은 **연동 추적 레코드 · 동의 증적 · 연동 지표 집계 셋**이며 각각 보관 규칙을 갖는다. 상세 [`devspec/database.md`](devspec/database.md).
- **암호화·복호화 규약 대칭**: 연동 라이브러리가 암호화하고 허브가 복호화한다. 두 구현은 **같은 규약의 양쪽**이므로 규약이 바뀌면 함께 바뀌어야 한다. 상세 [`devspec/external-apis.md`](devspec/external-apis.md).
- **연동 라이브러리 호출 호환성**: 발송처의 **C# 프로젝트에서 호출 가능**해야 한다. 이 제약이 라이브러리 형태(.NET 클래스 라이브러리)를 규정한다.
- **접근 통제 없음 (수용 리스크)**: 인증·요청 제한·발송처 검증을 모두 두지 않으므로 접근을 막는 수단이 없다. 세 항목을 수용 대상으로 명시한다.
	- **기밀성** — `encX`·`encY`가 URL 파라미터로 노출되고 생년월일(yyMMdd)은 경우의 수가 작아, 링크와 암호값을 확보한 자가 오프라인 전수대입으로 원문을 복원할 수 있다.
	- **무결성·출처** — 허브는 발송처키를 갖지 않아 진입한 요청이 정당한 발송처에서 왔는지 검증하지 못한다. 규약대로 만든 암호값이면 출처와 무관하게 복호화·중개된다. 완료 콜백도 추적 키를 아는 쪽이면 통지할 수 있다.
	- **반복 시도** — 요청 제한이 없어 진입 경로·서버 대면 API에 온라인 반복 시도를 막는 장치가 없다. 자가진단 API는 규약 적합성을 즉시 알려 주므로 반복 시도의 판정 수단이 될 수 있어 비공개 경로로만 노출한다.
	- 강화(링크 만료·1회성·발송처 서명 검증·요청 제한)는 후속 보완 항목이다(§미결·확인 필요).
- **데이터베이스**: PostgreSQL. 운영은 Azure Database for PostgreSQL, 개발·로컬은 별도 PostgreSQL 서버.
- **신뢰 위임**: 발송처키의 관리, 연동 추적 키의 유일성, 전달 데이터의 업무적 유효성은 발송처(서비스 A)가 책임진다.

## 프로그램 구성·기술스택·검증 방법

서비스를 이루는 프로그램과 각 기술스택·검증 방법(qa 케이스)이다. qa 단계가 이 표로 프로그램별 검증 케이스를 선택한다([`qa-execution.md`](../../ai/strategies/qa-execution.md) §케이스 선택).

| 프로그램 | 기술스택 | 검증 방법(qa 케이스) |
|---|---|---|
| 사용자 웹 (진입·본인확인·동의·승인·결과) | ReactJS(TS) + NestJS 정적 서빙 | 웹·SPA UI |
| 백엔드 API 서버 (복호화·전달·상태/완료/콜백/자가진단 API) | NestJS(TypeScript) | API·서버 |
| 보관 배치 | NestJS 스케줄 작업 | CLI·배치 |
| 연동 라이브러리 (암호화·요청 URL 생성) | C# · .NET Framework 4.8 클래스 라이브러리 | CLI·배치 (C# 콘솔 호출 하네스) |

- 사용자 웹·API·배치는 **단일 App Service**로 배포되는 하나의 애플리케이션 안에 함께 구성된다(배포 단위 1개, 논리 프로그램 3종).
- 연동 라이브러리는 **별도 배포 단위**다 — 발송처에 파일로 전달되며 허브 애플리케이션과 함께 배포되지 않는다.
- 연동 라이브러리는 호출 대상이 C# 하나이므로 **C# 콘솔 호출 하네스**로 검증한다 — 하네스가 라이브러리 함수를 호출하고 결과를 표준 출력·종료 코드로 내보내므로 CLI·배치 케이스 절차를 그대로 적용할 수 있다. 하네스는 라이브러리 산출물과 함께 만든다(§수행 범위 3).
- **규약 대칭(왕복) 검증**은 별도 통합 검증 항목으로 둔다 — 라이브러리가 암호화한 값을 허브가 복호화해 원문이 복원되는지 대조한다. 근거 데이터는 규약 적합성 테스트 벡터(`LIB-04`)다.
- 보관 배치는 인앱 스케줄 작업이므로, CLI·배치 케이스를 적용하려면 **수동 실행 진입점**이 필요하다. 진입점 제공 여부는 spec 단계에서 확정한다.

## 미결·확인 필요

방향 결정은 완료됐다. 남은 항목은 **값 확정 대기**·**spec 위임**·**후속 보완** 셋이며, 어느 것도 제품 루프 진입을 막지 않는다.

### 값 확정 대기

1. **수신처(B) 전달 주소** — 수신처 협의가 필요하다. build 착수 전 확정([`CLAUDE.env.md`](../../CLAUDE.env.md) §연동 구성 상수).
2. **허브 기준 URL(운영·개발)** — 배포 대상 확정 시점에 정한다. 발송처가 라이브러리 호출 시 입력하는 값이다.
3. **자가진단 API 경로** — 비공개 경로로 두며 실제 값은 build 착수 전 지정한다.
4. **동의 안내 문구** — 현재 **잠정값**으로 진행한다. 실제 문구 확정 시 상수 값 교체만으로 반영된다(화면 사양은 상수를 참조한다).
5. **동의 증적 보존 기간** — 법령·계약 요구에 따라 결정할 사안이므로 잠정값(60개월)으로 두고 배포 전 확정한다.
6. **성과 지표 목표 수치** — 기준선 관측 후 배포 전 확정한다(§성과 지표).

### spec 위임

7. **암호화 규약 세부** — 블록 모드·키 32바이트 정규화·패딩·IV 규칙·`encX` 전달 형식(URL 길이 한계). 확정값은 라이브러리와 허브 양쪽 구현의 단일 출처가 된다.
8. **인터페이스 상세** — 각 접점의 요청·응답 필드, 오류 규약, 프로토콜, 결과 구분 값 목록.
9. **라이브러리 상세** — 공개 API 시그니처, 오류 처리 방식, 배포 패키지 동봉 범위(샘플·문서·버전 표기), 규약 버전 호환 판단 방법.
10. **보관 배치의 수동 실행 진입점** — qa 케이스 적용을 위한 진입점 제공 여부.

### 후속 보완

11. **보안 강화** — 링크 만료(TTL)·1회성 사용·발송처 서명 검증·요청 제한은 이번 범위 밖이며, 수용 리스크(§시스템 제약사항)를 줄이려면 후속으로 다룬다.
12. **Delphi 프로젝트 지원** — 이번 범위는 C# 호출만 지원한다. Delphi 호출이 필요해지면 별건으로 마이그레이션 방식(래퍼·중계 등)을 정한다.
