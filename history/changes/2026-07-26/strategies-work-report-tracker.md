# strategies-work-report-tracker (2026-07-26)

> 완료된 작업의 수행 이력을 신규 `report` 트래커 일감으로 요약 보고하는 정책 신설. **2계층**(단계 오케스트레이터가 레그 report · `session-reporter` 가 세션 report)으로 구성하고, 공용 본문 양식을 정본으로 강제했다. 담당자 지시·조합 선택(1안+3안) 2026-07-26.

- **무엇**: 작업 보고 정책 신설과 그 배선.
  - **트래커 신설** — `report`. 산출이 아니라 **기록**이므로 다른 일감의 진행·승인을 좌우하지 않는다. 보고 대상의 **연관 일감**으로 달고(하위 금지 — 대상 close 시 열린 하위로 걸린다), 등록과 동시에 **`완료`(닫힘)** 로 둔다(열린 일감 목록을 보고물로 채우지 않는다). 제목은 `[report] <구분> — <대상 요약> (#<이슈번호>)`, 판정 아이콘은 붙이지 않는다.
  - **2계층 보고** — ① **레그 report**: spec·build·qa 오케스트레이터가 자기 레그 종료 직전 직접 등록(루프 그룹 일감에 연관). ② **세션 report**: 신규 doer `session-reporter` 가 작업세션 이슈 종결 직전 등록(작업세션 이슈에 연관). 세션 report 는 레그 report 를 **인용**하고 옮겨 적지 않는다.
  - **공백 차단** — directing·운영/메타 작업은 단계 오케스트레이터가 없어 레그 report 가 생기지 않는다. 세션 report 가 작업세션 이슈 단위라 그 경우에도 반드시 남는다.
  - **공용 양식 강제** — 작성 주체가 4종(spec·build·qa·session-reporter)이므로 양식이 갈리면 보고를 모아 읽을 수 없다. 5개 절(요청과 결론 / 수행 경과 / 산출물 / 담당자 결정 사항 / 잔여·후속)을 `work-tracking.md` §작업 보고에 정본으로 두고 전 주체가 그것만 채우게 했다. 경위 미화 금지·정본 전사 금지를 원칙으로 명시.
  - **신규 에이전트** — `ai/agents/session-reporter.md`(model `sonnet` · effort `xhigh` — 확정 사실의 정형 서술이므로 [`agents.md`](../../../ai/strategies/agents.md) §모델·추론 강도 정책의 '정형 작성·실행' 기준 적용). 세션 메모리가 아니라 **Redmine 노트·일감 상태·git commit 에서 재구성**하며, 노트와 실제 산출이 어긋나면 그 불일치를 그대로 보고하도록 규정(대조 단계).
  - **보고 실패가 작업을 막지 않는다** — 트래커 미구성·API 오류 시 사유를 대상 이슈 노트로 남기고 진행한다. 레그 종료·세션 종결 어느 쪽도 보고 때문에 막히지 않는다.
- **왜**: 일감·노트가 작업 단위로 흩어져 있어 "그 업무가 결국 어떻게 됐고 무엇이 남았는가"를 한눈에 볼 수 없었다. 담당자가 경과를 파악하려면 작업세션 이슈의 긴 노트 스레드와 산출 일감을 일일이 대조해야 했다. 보고 주체 선택지 중 단계 오케스트레이터 단독(레그 상세는 좋으나 directing·운영 세션 공백)과 전담 doer 단독(세션 종합은 좋으나 레그 상세 손실)의 장점을 모두 취해 2계층으로 확정했다(담당자 선택).
