# scripts-redmine-report-tracker (2026-07-26)

> `report` 트래커 생성을 서비스 호스트에서 1회 실행할 수 있는 멱등 스크립트를 추가하고, 운영 문서에서 그것을 가리키게 했다. 담당자가 이 PC 가 아닌 다른 장비에서 실행한다고 알려와 이관 가능한 실행본이 필요해졌다.

- **무엇**: `ai/scripts/redmine-create-report-tracker.rb` **신규**. `docker exec … bin/rails runner` 로 실행하며 ①트래커 생성 ②전 프로젝트 활성 ③기존 트래커(`작업세션`)에서 워크플로 전이 복사 ④**신규→완료 전이를 전 역할에 명시 생성**까지 수행하고, 부여된 id 와 후속 문서 기입 항목을 출력한다. 멱등하므로 재실행해도 누락분만 채운다.
- **왜**:
  - **④가 이 스크립트의 핵심이다.** report 일감은 "등록과 동시에 `완료`" 로 만드는데, 신규→완료 전이가 없으면 REST 로 `status_id=5` 를 보내도 Redmine 이 **조용히 기본 상태로 떨어뜨린다**(응답은 성공). 그러면 열린 하위 일감이 남아 부모(작업세션 이슈·루프 그룹 일감)를 닫을 수 없게 된다 — 보고가 작업 종결을 막지 않는다는 정책 전제가 깨진다. 워크플로 복사만으로는 원본 트래커에 그 전이가 있다는 보장이 없어 명시 생성을 넣었다.
  - 문서에는 생성 조건 4개만 있고 실행본이 없어, 실행할 장비에서 매번 스크립트를 새로 써야 했다. 트래커는 admin 전용이라 REST 로 대체할 수 없다.
- **영향**:
  - `ai/scripts/redmine-create-report-tracker.rb` — 신규.
  - `ai/strategies/work-tracking-redmine.md` §트래커 구성 — "미완 — `report` 트래커" 항목에 실행본 경로 추가 + ③ 조건에 전이 누락 시의 실패 양상(조용한 상태 강등 → 부모 종결 불가) 명시.
  - **정책 무변경** — 생성 조건·보고 정책 자체는 그대로다. 실행 수단만 추가했다.
- **미완**: 스크립트는 **아직 실행되지 않았다.** 담당자가 다른 장비(Redmine 서비스 호스트)에서 1회 실행한 뒤, 출력된 id 를 §요소 식별자·§프로젝트 생성 표준 절차 2번에 기입하고 §트래커 구성의 "미완" 항목을 제거해야 한다. 그전까지 보고 주체는 등록 실패를 노트로 남기고 진행한다.
- **관련 일감**: (없음 — 담당자 세션 직접 요청)
