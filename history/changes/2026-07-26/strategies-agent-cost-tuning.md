# strategies-agent-cost-tuning (2026-07-26)

> 서브에이전트 model·effort 배치를 2등급에서 **4등급 사다리**로 재편하고(모델 구성은 무변경, effort 만 하향), 함께 **입력 최소화·증분 회귀·반환 규약**을 실행 규칙으로 신설했다. 토큰 사용량 최적화 목적. 담당자 지시·조정안 채택 2026-07-26.

- **무엇**: 두 갈래 개정. ①등급 사다리 재편(effort 만) ②호출 규약 신설(입력·회귀·반환).

  - **①-a 4등급 사다리** — 기존은 `opus`/`max` 와 `sonnet`/`xhigh` 두 칸뿐이라 21개 에이전트 중 **15개(71%)가 최상위 조합**이었다. `effort` 는 5단계(`low`~`max`)인데 위 두 칸만 사용해 사다리 아래 절반이 비어 있었다. 등급을 가르는 축을 ①오판의 되돌림 비용 ②백스톱 유무 둘로 명시하고 4등급으로 재편했다.

    | 등급 | 구성 | 배치 |
    |---|---|---|
    | T1 판정·게이트 | `opus`/`max` | product-loop · prd-reviewer · spec-reviewer · code-reviewer |
    | T2 해석·설계 | `opus`/`xhigh` | spec · build · qa · test-planner · prd-to-{policies·service·datas·functions·screens} |
    | T3 전사·정형 사양 | `opus`/`high` | prd-to-process · prd-to-qa |
    | T4 확정 입력 기반 실행 | `sonnet`/`xhigh` | backend-developer · frontend-developer · mockup-builder · build-installer · tester · session-reporter |

  - **①-b 모델 구성은 그대로** — 담당자 조정으로 **model 변경은 0건**이다(opus 15 · sonnet 6 유지). 11개 에이전트의 `effort` 만 내렸다(9건 `max`→`xhigh`, 2건 `max`→`high`). 점진 개선 원칙 — 되돌림 비용이 낮은 축(effort)부터 먼저 조정하고 관측한다.

  - **①-c 강등 제외 명시** — T1 4종은 아래 등급 전부의 백스톱이므로 강등 대상이 아니다. `tester` 는 T4 중 유일하게 **상위 평가자가 산출을 재판정하지 않아** 오탐 PASS 를 하류에서 잡을 수 없으므로 `xhigh` 를 유지한다(등급 배치와 별개로 문서에 명시).

  - **①-d 되돌림 기준** — 등급 하향은 잠정이다. `spec-reviewer` 가 프로세스·검증 TC 도메인에서 `오류` 이상을 2회 이상 반복 반환하면 T3→T2, 교차검증 회귀 3회 소진이 반복되거나 오케스트레이터가 판정을 잘못 라우팅하면 T2→T1 로 **해당 에이전트만** 되돌린다. 판정은 Redmine 정본에 이미 남으므로 별도 계측이 필요 없다.

  - **②-a 입력 최소화** — 디스패치 주체는 doer 가 실제로 의존하는 입력만 넘긴다. `stages/spec.md` §도메인 의존 순서에 **"필수 입력" 열**을 신설해 도메인별 정본을 두고, PRD **전문**은 정책 도메인 1개에만 준다(하위 도메인은 선행 도메인 사양이 PRD 결정을 이미 담고 있다). 범위 밖 자료는 본문 없이 **경로 목록만** 알린다. 필수 입력에 없는 자료가 실제로 필요하면 doer 는 추측하지 않고 사유와 함께 회신하며, 반복되면 표를 개정한다.

  - **②-b 증분 회귀** — 평가자 지적으로 작성 doer 를 회귀 호출할 때 **지적된 절·지점만** 고치게 하고 문서·구현의 전면 재생성을 금지한다. 회귀 호출에 지적 항목·대상 절(파일)·직전 산출물 경로(commit)를 넘기고, doer 는 무엇을 고쳤는지 절 단위로 회신한다.

  - **②-c 반환 규약** — doer 반환값은 **결론 요약 + 산출물 경로 + 후속 판단 항목**만이다. 산출 문서·코드·검증 로그 본문을 반환값에 싣지 않는다. 오케스트레이터가 본문을 확인해야 하면 경로로 직접 읽는다.

  - **③ report 본문 양식 6절 신설 — 실행 프로파일** — 본 개정의 효과가 구조 추정에 머무르므로, 근거를 누적할 자리를 `report` 양식에 만들었다(양식 5절 → **6절**). 기록 대상은 **서브에이전트별 호출 횟수(등급 병기)·회귀 횟수**이며, 토큰 소비량은 **실측 값이 있을 때만** 적는다. 호출 횟수를 본체로 삼은 이유는 실행 주체가 자기 디스패치 이력은 정확히 아는 반면 자기 토큰 소비량은 신뢰성 있게 알 수 없기 때문이다 — 모르는 숫자를 채우게 하면 이 절이 근거로서 무가치해진다. 회귀 횟수는 0회여도 명시하게 했다(증분 회귀 규약의 작동 여부를 판별하는 유일한 신호이므로 생략을 금지). 세션 report 는 레그 report 의 6절을 **합산**한다.

- **왜**:
  - **등급** — 기존 정책은 코드 작성 doer 를 `sonnet` 으로 두는 근거로 "opus 평가자가 리뷰·판정하므로"를 들면서, 구조가 동일한 사양 작성 doer(`prd-to-*` 7종, 전부 `opus`/`max`)에는 같은 논리를 적용하지 않았다 — 이들도 `prd-reviewer` 가 게이트한 PRD 를 입력으로 받아 250~300줄 템플릿을 채우고 `spec-reviewer` 가 교차검증한다. 백스톱 논리를 전 역할에 일관 적용해 사다리를 다시 그었다.
  - **호출 규약** — 비용은 에이전트 수가 아니라 **실행 횟수 × 입력량**으로 결정된다. spec 레그 1회는 writer 7회 + 도메인별 회귀 최대 3회 + reviewer 증분 7~8회이고, writer 7종이 각자 PRD 전문을 재적재하며 회귀 1회가 최초 작성 1회와 같은 비용이었다. 등급 조정만으로는 한 자릿수%에 그치므로 실제 절감의 무게는 이쪽에 있다.
