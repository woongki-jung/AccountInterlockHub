# scripts-aipm-claude-exe-resolution (2026-08-02)

> 개정한 운영 문서의 변경 경위. 본문 정본은 해당 문서.

- **무엇**: `ai/scripts/ai-pm-session.ps1` — 세션 기동 전에 **claude 실행 파일 경로를 확정**하는 해석 단계를 추가하고, 기동을 `& claude` 에서 `& $claudeExe` 로 바꿨다. 해석 순서는 `Get-Command claude` → `%USERPROFILE%\.local\bin\claude.exe` → `%LOCALAPPDATA%\Programs\claude\claude.exe` → `%APPDATA%\Claude\claude-code\**\claude.exe`(최신) 이며, 전부 실패하면 명시적 오류로 중단한다.
- **왜**: CLI 설치 경로가 **사용자 PATH 에만** 등록돼 있으면, 그 등록보다 먼저 떠 있던 부모 프로세스(탐색기·터미널)에서 상속된 환경에는 반영되지 않아 `claude` 가 해석되지 않는다. 스크립트가 `$ErrorActionPreference = 'Stop'` 이라 이 경우 `& claude` 가 **터미널 오류를 던져 래퍼가 그 자리에서 종료**된다.
	- 증상이 특이하다 — 워처 대기 중에는 `& claude` 에 도달하지 않으므로 래퍼가 멀쩡히 몇 시간을 돈다. **처리 대상을 감지해 '세션 기동' 하는 순간에만** 로그 한 줄 없이 사라진다. 2026-08-02 실측: #467 노트 감지(10:58)·#513 `New` 감지(11:21) 두 번 모두 래퍼가 즉시 종료됐고, `_session/activity` 에 `워처 감지 기동: …` 만 남고 `watchdog.log` 에는 후속 기록이 없었다. 담당자 지시가 접수되지 않고 조용히 방치되는 경로다.
- **영향**: `ai/scripts/ai-pm-session.ps1` 만. 설정·문서 배선 변경 없음. PATH 가 정상인 PC 에서는 종전과 동일하게 동작한다(`Get-Command` 가 1순위).
- **검증**: 수정 후 재기동해 워처가 #513(`New`)을 감지 → 세션 프로세스가 기동되어 **유지**되는 것을 확인했다(수정 전에는 즉시 종료). 래퍼·워치독·세션 3계층 동시 생존 확인.
- **관련 일감**: (없음 — 담당자 세션 직접 요청)

## 운영 메모 — 세션 기동 위치

ai-pm 래퍼는 **담당자의 대화형 데스크톱에 속한 터미널**에서 띄워야 한다. 다른 세션(에이전트 도구 컨텍스트 등)이 대신 띄우면 그 프로세스의 윈도우 스테이션을 상속해 **콘솔 창이 담당자 화면에 보이지 않고**, 그 도구 컨텍스트가 사라질 때 함께 종료될 수 있다. 부트스트랩 §4-C·§5 의 "래퍼는 계속 떠 있어야 하므로 로그인 세션으로 상주시킨다" 가 이 뜻이다.
