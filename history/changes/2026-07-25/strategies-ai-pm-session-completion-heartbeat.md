# strategies-ai-pm-session-completion-heartbeat (2026-07-25)

"질의 후 즉시 종료, 응답 감지·새 세션 기동은 워처(1계층)의 몫" 으로 통일하고 하트비트를 "실제 작업 중" 신호로 재정의. #2안(세션 완료 프로토콜 보정) 채택 — 담당자 승인 2026-07-25.

  - **모순 제거(핵심)**: 전략 §글로벌 운영 원칙(소통 통로)·페르소나 처리절차 6번이 "질의 게시 후 §운영 연속성 ① 자가 웨이크 폴링으로 담당자 응답을 기다린다"고 지시해, §① "`inflight` 비면 종료"와 **정면 충돌**했다. 두 곳을 **"`inflight` 비면 즉시 종료 — 응답 감지·새 세션 기동은 워처(1계층)의 몫"** 으로 교정.
  - **§① 종료 조건 강화(엄수)**: 다음 틱 예약 **전 매번 `inflight` 확인**, 0 이면 ScheduleWakeup `stop`·즉시 종료. `inflight` 빈 채 웨이크 루프 유지 = **금지**(하트비트 신선 유지 → 워치독 회수 실패 → 워처 블록 → 회신 유실). §질의·승인 요청 후도 "반드시 종료"로 강화.
  - **하트비트 재정의**: `last-poll` = "실제 작업 중" 신호. `inflight` 0 종료 대상이면 touch 중단. 긴 작업용 하트비트 유지 장치는 `inflight` 0 즉시 해제.
- **왜**: 헤드리스 `claude` 세션은 "종료"해도 프로세스가 idle-alive 로 남는데, 위 모순 지시 때문에 세션이 완료 후에도 자가 웨이크를 유지해 하트비트를 신선하게 만들었다. 지난 워치독 유휴회수 수정([`runtime-ai-pm-watchdog-idle-reap`](../2026-07-23/runtime-ai-pm-watchdog-idle-reap.md))은 **하트비트가 정체될 때만** 회수하므로 신선 유지되는 이 케이스를 못 막았다. 담당자 판단(2026-07-25): 시간 기반 강제 회수(#1안)는 긴 정상 턴(directing 퍼실리테이션·대형 노트 작성 등, `inflight` 0 이며 watermark 미전진)을 오살할 위험이 있어 폐기하고, **근원(세션이 완료 시 하트비트를 놓게)** 만 고치는 #2안 채택.
