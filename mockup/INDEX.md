# 목업 인덱스 — 사용자 연동 4화면

본 문서는 `mockup/` 의 화면↔SCR↔IA 매핑, 열람 방법, 흐름 요약, 디자인 근거, 사양 보완 후보를 담는 추적 문서다. 클릭 진입은 [`index.html`](index.html)(열람 허브), 추적·매핑은 본 문서가 담당한다. 정본은 [`ai/agents/workflow-mockup/mockup-builder.md`](../ai/agents/workflow-mockup/mockup-builder.md) §3단계.

## 단일 경로 위의 네 단계 (화면별 URL 없음)

이 제품의 사용자 표면은 **경로 하나**다 — 진입부터 결과까지 `<INTERLOCK_ENTRY_PATH>` 라는 같은 URL 위에서 진행되고, 단계 전환은 리다이렉트 없이 같은 문서 안에서 서버 응답이 결정한다([`spec-screens.md`](../docs/specs/screens/spec-screens.md) §이 표면의 형태). 즉 **SCR-001~004 는 화면마다 URL 을 갖지 않는 하나의 여정의 네 단계**다.

목업 파일은 담당자가 각 단계를 독립적으로 열람·검토할 수 있도록 **화면 1개 = 파일 1개**로 나누었다 — 이는 목업 열람 편의를 위한 분리이며, 제품의 URL 구조를 반영한 것이 아니다. 실제 제품에서는 이 네 화면이 전부 같은 문서 안에서 내용만 교체되며 그려진다.

## 열람 방법

1. `mockup/index.html` 을 브라우저로 직접 연다(더블클릭 또는 `file://` 경로 열기) — 인터넷 연결이 없어도 된다. 외부 자원(CDN·웹폰트·이미지)을 쓰지 않는다.
2. 허브에서 카드를 클릭해 원하는 화면으로 이동하거나, 각 화면 상단의 **목업 전용 도구모음**(어두운 바탕 + 노란 테두리)으로 다른 화면·허브를 오간다.
3. 각 화면 도구모음의 **상태 전환 버튼**을 눌러 사양에 정의된 화면 상태·변형을 하나씩 확인한다(§시연한 상태·변형 참고). 일부 화면(SCR-001·SCR-002)은 실제 입력 필드·체크박스도 조작할 수 있다(값 검증·API 호출 없음 — 외형만 반응). SCR-004 는 페이지를 열면 즉시 복귀 이동 3초 카운트다운이 시작된다(§시연한 상태·변형 참고).
4. 도구모음은 **목업 전용**이며 "목업 전용 — 제품 UI 아님" 라벨이 항상 붙어 있다. 카드 안쪽 흰 영역만 실제 화면 사양이다.
5. Redmine 첨부로도 같은 파일 6종(html 5 — SCR-001~004 + `index.html` — 과 이 문서)이 미러링되어 있다 — 목업 일감(§Redmine 미러 참고)에서 내려받아 열어도 된다.

## 화면 흐름 요약

정본은 [`spec-screens.md`](../docs/specs/screens/spec-screens.md) §화면 간 이동 경로. 모든 전환은 서버 응답이 결정하며 화면이 스스로 단계를 건너뛰지 않는다.

1. 발송처 링크 진입 → 구조 판정 통과 시 **SCR-001**, 진입 자체가 실패(`EX-SEC-001`·`EX-SEC-004`·`EX-OPS-002`)면 **SCR-004(경로 ②)**.
2. **SCR-001** 확인 제출 → 성공(`stage=CONSENT`)이면 **SCR-002**, 확정 결과 재안내나 오류(`EX-SEC-001`·`EX-SEC-002`)면 **SCR-004**, 형식·재입력·처리 오류는 **SCR-001 유지**.
3. **SCR-002** 승인 클릭(필수 동의 충족 시 항상) → **SCR-003**. 필수 미충족 상태에서 승인 버튼(`aria-disabled`)을 누르면 요청을 보내지 않고 **SCR-002 유지**(유효성 안내 — 화면 게이팅). 서버 재검증 실패(`EX-BIZ-001`)·처리 오류(`EX-BIZ-003`)도 **SCR-002 유지**. 재복호화 실패(`EX-AUTH-001`·`EX-AUTH-002`)는 **SCR-001** 로 되돌아간다(재입력 안내). **거부·취소 종료 수단은 없다** — 동의하지 않는 사용자의 종료 수단은 창을 닫는 것이다(`BIZ-003-03`).
4. **SCR-003** 은 조작 요소가 없다 — 응답 수신으로만 다음 화면이 정해진다. 결과 확정(경로 ①·②·③)은 **SCR-004**, `EX-BIZ-001`·`EX-BIZ-003` 은 **SCR-002**, `EX-AUTH-001`·`EX-AUTH-002` 는 **SCR-001** 로 되돌아간다. 응답 미수신은 같은 화면에서 `Unconfirmed` 안내만 한다.
5. **SCR-004** 는 이 여정 안에서는 끝이다 — 화면 간 이동 수단이 없다. **연동 완료(①)** 는 `returnUrl` 이 실려 오면 결과를 3초 보여 준 뒤 **여정 밖 복귀 주소로 자동 이동**한다(브라우저 이력 치환). 완료가 아닌 결과(②·③)는 이동할 주소를 받지 못해 화면에 머문다. 새로고침·같은 링크 재진입은 항상 **SCR-001** 부터 다시 시작하고(세션 없음), 결과가 확정된 추적 키라면 본인확인 통과 후 다시 **SCR-004**(경로 ①·③ 은 확정 결과 재안내)로 온다.
6. 뒤로 가기로 단계를 되돌릴 수 없다 — 리다이렉트를 쓰지 않아 브라우저 이력에 단계가 쌓이지 않는다.

각 화면 파일 하단의 "화면 흐름" 박스(점선 테두리)에서 위 전환을 실제 링크로 클릭해 볼 수 있다.

## 시연한 상태·변형

목업 지시(§3) 항목별 구현 여부. 전환은 각 화면 상단 도구모음의 버튼으로 조작한다.

### SCR-001 본인확인 — 6개 상태

| 상태 | 사양 대응 | 비고 |
|---|---|---|
| 초기 | Initial | 빈 입력, 알림 없음 |
| 입력 중 | Editing | 샘플 값 입력됨(보너스 — §3 필수 항목 아님) |
| 확인 중(로딩) | Submitting | 버튼 Spinner+"확인 중", 입력 필드 잠금(`readonly`+`aria-busy="true"` — 이 상태에서만 서고 나머지에서 해제) |
| 입력 오류(형식) | ReEntry(형식) | `EX-AUTH-001` 기본 문구, 필드 경계 danger |
| 재입력 안내(불일치) | ReEntry(불일치) | `EX-AUTH-002` 기본 문구, **값 유지 + 전체 선택**(실제 `input.select()` 호출), 시도 횟수 미표시 |
| 처리 오류 | Retryable | `EX-BIZ-003` 기본 문구, 버튼 재활성 |

§3 요구 5항목(초기·로딩·입력오류·재입력안내·처리오류) 전건 구현. 실제 "확인" 버튼 클릭도 확인 중 상태로 전환된다.

### SCR-002 동의·승인 — 6개 상태

| 상태 | 사양 대응 | 비고 |
|---|---|---|
| 초기 미동의 | Initial | 안내 문구 표시, 미체크 → 승인 버튼 `aria-disabled="true"` |
| 동의 완료 | Initial(체크됨) | 승인 버튼 활성 — 비활성과 대비해 시연 |
| 안내 문구 없음 | (빈 값 변형) | NoticeBlock **영역 자체를 렌더하지 않음**(`EXC-BIZ-07`) |
| 유효성 안내(화면 게이팅) | Gated | 미동의 상태에서 승인 버튼(`aria-disabled`)을 눌렀을 때 — **"모든 항목에 동의해 주셔야 합니다"**(`BR-004`, 서버 호출 없음) + 첫 미충족 항목(체크박스)으로 포커스 |
| 서버 EX-BIZ-001 | Blocked | 서버 재검증 실패 — **"필수 동의 항목에 모두 동의해 주세요."**(`BR-005`) + 포커스. **Gated 와 문구가 다름에 유의**(같은 알림 영역·다른 문구) |
| EX-BIZ-003 재시도 | Retryable | 처리 오류 문구, 승인 버튼 재활성(체크 상태 유지) |

§3 요구(거부 폐지 반영 상태 6종) 전건 구현. 체크박스를 직접 클릭해도 승인 버튼 활성 여부가 실시간 반영된다. **거부·취소 버튼은 없다** — 액션은 "동의하고 연동하기" 하나뿐이며(`BIZ-003-03`), 클릭 시(활성 상태) 실제로 SCR-003 으로 이동한다. **ConsentList 잠금(제출 중) 상태는 두지 않는다** — 유일한 트리거였던 거부 제출이 사라졌고, 승인은 발신 즉시 카드 전체가 SCR-003 으로 바뀌어 목록이 화면에서 사라지므로 잠글 대상이 없다(§사양 보완 후보 3 참고).

### SCR-003 연동 진행 안내 — 2개 상태

| 상태 | 사양 대응 | 비고 |
|---|---|---|
| 대기·진행 표시 | Waiting | Spinner(32px)+제목+보조 문구, `role="status"`·`aria-live="polite"`·`aria-busy="true"`, 조작 요소 0 |
| 응답 미수신(Unconfirmed) | Unconfirmed | 위 표시에 InlineAlert 추가(재진입 안내) — 대기가 끝났으므로 **`aria-busy` 는 해제**(`role="status"`·`aria-live="polite"` 는 유지), **네 번째** 결과 경로 아님 |

§3 요구 2항목(대기·진행 표시 · Unconfirmed) 전건 구현. 이 화면은 사양대로 버튼이 전혀 없다.

### SCR-004 연동 결과 안내 — 경로 3종 × 사유 4종(경로②) × 재안내 on/off × 복귀 이동 실시연

| 축 | 값 |
|---|---|
| 결과 경로 | ① 연동 완료 / ② 링크·복호화 오류 / ③ 수신처 전달 실패 — **네 번째 경로는 만들지 않는다**(`BIZ-001-02`) |
| 경로 ② 사유(하위 토글) | `EX-SEC-001`·`EX-SEC-004`·`EX-SEC-002`·`EX-OPS-002` 기본 문구 4종(제목·아이콘·색은 동일) |
| 확정 결과 재안내 | 배지 "이미 처리된 요청입니다"(제목 바로 아래) + 설명 문단 끝 한 문장, on/off 토글(**경로 ①·③ 한정** — 경로② 선택 시 토글 비활성화·자동 해제) |
| 복귀 이동 | `returnUrl` 있음/없음 토글(경로와 무관하게 복귀 안내 영역 표시를 켜고 끔 — **표시 조건이 경로 번호가 아니라 이 필드의 존재 여부**임을 시연) · 외부 이동 on/off 토글(**기본값 OFF** — OFF 면 실제 이동 대신 "이동했습니다"로 대체, ON 이면 실제로 `<COMPLETION_REDIRECT_URL>`(잠정 상수, 실제 값은 `CLAUDE.env.md`)로 이동) · **3초 카운트다운**("3초 후 이동합니다" 1초마다 3→2→1 갱신)을 페이지 진입 즉시 실연 |

§3 요구(결과 3경로 전부 + 확정 결과 재안내 배지 변형 + 복귀 이동 실시연) 전건 구현. 경로② 는 사유 4종까지 하위 토글로 시연해 요구 범위를 넘겨 구현했다. **경로② 는 확정 결과 재안내 대상이 아니다**(`EXC-BIZ-14`) — 화면은 경로② 선택 시 재안내 토글을 비활성화하고 안내 문구를 보여준다. **복귀 이동**은 기본 상태(경로①·`returnUrl` 있음·외부 이동 OFF)로 열자마자 카운트다운이 시작돼 3초 뒤 "이동했습니다"로 바뀐다 — 리뷰 중 페이지가 외부로 튀는 것을 막기 위한 목업 전용 대체 표시이며(제품 UI 아님, 노란 점선 태그로 표기), "복귀 데모 다시 보기" 버튼으로 재생할 수 있다.

## 디자인 근거

정본은 [`design-system.md`](../docs/specs/screens/design-system.md). 목업은 아래 값을 하드코딩으로 그대로 반영했다(throwaway 이므로 CSS 커스텀 속성 이름은 정본과 동일하게 유지하되 토큰 파일을 분리하지 않았다).

- **색 토큰 23종** — `--color-*` 전량을 각 파일 `:root` 에 원문 16진수 값 그대로 포함(예: `--color-primary:#1F5EAE`). design-system.md §색 대비 검증 실측 27행이 보장하는 조합(본문 4.5:1·경계/아이콘 3:1)만 사용했고 임의 색을 추가하지 않았다.
- **결과 3경로 시각 구분 3중(색+아이콘+제목)** — 아이콘은 전량 인라인 SVG(`aria-hidden="true"`). `--color-neutral`/`--color-neutral-weak` 토큰은 결과 패널에서 쓰이지 않고 보조 배지(재안내)가 전담한다.
- **복귀 안내 영역** — 진행 링·진행 막대 애니메이션을 쓰지 않고 텍스트만 갱신한다(카운트다운은 1초 간격 `setInterval` 로 문구를 교체). 카운트다운을 감싸는 요소는 `aria-hidden="true"`. 수동 이동 링크는 `--color-primary`·세미볼드·밑줄 유지, 최소 히트 영역은 `min-height:var(--size-hit-min)` + `inline-flex` 중앙 정렬로 확보. 이동은 `location.replace()`(이력 치환)로 수행한다.
- **모바일 우선 단일 컬럼** — 브레이크포인트 2개(`480px`·`768px`)를 그대로 구현. 기본(0~479px) 카드 패딩은 수직 `--space-lg`/수평 `--space-md` 비대칭, `480px` 이상은 카드 최대폭 440px+패딩 균일 `--space-lg`, `768px` 이상은 카드 최대폭 480px(`--size-content-max`).
- **터치 히트 영역 44×44** — 버튼 높이 `--size-control-height`(48px), 동의 항목 행 `min-height:var(--size-hit-min)`(44px), 행 전체가 레이블.
- **입력 글자 16px 하한** — 생년월일 입력 `--font-size-lg`(18px)로 하한을 상회.
- **포커스 표시** — `:focus-visible` 전역 적용, 채워진 버튼 위에서는 흰 안쪽 링(2px)+포커스색 바깥 링(box-shadow)으로 이중 표시.
- **외부 자원 0** — 시스템 글꼴 스택 + 인라인 SVG + 인라인 `<style>`/`<script>` 뿐이며 CDN·웹폰트·이미지 링크가 없다. 오프라인에서 그대로 열린다.
- **감소 모션** — `prefers-reduced-motion: reduce` 에서 Spinner 회전 주기를 0.9초 → 1.6초로 늦춘다(제거하지 않음). 복귀 이동 카운트다운은 애초에 애니메이션이 없어 감소 모션 설정에서 달라질 것이 없다.

**상수 실값의 목업 예외** — 사양·코드 본문은 연동 구성 상수의 값을 복제하지 않는다(`OPS-001-04`). 다만 **목업은 오프라인 시연 산출물**이라 실제 문구·실제 길이·실제 동작을 그대로 보여 줘야 하므로, **이 금지의 예외로 상수 실값 전반을 파일 안에 갖는다.** 현재 보유분은 셋이다.

- `<CONSENT_NOTICE>` — `SCR-002.html` 안내 영역의 문단. 실제 문구가 그대로 그려져야 길이·단락 수가 레이아웃 전제(최대 400자·3단락)에 맞는지 보인다.
- `<CONSENT_ITEMS>` 의 **항목명·설명** — `SCR-002.html` 동의 항목 행. 이 길이가 목록 레이아웃·행 히트 영역·`필수` 배지 배치를 좌우한다. (항목 코드는 화면에 그려지지 않으므로 갖지 않는다.)
- `<COMPLETION_REDIRECT_URL>` — `SCR-004.html` 의 `COMPLETION_REDIRECT_URL` 변수(단일 출처를 가리키는 주석을 값 바로 위에 둔다). 복귀 이동을 실제로 눌러 볼 수 있게 한다.

값의 **단일 출처는 [`CLAUDE.env.md`](../CLAUDE.env.md) §연동 구성 상수**이고 목업의 값은 시연용 사본일 뿐이라 정본이 아니다 — 상수가 바뀌면 목업을 따라 고친다. **사양·코드는 이 예외를 쓰지 않는다**(검증 TC 는 기대값 판정을 위한 자체 예외를 따로 갖는다 — [`spec-qa.md`](../docs/specs/qa/spec-qa.md) §테스트 환경 요약). **비공개여야 하는 값은 어느 예외의 대상도 아니다** — `<SELFCHECK_PATH>` 처럼 경로 비공개가 유일한 완화 장치인 값은 목업에도 두지 않는다(현재 보유 0건).

## 사양 보완 후보 — 처리 결과

목업 제작 중 발견한 모호·누락·상충을 spec 오케스트레이터에 보고했고, **전건 처리·반영이 완료**됐다(`accountinterlockhub#477`). 각 항목의 확정 내용·근거·목업 반영 결과를 기록한다.

### 1. 경로 ② + 확정 결과 재안내 조합 — 해소(구조적으로 도달 불가로 확정)

- **확정 내용**: 추적 키는 복호화 판정 3·4단계 통과로만 얻어지는데, `DECRYPT_FAILED`(경로 ②)를 만드는 실패가 바로 그 3·4단계 실패라 추적 레코드 자체가 만들어지지 않는다(허브에 세션이 없어 앞 요청의 키를 이어받을 수도 없다). **재안내 배지가 붙는 경로는 ①·③ 뿐이며 경로 ② 는 재안내 대상이 아니다.**
- **근거**: [`policy_BIZ.md`](../docs/specs/policies/policy_BIZ.md) `EXC-BIZ-14` · [`screen_SCR-004.md`](../docs/specs/screens/screen_SCR-004.md) §확정 결과 재안내("대상 경로 — ①·③ 뿐") · [`process_PROC-105.md`](../docs/specs/processes/process_PROC-105.md)(`RECORD` 출처가 싣는 결과 구분은 `SUCCESS`·`DELIVERY_FAILED` 뿐 — `DECRYPT_FAILED` 는 방어적 분기로만 표기) · [`data_ENT-001.md`](../docs/specs/datas/data_ENT-001.md)(`result_code` CHECK 열거형 3종, `USER_DENIED` 없음).
- **목업 반영**: `mockup/SCR-004.html` — 경로 ② 선택 시 "확정 결과 재안내로 보기" 체크박스를 `disabled` 처리하고 자동 해제하며, "경로 ②는 확정 결과 재안내 대상이 아닙니다(`EXC-BIZ-14`)" 안내 문구를 노출한다.

### 2. SCR-001 처리 오류(EX-BIZ-003) 인라인 알림의 위치 서술 차이 — 해소(목업 구현대로 확정, 변경 불요)

- **확정 내용**: 인라인 알림은 오류 유형(입력·처리)과 무관하게 **화면 사양이 고정한 알림 영역 한 곳**(본문 영역 아래·액션 영역이 있으면 그 위)에만 나타난다. design-system.md 의 "카드 상단" 서술은 폐기됐다.
- **근거**: [`design-system.md`](../docs/specs/screens/design-system.md) §상태 표현("인라인 알림의 위치는 오류 유형에 따라 달라지지 않는다") · [`design-system-components.md`](../docs/specs/screens/design-system-components.md) §InlineAlert "위치".
- **목업 반영**: 목업은 처음부터 이 방식(입력 아래 단일 알림 영역)으로 구현돼 있었다 — **파일 변경 불요**. 사양이 목업 구현에 맞춰 확정됐다.

### 3. ConsentList "잠금(제출 중)" 상태 — 해소(상태 자체를 두지 않는 것으로 확정)

- **확정 내용**: 잠금 상태를 **두지 않는다**. 목록을 잠근 채 응답을 기다리는 흐름은 거부 제출뿐이었는데 그 경로 자체가 폐지됐다(`BIZ-003-03`). 남은 제출은 승인 하나뿐이고, 승인은 발신 즉시 카드 전체가 진행 화면(SCR-003)으로 바뀌어 목록이 화면에서 사라지므로 잠글 대상도 트리거도 없다. 체크박스를 `disabled` 로 두는 상태도 없다 — 목록은 승인 제출 직전까지 항상 조작 가능하다. 비활성 토큰 쌍(`--color-disabled-bg`/`--color-disabled-fg`, 대비비 4.82:1)은 지워지지 않고 **승인 버튼의 비활성 표현에만** 쓰인다.
- **근거**: [`design-system-components.md`](../docs/specs/screens/design-system-components.md) §ConsentList·ConsentItem("잠금 상태가 사라진 이유") · [`screen_SCR-002.md`](../docs/specs/screens/screen_SCR-002.md) §화면 상태 전이("거부 제출 상태를 두지 않는다").
- **목업 반영**: `mockup/SCR-002.html` — `.consent-list.locked` CSS 규칙·`aria-busy`·체크박스 `disabled` 토글을 전량 제거했다. 토글 목록에서도 "거부 처리 중" 상태를 없앴다.

## 사양 보완 후보 — 확인 대기

이번 라운드(경로 재넘버링·거부 폐지 반영)에서 새로 발견한 모호점은 없다 — 위 세 항목의 결론이 번호만 당겨졌을 뿐 그대로 유지되고, 복귀 이동(§복귀 이동)·화면 게이팅(§조건부 표시)의 조건·문구·토큰은 화면 사양·디자인 시스템에 값 단위로 명시돼 있어 임의 추정 없이 그대로 반영했다. `screen_SCR-004.md` §접근성(복귀 이동) 6 의 "자동 이동 중지 수단을 둘지"는 **사양 자체가 이미 담당자 확인 사항으로 명시**해 둔 미결 항목이라 목업이 임의로 만들지 않았다(중지·일시정지 버튼 없음, 상시 노출되는 수동 이동 링크만 제공).
